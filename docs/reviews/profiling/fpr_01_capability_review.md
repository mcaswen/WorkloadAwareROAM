# FPR-01 实现审查

2026-09-14；依据[小规划](../../plans/profiling/fpr_01_capability_plan.md)、[代码事实](../../codebase/profiling/fpr_01_capability_facts.md)、[能力报告](../../research/profiling/fpr_01_capability_report.md)。

## Critical

没有把 DWARF 的主线程局部成功写成全线程通过。缺栈样本保留分母，最终使用大规划允许的独立 FP 构建；软件事件、三线程栈和 Tracy 完整短轨迹均有实际产物。此结论不覆盖自然任务采样。

## Major

1. 目标级接口统一客户端定义，默认关闭直接返回；现有普通原型重新生成后无需编译且程序 SHA 相同，没有生产热路径或控制流变化
2. 解析采集使用自有进程组、有界等待和独立日志；退出失败保留原始数据，不能由存在 .tracy 文件推断成功
3. Windows 挂载盘写入与 DWARF 展开限制均已记录；采集改用 ext4 后归档，不改变待测任务，也不强制系统权限调整
4. 环境、解析验证与 CMake 分工明确；暂无业务依赖倒置，下一阶段应继续复用能力，不能把自然循环复制进解析 runner

## Minor

- 官方 Linux 发行工具替代本地编译 headless 工具，版本/哈希已核验；客户端仍本地构建，遵循冻结源码
- 新输出目录需新增 `.gitignore` 对应条目，不能依赖不存在的 benchmark-output 全域忽略规则；已补入
- 同二进制短对照的下降不能视作加速；Tracy 夹具低标记数量的 +1.55% 不能代替自然开销验收
- DWARF 底层问题、自然丢失比例、公开标记关闭参数不求值和复杂异常会话仍由后续阶段承接

## 结论

FPR-01 按条件性 FP 路径闭环，可进入 FPR-02。仅采样工具与解析验证就绪，GWR 未启动；未报告任何自然函数瓶颈或算法提速。
