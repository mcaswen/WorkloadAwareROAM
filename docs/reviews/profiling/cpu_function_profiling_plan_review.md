# CPU 函数 profiling 大规划审查

2026-09-14；对象：[perf + Tracy 大规划](../../plans/profiling/cpu_function_profiling_major_plan.md)。事实依据为其列明的代码/环境核查及官方工具文档；这是规划审查，不是工具验收。

## Critical

未发现文本将尚未具备的功能冒称已实现。perf 命令当前缺失，WSL 事件源/配置仅是能力线索，实际事件、调用栈和线程覆盖必须在 FPR-01 验证；软件采样不通时不能以 Tracy 替代后标记双工具完成。

规划显式分离函数采样、插桩区间和无采集 benchmark，禁止用多线程 inclusive 时间之和、未知符号的残余分布或不同进程时间戳制造完整耗时结论。

## Major

1. **采样窗口需排除初建和诊断。** 探针目前的全量样本初建足以淹没短更新热点。规划 §8 以控制通道/应答与现有完整帧窗口对齐，并将握手单列；FPR-02 必须实际核查窗口，不用固定 sleep 猜初始化结束。
2. **插桩自身不能污染正常运行。** 规划 §5/7/10 要求宏参数不求值、目标级定义、唯一客户端与关闭产物检查；未连接不视作无开销。此边界是共享工具进入生产源码的关键门禁。
3. **短轨迹与高频函数可能造成相反风险。** perf 样本不足需要有限原轨迹重放；Tracy 则避免每样本事件。规划按不同工具分别控制规模，保留不足结论，不通过空转或改 workload 提高“充分性”。
4. **线程可见性不等于 OS 原因解释。** 规划保留真实任务区间/等待，但在调度事件不可用时不声称测得纯 off-CPU、调度开销或算法必要 span。不得把 chunk 编号当线程编号。
5. **退出和 trace 完整性有明确责任。** 会话归工具层，连接/排空有界，失败保留产物；不得将无限等待放入普通应用生命周期。具体官方版本的尾部完整性须在解析夹具验证后冻结。

以上风险均已进入阶段验收；未以重写调度器、扩图形后端或增加通用 profiler 框架解决。

## Minor

- Runtime 标记、采集会话、perf/Tracy 后端和报告各自独立，既有 PerformanceTimer 与 WorkLedger 继续复用，职责边界合理。
- 版本锁定及工具下载属于 FPR-01 的后续行为，当前只核对官方来源；完整 SHA/归档校验必须在实际取用前登记。
- 配置关闭与最小相关测试足够时，不重复全 CTest/两个后端；共享线程池修改只增加必要同步/异常检查。
- 原型 B/C、Classic/DOD 都保留各自语义和资源配置；函数热点不能自动转化为家族间同任务性能比较。

## 结论

可以提交人类 Review 的架构方案：先实际采样，再定向标记，再给出真实热点与时序报告；工具可运行不是最终完成条件。**当前仅文档，尚未实施或提交，GWR 优化亦未启动。**
