# QPC-04D 架构与阶段出口审查

日期：2026-09-16。依据：[已确认规划](../../plans/cpu_refinement/qpc_04d_error_first_ordering_plan.md)、[本轮代码事实](../../codebase/cpu_refinement/qpc_04d_error_first_facts.md)、[有限实验结果](../../research/cpu_refinement/qpc_04d_error_first_results.md)。审查对象为接收排序政策及其公共输入、续接、诊断和实验工具，没有重新审查整个Transactional架构。

## Critical

未发现阻止本阶段提交的实现级Critical问题。接收资格与排序值已经分离，P数组及donor代理不变；没有将E写回P而暗中改变两个政策。初始化、换视图、局部接口与复用槽全部生成目标键，P不变/E变化有独立用例。准备记录沿原私有prepare→publish生命周期进入索引，没有新增发布分配或失败后部分状态写回。

质量的Canyon退化属于实验检出的**政策限制**，不是由测试通过抹掉的成功项。该输入不满足规划的有限不退化出口，不能默认启用或宣称完整持续质量通过；报告已明确MIXED并保持旧默认。

## Major

### 1. 质量与成本限制已经影响政策准入

规划§8及结果§4/7：Peking/Sierra有限正面，Canyon返回Emax增加约0.4357px，逐点excess范围也扩大。三组暖CPU约2.0–3.2倍，Peking配对搜索和Sierra样本续接的工作放大有实际账本。

处理：保持显式实验开关，不将“排序实现正确”写成“质量修复通过”；不修改阈值、扩大目录或临时优化Reservation。质量与成本需作为后续Review输入，不能通过继续编号自动解除。

### 2. 公共配置、核心状态与索引的职责边界成立

公共settings唯一声明枚举，Configuration引用无行为类型；schema/catalog/ExperimentCase校验，Replay/SeedBuilder传递，既有SeedKey负责重建，SetView拒绝热切换。默认/显式Composite保持历史taskId，非Transactional不启用ErrorFirst，动态参考明确拒绝未定义组合。

Samples负责从已得到的maximum构造单一键，原块索引仍只管理排序与修复，Reservation只消费有序根。没有复制第二套堆/树、额外全Q扫描或长期E缓存；未改Controller、Commit、Mesh、几何目录或渲染器。没有发现反向实验依赖或新的God Object。

### 3. 证据完备性存在两个明确限制

规划§6.1要求自然seed hash相同，实测没有单独保存完整自然seed mesh hash；已有完整适配夹具seed内容比较、自然冻结见证seed几何比较及生成路径/输入审计。它们支持政策不改变种子，但不能冒充该项原定实测，结果已明确偏差。

规划§7/8要求较细索引账本与最终析构成本；现有公共CSV未导出这些量。本轮没有为补齐每一计数扩建profiler，保留完整CPU、既有阶段与工作量，源码复杂度和实测分开。后续若要归因索引单位成本或冷销毁，必须另有直接证据，当前不推断为零。

这两项限制不推翻已测自然最终输出/质量，不授权补全矩阵，也不支持将有限验证升级为形式证明。

## Minor

### 1. 诊断排名与历史字段兼容

ErrorFirst排名读取真实Raw全序；`priority`仍表示复合P，政策另存`policy.json`。最多两个自然全根观察点，不影响正常成本。独立脚本从完整CSV重新排序，而非调用生产helper。

旧诊断`outside_prefix`也可能表示资格未触发。报告对Sierra95已核对P与4px门槛，没有把名次0误写成前缀截断。正常`PairAuditComplete=false`的feasible也没有被解释成穷尽局部可行性。

### 2. 验证覆盖与避免冗余

执行新排序专项、原核心、边界续接、公共适配和输入解析五个C++目标；Python只跑相关两项输入/身份用例。覆盖对政策变化有风险的并发、失效、接口、原子性及配置行为，没有跑全CTest、DOD/CBT矩阵或双后端。

自然A复用历史质量前先匹配216机会输出/工作；B正常/诊断/视觉同样匹配；Peking同政策1/8线程有真实非空事务。默认前后性能未越过规范工程门槛，停止重复。注释覆盖约15.2%，新增代码采用展开式写法和有语义的中文摘要，未重排旧紧凑模块。

### 3. 工具与产物归属

采集与分析分文件，前者只编排现有runner/quality/trace，后者核对前缀、归约质量/成本和生成实际截图页。诊断无生产反向调用；临时raw mesh、逐样本数组、二进制、日志进入忽略目录，约6.4MB派生JSON与PNG附带来源和复现入口进入版本管理。

### 4. 视觉验收保持独立

六页实际图已查看，旧点与新最大点均保留；未观察到所查画面的明显新增内部裂缝，但法线/面片明暗问题仍在。热图固定量程，视域外有标识；用户视觉签收待验收，不以数值代签。

### 5. 报告补充的原因审查

按规划§11，未修改生产C++，只扩展现有分析脚本的`explain`归约和相关文档。暖工作与阶段增量使用同一窗口；修正`touches`是认证样本访问、`indexWrites`是输出网格索引写入，未把它们解释为续接或候选索引维护。预留复杂度来自当前有序集合/逐事务检查实现，不宣称为算法下界或实际拟合。

唯一追加的Canyon只读追溯约13.02秒，96机会输出哈希和公共工作匹配冻结B。frame24内部donor删除5928，在空可见认证集合下通过；后续覆盖根P低于4，未生成恢复请求。报告把直接事件、允许接受的源码条件和后续资格阻塞连起来，不再把返回新最大点停留在现象描述。固定存活高度并不禁止删点改变插值，这一缺口属于现行质量政策边界；不是本轮索引实现失效。

归约产物保留原始文件及源码SHA，可由`explain`重生成。事后见证不加入原定质量门禁，也不代表全部excess簇来源；公共输出/工作一致不冒充完整内部决策轨迹一致。没有重复C++构建、全测试或性能采样，未扩大下一阶段授权。

补充核查已独立从CSV重算同暖窗口计数及阶段均值，并核对源码SHA、归约产物一致性、文档链接和脚本语法。由保留端点复算的新对角线中点高度与追溯相同，最终见证坐标/误差与原独立质量输出相同；生产代码无差异。没有把自报的兼容标志作为唯一依据。
