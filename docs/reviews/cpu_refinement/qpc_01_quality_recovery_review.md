# QPC-01：架构与阶段验收审查

2026-09-16。对照[小规划](../../plans/cpu_refinement/qpc_01_quality_recovery_audit_plan.md)、[实现事实](../../codebase/cpu_refinement/qpc_01_quality_recovery_facts.md)、[结果](../../research/cpu_refinement/qpc_01_quality_recovery_results.md)。用户要求每个小阶段完成后验收，本页不授权下一阶段。

## Critical

本阶段没有未解决的诊断正确性阻塞。新观察器读取真实已冻结batch，生产核心文件SHA不变；240机会的mesh/hash、面数、工作量和flip计数与FER一致。没有用另一个相机、NO/ZO约定、Legacy目标重放或额外恢复轮数替代原输入。

持续质量尚未通过：边界种子误差无法由当前原语恢复，部分内部根受阈值/前缀/目录共同限制。这是本阶段揭示的研究阻塞，不是诊断完成后可自动关闭的产品质量问题。

## Major

1. **有限代表不能覆盖全域归因。** 最大簇只占山地超额样本约1%；报告明确没有把几个见证归纳成全部错误的共同原因，亦未把cell连接当连续几何证明。
2. **观察器费用不能混入runtime。** 全扫定位/排名、所有旧点和边界检查、额外donor认证是有意的离线诊断；只链接研究入口，正常算法未调用。总进程耗时另列。
3. **原生CPU工具的CBT-on链接组合已有问题。** 打开tests后Registry引入SDL/D3D依赖导致编译失败；本轮在CPU研究构建关闭CBT，逐帧结果验证该选择不改变所测CPU任务。问题保留，不顺手扩大到GPU/Registry重构；不能报告该组合已修好。
4. **后续边界修复可能改预算粒度。** 当前+2/−2事务规则与边界+1不是同一契约。报告只列必要设计问题，没有借诊断授权先实现原语。

## Minor

- 初始误将稀疏locations理解为全坐标表，采集前检查立即失败；修正为按原评价器重建Q，并核对全部保存位置及独立小网格。失败日志/过程保留，未基于错误分组运行trace。
- 首次NumPy边键uint64/int64混合报错，已显式同类型；选样成功后未改变规则。
- 第一版误差分布图近邻标签重叠，已合并标签并加引线重新查看；时序图注明各子图尺度、不可见缺段和固定投影含义。
- 原provenance紧凑代码未整体格式重写；新增编排/逻辑使用展开风格和自然中文summary注释，避免无关格式diff。

## 文件职责与规划比对

- Benchmark只负责已有ReplayInput→真实Pipeline的编排；没有第二份场景公式或公共平台adapter。
- Provenance扩展观察能力，默认旧接口保留，两个构造入口共享同一底层初始化；新脚本不进入算法层。
- 采集与归约/科学图分成两个小脚本，新增归约文件已回填规划；没有建立通用profiler或几何搜索框架。
- 全部根观察解决共享边owner遗漏风险；stage字符串只是末次结果，完整Attempts另存，避免误判全部shape失败。
- production normal before/after相同工作量；历史PQ默认三文件逐字节一致，已覆盖本改动兼容风险。七项错误输入检查和240机会真实oracle比对替代无关全CTest。
- 原源文件、预算、相机、Q、prefix及高度政策未变化；无性能/质量策略实现夹带。
