# GMP-02 事务组合与续接审查

2026-09-14；同 Agent 自审。依据 [小规划](../../plans/cpu_refinement/gmp_02_transaction_batch_plan.md)、[推导](../../research/cpu_refinement/transaction_batch_derivation.md)与有限脚本结果。

## Critical

本阶段完成了条件式一般组合证明，明确所有证书读取、边关联不存在性、旧高度写入和派生归约的前提；没有把删除面不交当成完整并发条件。有限脚本中相邻交换虽然删除面不交，但共写接口边，第一次正例假设因此失败。保留该组合作为拒绝例，正例改用中间隔一列的两个交换，没有放宽冲突断言。

样本支持使用完整闭补丁及外接口关联。95 个固定点中有 56 个进入受影响支持，13 个发生变化的样本旧 owner 在保留面上；局部重算与全量参考相同。这是旧 owned-only 策略确实会漏项的具体证据。

## Major

两组正/反序共四种应用排列通过：两个净零交换，以及只共享保留点的两个接收操作。边/点嵌入、面数、公共边界、owner、闭面关联、顶点邻接和诊断评分均与独立重建一致。高度证书 R/W 冲突、重复贡献和额外无预算接收作为负例检查。

脚本的局部修复只限制受影响记录，定位/评分辅助仍含全域诊断扫描；没有验证未来高效索引或生产持久状态实现。正常路径的局部支持与 O(sd)/O(D²) 费用来自纸面前提，不从这份小脚本的运行时间外推。未实现自然透视拟合或真实多线程。

## Minor

旧几何函数按职责复用，未修改旧检查脚本或生产代码。本阶段新增一个验证脚本和一份推导，不增加通用事务/缓存平台；状态表明确相机变动可以全域刷新。
