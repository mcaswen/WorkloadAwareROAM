# 事务化 LOD 平台接入大规划自查

> 2026-09-15。对象：[接入大规划](../../plans/cpu_refinement/transactional_platform_integration_plan.md)与[接入边界事实](../../codebase/cpu_refinement/transactional_platform_integration_baseline.md)。本页是方案自查，不是独立同行评审、实现验收或用户批准。

## Critical

**未发现仍被方案隐瞒的关键架构冲突；目标边界已于 2026-09-15 获用户确认。** 以下关键问题已作为显式契约处理：

1. 新一般网格不能被解释为 DOD 层次状态。方案选择独立算法 ID、自有核心与公共输出；冷启动只调用一次 DOD，后续不向旧状态写回或获取目标 J。
2. 原型依赖不能原样反向接入生产。运行核心、研究输入/验证和公共同步工具分开归属；CMake 不再要求构建 tests 才能提供核心。
3. 静止视图跳过会改变有限批次算法行为。新增持续更新能力，不以空批次判断全域收敛；暂停/单步与正常一批/更新机会明确区分。
4. 深度域不一致不能只在 renderer 修正。NO/ZO 明确进入输入和配置，覆盖样本、拟合约束、区间及精确回退，避免仅改最终可见性 if。
5. 消费 Pending 后上传失败不能靠再次 Consume 自动恢复。方案明确桥接失败与上传失败的全量重新同步责任，且不重置算法掩盖问题。

## Major

以下风险保留并进入对应阶段的验证，不认为已经解决：

- **初始化与 reference**：一次公共 DOD 输出是否能形成满足声明域的种子仍需 TPI-02 证明；HeightMap 新增原始数组必须保持旧 float 语义，记录冷启动/内存影响。若种子协议失败，不得暗中多跑 Legacy 或换成历史 seed。
- **连续质量与可用视图域**：已知跨视图误差、前缀停滞及近面异常继续存在。捕获异常只证明失败可控，普通交互若频繁失败，仍不能宣布实用接入通过。
- **公共 float 输出**：内核 binary64 合法不是最终光栅输入保证。方案要求受影响输出的有限/退化检查，并用实际公共 mesh 做独立质量评价。
- **共享池迁移**：涉及旧 DOD/MPR 的构建和前向声明，必须保持原行为及异常排空契约。优先使用薄兼容与共享实现，不在这一步同时换任务算法。
- **时间与状态公平**：核心移植前后、适配前后、图形后端和算法家族是不同对照。方案分开冷启动/普通调用/上传/帧时间，以及同任务 B/C 和不同语义 Classic/DOD；旧 SVE 数字只作背景。
- **实际平台环境**：原生 Windows 与 WSL 图形可用性尚未验收。两个后端分别记录运行结果，缺失时标记未验证，不用编译或另一平台替代。

上述风险各有对应职责和阶段出口；没有以“平台必然更快”作为架构依据，也没有要求在接入前穷尽全部优化。

## Minor

- 核心搬移会改变 profiling 源码归档路径，脚本需同步当前清单；历史报告和已记录二进制来源不能随新目录机械改写。
- 原型版本在纯视图变化时递增，不是内容哈希；消费者按范围、数量与恢复状态判断上传，不能仅凭 generation 增加全量复制。
- 新算法不适用旧五阶段字段，报告必须显示不适用或独立阶段模型；请求线程数量也不能冒充真实参与数量。
- 默认 `all`、旧 formal 配对与上传实验不会自动扩成新矩阵，避免一次接入悄悄改变历史实验范围。

## 文件职责与阶段顺序核查

核心由 `algorithms/greedy_transactional_lod` 持有；SeedBuilder、公共适配和 RenderBridge 分离初建/生命周期/输出。公共工具不反向依赖算法，研究层依赖运行核心。renderer 保留各自资源模型，只处理算法选择、调用与输出消费。

TPI-01 先解决依赖和共享线程回归，02 锁定公共/输入/数值契约，03/04 分别接入两个消费者，05 才作持续质量与剩余性能空间判断。每阶段包含前后性能和必要正确性验证，未要求全量 CTest 或重复 SVE 矩阵。

**用户已批准按大规划自主闭环。当前仅完成文档与源码边界核对，TPI-01～05 尚未实施；后续逐阶段记录验证与提交。**
