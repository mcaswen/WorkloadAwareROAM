# PQ-04：有限局部恢复调查的阶段审查

2026-09-15。审查对象为[规划](../../plans/cpu_refinement/pq_04_local_recovery_plan.md)、[代码事实](../../codebase/cpu_refinement/pq_04_local_recovery_facts.md)与[结果](../../research/cpu_refinement/pq_04_local_recovery_results.md)。按用户授权自主闭环、逐阶段提交。

## 结论

**本阶段有限存在性诊断完成，并获得正例；持续质量修复未通过。** AB翻边证明原E/F/H未覆盖同一小域内所有恢复机会，不能把这项结论扩大为已实现完整恢复算法。

## Critical

未发现阻止保留本次诊断的新增Critical问题。

- 原24帧仍应用原Plan结果；诊断只借用状态并写私有几何。
- 形状先于质量，独立有理几何核对全部17项，没有用采样误差接受替代结构正确性。
- 旧点与净面数实际保持，唯一正例不依赖新增高度自由度、donor或放宽预算。
- 未查询的高度、形状拒绝和构造拒绝分开记录，没有把未尝试写成质量失败。

生产持续质量仍有原阻塞。这里的“未发现新增问题”不表示原生产算法已符合长期质量要求。

## Major：后续不能越过的研究边界

1. **连接改变也能产生逐点退化。** 结果§5.2记录0.026626px代价。冻结旧点只排除了旧顶点移动，不提供所有未来视图或逐点非退化保证。后续需要明确生产接受政策，不能仅凭本正例加入默认目录。
2. **净0存在性不等于生产可执行事务。** 当前私有`Kind='R'`没有进入生产意图、预留、提交或续接链。即使无需额外三角形预算，也要定义与原批次的冲突、样本归属、优先级更新和停止语义；本阶段正确地没有预支这些能力。
3. **一次恢复不保证持续进展。** 翻边后两处最小角仍在等号，有限后续插点全失败。它只否定“本固定域没有局部恢复机会”，没有证明可以靠同类操作把残差收敛到DOD。
4. **诊断成本不是生产费用。** 根定位全扫N，质量路径包含重复旧测量、闭支持审计和输出；不能将20.8ms当未来翻边的必需开销，也不能称其可以全部消失。需在真正接入时另计发现/认证/维护成本。

以上是后续研究边界，不是要求在PQ-04里继续扩几何原语或持续轨迹。

## 架构判断

新增职责位于实验模块，原探针只增加一个互斥调用入口；没有向生产核心或旧大型追溯文件堆入几何搜索。C++有限构造和Python独立验证分属不同职责，复用已有区间求交、原认证、限额启动和报告比较。

`Run`的专用编排与日志仍在同一实验文件，范围是单个已冻结案例，不建设可扩展恢复框架。样本模型公开方法用于解析对应测试；没有引入泛化状态接口、反向生产依赖或全状态副本。当前拆分符合批准的小规划边界。

可以关闭PQ-04并提交。下一步若进入生产恢复，应将净0连接修复作为一个需明确语义和续接义务的候选，与PQ-03的高度选值政策分开处理；本审查不自动授权改变生产算法。
