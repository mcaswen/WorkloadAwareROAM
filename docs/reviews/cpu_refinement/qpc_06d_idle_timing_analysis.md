# QPC-06D：静止区间小幅差异的独立分析

2026-09-17。对象为[06D计划](../../plans/cpu_refinement/qpc_06d_receiver_task_balance_plan.md)的回归检查；不是新增修复规划。原始证据`benchmark-output/cpu-refinement/qpc-06d/run-01/recheck/dem-canyon-P/`，归约见[summary](../../research/cpu_refinement/data/qpc_06d_task_balance/summary.json)及[复测CSV](../../research/cpu_refinement/data/qpc_06d_task_balance/timing-recheck.csv)。

## 现象与影响范围

Linux Canyon P恢复事件frame64～95的CPU均值首测1.513→1.631ms；唯一一次定向旧/新复测1.473→1.556ms，即+0.083ms/+5.64%。中位0.613→0.684ms，但P95从2.902降到2.800ms。该区间包含冷视图/首次求解和后续空机会，不能把整个均值当作一个空缓存查询。

Windows同输入复测事件均值1.758→1.671ms、P95改善；中位0.178→0.232ms。移动段新版本在两系统仍下降约33%，这不消除静止差异。差值超过0.05ms的绝对筛查线，已触发并完成一次复测，不追加第三次。

## 已做排查与排除项

1. 前后使用相同冻结配置，原二进制及其源快照保留。所有96帧输入、曲面、逻辑结果及整数工作一致，排除改变质量/工作人口造成这里的时间差。
2. 从同一既有CSV进一步选出30个`viewMs=receiverMs=sampleRepairMs=touches=vertexWrites=indexWrites=0`的恢复机会。Linux均值0.5513→0.6169ms，中位0.6121→0.6722ms；Windows均值0.1818→0.2176ms，中位0.1629→0.2184ms。这个筛选仅定位来源，不替代预注册32帧主分母。
3. `TransactionalPipeline::Update`先查`_idlePlan.Find`，命中后直接返回，在`TransactionalReservation::Plan`之前结束。新`RunIndependent`只在后者的接收阶段出现。因此不能把这些空机会差值解释为新增原子领取或160根认证本身的直接开销。
4. 原有空批复制/释放和平台统计仍在边界中，没有因本修改删除。既有工作量列不能拆出分配器/缓存/抢占时间，所以“修改改变跨帧堆布局”与“有限运行波动”均仍是待证假设。
5. Linux上述空机会旧时间范围0.245～0.764ms，新0.269～0.837ms，帧间波动远大于均值差；但帧非独立重复，不能仅凭分布重叠宣称已证明无版本影响。跨系统事件均值符号也不同。

## 原因判断、处理与边界

已证实的是小幅残余和它位于未执行新调度入口的空机会中；**未证实版本因果关系与具体机制**。既不能写成“新增调度导致回退”，也不能写成“肯定是噪声，已修复”。当前静止低延迟性能保持未定状态；移动任务均衡的主目标另行成立。

遵守开发规范的微小差值和复测上限，本阶段不继续采样、不加入缓存/分配器修复、不自行扩展优化规划。实现与证据随阶段交付，原始慢数据保留，不进入下一阶段。如用户认为该低延迟差值具有实际影响，再在独立小规划或后续规划中指定相应修复；本记录不替代该决定，也不将性能问题标成修复型关闭。
