# GTP-02 局部续接实施审查

2026-09-14；同 Agent 自审。依据[规划](../../plans/cpu_refinement/gtp_02_persistent_state_plan.md)、[代码事实](../../codebase/cpu_refinement/gtp_02_persistent_state_facts.md)与[结果](../../research/cpu_refinement/gtp_02_persistent_state_results.md)

## Critical

未发现阻止本阶段闭环的未处理问题。自然连续三轮的拓扑、owner、闭面贡献、评价和下一 raw 与全量 oracle 一致，Pending 延迟消费与槽复用完成；正常更新没有重导入、全状态复制或全 Q 修复。高度保护不替代原视域接受契约，视域外退化明确记录

准备与发布已拆分并覆盖全部派生状态。容量、局部目标、样本、输出和 Pending 先完成，最后配额检查后仅做预留写入及节点转移；没有在核心已发布后进行可能失败的几何恢复。模块内 Prepared 值的受信任范围保持明确，未将其暴露成生产公共接口

## Major

1. **全局成本仍存在。** 下一 raw 的元数据全序和 donor 池构建没有声称 O(k)，尤其 Peking 无实际修改时 donor order 仍约 8ms。竞争性动态 A 不能每个事务全扫 Q，后续要明确正常候选维护与停止
2. **持续质量尚未完成。** 正常 Peking 的 Hmax 达到 4.112899，当前视图 screen max 不增。GTP-03 必须检查移动/返回视点，不能把本阶段 PASS 写成长期质量 PASS
3. **保护并非免费。** test129 保护约 77ms，增加后仍有批宽，但属于不同事务集合。精确证据同批复用，不使用每个 pair 重做全 Q 的实现
4. **容量开销已显式化。** 实施中将精确逐次 reserve 改为共同几何增长，避免每次空额度细分搬移整段 mesh；记录 Peking 首轮约 4MB 的偶发成本，后续轮没有隐瞒全扫
5. **性能检查没有选样。** 首次 test 初建相关差值越线后只做一次预定复测；旧版本本身变动明显，共同边界无可重复回归证据。新增局部维护与 mesh 工作单列，未直接以初建对持续帧报告加速

## Minor

Samples、Mesh 和 Commit 按所有权分开；公共 mesh 值复用已有 GLM，生产无反向依赖。没有新求解器、线程池或普适事务平台。共享采样/评分计算经小范围提取复用，完整刷新保留为独立编排的 oracle
