## Major

1. Linux与Windows费用不能定量移植。报告已分别展示正常平台阶段、Linux函数采样与Linux线程时序；不把百分比乘原生毫秒数，不将任务时长和叫CPU work。
2. 两政策会产生不同曲面/支持/批宽。已报告实际面数和操作人口；50k预算的Sierra仅约9千～1万面，不能误标饱和50k。L/P时间是成本对照，不是等价加速。
3. 均摊任务敏感性不是承诺。当前缺少每根时长，不能声称重分块必然得到1.8×；异常、配额和汇总成本在后续候选验收中必须纳入。
4. 当前性能/持续质量总目标仍未通过。诊断完成不能替代优化实施，也不能凭热点比例解除严格数值或质量义务。

## Minor及已处理

- Sierra L仅1811个ROI样本，原计划允许至多一次补采；本次保留低样本标记，限定为粗粒度路径参考，不追加采样追求精细排名。
- 未知祖先较多，原始统计完整保留；业务符号采样与缺栈严格区分，没有把整个未知inclusive说成未知CPU时间。
- 完整模板符号/调用栈很大，保留所有函数、调用边；全栈CSV仅gzip压缩，summary删除与CSV重复的大符号列表。
- 同线程self扣子区间、跨线程派发关联继续复用已有解析规则；新增归约增加权重恒等、96帧、模式行为与嵌套检查。未建设新的通用profiler。
- 明确`gtp.receivers`是cursor构造、`pointwise.certify`包含receiver/donor，Measure嵌套Fit，不重复相加。
