# QPC-06F 实施后架构审查

2026-09-18。依据：[阶段规划](../../plans/cpu_refinement/qpc_06f_height_rejection_plan.md)、[实现事实](../../codebase/cpu_refinement/qpc_06f_height_rejection_facts.md)、[结果与限制](../../research/cpu_refinement/qpc_06f_height_rejection_results.md)。这是实现闭环审查，未扩展其他模块。

## Critical

未发现阻断交付的问题。历史提示仅为样本身份；当前支持/覆盖/人口/高度必须重新确认。提示只能拒绝，成功仍完成双域完整证书。34,705次提示拒绝全部经原认证确认；两场景96帧同政策结果、预算、公开网格哈希一致。有限核查没有被写成全实现形式化证明。

形状类别、NeedsFlipRecovery、目录/根序、预算和预留规则保持；影子重放只在诊断启用。没有通过移除未知/触限样本、替换数值精度或改变前缀获取速度。

## Major

没有新增需阻断的小规划边界问题。数值充分判据、提示表和Pipeline所有权分别放在独立文件；Reservation只负责读取和确定归并，worker不写共享map。提示表下层不反向依赖控制器或研究设施。现有PointwiseQuality仍负责完整认证，没有在Reservation复制高度数学式。

**研究限制继续保留：**Sierra源高仍1.66×旧Fit，有限降本不解除04H全部性能问题或质量风险。完整支持整理、成功/无提示认证与Samples::Prepare仍贵。该项是未完成研究目标，不应以本轮通过删除，也不构成本轮等价优化必须无限扩展的理由。

## Minor

1. **异常语义澄清已回填。** 原规划笼统写“异常丢弃新提示”，实际Remember可能已归并部分记录，后续Apply准备失败时提示也可保留。业务状态不半发布；每次提示都重证，故无需为无权威辅助状态新增完整回滚事务。规划、事实与推导已对齐此边界。
2. **有限空间的精确口径已记录。** 固定数组2048条；有序索引满表替换先分配再删除，瞬间最多2049个map节点。不能把固定容量写成零分配。峰值entries只是持久条目观测，不是RSS。
3. **诊断成本分离。** RecoveryTrace手动Plan/Apply持有自己的提示表，并打开影子重放；普通路径只有Pipeline表且不开影子。诊断时间不用于性能门禁，task_wall_sum不当CPU时间。
4. **采样限制公开。** perf的未知祖先很多，保留函数/调用边原始摘要，不声称完整精确调用图。跨平台毫秒不拼接；实际收益使用原生普通计时，且每变体一个进程仅支持工程判断。
5. **成本恒等式已纠正。** Recheck可预热同次面系数，提示未拒绝后剩余遍历不能直接等于原遍历。HR-05、规划和总览改用v'_i；原初稿简式只在非负计数模型下作为充分条件，不宣称机器时间必然满足。
