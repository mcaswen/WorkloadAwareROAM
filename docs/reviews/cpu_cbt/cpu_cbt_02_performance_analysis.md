## 1. 结论与影响范围

test129 的 `reference → serial` 细分组合调用中位数差，在首轮和唯一一次复测中均超过原冻结门槛。复测配对差中位数为 **+0.12355 ms**，门槛为 **0.06740 ms**。这是新串行提交边界的局部成本问题，不能写成“全部性能验收通过”。完整 `updateMs` 与 `updateAndMeshMs` 的中位数/P95 均未越过各自门槛，默认参考档也未发现同期开销退化证据。

当前不继续微分计时、调阈值、增加场景或改实现。按[开发规范第 7.3 节](../../standards/development_guidelines.md#73-工程性能回归的实际影响门槛)保留分析，由用户决定另开修复小规划，或调整后续规划处理；若用户决定暂时关闭，同样应保留本记录，不将关闭追认为性能没有差异。

## 2. 冻结协议与触发

沿用 CPU-CBT-01 修改前五个独立进程的统计值：`max(0.05 ms, 原统计值的5%, 原五值极差)`。中位数与 P95 分别冻结；不是用本轮较大的波动范围重新定门槛。独立进程为主要统计单位，版本差取同块进程统计的差，再取五对中位数，不把 96 轮当成独立重复。

首轮为两场景各一个预热块和五个测量块，共 48 个进程，含 8 个预热。检查 B→R 与 R→S 的 12 个共同计时指标、中位数/P95，共每场景 48 个工程比较项。B 是归档旧程序；R/S/P 为新程序中的原参考、新串行、新四线程。

| 首轮触发项 | 配对差中位数 ms | 冻结门槛 ms | 唯一复测差 ms | 处理 |
| --- | ---: | ---: | ---: | --- |
| test129，R→S，`bisectCommitMs` 中位数 | +0.07960 | 0.06740 | +0.12355 | 同一项复现，保留局部退化 |
| Peking，R→S，`classificationGeometryMs` P95 | +0.35160 | 0.34157 | +0.09962 | 未复现，关闭为无稳定版本相关退化证据 |

复测只运行这两个场景的 R/S：每场景预热 `R,S`，五个测量块 `RS,SR,RS,SR,RS`，共 **24 个进程，含 4 个预热**。不重跑 B/P，不改源码、程序、输入、线程、诊断开关、环境设置或门槛。

复测另出现 test129 分类 P95 `+0.051775 ms`（门槛 0.05 ms）、Peking 分类几何中位数 `+0.55730 ms`（门槛 0.29210 ms）。这两项首轮未触发，尚不满足同项持续复现；如实保留于 `repeat-analysis.json`，不选择性删除，也不因不同统计量轮流触发启动第二次复测。

## 3. 定位过程与原因边界

**已证实：** 两轮采集的工作计数、拓扑、状态及完整网格摘要都与三档直接字段诊断对应，输入和输出没有因新增工作量改变。R/S 使用同一程序，S 不创建线程池，不派发任务。因此这项 R→S 差值不能归因于线程调度或等待。

test129 有 81/96 轮没有细分模板，仍执行原参考或新内核的完整数组准备。复测这 81 轮的 `bisectCommitMs` 进程内中位数如下：

| 配对块 | R ms | S ms | S 的 `bisectPrepareMs` ms |
| --- | ---: | ---: | ---: |
| 1 | 0.95450 | 1.07490 | 1.07380 |
| 2 | 0.93610 | 1.07810 | 1.07730 |
| 3 | 1.00060 | 1.09380 | 1.09260 |
| 4 | 1.01340 | 0.99820 | 0.99610 |
| 5 | 0.99740 | 1.11790 | 1.11610 |

空模板轮不存在局部填写工作，额外成本已经出现；S 的提交成本几乎都位于 `PrepareMs`。故问题首先定位到**新内核准备路径及其内存行为**，无需先调查模板算术或传播正确性。

**源码事实：** 新内核在复制三个完整物理数组之前，创建逐模板记录，并由 `PrepareOwnership` 每轮创建/清零 `ids.size()` 字节的独占槽标记。标记长度是 131078，即使没有模板也创建。随后仍复制编号、邻接和节点数据，预留结果列表。新串行与新并行使用同一准备流程；原参考没有这个独占槽标记。所有权预检是本阶段批准的安全边界，不能为性能结果直接删除。

**尚未证实：** 当前分段把预检、分配、清零和三个数组副本合为一项，不能断言全部 0.12355 ms 都由 131078 字节清零造成。分配器状态、缓存状态、编译布局及系统调度对差值的贡献未隔离。各进程绝对成本也存在波动；没有做硬件计数器或逐分配跟踪，不能声称已经找到唯一根因。

## 4. 修复授权边界

若另开修复小规划，首个可 Review 的方向是为**空模板输入**核查等价的准备路径：仍返回原语义要求的数组结果，避免没有所有权要检查时创建标记和记录。该方向只是假设，尚未修改，也不承诺它足以消除全部差值。

稀疏复制、持久工作缓冲、绕过空提交、改变整个更新的存储或发布接口，均超出 CPU-CBT-02 已批准边界。当前完整更新并行收益不明确，不建议为了局部成本顺手扩成此类存储重构。用户也可决定将问题交后续规划处理或暂时关闭，而结束当前原型投入。
