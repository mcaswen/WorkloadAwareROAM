## 1. 架构审查

### Critical

未发现阻止本阶段交付的问题。两个固定轨迹共 192 轮通过拓扑、预算和全量网格审计；失败不发布、同轮旧合并重验和释放复用有定向证据。

### Major

未发现偏离已批准文件归属、依赖方向或轮次语义的问题。`CpuCbtState` 持有数据和生命周期，`CpuCbtUpdate` 包装轮次，`CpuCbtMesh` 负责几何；诊断与 CSV 留在独立驱动。直接复用参考七组纯 C++，未修改参考模板、引入 DOD 依赖或图形运行时。第一阶段全串行，没有提前加入正式并行算法、质量调度或长期实验平台。

### Minor / 已知边界

1. 当前参考提交复制完整物理池，即使稳定无模板也有成本；分类和网格各自全量求几何。这是已批准参考串行档的实际行为，成本已保留，不在本阶段顺手优化。下一阶段必须通过 reference serial / new serial / new parallel 区分移植与线程收益。
2. 驱动的 FNV64 拓扑/网格摘要用于同平台重复一致性；不是一般逻辑同构证明。解析夹具另有直接字段核对与自然轨迹的独立全局审计。
3. 嵌套参考仍为本地依赖，原型默认关闭；复制到其他机器时需准备相同纯 C++ 子集。目标在缺失源或 GLM/STB 时明确失败，不导入整个参考工程。

上述均已在代码事实与规划边界中记录，无需扩大本阶段修复范围。

## 3. 正确性验证

MSVC 19.38.33145、VS 2022 x64、Release、本地 GLM/STB。原型两个目标构建完成；`ctest --test-dir build/cpu-cbt-01 -C Release -R '^CpuCbt$' --output-on-failure` 最终 1/1 通过，测试耗时 0.31 秒。

定向夹具覆盖四种细分模板、长兼容链的保守预留及拒绝不残留模板、共享闭包去重、满物理池、两类合并、旧合并在同轮细分后失效而另一请求仍有效、持续 split/merge/释放复用、B=6、非法邻接/深度及失败不发布。首次同轮组合夹具未正确建立面对面兼容关系，修正了夹具的基础邻接和强制模板；没有修改参考算法。最终用例同时断言“细分前两请求均可合并”和“细分后只剩一请求可合并”。

每个自然输入只运行一次 validate，覆盖全部 96 轮：活动编号、六前缀和无祖先重叠、占用一致、邻接反向引用、非退化、UV 全覆盖、完整内部边配对及边界。端点实际距离容差 1e-6，总面积容差 1e-5，未放宽容差。每场景另有一次预热和五个独立 measure 进程；逐轮非计时、非诊断工作字段和拓扑/网格摘要均与 validate 记录一致。没有把这些计量进程重复算作全局审计。

环境为 Ryzen 9 9950X3D（16 核、32 逻辑处理器）、Windows 11 build 26200、内存 131654004 KiB、Normal 优先级、Balanced 电源、全亲和性。未同时构建或采集另一条性能路径。系统后台负载未被独占，因此报告是该记录环境下的基线，不是独占硬件极限。
