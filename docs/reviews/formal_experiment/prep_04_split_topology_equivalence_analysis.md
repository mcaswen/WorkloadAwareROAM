# PREP-04：细分拓扑策略不等价分析

> 日期：2026-09-10\
> 状态：已复现，阻断 PREP-04 完整目标集验收；修复方案尚未确认\
> 关联：[PREP-04 小规划](../../plans/formal_experiment/prep_04_minimal_cpu_pairing_plan.md)第 6.4、8.2、10 节，[当前配对事实](../../codebase/formal_experiment/cpu_pass_pairing_contracts.md)

## 1. 结论与范围

FACT：`peking547-a-b20000 / splitTopology / sampleIndex=14 / selectionRank=3` 的串行立即执行与并行辅助执行产生不同的活动拓扑、队列成员、修改集合及最终网格。两者各自通过预算、邻接、裂缝、队列和网格有效性检查，但不满足规划要求的同输入、等价输出配对。

这不是已确认的 PREP-04 性能退化，也不是可忽略的哈希顺序差异。当前阶段不应通过删掉该目标、改用一个线程或放宽结果比较来完成验收。来源冻结输入没有被重选或修改。

## 2. 实际失败与复现

完整目标集运行 `benchmark-output/prep-04/integration-20260910/all-1/` 在首个 Peking 场景的第 14 帧失败。`run-metadata.json` 保留 failed，原始记录为 pending 文件，没有被发布为 `pairing_complete`。同帧早先已测的 merge topology 行也被撤销成功资格，这是来源帧原子确认规则的预期行为；直接发生结果不等价的是 split topology。

## 3. 原因证据

FACT：只读计划生成 19,857 个候选，其中安全内部候选只有 2 个，其余 19,855 个为边界候选。按全局优先级排序，前五项均为边界项；两个安全候选分别位于零起始 rank=44 和 rank=353，对应路径 `140737488378281`、`10650`，分配到不同安全块。

FACT：`PlanDataOrientedRoamSplitTopology` 排序后跳过边界候选，使用剩余预算选择安全内部候选。`CommitScoredSplitTopology` 先提交这些候选，随后同步预算并调用 `RunSplitSerialConvergence`。串行立即执行直接进入全局长期队列收敛，不先提交这两个候选。

INFERENCE：空间上安全、互不冲突的提交不等于与全局优先级及有限预算交换语义可交换。提前细分较低优先级节点改变了收敛前的预算、拓扑及可合并集合；后续串行收敛没有保证恢复到纯串行策略的同一固定结果。两条安全候选与实际独有叶之间的对应关系支持这一机制，具体修复仍需分析动态闭合与预算交换，不宜只加一个简单排序条件即宣称证明等价。

FACT：PREP-04 没有修改拓扑计划文件，`RunSplitSerialConvergence` 与实施前正文逐字一致，生产 split commit 路径也保持原逻辑。另将 HEAD `2dac3ea` 的整个 `DataOrientedRoamTopology.cpp` 导出并重新编译，替换诊断程序中的该翻译单元后，仍得到相同输入和上述两个不同结果。日志为 `topology-baseline-diagnosis-20260910.log`。这是旧拓扑实现的定向复现，其他链接组件来自当前构建，不能冒充原应用二进制的完整性能对照。

## 4. 验收影响

Critical：PREP-04 第 8.2 节要求六场景全部冻结目标可靠配对，目前该要求不满足。36 项 CTest 通过仅证明既有夹具范围，不能覆盖或推翻这个实际反例。

测量执行器正确保留前序修改、识别不等价并拒绝发布。正式重复周期、三次短运行稳定性和跨目标胜负解释不应在已知不等价的目标集合上继续声称通过。容量处理与普通生产实现前后性能属于独立核查，可继续执行；它们不能解除本条阻断。

## 5. 待确认的修复方向

建议先新增独立的细分拓扑等价性修复小规划，再回到 PREP-04 完成验收。拟议职责边界为：

| 文件或模块 | 拟议职责 |
| --- | --- |
| `DataOrientedRoamTopologyPlan.h/.cpp` | 明确可提前提交集合相对于全局优先级、闭合与预算的条件；不能把空间安全当作结果等价证明 |
| `DataOrientedRoamTopology.cpp` | 在既有生产提交与串行收敛流程中执行已确认的条件；不引入实验专用拓扑算法 |
| `DataOrientedRoamWorkloadProbe.cpp` | 若可执行计划语义改变，复用相同计划并重新定义受影响的工作量事实 |
| 现有 DOD 测试与冻结发现/配对集成 | 增加该实际反例、预算临界和动态闭合覆盖；验证来源、完整输出与真实线程派发 |

关键决策须先确认：保留严格输出等价作为 CPU 配对前提；对不能证明可交换的输入是否允许生产策略串行回退；计划规则变化后，受影响的输入/目标版本和冻结发现如何重新生成。回退可能减少可测并行覆盖，应如实交给后续 CPU gate 判断，不能隐藏它来制造交叉信号。

另一选择是暂缓 PREP-04，在重新审查研究问题后讨论不同质量输出是否可比；这会改变已确认的实验契约，不是本阶段局部修正。当前未实施任何生产策略修复，也未改变等价标准。

依据项目 `AGENTS.md` 的“实现中如必须改变已确认的边界、职责、依赖方向或公共接口，应先说明并重新确认”，以及小规划第 10 节的范围约束，生产拓扑语义修复需另行确认。当前实现、失败数据和本分析已形成可审阅结果。
