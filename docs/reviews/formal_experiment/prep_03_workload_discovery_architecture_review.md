## 4. 问题与整改

### Critical

未发现未处理的关键架构问题。源状态保持由 Pipeline 所有；只读计划没有真实提交、预算消耗或几何写入能力。失败场景不向下阶段发布标准目标入口。

### Major

已整改两项：合并候选曾在提交编排和计划中重复排序，现由计划统一排序；外层追溯失败最初仍保留标准目标名称，现改名为拒绝目标证据。均未改变确认的模块边界、选择规则或生产拓扑策略。

### Minor

已补充发现摘要中的有效/无工作/失败计数，避免只能依赖总行数解释完成状态；迁移的网格类型注释压缩为三行摘要，旧配对准备说明同步改为公共帧准备。临时测试构建曾因 const 分块参数和构建未完成而失败，修正后以最终完整构建和全量回归为准。

OpenGL 首轮的旧输入准备测试在并行构建期间触发 180 秒超时；构建结束后的独立复核以 16.98 秒通过，D3D12 同项也正常通过。未改变测试门槛；日志完整保留为 `prep03-ctest.log` 和 `prep03-preparation-recheck.log`，没有将超时首轮写成全量通过。
