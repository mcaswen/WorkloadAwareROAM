# NMP-01：严格目标规划实现与阶段验收审查

> 日期：2026-09-13；规划基线 `c2cd2d8`。NMP-01 实施与验收已完成；保留早期字段审计过程，最终结论分开评价语义、局部性和成本。
> 对照：[小规划](../../plans/roam_parallelism/native_materialization_01_plan.md)、[原生事实](../../codebase/roam_parallelism/native_materialization_integration_baseline.md)、[开发规范](../../standards/development_guidelines.md)。

## Critical

固定输入范围内未发现严格语义解耦的 Critical 问题。独立模拟/控制器、完整轨迹、净 Δ/Γ、自然诊断和成本测量均已实施；三点与 Legacy 严格决策和逻辑终态一致，来源未修改。正常输出未携带最终邻接、活动数组或堆布局。该结果不替代后续原生物化和生产切换验收。

## Major

### 1. 关系恢复协议已收敛，实际物化充分性仍待验证

小规划 §4.3 要求每个 `InternalRelationChange` 字段具有具体读取者和不能由净目标局部恢复的理由，§10 步骤 1 明确要求必要性不清时暂停。

解析审计在相同合法叶目标中发现 72 处内部左右邻接差异，原生 `AppendPersistentMergeQueueNeighborhood` 得到的集合有 48 处不同。这意味着不能把左右邻接当作根本无人读取的字段；也不能反过来以“读取集合不同”证明完整严格决策必然不同。

尤其要区分：夹具用人工评分构造两种历史，**不是同一完整已评分输入的严格等价反例**。当前证据也没有证明任何字段不能从 M₀+Δ 局部恢复。直接导出这些历史关系，或直接宣布它们均可忽略，都缺少必要依据。

用户确认后已完成同状态单变量审计：仅替换两个内部左右字段，五种严格续接的根决策、强制尝试、预算账本、逻辑堆和缓存/历史投影全部一致。再对同一父节点从活动叶孩子的 Base 恢复左右关系，五种续接仍一致；相对原状态只有一个字段需要改写，另一个本来就满足恢复规则。

幂等边界也得到明确：固定拓扑/视图/轮次且候选完整时，两次邻域失效/刷新实际重新插入了 8 个条目，未改变逻辑队列。人工删除仍合法的候选后，刷新会重新插入它；这是完整性前提的组件反例，不是自然失败分支的证据。严格循环以最大有限分数复核合并，本组完整 Qm 的候选均可通过，未触发失败合并移除。

本轮继续检查深层内部与休眠缓存：30 个孩子仍为内部节点的父记录参与恢复，48 个关系字段发生变化，随后 38 个成对严格循环步一致；合并至根后清空 124 个休眠节点的三邻接，320 个字段发生变化，随后 76 步细分续接一致，124 个缓存节点全部重新激活。两项均用原址还原与完整快照排除干预外的改变。活动内部 Base 同时按同深度反射伙伴、反向关系和边界规则检查。

**处理：小规划 §11.9 已采用明确恢复协议，首版不准入 `InternalRelationChange`。** 活动叶邻接由目标边恢复；内部 Base 按固定伙伴恢复，内部 Left/Right 从目标孩子 Base 规范化，休眠邻接可清空。Planner 决策过程中仍精确维护临时原关系，不以规范化后的关系改变严格选择。当前是源码读取依据和有限夹具证据，未宣称对任意合法状态完成证明；NMP-02 必须核查真实局部恢复及新旧切换续接，不能以本轮审计代替物化验收。

### 2. 压力点的堆覆盖和规划成本限制生产收益

小规划 §7/9 要求分别报告节点覆盖、堆覆盖和 Tplan。本轮两个普通点的节点写覆盖低于 1%，堆写覆盖低于 6%；压力点旧节点写覆盖为 8.393%，但细分/合并堆写覆盖达到 37.802%/57.594%，堆读覆盖达到 55.783%/76.035%。因此不能用节点局部性宣布所有私有结构均满足 u≪Q。

压力点 Tplan 两次为 1105.828/1071.302 ms，Legacy 完整细分阶段为 64.336/58.924 ms，均值费用比约 17.66。实际存在数百万节点/堆查询和成员维护，标准有序容器让一次原数组访问变成覆盖查询，heap 修复又重复调用这些查询；求值缓存与净出口也有额外费用。这些是代码与计数能确认的工作，但未用 profiler 确认各项耗时占比，不将“换容器就一定快”当结论。

**处理：语义解耦通过，稀疏性分结构评价，性能明确记录为当前实现不适合直接替代生产阶段。** 第一版容器慢不自动否定解耦，但压力堆覆盖也不能简单归为常数开销。NMP-01 验收闭环完成；NMP-02 或覆盖表示优化需基于此结果 Review，未擅自实施任何一种。

### 3. test129 原路径短计时有未解释偏移

小规划 §11.10 保存了同条件、同来源身份的前后短测和唯一一次复测。test129 首次后版本均值为 0.149 ms，冻结前版本为 0.084 ms，绝对差约 0.065 ms，超过本次 0.05 ms 筛查线。旧二进制对照复跑均值为 0.097 ms，新版本复测为 0.224 ms，其中含一个 0.349 ms 样本；样本量不足以区分稳定版本影响与波动。

该次工作区组件变更未改 Legacy 热函数，新工作区也未从原计时入口调用；这不能排除链接布局等间接影响，也不足以解释离群值。Peking 两点未显示同等级的明显退化，但不能用它们抵消 test129 风险。

**处理：保留历史偏移原因未知，不声明已修复。** 最终控制器短测的 Legacy 为 0.040741/0.051282 ms，没有显示新的明显退化；单组更低值仍不能解释此前波动或证明共享提取产生优化。按开发规范停止追加微秒调查。新的 Planner 测量单列于问题 2，不与旧 Legacy 波动混称。

## Minor

### 1. 来源必须按 ID 选择

清单读取器返回顺序不应由调用者假设。初版按位置取场景，压力项误用了 test129 参数；现按精确场景 ID 查找，来源错误记录标为无效，正确输入、二进制与来源头另存 v2。无效数据未用于研究结论。

### 2. 无窗口 CMake 依赖准备

原配置只在应用分支准备 GLM/STB，关闭应用后相关 CPU 测试会被跳过。现测试分支显式准备这两项，复用已有幂等函数，不加载窗口或图形后端；已在 Ubuntu 的 Release 配置构建实际探针与审计目标。

### 3. 当前支持配置与诊断费用必须保持显式

`BuildNativeSplitTarget` 支持本阶段冻结的共形约束开启、预算合法、评分镜像关闭输入；不支持的配置拒绝执行。此范围与本轮计量契约一致，不代表 GUI 的全部设置已兼容。02 接入前须处理镜像字段并验证新旧切换。轻量轨迹为编译期策略，不同读集合/全量回调则由 bool/空回调关闭；仍有少量条件检查及标量计数，全部包含 Tplan，不声称零仪器成本。

## 文件与依赖核查

- 测试来源持有高度图、流水线与副本，副本先析构；原生状态借用地址不悬空。
- 探针只在外层恢复 Legacy 副本，Planner 直接借用 M₀；完整参考投影与轨迹在计时外，没用旧阶段替新 Planner 生成答案。
- 审计在测试目录使用原生步进和验证接口；不反向引入生产依赖，也未修改 MPR。历史见证、隔离干预与组件条件仍属同一字段审计职责，未引入通用模拟或跟踪平台。
- 输入替换后原址还原，再用完整快照核查容量和地址，排除附带状态修改；逐步结果以稳定身份比较逻辑队列，不能误用原始输入 hash 判失败。
- 早期 `AnalyzeSplitOperation` 的克隆/全量哈希只用于微型字段诊断。新 `DecisionTrace` 已独立覆盖 `forcedFrom`、尝试进入/退出、预算预留/释放、根成败、处置和停止，轻量 Legacy 入口不调用旧足迹观察。未测试 mesh/Pending 消费。
- 新核心只借用 `const State&`，私有覆盖和虚拟记录不可复制；来源必须在同步调用期间保持有效且无人修改。测试以完整快照核查未写来源，不把 `const` 声明本身当作全部证据。
- View 管字段/预算，Queues 管堆存储，Simulation 管根内部必要逻辑与候选演化，Planner 管独立严格循环和净出口；未将这些职责合并进原 Topology 大文件。`NativeTargetPlan` 只保存具名义务、净事件、纯分数缓存及摘要；源字段默认值通过 View 的计费入口读取，完整参考端独立扫描所有缓存提取例外。
- 所有查找从已有缓存或堆借用，构造不建全域字典。曾恢复原值的覆盖记录仍保留，尾部截断/重用不能复活源条目；累计覆盖、净字段数、旧槽位和新槽位分列。诊断读集合为额外开销，普通模式不建立集合。
- 新源码注册进共同 DOD 清单，Legacy 评分外壳复用同一纯域评分/迟滞规则，高层控制保持独立。旧堆没有改用覆盖访问器；静态堆原语目前只在新堆使用。未为形式上共享每个 helper 而扩大原热路径改造。
- 存储组件测试单独放在 `DataOrientedRoamNativePlanningTests.cpp`，避免与关系见证/续接审计堆在同一文件。测试中的任意伙伴改组只验证存储约束，不冒充合法菱形资格。
- 完整控制测试单独放在 `DataOrientedRoamNativePlannerTests.cpp`，外部投影/规范化支持头只由测试与探针使用。自然诊断不存逐循环全状态，仅保留完整事件与最终投影；微型夹具逐循环核查。对参考投影的全域扫描不能算作 Planner 的正常工作。
- 新增中文注释采用自然语义；公共边界结构使用 `<summary>`，无 `@brief`、阶段编号或批量脚本替换。
- 原始 CSV、二进制与临时输出均位于既有 Git 忽略目录。规划提交与实现提交分开；实现后续按用户许可提交为 `2f04f48`。

## 验证与成本

执行内部关系定向测试：120 对相同叶目标，两边检查合法拓扑、队列不变量及硬预算；关系计数和邻域差异写入 `relation-audit-validated.txt`。原生基线按三输入各一次热身、两次计量完成，数据及波动限制见小规划 §11.4。

扩展后的同一测试可执行文件在 Ubuntu Release 通过，记录为 `relation-continuation-audit.txt`。包含两种干预各五条完整续接，共 176 个成对严格循环步；循环计数包含停止步，不等于 primitive 操作量。只在新增具体检查后重跑此目标，未扩展自然输入、全部 CTest 或后端构建。

工作区阶段的 NativeTarget/NativePlanning 组件验证已完成。最终受影响的 NativeTarget、NativePlanner、旧 SplitPrefix 定向测试通过；新增 k=0/h>0 和部分成功前置断言后，仅再次运行 NativePlanner。没有全量 CTest、MPR 矩阵或图形后端验证。

最终三点诊断分别比较 69、413、156720 个完整事件，目标、义务、逻辑堆、预算和来源快照一致，均未截断。自然 Γ 数量为 6、44、16610，当前均为 forced 例外；压力净事件为 27783。具体工作量与全部两次计时值见小规划 §11.12，数据来源身份与冻结 v2 相同。

Ubuntu 没有 `pwsh`；只读 Python 按原脚本相同计数规则检查受影响门禁，最终 src 15.486%、DOD 20.048%，新增注释正文、摘要、标点和阶段标记另检。未用脚本替换源代码。最终构建没有新增自有代码警告，GLM 与 FormalCpuPairCsv 既有警告保留。观察作用域与模拟器禁止复制，避免重复完成事件或多个计数副本共用可变工作区；此编译期限制和后补测试断言不需要重复自然计量。

## 结论

NMP-01 的实现与验收工作已完成：固定范围内严格目标决策与生产修改解耦成立；节点/义务保持局部，压力堆覆盖较广；当前规划费用很高，不构成完整更新性能收益。后续应先 Review 压力覆盖和成本，再决定 02 或优化归属。MPR 独立 oracle、生产物化/镜像/mesh 消费/切换仍保留各自边界。

后续用户要求先提交，再制定独立性能优化小规划；本实现及验收已提交为 `2f04f48`。[NMP-01P](../../plans/roam_parallelism/native_planner_performance_plan.md)已获授权并在实施，当前中间版本语义一致、压力性能未达门槛，继续优化。新成本和架构核查在[性能审查](native_planner_performance_review.md)记录，不改变本审查的原始数据、风险或验收范围。
