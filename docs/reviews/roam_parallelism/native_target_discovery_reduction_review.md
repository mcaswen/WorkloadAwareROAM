# 方向性候选维护与在线 Δ/Γ 归约审查

> 日期：2026-09-13。
> 对象：[两项推导](../../research/roam_parallelism/native_target_discovery_reduction_derivation.md)、[NMP-CB 规划 §7.3](../../plans/roam_parallelism/native_candidate_birth_proof_plan.md)。
> 结论：**限定的纸面结果可以保留；不批准删除完整反向维护，也不据此启动生产实现。**

## Critical

最终文档没有把抽象几何资格等同于原生逻辑成员，也没有把在线输出描述成已经发现目标。已检查并保留以下关键边界：

- D1/D2 依赖固定事件偏序及合法理想；原生单组/双组、Base 和代表变化的映射仍未闭合。N3 只证明父子活动资格，不承担全部合并资格。
- 普通与 forced 细分都有 SplitBuild 标记，但实际 CanMerge 不直接检查该标记；抑制来自队列及控制分支。有限哨兵不是缺席，负哨兵在极端迟滞阈值下尤其不能过滤。
- 失败重新接纳、storedScore 变化和伙伴撤销不由几何方向性排除。失败集合为空也不证明来源登记完整。
- Δ 归零不能清除全部 Γ。Activity 会改变 DefaultHistory，即使某字段没有再次写入，也可能产生或撤销该字段义务。
- 新缓存的初始 ActivatedBuild 为本轮，不是全零来源；CacheBirth 只输出新建且最终休眠的节点。
- ForcedActivation 使用最终赋值而非历史 OR；失败重新登记即使处于抑制状态，仍清除代表/伙伴的失败生命周期。

上述事项均已纳入证明条件、归约规则或明确反例，没有通过删减原严格测试绕开。

## Major

### 1. 方向性并没有完成便宜的原生例外枚举

推导 §2.5 的删减命题是条件定理。关系对应、缺席候选、改键和抑制登记的证据维护工作 C 尚未给出足够小的界。若为验证这些条件仍扫描旧的完整保守邻域，原邻域成本不能计为已经省掉。

因此只能认可方向性和原生局部引理，不能将它标记为已获得完整新发现算法。自然样本没有某种失败也不替代对完整声明输入域的证明。

### 2. 在线输出正确性不等于工作量减少

E1/E2 与 CacheBirth 规则是具体的增量归约，失败部分保留当前终态谓词的小尾筛。输出与现有 Extract 等价的归纳清楚，不依赖 Legacy 提供答案。

但现有 Extract 已按 touched 扫描，并没有未登记的全来源扫描。在线归约增加的字段通知、输出索引写入、峰值容量及排序费用必须与省掉的出口访问比较；`w+5z` 可以远大于不同节点数 t。不能把结束后访问消失自动计为整个调用少做同等工作。

### 3. 不是仅由净 Δ 决定的完整 Γ 算法

五字段例外还依赖最终历史；CacheBirth 依赖创建与休眠；失败义务依赖原生最终资格、代表和登记。输出视图消费这些信息，不自行推导其来源。失败尾筛的 f 可能大于最终失败义务数，Path 及资格查询费用明确保留。

本轮没有证明原生端点 Materializer 已恢复全部 Γ，更没有补完 target discovery。不能从输出等价式推出“仅给 Δ 就能恢复全部 native continuation state”。

### 4. 历史成本的解释准确，性能承诺仍未成立

压力样本 16208+11575=27783=k，不支持大量成功事件相互抵消。25115 次恢复属于队列维护，而且已有延期实现避免了其中的物理删除，不能重复计入新算法收益。

方向性若落实可能影响主循环，但删减仍有条件；在线归约主要针对输出，不能凭当前约 14 ms 提取项解释如何跨越约 114 ms 的循环费用。旧计时口径和插桩限制保持，没有把 61.801 ms 改称完整复制、运行与同输出的总费用。

## Minor

两项工作削减的研究记录独立成文，旧候选证明通过链接复用，不继续向其堆入输出状态职责。规划只追加用户批准的证明范围与结果，审查独立存于规定目录。没有引入生产接口、运行依赖或新持久数据结构。

有限核查仅存于原有忽略目录。脚本是本轮抽象检查产物，不进入 CMake，不作为新的可维护 ROAM 平台。没有新颖性主张，避免把通用偏序或增量输出维护包装为原创算法。

## 验证与规划核对

- 方向性核查覆盖 1099 个至多 5 顶点的前向 DAG 编码及 56145 对嵌套理想，不将编码数量称为非同构结构数量。
- 端点归约覆盖 18432 组字段更新顺序、110592 次中间输出核对及 2000 次固定种子操作。完整端点表只作为独立答案，没有参与在线更新。
- 六组定向边界包含生命周期、有限哨兵和字段默认值变化；任意字段序列不冒称严格控制器的可达状态。
- 一次 Ubuntu 标准库核查耗时约 0.174284 s，脚本身份和产物位置记录于研究文档。它不是 Lean 验证，也不是 Planner 性能。
- 本轮只增加研究/审查文档并同步已有阶段记录；未修改生产源码、原测试或构建配置。生产性能沿用 NMP-01P 既有报告，不跑无关构建、自然输入矩阵或全 CTest。

与用户批准的两条推导一致：已给出命题、证明、源码对应、反例、成本和出口；未实施新堆、Planner、订阅设施或性能采样。方向性停在原生删减需要 Review，在线输出停在正确性构造成立且收益待测。没有将整个 NMP 路线标记为通过或终止。
