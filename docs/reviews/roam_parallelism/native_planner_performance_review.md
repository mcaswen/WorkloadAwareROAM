# NMP-01P：规划器性能优化阶段核查

> 日期：2026-09-13；类型：中间实现架构/正确性/成本核查，非 NMP-01P 最终通过或终止。
> 提交记录：本核查完成后，用户已授权提交当前实现与文档；下文的未提交状态保留为核查时记录。
> 对照：[性能小规划](../../plans/roam_parallelism/native_planner_performance_plan.md)、[实现事实 §12](../../codebase/roam_parallelism/native_materialization_integration_baseline.md#12-nmp-01p-当前中间实现)、[原阶段审查](native_materialization_01_review.md)。实现基线 `2f04f48`，当前优化尚未提交。

## Critical

当前中间实现未发现尚未解决的严格语义或所有权错误。Legacy 控制器及热路径独立，来源只读，私有关系和堆不进入返回值；无整状态克隆、生产原地执行、排序放松或 Γ 扩容。

原方案、80%/50%门槛及测试后直接调整优化的权限均已由用户明确授权。已按小规划逐项登记并实施连续决策堆、成员投影和局部访问，撤回没有可靠总收益的七字段拓扑投影；当前三点完整自然对照一致。压力性能仍未达门槛，不能称已具备生产替代收益。

## Major

### 1. 连续存储不能沿用 MPR 的稳定指针假设

对应小规划 §3.2/4。当前 map 记录地址不会因插入搬移，新向量会扩容；forced 递归也会创建记录。若仅把 map 替换为 vector 后继续跨调用保存引用，将产生悬空引用或静默写错记录。

实现使用稳定记录下标，不跨递归保留vector引用；页编码引用属于独立页对象，记录/目录向量扩容不移动页。ReadCursor只在无View修改的资格/邻域读取区间使用，WriteFields不向调用方导出可变引用，保留逐项检查和无效写过滤。组件与原逐步严格夹具已核查扩容、冲突、显式无效、虚拟创建、64位轮次、位标记独立性和源不变。分配失败终止本次调用，不使用半更新工作区继续规划。

### 2. 堆值搬移必须封闭中间反向位置状态

对应 §3.3/9.4/9.11/9.12。FillHole不重入、不发回调，返回前恢复反向位置；入口准备完整私有槽位，内部合法下标由算法保证，保留逐次计数。Path仅缓存不可变排序键，Validate对照实际身份，未降低平分/位值检查。封闭候选维护有显式状态，Merge Top、Validate、Metrics拒绝不完整区间，原防御失败出口也显式结束。成员、任意删除、尾部复用、改组及完整投影均已比较。异常仍由调用级RAII释放工作区。

### 3. 有实测改善，仍未达到压力性能门槛

对应 §6/7/9.13。新入口原Planner压力约941.159ms，当前133.892ms，同轮Legacy61.801ms，约2.166倍；压力Planner两次131.344/136.439ms。相对旧Planner约缩短7.03倍，仍未达49.441ms硬线和30.901ms理想线。普通点约0.050/0.529ms，相对原入口基线未见明显退化，但20k波动较大，不宣布稳定性能优势。不用旧Legacy最慢值或Planner最快值拼接通过。

小规划§9.13记录新的两层成本、访问量与复杂度差距。粗遍134.839ms中循环114.357ms，提取/汇总/销毁约20.48ms；细遍224.547ms，队列61.678、资格39.836、候选其余23.749、邻域21.844ms。细遍有插桩扰动，不按比例当作普通时间。仅消除收尾仍不足以达标；下一机制必须实质改变循环费用。当前没有证据认定优化空间用尽，未恢复固定包数终止限制。

### 4. 连续投影的N/Q项必须显式计费

对应§9.6/9.7。两堆首次实际修改复制Score/Node/Path，成员投影首次旧节点写复制四字段N行，虚拟尾部独立增长；只读构造不触发副本。预留总36642456字节，分表峰值和44669251字节是上界。节点/评分仍有页初始化；本版不能再声称整个工作区按触及记录准备或来源读取全部局部。

View的`readOldNodes`只计它自身的读取，不能漏掉成员投影全部745072行复制；SourceCopies分表记录，复制/增长/释放在Tplan。未复制活动索引、几何、mesh/Pending或全生产State，未从旧执行器获得目标。七字段拓扑投影试验没有可信总收益，已撤回其源码和双写，历史数据保留。

### 5. 纯评分复用不能顺便复用动态资格

对应 §3.4/6.3。已核对单调用不可变几何、视图与设置；命中只复用纯分数，活动资格、轮次抑制、合并资格和请求位置保持。缓存开关的完整轨迹、投影、Δ/Γ和分数位值一致；请求85900、求值51667、命中34233分别计量。

不跨帧，不将抑制值写入缓存。缓存单项和仅内联的完整时间收益未获得稳定证据，当前不作为独立性能结论；后续表示变化后仍需决定是否值得保留，不能只因代码已经写好就认定有利。

## Minor

- 记录/页索引、连续堆槽和成员投影职责独立；均归规划器内部，不决定高层策略。字段编码留在View，纯缓存留在Simulation，原五个组件所有权和依赖方向保持。
- 测量扩展既有探针；普通计时关闭全量诊断和新增区间计时，成本诊断与整体结果分开解释。
- 中间步骤只跑压力点，最终回到三个原输入；复用 NMP-01 关系恢复、MPR 和后端证据，不重跑全部测试。
- 旧容器总字节尚未知，新容量不能与旧载荷直接相减宣称内存改善。进程 RSS 也不等于 Planner 临时峰值。
- 原 test129 微秒波动保留历史未知状态；本轮不以性能优化授权重开无关调查。

## 结论与核查记录

当前中间版本支持继续优化；没有把性能未达标改写为语义解耦失败，也不允许以四倍改善替代80%门槛。NMP-01P保持实施中，NMP-02未开启，不作最终通过/终止判断。

验证选择：Ubuntu Release只构建原探针及NativePlanning/NativePlanner目标；组件和11个严格配置覆盖存储与维护变化，三点自然完整比较69/413/156720事件、续接投影、Δ/Γ、预算/停止、源完整快照。中间短测每次均对应新改动或明确消融风险，未扩大场景、轨迹或线程矩阵；原NativeTarget、MPR和图形后端复用已有结果。最后清理无人使用的包装并补注释，仅重验受影响组件，复用仍适用的自然性能数据。

逐文件核查未见工作区句柄逃逸、把最终状态塞入Γ、Legacy依赖新表示或测试被生产包含。注释保留自然句内标点、summary与三行正文边界；只读Python检查复现仓库规则，src覆盖率15.618%、DOD20.083%，未用脚本替换源码。原始二进制、CSV、日志和只读分析脚本位于既有忽略目录，本轮无新Git提交许可，未提交。

剩余需验证：在当前严格语义下，能否减少重复候选/资格维护，且收益足以覆盖剩余63.1%的硬门槛差距。跨primitive/根延期或跨修改资格缓存尚未有完整失效/观察证明；并非被禁止，也不能仅凭设想保证收益。详细诊断中的比例不是真实CPU不可降低的下界，本审查不宣称Planner理论上不能达标。
