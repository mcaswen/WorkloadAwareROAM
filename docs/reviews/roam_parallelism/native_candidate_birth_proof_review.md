# NMP-CB 候选出生与发布证明实施审查

> 日期：2026-09-13；对象：[已确认小规划](../../plans/roam_parallelism/native_candidate_birth_proof_plan.md)、[证明与核查结果](../../research/roam_parallelism/native_candidate_birth_proof.md)、独立测试及其 CMake 注册。
> 结论：**Pass（保守局部发布契约），不认定最小出生规则、性能或生产接入通过**。

## Critical

未发现阻止本阶段出口的问题。以下约束已逐项核对：

- `HeadRelevant` 保留有限哨兵、迟滞停止项及应先选出后失败的成员。测试不仅求参考登记表极值，还直接比较 Legacy 真实 heap front；故障改键夹具先维持合法来源堆形状。
- 出生、持续改键、身份变化、失败重新接纳都经有限局部集合登记；每个查询前要求当前有效版本存在。旧有效头无法掩盖漏发新高分成员，两类遗漏由独立完整成员答案检测。
- forced 路径与普通路径写相同 SplitBuild；部分成功未按失败根回滚。整组合并的发布边界与单侧完成事件区分。
- 失败缺席不是理想资格的反面。实际错误注入触发 3 次失败移除、2 次重新接纳；显式同拓扑例另外核对失败记录的撤销。
- 没有调用 Lean 的端点修复结论保证原生 Γ；没有实现第二个目标发现控制器，也未将来源 Legacy 的时间算成新算法时间。

证明仍以前提化的有限合法登记/键域为边界。NaN/Inf、坏关联索引、任意破损缓存不在普遍正确性声明中；故障夹具支持的是列明的防御分支，不能推出支持全部损坏输入。

## Major

### 1. 保守规则仍承担主要的局部维护

结果 §3/§5 使用原生 7 种种子及其 parent/base，至多 84 个节点，并保留资格解析和逻辑登记变更。自然核查仍有 170 次资格解析。通过依据是任意位置堆删除、反向位置修复及端点不变重复发布可省，不是这些检查已经被取消。

因此本阶段满足规划“至少明确一种可删除动作”的 Pass 条件，但不能据此宣称已解决 428207 次检查或 1795522 次邻域访问。大幅 Tplan 改善和完整 Membership 投影取消仍为 `UNCERTAIN`，必须后续实现与计量。

### 2. 测试复杂度不能用作算法复杂度

新测试持有旧状态诊断副本、扫描全部队列求独立答案，并以线性查找模拟头部。这些都在 `tests/` 内，没有进入生产。自然例约 176.786 ms 是这些核查的包络，不能与旧 Tplan 比值比较。

实际局部规则使用已给定操作节点、有限邻域和成员→组登记；事件 Path 的全域定位仅在观察适配器。评分、字段寻址、登记查询和初始化在纸面成本中分别计费；没有免费化来源 Q 或把 m 当净 Δ。

收尾特别区分了 Q₀ 条目读取与索引构造：使用有序登记表时，未排序来源一般还需 O(Q₀ log Q₀) 构造；报告保留 `C_seed(Q₀)`，没有以线性读取量冒称总初始化线性。

### 3. 观察与泛化范围有限

在基础 split 完成、整组 merge 返回、请求/停止及根返回等现有事件边界核查。半个菱形和每次字段写没有机械全量验证，使用源代码的无查询区间论证。12 个有限配置不是完整状态穷举，其中 8 个仅覆盖深度停止；自然范围只有原 test129 的最多 8 个迭代，不支持 workload 泛化。

## Minor

- 复用基础测试来源、同步事件和纯评分规则，独立读取真实队列作答案。已去掉不必要的 NativePlanner 测试支持依赖；未修改旧测试断言或公共源码。
- 注释使用自然中文和 `<summary>`，复杂类型、无查询边界、旧键保留及诊断费用均有说明。没有 `@brief` 或为凑覆盖率逐字段翻译。
- CMake 只增加独立目标名称，生产源集合和既有可执行程序保持。文件/依赖归属与已确认规划一致。

## 后续只读决策队列推导审查

对象为用户确认后的规划 §7.2、研究报告 §7 及忽略目录内的抽象核查。该部分不追认新的 C++ 实现，也不改变上文原生有限核查的范围。

### Critical

本轮纸面队列证明未发现未处理的关键反例。已核对：

- 旧边界覆盖未展开子树；旧根失效必须展开孩子，新版本改善键则必须发布到 B，不能借旧父键约束它的新键。
- 查询有效头不弹出；因此每次旧弹出都对应一个已改变的初始身份，才有 `r≤t₀`。不能把该界套用到消费式枚举整个排序列表。
- 删除再恢复初始键仍保留非零版本，避免已展开的旧条目失去覆盖或旧版错误复活；同一代表的不同组身份没有混为一个版本。
- 有效性只看原生逻辑登记，未用 `CanMerge`、迟滞或抑制判断提前过滤本应被控制器观察的项。
- 初始隐式覆盖明确要求冻结的合法已评分堆及可按需读取的来源关联，没有把来源构造、评分或全量 Path 索引免费化。

有限小模型的三个错误变体都产生可检测的错误头部，支持检查器能够发现对应遗漏；其操作由外部给定，不证明原生出生枚举或新逻辑状态已经实现。

### Major

**1. 资格缓存与跳过登记必须分开。** 研究报告 R-C 只对完整读集不变的纯 G 求值成立。失败重新接纳、storedScore 更新、伙伴关联和 Γ 处置仍须执行。保留原维护触发、复用 G 结果有条件正确；省掉整个刷新动作则已有反例。不能把这个区别隐藏在“cache hit”分支里。

**2. 局部费用尚未闭合。** 订阅通知的扇出 U、绑定动作 A、实际重算数 e 和原邻域枚举均未得到足够小的上界或原生数据。当前证明没有说明 428207 次检查、1795522 次邻域访问可减少到什么比例。节点私有表示依然可能承担比 Legacy 更贵的访问，不应直接批准完整 Planner 实现。

**3. 队列启动界不能扩大为发现算法总界。** C/A 只读借用来源关联的适配成本、节点索引、缓存/历史、Δ/Γ 输出和生产端点队列恢复均另计。先构建全 Q₀ 登记表或全 N 投影再调用本查询，不能声称已经实现其隐式启动优势。

**4. 2～5 倍目标未获得证明。** 只删除队列维护不保证完整费用达标。报告已明确当前约 20.475 ms 出口若保持不变，对 12.360 ms 发现目标构成直接的条件预算冲突；这不是未经测量的新实现时间下界。旧 Legacy 数值也没有被误称为包含完整复制及相同结果提取的基线。

### Minor

文件归属仍为既有研究证明、阶段记录和审查；抽象脚本留在已有忽略目录，未引入项目运行依赖。报告区分纸面一般归纳、有限抽象核查、旧原生证据和未实现性能，不以检查数量或通用数据结构证明包装新算法贡献。

### 验证与出口

Ubuntu 标准库模型最终核查 17986 次，每次两次非消费查询；3 种错误变体均被检出。补入错误变体后只再运行该小模型一次，约 0.041604 s。脚本和结果路径、最终哈希见研究报告 §7.8。

没有修改 `src/`、原 CTest 或构建配置，复用已有生产性能记录，不运行无关构建/基准。当前可认可的是“只读队列替换的条件定理”；更小原生支持、完整目标发现费用和 2～5 倍收益仍需 Review，不自动进入新的生产路径。

推导和抽象核查完成后的文档空白差异检查、定位检查及进程查询遇到 WSL 持续无输出，已中止这些收尾命令，未宣称对应工具检查通过。公式、证明前提、核查数字和阶段边界已按本轮补丁逐项复核；没有因此追加生产测试或修改环境。
