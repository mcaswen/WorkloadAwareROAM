## 1. 目标与边界

先检验固定细化依赖、阈值最小闭包和硬预算判定能否形成完整证明链，再分析完整并行成本。产物区分机器检查的抽象定理、纸面几何论证、已有文献结果、反例和尚未证明的实现对应关系。不得以有限例子或自定义公理代替待证结论。

本轮只创建理论文档与独立 Lean 证明，不修改 Classic/DOD、CMake、评价器、基准输入或已关闭探索。当前实验问题定义保持有效。新工作区最初按授权保留供审阅；用户随后认可本轮理论结果，并明确授权将这些材料独立提交。

## 3. 推导顺序与停止条件

1. 对标准二分层次建立逻辑事件与固定前置关系的纸面对应；独立证明一般关系闭包性质，明确二者的验证层级。
2. 从叶条件证明必选集合的必要性与充分性，不把这条等价直接作为公理；显式处理初始网格和不可细分终端。
3. 推导最小阈值闭包、成本与硬预算判定，检查能否得到阈值谱表示。
4. 分析完整算法成本，给出反例与未完成义务，审计所有定理假设。

若网格对应、误差单调性或几何上界无法证明，保留具体缺口，不通过更换评价目标或假设结论绕过。抽象证明仍可作为有明确适用范围的结果，但不得宣布实际 ROAM 算法已经验证。

## 4. 验证与性能口径

使用 Lean 内核检查无限量化的抽象命题，禁止 `sorry`、`admit`、自定义 `axiom` 和 `native_decide`。打印核心定理公理依赖；允许标准逻辑基础，但逐项披露。小反例使用内核可归约的有限判断，标为反例而非普遍证明。

本轮没有生产代码或构建变化，不运行无关 CTest、图形后端矩阵或 ROAM 性能测试。只记录证明检查自身耗时，不能将其解释为未来 CPU 算法成本或性能前后对照。链接、UTF-8、未跟踪产物、证明假设和文献新颖性边界做定向检查。最终审查写入 `docs/reviews/roam_threshold/theory_workspace_review.md`。
