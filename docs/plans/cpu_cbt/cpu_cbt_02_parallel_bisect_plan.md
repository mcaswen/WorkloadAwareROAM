## 1. 目标和本次收紧

本阶段验证：**固定候选、联合模板、槽位分配和硬预算后，按独占输出槽并行填写模板，能否产生真实多核工作，以及它对完整 CPU 更新时间究竟有多大影响。** 结果必须与原参考串行逐轮一致；性能不要求预先为正。

三档固定为原参考串行 `reference`、新内核串行 `serial`、新内核四线程 `parallel`。前两者分离移植成本，后两者分离线程收益。外部邻接传播、联合计划、分配、合并、占用归约和发布仍串行。

**本次已确认的范围收紧：分类几何、分类和网格生成也保持第一阶段串行实现。** 大规划允许的分类/网格并行能力暂不实施；先使三档完整更新时间差异能够归于细分提交路径。如果只有局部模板收益，而完整更新没有收益，则报告原因并结束本次原型判断，不追加几何并行寻找正结果。这是阶段范围选择，不宣称几何阶段无法并行。

不加入质量恢复、ROAM 排序、预算再分配、动态阈值、工作窃取、稀疏复制、缓存、并行传播或新线程池。不恢复 GATE-03、PREP-06 或 GPU 路线。

已阅读[开发规范](../../standards/development_guidelines.md)、[规划规范](../plan_guideline.md)、[审查规范](../../reviews/review_guideline.md)、[CPU-CBT-01 小规划](cpu_cbt_01_serial_update_plan.md)、[代码事实](../../codebase/cpu_cbt/cpu_cbt_update.md)和[阶段审查](../../reviews/cpu_cbt/cpu_cbt_01_serial_update_review.md)。本次另逐段核对参考 `CbtBisectCommit`、现有包装/驱动/夹具、线程池及其真实派发测试，未重跑已完成的实验。

## 2. 决定实现边界的事实

| 已核实事实 | 对本阶段的约束 |
| --- | --- |
| `CommitCbtBisects` 中 `EvaluateNeighbors` 读的是传入 `currentNeighbors/bisectorData`，模板节点编号读输入 `heapIds` | 填写可以读取其他模板的最终计划，但不能读它们尚在写入的结果数组 |
| `WriteCommittedData` 读取结果中的本槽新编号以编码深度，其他字段来自输入节点 | 允许读取自己已经写入的输出槽；不要求把所有输出读取一概禁止 |
| 原函数先写完所有模板，再遍历 `PropagationNodes` | 屏障后仍须按原模板顺序传播，不能因任务先完成而提前传播 |
| 原函数向新增槽列表、传播列表 `push_back`，累加全局模板计数并可能写 `Valid=false` | 这些共享副作用须改为逐模板记录和顺序归并，不能直接并发原循环 |
| 原函数用 `std::find` 扫描已提交槽列表来检测重复分配 | 新内核采用完整所有权预检；检查实现变化产生的成本差计入移植，不算线程加速 |
| 现有 `DataOrientedRoamThreadPool::ParallelFor` 接收任务编号，返回前等待整批完成；任务编号不等于实际线程身份 | 驱动适配区间并单独记录真实 `std::thread::id`；不能以请求四线程就宣称四线程执行 |
| 线程池任务没有异常捕获边界 | 任务体不允许异常逃出；分配和可失败布局检查留在调用线程，局部失败使用预分配记录 |

第一阶段 `update` 中位数约为 test129 4.11235 ms、Peking 10.18965 ms；参考细分组合调用约为 0.79580 / 0.85965 ms。后者含完整数组副本、局部填写、检查和传播，不能当成可并行填写时间。

已有冻结轨迹中，真正有细分模板的轮数分别为 **15/96、33/96**，最大单轮模板数为 **1532、6909**。这些是本规划前已经存在的工作量证据，用于冻结报告分层，不根据新性能选择轮次。

## 4. 模板所有权和执行顺序

### 4.1 提交前预检

设模板 `i` 的保留物理槽为 `p_i`，所需新槽数为最终模板位数之和，则：

```text
OwnedSlots(i) = {p_i} ∪ {该模板实际使用的 1～3 个新槽}
对 i != j：OwnedSlots(i) ∩ OwnedSlots(j) = 空集
```

调用线程检查数组长度、活动父槽唯一、四模板取值、全部实际使用的新槽唯一且原先空闲、位于动态域、新槽与所有父槽不重叠，以及新逻辑编号所需整数范围。轮次中的最大位长和三角形预算检查继续执行。辅助所有权数组采用普通字节或整数，不用并发 `vector<bool>`。

检查完整后复制输出物理数组，预分配每模板结果项：有效状态、最多三个新槽、可选传播槽及模板种类。可以将前置检查与准备分为私有函数，但不制造通用资源认领器。预检与数组准备在新串行/新并行中完全相同，均纳入总耗时。

### 4.2 只读来源与局部写入

| 模板 | 必需读取的旧代邻居计划 | 独占输出槽数 | 延迟传播记录 |
| --- | --- | ---: | --- |
| center | 可选 `Twin` | 2 | `sibling0` |
| right-double | `Previous`，可选 `Twin` | 3 | `sibling0` |
| left-double | `Next`，可选 `Twin` | 3 | 无 |
| triple | `Previous/Next`，可选 `Twin` | 4 | 无 |

所有邻居引用计算沿用参考 `EvaluateNeighbors` 的输入代公式；源节点的最终模板位和分配映射在派发前已冻结。输出编号、三邻接和节点数据只写 `OwnedSlots(i)`。`WriteCommittedData` 可读取本模板刚写入的编号；共享计数、全局 `Valid`、占用位字、输出容器大小不在任务中修改。

循环体仅使用已分配数组与逐模板状态，不分配字符串、不扩容、不抛异常。非法邻居模式等局部失败记入自己的结果项，屏障后由调用线程汇总；不让工作线程直接发布状态或修改共享错误文本。未执行项保留独立的初始状态，屏障后可检测遗漏。

### 4.3 屏障、归并和传播

执行器返回后检查全部模板结果，按原 `AllocationNodes` 次序、模板内槽次序生成 `CommittedDynamicSlots`，归并计数及 `PropagationNodes`。再按原记录次序移植参考传播分支，读取已经完整填写的新代并修补共享邻接。

传播对无细分、center、right-double、left-double 目标的处理、事件标记及无效情形保持原样，不因某个分支看似可合并而重写。新旧状态仍在更新末尾才移动发布；合并、占用和六永久槽规则与第一阶段一致。

如果移植中发现模板本地填写实际需要另一个模板的新代数据，或必须并发传播才能保持语义，保存最小反例并停止相关实施。不得绕过所有权断言、加入锁/原子协议或退回逐根并发调用参考函数。

## 5. 线程适配与三档定义

`CpuCbtExecutionSupport.h` 复用现有池，不改变线程池的任务队列。配置线程数为 `W`，模板数为 `K`：`K=0` 不派发，`K=1` 直接执行；其余按 `m=min(W,K)` 个连续区间划分，区间 `j` 为 `[floor(K*j/m), floor(K*(j+1)/m))`。`W=1` 在调用线程处理全区间；没有按耗时调出的粒度阈值或自适应策略。

多线程进程启动时 `EnsureWorkerCount(W)`，创建耗时在 metadata 单列，96 轮复用。四线程指四个池内线程；调用线程派发并等待，不额外作为第五个填写线程。

适配器还承担派发失败的生命周期边界：现有池在入队中途遇到分配异常时可能已有部分任务排队，不能让异常直接越过内核并销毁被借用的临时数组。适配器捕获调用线程上的派发异常，先调用池的 `Shutdown` 唤醒、等待并回收已接受任务，再重新抛给更新边界；随后停止当前进程，不复用已关闭的池。任务体自身仍不抛异常。该处理不修改原线程池，也不增加重试或后台取消协议。

| 档位 | 细分提交 | 模板执行 | 其他全部阶段 |
| --- | --- | --- | --- |
| `reference` / R | 原 `CommitCbtBisects` | 原函数顺序循环 | 串行 |
| `serial` / S | 新 `CommitCpuCbtBisects` | 同一新内核，调用线程 | 串行 |
| `parallel` / P | 新 `CommitCpuCbtBisects` | 同一新内核，固定四线程上限 | 串行 |

仅诊断时，适配器预分配区间记录，记录实际线程身份、非空区间和处理模板数，结束后归并。任务编号、请求线程数与实际参与线程数分开报告。性能关闭线程身份采集，不用诊断屏障人为保证自然运行的线程参与。

真实并发夹具在至少两个非空模板区间入口放测试专用屏障，同时核对不同线程身份与参考结果；不在算法或性能路径加入该屏障。若自然小批次被单个池线程执行完，照实记录，不改阈值、加睡眠或扩大数据制造并行证据。

自然诊断中 R/S/P 从各自相同六基础初始状态真实推进；每轮先直接比较状态和网格，再对 P 执行既有独立拓扑/UV 审计。R 与第一阶段冻结的逐轮工作量及摘要关联，第一阶段已覆盖的独立审计不再重复三次。容差仍为端点 1e-6、UV 面积 1e-5，不放宽。解析 1/2/4 已覆盖线程档差异，自然输入不再额外跑二线程轨迹。

CSV 协议升级到 2，保留第一阶段原字段，追加实现、线程数、活动节点状态摘要和新细分分段耗时；不可把新列位置套到旧 schema。validate 的 R/S/P 分目录，另输出线程证据和对照结果；普通 metadata 继续记录参数、视图、初始化/加载成本，新增线程池创建成本。仅用现有 CSV 编码和普通文件，不扩展正式实验 schema。

| 诊断契约 | validate | measure |
| --- | --- | --- |
| 参数、硬预算、索引、模板所有权等执行必要检查 | 开 | 开，S/P 相同 |
| `EvaluatePoolOnlyDemand` | 关；复用第一阶段预算诊断 | 关，未采集字段留空 |
| R/S/P 独立轨迹直接字段比较 | 开，在性能结果之外 | 关 |
| 全局拓扑和几何审计 | P 每轮一次 | 关 |
| 真实线程身份/区间记录 | 开，仅模板执行器 | 关 |
| 强制同时到达屏障 | 仅 CTest 指定夹具 | 关；自然 validate 也关 |
| 基础计数、分段计时、轻量摘要、CSV | 开，诊断耗时不作性能结论 | 开；摘要与 I/O 在算法计时外 |
| 质量评价、逐字段访问追踪、逐节点日志 | 关 | 关 |

## 8. 性能对照及结论规则

### 8.1 前置身份和版本联系

实施前优先复用 `benchmark-output/cpu-cbt/cpu-cbt-01/after/` 的源码包、16 个参考文件身份、两个程序及 Cache，以及 `measurement-report.json`、逐轮/段结果。旧 probe SHA-256 为 `ff38b36f802ba98dd4789f595f78a06de52cd60d53745fd6859f7c87419ae1dc`。核查当前提交、实际编译源码/依赖、资产与硬件/编译器/Release/亲和性/优先级/电源；将证据副本或不可歧义的身份索引保存到 `cpu-cbt-02/before/`，不覆盖第一阶段。

如果条件未变，既有五进程统计可作为修改前门槛，不重复前置采集；若环境/编译条件改变，在改代码前用旧源码/程序按新条件补一轮预热和五个独立进程，冻结新门槛并保留原报告。不得用改完后的同期大极差重定门槛。

原型关闭的生产路径源码、编译入口及程序身份未变时复用 CPU-CBT-01 的关闭路径证据，不重复 DOD、图形后端或其旧微秒问题。若修改意外扩到这些路径，先重新评估影响再选必要检查。

### 8.2 一次有界采集

主研究对照仅 R/S/P 三档。另在同批次加入第一阶段归档程序 B，检查新增入口是否使参考串行路径本身改变；B 是版本前后联系，不是第四种算法。B 使用旧命令，不带新增参数：

```powershell
benchmark-output/cpu-cbt/cpu-cbt-01/after/parallel_roam_cpu_cbt_probe.exe --scenario cpu-cbt-test129-b4096-v1 --mode measure --output benchmark-output/cpu-cbt/cpu-cbt-02/measurement/test129/block-1-B
```

每场景一个预热块 `B,R,S,P`，五个测量块依次为 `B,R,S,P`、`P,S,R,B`、`B,R,S,P`、`P,S,R,B`、`B,R,S,P`；每个字母为独立进程，从六基础状态开始。两个场景按 test129、Peking 顺序运行，共 **48 个进程，含 8 个预热进程**。整个采集顺序执行，不同时构建或启动其他性能任务；收集操作用本阶段本地短脚本/命令完成并随证据保存，不新增项目级运行框架。

独立进程是主要统计单位。保存每进程完整 96 轮/三段的中位数、P95 和累计耗时，再报告跨五进程统计、配对差、比值和范围。B/R 对照旧字段；R/S/P 工作量、拓扑、状态和网格必须一致。任务调度、屏障、数组分配/副本和结果归并全部在对应总耗时内；加载、初始化、池创建单列，摘要与输出位于算法计时外。

新内核直接计时：`bisectPrepareMs`（预检/副本/预分配）、`templateFillWallMs`（调用执行器至所有模板完成，含派发和等待）、`bisectCollectMs`（检查结果并顺序归并）、`bisectPropagationMs`（顺序外部传播）。现有 `bisectCommitMs` 保留为完整提交调用成本，另保留完整 `updateMs`、`meshMs`、`updateAndMeshMs`。空模板批次填写项为零；参考 R/B 的内部填写/传播时间为未测量，不从组合耗时中相减推算。

由于 96 轮中多数无模板，完整轮序统计始终保留，另预注册以下**有细分轮**的局部统计，三档使用同一掩码：

- test129：`0～9, 33～34, 64～66`，共 15 轮。
- Peking：`0～14, 32～40, 64～72`，共 33 轮。

掩码来自 CPU-CBT-01 冻结工作量；若新版本工作量不同即先判不等价，不能重选掩码。报告这些轮的累计/中位数/P95 填写成本与模板数，以及全 96 轮更新总成本和原适应延迟，不能只展示局部最快批次。

报告至少分开：R→S 的移植成本；S→P 的模板填写局部加速；S→P 的完整 `update` 加速；S→P 的 `update+mesh` 加速。后两项用直接墙钟计算，不累加各阶段中位数。分类与网格本轮保持串行，不以它们的收益补充拓扑证据；也不与 ROAM 计算异质量加速。

### 8.3 工程影响与研究判断

B→R 的旧路径，以及 R→S 的新执行边界成本分别报告；共同指标的工程门槛均由第 8.1 节修改前 B 的五进程统计冻结：`max(0.05 ms, 修改前统计值5%, 修改前五值极差)`，不改用实现后 R 的极差。新内核内部阶段没有对应旧计时，只报告绝对成本与 S/P 差异，不制造原基线。首轮触发才对同一受影响场景/对照完整复测一次，固定开关和门槛；禁止全矩阵反复重跑。未稳定复现可按规范关闭为无版本相关退化证据，微秒级差异只记录。

确认有实际影响的工程退化时，单独写 `docs/reviews/cpu_cbt/cpu_cbt_02_performance_analysis.md`，区分已证实与未证实原因，再由用户选择独立修复小规划或调整后续规划。对可选四线程档，小工作量下 S→P 变慢本身是本次策略测量结果，不通过调阈值隐藏；新串行移植或原参考路径的持续退化仍按工程规范处理。

真实并发、正确性、性能证据完整才可将实现阶段标为完成。没有获得完整更新收益时也可以得出有效负结果；记录预检、副本、归并、传播、合并、分类几何等实际成本，说明局部收益为何不能传递到整体，不把结论扩大为所有 CPU 批量更新都无价值。只有观察到有意义的完整收益与可用并行工作后，才提交是否进入质量调度的投入建议；不自动开启该研究。

## 9. Review 项、风险与实现记录

用户已通过“按照 02，前进”确认本小规划的具体架构决定：**只并行模板填写；回调定义归属 `CpuCbtBisect.h`；两个驱动通过一个测试专属薄适配头复用原线程池；模板独占写入、屏障后顺序传播；自然输入不扩展，R/S/P 加同期旧程序联系形成一次固定采集。** 分类/网格并行暂缓的范围收紧已同步到大规划并按此实施。

主要风险是新预检/副本和池派发成本抵消很小的局部收益，以及参考顺序传播仍占较大比例。前者由三档与分段计时分离，后者先按既定边界测量；均不授权自动重构存储、并行传播或调参。静态字段访问核对和所有权预检是并发安全的主要依据，参考对照、改变区间执行顺序和真实线程夹具是补充证据，不声称测试等于形式证明。

移植须保留参考来源、提交和既有第三方说明，适用范围仍是当前本地研究；本规划不改变既有公开发布边界。
