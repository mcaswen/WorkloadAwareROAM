# 最小 CPU 类 CBT 批量更新实现规划

> 类型：Major Plan；新增一个有界实验模块，拆为两个可独立验证的阶段
> 状态：Major Plan 已获用户通过；CPU-CBT-01 已实施并核查，CPU-CBT-02 尚未启动
> 日期：2026-09-12
> 项目起点：`b078d59`，GATE-03 已关闭并归档
> C++ 参考起点：`third_party/RoamTesting` 的 `d462089`

## 1. 目标和研究边界

本规划落实用户决定：**利用已有 C++ 参考实现，建立能在共享内存 CPU 上持续执行批量细分与合并的最小类 CBT 原型。** 先获得可运行、可核对、可测量的更新机制，再讨论如何调整质量调度使其接近 ROAM。

本轮交付必须包含从高度图到连续拓扑更新再到 CPU 网格输出的完整路径，以及至少一个真正由多个 CPU 线程执行的拓扑修改环节。仅包装一次静态参考调用，或只有分类与网格生成并行，均不足以完成整个规划。

### 1.1 范围

- 保留参考代码的六基础三角形、逻辑 `heapID`、动态槽池、兼容链、四种细分模板和两类合并语义。
- 首版采用参考面积分类与固定候选顺序，构造整批细分计划；共享闭包通过已有节点模板合并处理，不恢复 GATE-03 的逐根不相交闭包筛选。
- 增加独立的硬三角形预算。每轮先细分、后合并，持续保留上一轮状态。
- 将细分模板的独占槽位写入并行化；分类和网格生成使用相同的同步范围执行接口。
- 输出普通 `TerrainMeshData`，通过独立无窗口程序验证与测量。

### 1.2 非目标和结论边界

本轮不研究 GPU，不引入着色器、图形命令、显存管理或渲染后端；不接入算法下拉框，不修改生产 `ITerrainLodAlgorithm` 注册和 ROAM 设置。不恢复 GATE-03，不启动 PREP-06，不修改正式研究问题。

不实现全局质量排序、闭包收益优化、与 ROAM 的质量配平、完整 Pareto 实验、通用任务图、访问追踪平台、无锁槽池或动态工作窃取。规划中的两个阶段是最大工作边界，出现停止条件可以提前结束。

这是**参考 primitive 驱动的 CPU 轮次原型**，不是新算法贡献的完成声明。阶段顺序有参考宿主循环依据，CPU 编排中的固定顺序、硬预算与状态组织仍是本项目选择，具体来源映射见 [CPU-CBT-01 第 2 节](cpu_cbt_01_serial_update_plan.md#2-一轮更新的语义来源)。分类优先级与独立几何质量仍分离；原始高度样本加冻结双线性插值继续作为主参考。本轮不扩展已暂停的 RMS、配对 `D_max` 等评价能力，也不把面积阈值或与串行输出一致解释为质量已逼近 ROAM。

## 3. 总体架构与职责

新增 `src/algorithms/cpu_cbt/`，作为仅由实验目标使用的 CPU 算法模块。采用普通值类型、分阶段函数和一个同步执行回调，不建立算法插件层或通用并发框架。

```text
测试 / 小规模计时驱动
  ├─ 高度图、冻结相机输入、结果核查与报告
  ├─ 适配现有线程池 → 同步范围执行回调
  └─ CpuCbtUpdate
       ├─ CpuCbtState：持久槽池及当前拓扑
       ├─ C++ 参考：分类、计划、分配、顺序合并
       ├─ CpuCbtBisect：模板填写、屏障、顺序邻接传播
       └─ CpuCbtMesh：几何求值与 CPU 网格输出
```

`CpuCbtUpdate` 不依赖测试、线程池具体类、渲染或质量评价器。测试驱动可以同时依赖 CPU CBT 与现有线程池，仅编译线程池文件，不链接整个 DOD 算法。后续是否将线程池提到共享目录由真实复用需求决定，本轮不为它重构现有 ROAM。

### 3.1 复用选择

| 选择 | 对象 | 边界与理由 |
| --- | --- | --- |
| Reuse | 上述七组参考实现与两个 `CbtGpuAbi` 头文件 | 显式编译纯 C++ 子集。头文件中的布局常量不意味着运行时依赖 GPU；首版不为去掉历史命名重新定义全部类型 |
| Reuse | 项目地形、视图与网格类型 | 共享输入输出，不复制高度图加载或屏幕投影实现 |
| Wrap | 参考函数组成的一轮更新 | 补齐持久状态、分类状态映射、瞬态重置、预算和发布顺序；不改参考分类公式 |
| Wrap | 现有线程池 | 在驱动中适配同步范围回调；算法只约定区间执行一次且返回前完成 |
| Create | CPU 细分提交函数 | 原函数把局部填写和传播封装在一起，无法直接安全并发。仅移植这段必需逻辑，原函数保留作对照；不另写占用树、计划器和合并器 |
| Extend | 构建配置与定向验证 | 只增加可选目标和少量夹具，不修改旧实验 CSV、策略选择或 GUI |

## 5. 数据、接口与执行契约

### 5.1 状态和生命周期

初始化固定使用 `Capacity128K`，即 131072 个动态槽，另加六个基础槽。原型只实现这一种自然输入容量；已有小尺寸解析夹具可复用其紧凑映射，不新增第二套正式槽池实现。

设置包含地形尺度、高度尺度、面积阈值、`MaxHeapBitDepth` 和 `TriangleBudget`。深度明确采用 `heapID` 位长，基础为 4，首版自然输入最大为 20；不复用语义不明的 ROAM 深度设置。所有潜在新编号必须在提交前验证深度与整数移位范围。

`CpuCbtState` 持有当前已发布状态，临时数组属于一次更新。旧代只读，新代写入，完成后移动发布；不在原型中实现稀疏增量复制。输入高度图由调用者持有，并在同步调用期间保持不变。一个状态不允许同时更新或在更新中被外部读取。

第一阶段实际入口 `UpdateCpuCbt(state, heightMap, view, options)` 同步串行完成一轮拓扑更新，返回成功状态、工作量与分段耗时；`options` 仅控制只读需求诊断。第二阶段才按小规划接入同步执行器，不提前预建并行内核。`BuildCpuCbtMesh(...)` 单独生成网格。报告不持有临时数组引用。参数错误或计划无效时返回错误且不发布半成品，驱动停止当前输入；不静默改成另一种算法。

### 5.2 一轮固定顺序

1. 读取上一轮全部活动叶，按物理槽位递增取得固定顺序；初始化本轮瞬态分类和模板数据，不清除持久拓扑或占用树。
2. 求当前三顶点及父级辅助位置，调用 `EvaluateCbtClassification`。细分结果设置细分状态；非基础层的负分类结果设置合并状态，仅偶数 `heapID` 发出根合并候选。可见性不决定一个叶是否计入预算。
3. 按固定顺序收集候选。并行分类先写各活动序号的结果，再顺序收集，线程完成先后不得改变候选顺序。这里没有全局 greedy 质量排序。
4. 在本轮开始拓扑上顺序执行 `PlanCbtSplits`，联合形成最终模板；从旧占用树分配槽位，固定模板和分配结果。不同根请求共享兼容节点时遵循参考模板合并，不重复提交该节点。
5. 提交整批细分模板，完成后传播外部邻接。第一阶段直接调用顺序参考；第二阶段只替换细分提交函数。
6. 使用本轮最初收集的合并候选，在细分后的拓扑上调用顺序 `CommitCbtSimplifications`，由它重新核对合并条件。合并传播结束后才得到完整下一代拓扑。
7. 顺序应用动态槽的占用与释放变化，执行 `Reduce`，重建活动索引，核对预算并发布。下一轮才能使用新占用树进行秩选择。
8. 按需生成完整 CPU 网格。新生成叶的重新分类属于下一轮，不在当前轮追加候选。

本轮不能借用后续合并才释放的槽位或三角形额度来提前细分；不引入跨阶段预算交换。连续调用必须真实经历细分、合并和释放后再分配，不能每轮从六个基础三角形重建。

### 5.3 硬预算

令动态占用数为 `D`，总活动三角形数为 `N`，预算为 `B`。首版保持六个基础物理槽活动，验证 `N = 6 + D`，且 `6 ≤ B ≤ 6 + Capacity`。预算在一次轨迹期间固定；不支持把当前状态的预算瞬间降到 `N` 以下。

提供给参考计划器的额度为：

```text
availableMemory = min(oldFreeDynamicSlots, B - N)
```

提交前再次检查 `RequiredSlotCount` 与实际唯一分配数一致，且不超过两种剩余额度。四种模板每增加一个动态槽即增加一个活动三角形，因此先保证细分后的 `N_split ≤ B`，后续合并只减少数量。分别核对细分后和整轮后的数量，不能只凭最终合并把超预算掩盖掉。

这只是保守硬上限控制，不是闭包收益调度或预算充分利用算法。记录实际 `N`、`U=N/B`、预留拒绝和剩余额度；允许因面积分类、深度或保守预留而未用满预算，但不能把低利用率描述为质量优越或性能优势。

## 6. 首版真实并行的边界

### 6.1 并行任务

第二阶段以最终 `AllocationNodes` 中的**模板节点**作为细分工作单元，不以最初根请求为工作单元。对于模板 `i`，它只写：

```text
OwnedSlots(i) = {retained parent slot} ∪ {allocated sibling slots}
```

主线程预检查父槽唯一、所有新槽唯一且原先空闲、新槽与父槽集合不重叠、模板与所需槽数匹配。模板读取同一冻结输入代的编号、邻接、最终模板和分配映射，不读取其他模板尚在写入的新代。

预分配输出数组与逐模板结果项。线程只填写所属槽位、自己的传播记录和计数；不对共享 `vector` 执行 `push_back`，不写压缩占用位字，不进行跨任务计数累加。区间按固定规则划分，每项只执行一次，任务体不抛异常；预检查和分配留在调用线程，必要错误通过逐项状态返回。

范围执行返回构成屏障，主线程按原模板顺序收集记录，再顺序运行与参考一致的外部邻接传播。之后合并、占用树归约和发布继续串行。首版不声称整个拓扑更新已完全并行。

### 6.2 执行接口和对照方式

同步范围回调接收元素数量和区间任务，返回前完成全部区间。单线程模式由调用线程执行；多线程模式由驱动包装现有持久线程池，线程创建不放入每轮更新。任务返回后才允许读取下一阶段输入，接口不支持嵌套派发或后台持有状态。

最小对照包含三种方式：

1. 原始顺序参考提交，用于核对移植语义。
2. 新模板提交，单线程执行，用于测量移植自身成本。
3. 新模板提交，多线程执行，用于测量真实并发收益。

三者使用相同候选顺序、同一计划和槽位分配。对照活动 `heapID`、邻接、算法有效的节点状态、占用、工作计数和网格；空闲槽残留、容器预留容量、耗时和线程身份不参与语义相等。持续轨迹还需逐轮核对，不能仅比较最后一帧。

分类和网格生成可按活动序号并行；它们的收益单列。必须观测到至少两个线程处理非空细分模板区间，不能由几何阶段的多线程活动替代拓扑并行证据。线程记录只在正确性诊断中启用。

## 7. 实施阶段

每个阶段实施前另写表中小规划，固定本阶段命令和基线，再经用户确认实施。当前文档只确认整体架构。

### CPU-CBT-01：顺序参考驱动的持续 CPU 更新

**内容：** 创建状态、更新、网格和两个驱动文件；接好可选构建目标。实现固定分类语义、整批计划、硬预算、顺序细分与合并、占用归约及连续网格输出。本阶段不创建新细分内核。

**验证：** 选择参考夹具中的边界细分、共享兼容链、四种模板、两类合并与释放复用；检查根层、槽位/编号一致性、双向邻接及预算。连续更新夹具覆盖细分、合并和释放后复用；自然输入限定为 test129 与 Peking，按第 8 节的固定近—远—近视图运行，报告实际分支覆盖，不为补齐分支调参。新增路径成本单列，同时完成受影响构建入口的关闭状态性能对照。

**阶段出口：** 无窗口程序能持续更新两个高度图并输出 CPU 网格，所有已选正确性检查满足，成本和预算利用率有记录。新增代码与已确认职责核对后写入阶段审查。

**停止条件：** 若直接复用需要引入图形运行时、大范围复制旧公共接口，或参考函数不能形成合法持续状态且修复需要改变模板/合并语义，记录具体反例并停止相关实施，先 Review 边界。不得为跑通原型静默重写参考算法。

**实现情况：** 2026-09-12 完成。持续串行更新、硬预算、旧合并重验、释放复用和全量网格已实现；1 项定向 CTest 与两个自然输入各 96 轮诊断通过。自然预算受限轮数为 55/96、48/96，最终三角形数为 4096、19999。前后旧探针二进制一致；首轮触发后唯一一次复测未重现退化，按规范关闭。新增串行成本及逐轮证据已归档，见[小规划实现结果](cpu_cbt_01_serial_update_plan.md#实现结果与核查)和[阶段审查](../../reviews/cpu_cbt/cpu_cbt_01_serial_update_review.md)。尚无并行收益或质量恢复结论。

### CPU-CBT-02：并行模板提交和最小 CPU 对照

**依赖：** CPU-CBT-01 的持续更新、预算及参考对照已成立。

**内容：** 新增 `CpuCbtBisect`，按第 6 节移植模板填写和顺序传播；加入同步范围执行。并行分类和网格生成复用同一接口，不增加调度策略。保持计划、分配、合并和发布顺序不变。

**验证：** 四种模板与共享兼容链分别对照原参考；冻结种子的少量合法混合批次覆盖相邻模板，核查所有权与逐轮完整结果。正确性使用 1/2/4 个执行线程，性能只使用 1/4 两档和原参考档，不扩成线程扫描。自然输入沿用第一阶段，不按速度重新挑输入。

## 8. 最小验证和性能协议

### 8.1 固定输入与正确性

首版自然资产仅为 `Hm_Terrain_Test_129.pgm` 与 `Hm_Terrain_Peking_513.png`，加载后记录真实尺寸及散列，不根据文件名推断尺寸。分别使用 `B=4096/20000`；动态容量统一 128K，最大位长 20，面积阈值首版固定为 50 像素平方。test129 的地形尺度/高度尺度为 `30/4`，Peking 恢复冻结参数 `80/12`，分辨率均为 1280×720。此前把两个资产统一写为 `30/4` 的表述在自然运行前纠正。

两个资产共用一个确定性俯视近—远—近序列：相机高度依次为 20、80、20，每段保持 32 轮，朝向地形中心，固定 60° 视场、0.05/1000 近远面、右手投影。使用现有 `BuildTerrainLodViewInput` 生成输入；具体向上向量、裁剪空间标记及矩阵在第一阶段小规划中冻结，后续版本复用。每个独立进程从六个基础三角形开始，执行相同 96 轮，不假定已经收敛，也不复用 DOD 的内部冻结状态。

资产尺度沿用历史参数，但本轮相机、分类与初始拓扑构成独立原型负载；使用新的 `cpu-cbt-*` 场景编号，不能直接与 P5/GATE 历史工作负载比较性能或行为。预算竞争与收敛过程的逐轮记录按 [CPU-CBT-01](cpu_cbt_01_serial_update_plan.md) 冻结，不为触发预算竞争改变上述参数。

自然输入没有触发的分支由解析夹具覆盖，不再加地形或调阈值。资源耗尽与精确预算边界使用小尺寸夹具，包括 `B=6`、剩余额度不足以满足整条兼容请求、多个请求共享模板、动态槽耗尽、非法深度及合并释放后的重新分配。

除参考拓扑验证外，定向几何检查确认活动叶无祖先重叠、三角形非退化、共享边一致、内部边成对、边界位于单位地形域边界，以及 UV 总面积覆盖单位方形。容差在首阶段小规划依据浮点解码精度冻结；不能用很大容差掩盖裂缝。参考对照与这些独立不变量各有用途，不以双方同错作为正确性证明。

只运行新模块相关目标与本次变更影响的构建检查；不跑全部 CTest、全部图形后端、旧 GATE-03 或完整质量校准。检查通过后停止，只有新失败或新的代码变化才追加。

### 8.2 计时边界和工作量

每轮至少记录活动数量、候选数量、模板分布、实际新增/释放槽位、保守预留拒绝数、预算利用率；现有计数足够时不为逐字段读写次数添加访问器。

计时划分为分类几何与分类、计划/分配、数组准备、模板填写、细分传播、合并、占用归约/活动索引，以及最终网格生成。另记录完整 `UpdateCpuCbt` 和 `UpdateCpuCbt + BuildCpuCbtMesh` 的墙钟耗时；全量扫描、复制、分配、顺序收集与屏障均在相应总时间内。初始化、资产加载和线程池创建单列。

探针只输出已有工作结果和轻量计时，不在计时区间执行参考双跑、全局拓扑审计、几何合法性审计、线程身份采集、质量评价、逐项日志或 CSV 写入。正确性模式先按相同输入独立核对，计时模式保留参数、预算及提交所需的安全检查；具体开关集合在采集前冻结，版本间相同。

### 8.3 每阶段前后对照

- **CPU-CBT-01 实现前：** 按现行开发规范选取已有默认 CPU 探针的代表子集，保存或复用有完整身份且同环境的前置报告。新增原型没有功能等价的前版本，直接报告它的新增成本，不捏造零成本加速；原型关闭的旧路径在实现后仍运行该子集并比对。
- **CPU-CBT-02 实现前：** 固定第一阶段顺序原型的源码、依赖散列、程序和报告。实现后测原参考档、新单线程档、新多线程档；原参考/新单线程用于工程前后比对，新单线程/多线程用于执行策略比较。未变化且程序身份相同的旧生产路径可复用第一阶段证据，不重复采集无关后端。
- 每档 1 次独立预热进程、5 次独立测量进程，成对交错前后版本或执行档次。独立进程为主要统计单位，96 轮只用于进程内分布；每进程分别计算中位数和 P95，再报告进程间差异与波动，不把所有轮混成独立样本。
- 固定 Release、编译器、优化选项、硬件、线程数、资产、视图、诊断集合与计时边界。性能任务顺序执行，不同时构建或运行其他测量。报告包含项目与参考源码身份、可执行文件散列、命令和环境。
- 原始数据与对照放在 `benchmark-output/cpu-cbt/cpu-cbt-01/`、`cpu-cbt-02/` 的独立前后目录。小规划与阶段审查引用这些路径，不覆盖基线，也不把 CTest 用时当作性能报告。
- 工程退化按[开发规范第 7.3 节](../../standards/development_guidelines.md#73-工程性能回归的实际影响门槛)：超过 `max(0.05 ms, 原基线的 5%, 原基线五次极差)` 才调查，至多一次完整复测；微秒级差异记录即可。出现有实际影响的退化，单独记录分析与原因，经用户决定新增修复小规划或修改后续规划，不自行扩展修复。

速度不是预先要求为正的验收数值。正确性、真实并发和诚实完整的成本报告是本轮交付；无收益也可以完成原型并明确结束，不能宣称已解决 CPU 批量更新性能问题。

## 9. 风险、备选方案与 Review 项

| 风险或选择 | 本轮处理 |
| --- | --- |
| 串行计划、传播和合并限制总收益 | 保留为可测量的串行部分。本轮不因模板并行效果不足立即并行所有环节 |
| 参考函数的全数组副本和线性检查开销 | 纳入报告，区分原参考、新单线程与多线程；不把移除参考检查所得收益算成并行收益。若成为瓶颈，先给证据，再决定是否另做增量存储 |

| 本地参考依赖不随根仓库克隆 | 默认关闭并显式诊断；冻结实际编译子集身份。以后是否整理为可分发依赖另行决定，不在原型中导入整个旧工程 |
| 移植局部内核会形成两份相似逻辑 | 原函数作为固定参考，新函数承担 CPU 并发边界，差异有明确验证对象；仅移植必要部分，不复制其他六组算法或创建长期双实现管理层 |
| 只并行分类和网格可能更容易 | 不作为完整交付替代方案；本轮至少验证一次真实细分模板并行，若不能成立则按停止条件报告 |

提交用户 Review 的关键决定为：**独立无窗口模块；直接复用纯 C++ 参考子集；保守硬预算；先完成持续串行更新，再只并行独占槽位的细分模板；共享传播和合并暂时串行；固定两个自然输入，不建设新的实验平台。**
