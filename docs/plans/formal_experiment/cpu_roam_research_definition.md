# CPU ROAM 实验问题、贡献、已有工作与后续工作

> 日期：2026-09-12
> 状态：记录用户已认可的研究定位；具体实验矩阵和新增实现仍需小规划确认
> 实现依据：`a3738d6` 的 Classic/DOD 与 PREP-01～05 既有能力；CPU-CBT 随本次决定归档
> 用途：当前研究定义入口，区分已实现能力、已有证据、候选贡献和待完成验证

## 1. 当前研究定位

**研究 ROAM 在共享内存 CPU 上的多阶段执行组织、并行实现与优化，以及各执行方式的性能边界。** 以持久状态的 Classic CPU ROAM 和 Data-Oriented CPU ROAM（DOD）为对象，在明确的评分、预算、拓扑与结果契约下，研究哪些工作能够并行、如何组织和降低执行成本、何时产生局部及完整更新收益。

多阶段拆分、并行实现与优化、有效对照和系统性实证共同构成技术主体。没有改变基本细分/合并规则，不等于没有执行方法贡献；同时，通用技术的采用和工程工作量也不能自动证明原创性。

本轮讨论形成以下决定：

1. **不要求先提出新的拓扑算法。** 优先提炼和验证现有 CPU ROAM 执行组织、数据布局、批量计算、增量处理及同步安排中的具体技术贡献。
2. **不要求多个阶段必须存在执行交叉。** 工作量变化下的稳定单侧优势、真实交叉、依赖导致无法形成并行对照，以及证据不足，都是需要准确区分的结果。
3. **固定执行策略可以成为研究结果。** 若数据支持某个固定组合，则报告其收益和适用范围；不为了保留 Workload-Aware 名称而强行训练在线选择器。
4. 保留 P5、排序松弛 Gate 和 CPU-CBT 的历史结果与限制，不用新的定位改写旧门槛、筛掉不利数据或追认失败实验通过。
5. 用户希望优先评估 The Visual Computer 的投稿适配性；期刊先例支持这种贡献类型，但尚不能据此保证当前工作达到录用要求。

本页取代旧研究入口中“至少三个阶段出现稳定交叉，才值得继续整篇研究”的当前投入前提。旧 H1～H4 仍是历史研究假设，P5 仍未满足其完整路线门槛。PREP-06 上传重构、在线选择器、质量恢复、新拓扑算法和 GPU 研究均不由本页自动启动。

## 2. 实验问题定义

### 2.1 研究对象与约束

输入包含原始高度图、世界尺度与高度比例、视图与分辨率、深度、评分阈值、三角形预算，以及当前持久网格和队列状态。连续轨迹真实推进状态，不能将每帧重建结果混作增量更新成本。

必须区分两类比较：

- **同一 DOD 阶段内的执行替换：** 从相同阶段前状态运行不同合法动作，核对该阶段定义的结果等价与后续状态要求。
- **Classic/DOD 的完整算法比较：** 固定公共输入、评分及资源契约，逐帧核对约定的逻辑结果。两者实际评分条目数、内部布局和维护工作可能不同，不能把“同一任务”偷换成“每项内部操作数量完全相同”。

拓扑合法性、硬预算与声明的结果等价先于性能结论。当前实现的调度分数还包含细分密度因素，不能将本项目 Classic 自动称为原始 ROAM 的完整复现或独立几何质量的最优解。

如某一比较不能满足结果等价，须单列语义变化并另行确定独立质量评价，不能直接称为等质量加速。原始高度样本加冻结双线性插值的主参考决定保留；已通过的最小校准不意味着 RMS、配对退化指标及完整质量实验都已完成。当前不为等价执行比较扩大暂停中的评价器。

### 2.2 三个研究问题

| 编号 | 问题 | 需要回答的证据与可能结果 |
| --- | --- | --- |
| RQ1：执行组织与可用并行工作 | 在保持声明语义的条件下，如何将 ROAM 更新组织成可独立控制的阶段，哪些阶段可以形成实际多线程工作？ | 阶段前后置条件、依赖和同步边界、实际派发与回退、成功处理工作量；允许某些拓扑阶段主要有序执行 |
| RQ2：并行实现与优化收益 | 数据组织、批量计算、串行热路径优化和增量网格处理分别降低了多少成本，收益能否传递到完整 CPU 更新？ | Classic、DOD 串行、同一 DOD 并行配置及必要消融；分离实现变化、线程收益和输出工作变化 |
| RQ3：性能边界与执行配置 | 在不同工作量和线程配置下，哪些动作稳定占优，哪些存在可复现交叉，哪些尚无有效比较证据？固定组合能够取得什么收益？ | 完整成本的阶段配对、工作量与回退分层、冻结配置的独立轨迹验证；动态策略仅在有额外收益空间时再讨论 |

RQ2 的收益允许被实验否证，RQ3 不预设一定存在交叉。若没有稳定、可解释的优化收益或足够有价值的新认识，应收缩贡献声明；不得通过改变比较规则制造正结果。

### 2.3 阶段与计时边界

五个 CPU 阶段沿用既有定义：合并评分、细分评分、合并拓扑、细分拓扑、网格提交。阶段划分服务于输入输出、依赖和成本归因，不能以阶段数量本身主张新颖性。

每项合法执行的成本包含它实际需要的准备、派发、计算、同步、归并和最终维护。冻结状态副本、实验结果验证等测量设施开销单列，不伪装成普通生产开销；生产执行本身需要的准备和同步不能移到计时外。详见[阶段配对契约](../../codebase/formal_experiment/cpu_pass_pairing_contracts.md)。

报告至少区分：

1. 局部内核或阶段墙钟；
2. 完整 CPU 更新的直接墙钟；
3. 更新与 CPU 网格输出的总边界，并明确输出是否已包含在上一项中；
4. 如测量应用帧，再分别说明上传、绘制、等待和后端条件。

不将子项中位数相加代替整体中位数，不把 CPU 阶段收益直接称为帧率收益。OpenGL/D3D12 作为消费 CPU 网格的后端；各自的资源与上传语义独立，不要求本轮进行上传大重构。

性能比值统一使用 `Speedup = T_baseline / T_method`，同时报告绝对耗时和时间减少比例。讨论中的“快 50%”只是示例，尚非已验证结论；`1.5×` 加速对应时间减少约 `33.3%`，时间减少 `50%` 对应 `2×`，两者不可混写。

## 3. 候选贡献及其成立条件

以下是论文需要论证的贡献组织，不是对全部原创性的完成认证。

| 候选贡献 | 当前可依托的内容 | 仍需证明什么 |
| --- | --- | --- |
| C1：具有明确语义边界的多阶段 CPU 执行组织 | 五阶段输入输出、合法动作、依赖与同步、串行收敛和并行辅助边界 | 这些边界解决了什么 ROAM 特有困难，相对已有阶段划分与并行地形方法新增了什么 |
| C2：ROAM 的 CPU 并行实现与优化 | 数据导向布局、连续队列条目与紧凑状态、批量评分、串行专用路径、增量网格及安全并行执行 | 具体设计与成本机制，公平基线下的收益，以及哪些收益来自布局、线程或通用优化 |
| C3：受语义约束的有效执行对照与实证发现 | 同源状态配对、结果核验、实际执行与回退区分、完整成本和工作量记录 | 常见比较方式会混淆什么，当前方法如何消除混淆，最终揭示哪些有用且可重复的规律 |

三者形成“执行组织 → 实现与优化 → 受控比较与解释”的论证。并行实现不是只服务实验的附属工具；实验基础设施也不因文件多、检查细就自动成为独立创新。

不单独宣称发明 SoA、线程池、批处理、增量更新、冻结输入或成对计时。贡献应落在针对 ROAM 的具体组合、依赖处理、可验证边界与实证认识。若通用优化 Classic 也能等价采用，应共同启用或单独消融，不能全部归因于 DOD。

固定配置的端到端收益可以验证 C1/C2 的实用价值。即使某些阶段没有 crossover，也可以支持 C3；但“没有交叉”必须限定输入、动作、线程和实际派发条件，不外推为所有工作量下都不存在交叉。

目前核对的文献没有提供与本项目“阶段合法替换、相同前状态、实际派发区分、完整成本和连续更新验证”完全对应的实证方案。这只是**有限检索下的候选差异**，不能写成“已证明此前无人研究”或直接使用“首次”。

## 5. 现有证据、关闭的分支与不能提前声称的结果

### 5.1 P5 仍然是有界探索证据

P5 使用 113 个冻结目标和三个独立进程。下表保留原判定，不能把帧、重复块或策略行增加为独立进程样本数。

| 阶段 | 既有观察 | 当前可支持的解释 |
| --- | --- | --- |
| 合并评分 | 24 个实际并行目标；1 个稳定串行优势、17 个并行优势、6 个含平局或方向不一致 | 已测范围主要出现并行优势，尚不满足旧双向覆盖条件 |
| 细分评分 | 24 个实际并行目标；19 个并行优势、4 个三次平局、1 个含平局或方向不一致 | 已测范围仅观察到明确并行侧优势 |
| 合并拓扑 | 17 个目标中 5 个形成实际并行对照，12 个回退；可比输入中 2 个串行优势、3 个含平局或方向不一致 | 自然并行覆盖不足，不能据此概括全部合并工作量 |
| 细分拓扑 | 24 个目标全部安全块不足回退 | 没有自然并行交叉的有效比较证据，不能写成并行全部输给串行 |
| 网格提交 | 串行脏写/并行脏写有 4 个串行优势、3 个并行优势、4 个三次平局、13 个含平局或方向不一致 | 满足本轮双向信号规则；地形与绝对工作量仍混杂，泛化未验证 |

因此，既不能称“五个阶段普遍 crossover”，也不能称“完全没有 crossover”。P5 的环境波动、有限覆盖和描述性关联限制继续保留，详见[P5 审查](../../reviews/formal_experiment/prep_05_cpu_crossover_pilot_gate_review.md)。

### 5.2 关闭分支不覆盖当前主线

- **排序松弛 GATE-03：** 已关闭并[归档](../../../obsolete/ordering_relaxation/gate_03/README.md)。结果受保留严格头请求、保守不相交依赖模型、资源限制和未完成质量配对约束，不否定一般排序松弛或 CPU 并行。
- **CPU-CBT：** 本轮实现移入[过时区域](../../../obsolete/cpu_cbt/README.md)。真实并行模板填写已验证，但当前存储和编排下可并行部分很小，完整更新未显示明确收益。局部性能问题保留未修复事实；不据此否定 ROAM 的批量评分、增量输出或其他并行执行收益。
- **保留能力：** Classic/DOD、五阶段控制与配对、线程池、GATE-01 操作观察和 GATE-02 最小参考校准继续保留。关闭实验不自动移除共享设施，也不自动扩建它们。

当前尚不能宣称：DOD 相对有竞争力的 Classic 达到固定幅度的完整更新加速；固定配置在独立工作量上普遍最优；存在跨地形通用交叉预测器；全部拓扑已并行；已达到 TVC 的具体录用标准。

## 6. 需要完成的工作

本节是研究缺口与推进顺序，不是新的基础设施建设授权。优先复用现有能力，具体改动、输入范围和验收在对应小规划中冻结。

| 顺序 | 工作 | 交付与出口 | 范围限制 |
| --- | --- | --- | --- |
| 1 | 贡献与基线审计 | 把 C1～C3 映射到具体设计、源码和最接近文献；列清 Classic 与原始 ROAM/可得参考实现的评分、延迟更新、队列和输出差异 | 不凭名称认定“传统 ROAM”基线充分，不先补一个新算法 |
| 2 | 冻结最小完整更新对照 | 有竞争力的 Classic、DOD 串行、DOD 固定混合配置；必要时保留最大安全并行预设，说明其实际回退 | 通用优化共同启用；固定策略先选定再在独立轨迹验证，不在最终测试集上挑最优配置 |
| 3 | 完成阶段证据与少量有针对性的消融 | 区分布局/串行维护成本、线程收益、增量与全量输出；报告准备、同步、回退和工作量 | 用现有动作和可追溯版本；仅对影响贡献判断的缺口追加测量，不做所有开关的笛卡尔积 |
| 4 | 完整 CPU 更新性能与适用范围 | 直接墙钟中位数/P95、累计成本、绝对与相对收益、内存；覆盖已冻结的低/高工作量和预算压力，保留不利场景 | 阶段收益不替代整体收益；CPU 主线先用一个受控后端或无窗口路径，上传/帧率另行命名 |
| 5 | 检查结论稳健性并组织论文 | 根据主张选择必要线程配置和独立轨迹；若主张跨硬件泛化，再取得相应硬件证据。组织方法、实现、消融和限制 | 不预设广泛 crossover，不用额外场景反复寻找正结果；动态策略仅在固定策略之外确有可用收益时再 Review |

统计以独立进程为主要单位，预热、重复、版本顺序、诊断开关、输入身份和计时边界采集前固定。既有冻结配对用于解释阶段执行；持续轨迹另行实测完整配置，不能把每个阶段的最小耗时相加，冒充可实际执行的整帧最优策略。

如果有意义的性能提升成立，给出具体条件与原因；若固定策略已接近所测合法配置的最好表现，明确其参考集合与选择过程。若收益弱或主要来自削弱基线，应修正贡献判断，不通过新增模型、放宽正确性或切换 GPU 路线掩盖。
