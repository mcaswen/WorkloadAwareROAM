## 1. 问题、目标与范围

PREP-03 已冻结真实阶段输入和确定性目标，默认六场景实际得到 113 个目标，三个合并拓扑组覆盖不足。当前旧配对入口仍存在计时与输入契约缺口，不能仅将这些目标接入旧 CLI 就认定已获得可靠性能数据。

本阶段交付从冻结目标重建、五阶段合法策略配对、计时标定到最小中文分析的可追溯闭环。目标是让 PREP-05 能判断实际性能交叉，而不是提前实现完整正式框架。

已阅读[开发规范](../../standards/development_guidelines.md)、[规划规范](../plan_guideline.md)、[审查指南](../../reviews/review_guideline.md)、PREP-01～PREP-03 的相关规划与事实、[PREP-03 审查](../../reviews/formal_experiment/prep_03_workload_discovery_architecture_review.md)，并核对 [24 号协议](../../parallel-roam/24-formal-experiment-preparation-plan.md)的诊断开关、阶段计时、顺序及标定要求。已扫描 PassExperiment、PassExecution、冻结拓扑、线程池、结果验证、发现编排、清单/CSV、CLI、追溯脚本及邻近测试；历史事实与当前实现不一致时，以事实文档的实施后章节和源码为准。

## 3. 架构判断与核心流程

```text
run_cpu_pilot.py：来源摘要、实际命令、执行身份、落盘完整性
  → cpu-pass-pair-pilot
    → FormalExperimentRunner：参数、清单、目录、运行状态
      → FormalCpuPassBenchmark：场景顺序、目标匹配、值映射
        → Pipeline::BuildWithPassObserver：从根推进真实来源状态
          → PassInput / WorkloadProbe：核对冻结身份与获准特征
          → PassExperiment：策略集合、AB/BA 或六排列、块完整性
            → PassMeasurement：副本、线程准备、连续计时
              → PassExecution：现有生产评分、拓扑、网格执行
              → PassEvidence：停表后的正确性与结果身份
      → FormalTimingCalibration：空计时与真实无工作阶段标定
      → FormalCpuPairCsv：版本化记录与摘要
  → analyze_pass_crossover.py → 输入审计 / 配对统计 / 分组 / 中文报告
```

**推荐决策**：所有 pilot 策略最终调用 `ExecuteDataOrientedRoamPass`。它已经将评分与已评分拓扑分开，并覆盖网格规划、写入及收尾；直接调用能保留生产串行收敛，又使并行快照到串行尾部自然处于一次计时内。旧 `ReplayFrozen*TopologyPair` 继续用于同候选诊断，不将其分块串行方式引入 pilot。

这细化了大规划“扩展配对与冻结执行器”的实现方式：扩展已有 PassExperiment，增加真实阶段冻结入口，复用 PREP-03 的生产执行能力；不再让 pilot 依赖会重写输入的旧诊断执行入口。旧 `ReplayFrozen*TopologyAction` 的兼容用途与其计时语义明确保留为诊断，不把它标成新协议测量。本项作为本规划的关键 Review 决策，不在确认前修改源码。

职责与依赖保持以下边界：

- DOD 拥有状态、策略执行、计时副本和结果证据，不依赖 Benchmark、清单、CSV 或 Python。
- `experiment/formal` 拥有请求和记录值、序列化契约；不读取 DOD 节点或决定如何推进状态。
- Benchmark 转换领域值、安排重建与输出，不直接修改队列、节点、槽位和预算。
- Pipeline 与 HeightMap 的所有权不变；测量副本同步借用来源线程池和高度图，回调返回前完成使用，禁止回调重入同一流水线。
- Python 负责文件身份与离线统计，不重实现相机、DOD 策略或目标选择；从产物核对声明不代替 C++ 的真实状态验证。

采用同步观察、显式配置和纯值结果；测量、证据、配对顺序及离线统计分别内聚。不新增通用策略注册表、事件总线、热计划缓存或正式运行存储。

## 5. 输入、接口与运行文件

### 5.1 输入与筛选

脚本必须接收 PREP-02 完成目录及 PREP-03 发现完成目录，核对两者关联、冻结场景/相机/目标/覆盖/发现摘要和资产 SHA-256。旧准备或发现二进制允许与本次不同，但本次执行前后源码、二进制、配置、输入和资产必须一致。

C++ 先加载完整冻结场景、相机和目标，再选择要执行的场景、阶段和采样。不得修改原清单、重排 selectionRank 或改选其他点补足数量。采样点过滤要求同时指定唯一场景及具体阶段；未知/重复选择、样本 0、非法阶段和无匹配目标均失败。全组没有目标的已选场景/阶段保留 coverage 行，可与其他非空组一起运行；整个请求没有任何目标时记录 `targets_unavailable`，不生成看似成功的配对数据。

建议入口如下，确认后实现：

```text
--benchmark --profile cpu-pass-pair-pilot
  --scenario-manifest <frozen-scenarios.csv>
  --camera-manifest <frozen-camera-samples.csv>
  --target-manifest <frozen-target-states.csv>
  --output-dir <new-directory>
  [--scenario-id <id>]...
  [--pass-id all|mergeScore|mergeTopology|splitScore|splitTopology|meshEmit]
  [--sample-index <1..63>]
  [--pass-warmups <W>] [--pass-repeats <R>] [--pass-workers <P>]
```

默认 W/R/P 取所选场景清单中的 5/30/8；显式 CLI 覆盖只影响本次探索测量，并同时记录清单值和实际值，不重写输入。W 可为 0，R、P 必须大于 0，所有计数须检查相加/相乘溢出及可序列化范围。保留请求 1/2/8 的测试能力，不将非 8 请求静默归一。每组策略集合固定，串行始终请求 1。

只接受此模式自己的筛选与计数；普通 `--algorithm`、`--pass-policy`、并行下限、`--csv`、旧 `--pass-targets` 和发现 `--targets-per-pass` 均与新模式冲突。解析须跟踪选项是否显式出现，不能把结构体默认值当成用户覆盖；原模式的合法行为继续保留。

脚本入口使用 `--prepared-input-dir`、`--discovery-dir`、`--executable`、`--build-preset`、`--output-dir`，转发上述合法筛选和计数。一次脚本尝试对应一个实际子进程，独立运行身份来自尝试及实际执行来源，不能仅靠用户填写重复编号伪造独立运行。

### 5.2 DOD 接口与测量模式

以下描述接口边界，普通参数命名可局部调整：

- `RunFrozenDataOrientedRoamPassExperiment(const stageInput, passId, config)`：输入已经位于真实阶段之前，返回这一目标的全部策略块、预热及验证结果；同步借用，不返回状态引用。
- 现有 `RunDataOrientedRoamPassExperiment(previousFrameState, nextView, settings, config)`：沿公共阶段顺序准备来源，按阶段筛选调用上述核心，未测阶段仍按固定串行策略推进；默认仍支持旧入口五阶段回归。
- `MeasureDataOrientedRoamPass(const source, passId, action, config)`：复制、准备、执行、停表和取证，返回单次值记录；不读取清单，也不循环整轮目标。
- `CaptureDataOrientedRoamPassEvidence(state, passId)`：计时外验证与规范化结果。允许验证器写诊断统计，不执行待测策略、不重建或修复错误拓扑。

配置显式区分 `Diagnostic` 与 `PilotMeasurement`，旧工程入口保留诊断用途；pilot 必须使用测量模式。重复顺序共用一份实现。新增阶段筛选使用公共 CPU 阶段枚举的集合或掩码，拒绝上传和未知位，不新增与公共枚举平行的阶段体系。

### 5.3 记录、版本与完整性

场景/相机/目标仍使用 v1，发现使用 v2；新的 CPU 配对记录独立升为 v2，并冻结 `measurementProtocolVersion=1`。旧工程配对 CSV 当前为 v2，若改用共同测量核心，则单独升为 v3 并声明诊断模式；不将新旧 wallMs 当成同一口径比较。旧输入哈希字段保持原有身份用途，新记录明确使用 PREP-03 的阶段输入版本与哈希。

配对记录至少包含：运行身份、场景/阶段/采样、selectionRank/stratum、相机及视图身份、输入/选择/测量版本、阶段输入哈希、选择特征哈希和原始工作量、绝对块号、预热标记、块内序号和顺序字符串、请求/实际动作、请求/有效线程、执行路径、回退、连续 wallMs、复制/输入检查/结果验证成本、结果哈希、检查执行/通过状态、等价状态及失败原因。执行后的提交数量等必须单列为 `post_`，不能回填成共同的 `pre_` 或 `planning_` 特征。

## 6. 重建、计时与结果契约

### 6.1 从根重建真实目标

每个场景创建独立 HeightMap 和 Pipeline，按冻结相机顺序从 k=0 推进到最后一个选中目标。来源使用清单中的固定串行增量策略，开启来源诊断；不用任一被测策略的结果推进来源。观察器只在命中的阶段执行测量，其余阶段正常推进；一次测量后来源仍执行自身生产阶段。

命中目标时，在计时外核对 `HashDataOrientedRoamPassInput`、相机/视图身份、主要值、原始辅助向量及 `HashTargetSelectionFeatures`。只读探测返回值用于身份和解释，不向测量副本提供可执行热计划。目标身份不匹配时终止，不重选目标、不覆盖冻结文件。

每目标测量前后检查来源身份；测试另用 StateSnapshot 核对容量、地址、顺序、预算、网格和统计，不能仅凭规范化哈希声称来源未变。线程池预先扩容属于允许的执行资源准备，其任务必须同步结束；来源的算法状态不能改变。目标所在帧完成来源诊断后才确认该帧目标有效，中途或帧末诊断失败应使其已产生样本失效。

### 6.2 单个策略的连续计时

| 时点 | 操作及约束 |
| --- | --- |
| 计时前 | 从同一冻结阶段输入复制状态；清空统计并应用当前动作/线程请求；pilot 关闭 `EnablePassEvidence`、`EnableTopologyValidation`、`EnableTopologyPairEvidence` |
| 计时前 | 保留堆顺序、预算、先前拓扑修改、槽位映射、旧几何和帧序号；禁止调用会清空修改记录的旧冻结准备函数 |
| 计时前 | 统一预建并预热借用线程池，线程创建成本单列；每次副本重新核对真实输入身份，不以不同待测动作改变输入哈希 |
| 开表至停表 | 恰好调用一次 `ExecuteDataOrientedRoamPass`；普通线程唤醒、排队、调度、同步与生产内部维护均保留在包络内 |
| 停表后 | 保存执行统计，运行对应阶段验证、规范化结果及组内比较；记录取证成本，序列化和文件 I/O 在外层执行 |

串行拓扑只从已评分长期队列直接收敛，不建立/消费并行分块；并行拓扑在计时内重新快照、排序、规划、提前提交、维护并串行收敛。细分内部为预算执行的合并工作属于该次真实细分包络，不按统计子项重复加减。网格包含元数据规划、几何容量变化、写入、区间和调试属性收尾；不以预先规划或预分配掩盖该阶段实际成本。

`wallMs` 来自一对连续 steady_clock 时间点，不由子项求和，不扣除空计时或无工作标定值。内部原有生产计时保留其正常开销；开启额外诊断得到的记录必须有独立模式身份，不能混入 pilot 主时间。

### 6.3 执行顺序、线程与回退

- 两策略按绝对块号 b 交替 AB/BA；网格按 ABC、ACB、BAC、BCA、CAB、CBA 循环，A/B/C 分别为串行脏写、并行脏写、串行全量。
- b 从 0 到 W+R−1，前 W 块预热；正式 RepeatIndex 从 0 起，但顺序仍由绝对 b 决定。计数不满足完整周期时报告实际位置分布，不伪称顺序完全均衡。
- 每种动作在每个块中都从新的同源副本开始；任何错误使整个目标不合格，不能只删除较慢或错误的单条样本。
- 请求 P 不能被冻结执行改为 8；实际任务数量仍受当前工作量、安全分块及原有下限限制。pilot 的五个下限来自已校验场景（均为 0），安全约束仍存在。
- 有效线程统计沿用生产的阶段任务/线程请求兑现口径，不声称等于实际同时运行的系统线程数；额外记录调用线程、线程池或无工作执行路径。缺少有效线程池时拒绝将请求并行报告为真实线程池执行。
- 真实系统线程参与由计时外的受控派发测试验证。不能在每个正式样本中加锁收集线程 ID 来证明并行，从而改变所测成本。
- 无工作、下限未满足、安全分块不足、请求 1 和缺池等原因分别解释；并行辅助发生串行回退仍保留原始时间及预规划成本，不作为主动并行胜负样本。

### 6.4 正确性与等价

评分检查成员、逐节点分数、队列反向索引及堆不变量；拓扑检查预算、邻接、裂缝、活动叶、队列成员及网格修改的规范化语义；网格调用实际网格验证并比较全部有效顶点属性、索引及绘制规模。中间拓扑阶段不得对尚未提交的旧几何执行帧末网格一致性断言。

规范化结果允许合法的节点/槽位和提交顺序差异，但不得只比较数量或单个布尔值。每条记录明确 `validationPerformed`，哈希相等不能替代验证确实执行。网格三策略只要求最终可渲染内容等价，脏区间和写入数量可以不同；串行全量的额外写入属于成本。

## 7. 标定与最小分析

### 7.1 标定

每次独立配对尝试在采样前后记录各 1000 次空计时及 1000 次真实无工作阶段时间。空计时使用测量相同的时间点与单位；无工作项在有效根输入的合并评分边界，以相同测量核心执行串行空队列评分，证明工作量为 0，副本和验证不计入。前后分别为首个已选场景新建独立标定流水线，在根帧观察器中同步测量，不能保存来源观察器引用供事后使用。若实际边界不满足无工作条件则标定失败，不能临时改成空循环。

标定文件保留原始值、前后位置、种类、分辨率、P50/P95/P99；记录 empty/no-work 的量级和前后漂移，不从策略时间中相减。空计时 P99 高于 0.01 ms 时标记环境不满足测量要求，不输出胜负结论。工程验收还在两个中预算场景各阶段的最小 selectionRank 目标执行三次独立短运行（W=2、R=10、P=8）；目标集合在运行前固定，缺目标或回退照实记录，不临时替换。

按“同一目标 × 动作”的三次运行级中位数检查漂移，不能将不同工作量混成一个中位数。三值极差超过其中位数的 5% 时，按 24 号文档要求冷却并整轮重测一次，保留两轮；仍不满足则标记环境不稳定，停止胜负解释。近零样本同时报告绝对量和无工作状态，不用小分母强行解释。

### 7.2 分析输入与配对

分析 CLI 显式接收一个或多个已完成尝试目录和新的分析目录，校验源码/测量协议、冻结输入、场景、线程、计数与来源元数据兼容。不同后端、执行版本或参数分组，不能合并成一个结果。重复传入同一运行拒绝；复制目录不能变成新的独立运行。

先核对全部行、块、目标和摘要，再区分预热、无工作、回退和标定不合格数据。失败尝试只输出失败审计，不从其中抽取部分成功目标作胜负统计；标定不合格的完整尝试可报告原始量级，但不作胜负判断。

两策略只按共同块配对；网格从同一完整三策略块派生三组比较。并行脏写回退时，涉及它的策略对不作主动并行比较；若整个目标正确且完整，串行脏写与串行全量仍可比较。任何缺行、重复键、额外动作、非法排列、NaN/Inf/负耗时或输入/结果身份冲突均报错。排除及覆盖不足在报告中单列，不能静默裁剪。

### 7.3 描述性统计与噪声

每个“独立运行 × 目标 × 策略对”先计算块内差 `d = tA - tB`，再求中位差；相对收益明确分母及方向，分母为 0 时标记不可定义。不给相邻相机点或同目标的 30 个重复伪造独立样本身份。

最小 pilot 采用预先固定的保守描述规则：基础实际差阈值为 `max(0.01 ms, 较快策略中位时间的 3%)`；噪声量级同时参考对应运行前后空计时/无工作 P99 的较大值及配对差 MAD 的 3 倍，取各项最大值。中位差未超过阈值时记为平局/噪声不足以判断，不单凭正负号判胜。该规则为探索描述，MAD 不是置信区间；PREP-05 可在采集其判断数据前 Review 并版本化调整，不能看过结果后移动本次边界。

按冻结目标的 low/middle/high/coverage 层及原始工作量排序展示，每个运行分别报告；覆盖补点独立列出，不用耗时重新分箱。存在两个相反方向、均超过上述阈值的目标或区域时，只标记“观察到双向描述性信号”；并列展示跨运行方向一致性和有效目标数，不宣称通过正式稳定交叉或研究继续条件。没有信号时如实报告单边优势、回退或覆盖不足。

报告至少包含：输入及版本、标定、完整性、实际并行覆盖、各目标策略时间与差值、工作量分组、每次独立运行的结论和限制。中文 Markdown 与聚合 CSV 使用同一统计结果；绘图、bootstrap/Holm 和正式模型选择留给 PREP-08。
