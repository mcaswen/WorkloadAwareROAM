## 2. 规划前新增的定位结果

### 2.1 实验设计与数据

仅运行保留旧应用与已提交的新应用，没有改动生产源码、二进制、驱动、电源方案或全局进程配置。使用 OpenGL `standard`，六组各一次预热块和五次计量块，每块四个独立进程，交替 ABBA/BAAB；组间顺序按块反转，共 144 次进程。记录命令、PID、进程 CPU 时间、实际继承的亲和性和系统忙碌比例。

六组包括最大并行策略的新旧对照、旧程序自身对照、新程序自身对照、两个三级缓存分组内的新旧对照，以及串行策略的新旧对照。同程序对照中的 A/B 仅是位置标签，不是不同版本。

本机 API 返回两个三级缓存共享掩码：`0x0000ffff`，96 MiB；`0xffff0000`，32 MiB。限制亲和性只发生在调查父进程及其子进程中，结束后恢复；没有给正式应用增加绑核策略。掩码代表本机观测，不能硬编码为其他机器的处理器结构。

| 最大并行策略的条件 | 旧或 A 帧中位数（ms） | 新或 B 帧中位数（ms） | 五个块差的中位数（ms） |
| --- | ---: | ---: | ---: |
| 全部逻辑处理器，新旧 | 13.706125 | 13.192125 | −0.178525 |
| 全部逻辑处理器，旧/旧 | 13.844800 | 13.697500 | −0.177950 |
| 全部逻辑处理器，新/新 | 14.050300 | 13.763575 | −0.153125 |
| 96 MiB 分组，新旧 | 9.790725 | 9.696625 | −0.140800 |
| 32 MiB 分组，新旧 | 13.954725 | 13.554550 | −0.094750 |

旧/旧的五个帧差为 `[-0.177950, +0.736475, -0.568700, -0.799725, +0.186325]` ms。说明同一版本也能出现与历史版本差值同量级的变化，但这些新数据不能反推历史每个异常的唯一原因。两个缓存分组的区别还包含可调度处理器与频率等因素，不能把约 4 ms 的差异全部归因于缓存容量。

六组全部算法非计时字段分别一致。系统忙碌比例覆盖约 12.91%～26.27%，包含被测应用自身，不能直接解释为后台负载比例；未记录各线程实际迁移轨迹或每核频率，尚不能定量分解调度、缓存和频率贡献。

### 2.2 仍需定位的局部信号

96 MiB 分组下，`pass_splitScoreHeapifyMs` 中位数的五个块差为 `[+0.002900, +0.001300, +0.002475, +0.001025, +0.002000]` ms；相同条件下整帧和证据收集没有同方向恶化。这个小包络值得定向排查，不能用整体较快将其覆盖。

`DataOrientedRoamQueues.obj` 的修改时间早于 PREP-04 原始基线归档。进一步将对象文件中的函数与两份应用逐段匹配：`SiftSplitQueueDown`（192 字节）、`SplitEntryPrecedes`（49 字节）、`RefreshPersistentSplitQueuePriorities`（891 字节），各自在旧、新 `.text` 中唯一匹配；排除链接重定位字节后机器码相同，函数 RVA 不同。

这排除了这三个函数主体被重新编译成不同指令的解释，**没有排除调用目标、链接布局、输入地址、缓存或调度影响**。目前不应直接修改堆算法、增加缓存或强制函数对齐。

### 2.3 已确认的测量缺口

普通 `MakeScenario` 显式开启 `EnablePassEvidence`；`standard` 和 `budget-saturation` 关闭的是逐帧拓扑验证。`buildWallMilliseconds` 包含阶段证据收集，而 `CpuUpdateMilliseconds` 在该收集之前停止计时。原矩阵可以比较这条基准路径，但不足以证明三个诊断开关关闭时的生产成本。

PREP-04 新增的 `PassEvidence` 与普通 Pipeline 的 `CollectPassEvidence` 是不同调用边界，不能因名称类似就认为新验证代码污染了普通帧。此项核对已完成，后续应增加准确的诊断关闭对照。

### 2.4 已批准的实验契约

**统计单位。** 独立启动的应用进程是主要统计单位，每个进程先将其固定轨迹的帧数据汇总为一个中位数和 P95，再作跨进程版本比较。同一进程内的帧、线程、阶段子项以及同一 CSV 的重复读取都不增加独立样本数。报告同时列出每版本有效进程数、预热进程数和排序块数；ABBA/BAAB 用于抵消执行位置影响，块内先以相邻 A/B 进程构成方向一致的差值，保留进程差及块汇总，不将块和进程再重复计数。相同程序 A/A、B/B 与跨版本 A/B 分列。

**微秒级差值关闭。** 原极差仍负责触发调查，不能用新的结论标签撤销原始记录。剩余绝对差不超过 0.01 ms 的指标，允许在两个独立受控批次中按以下冻结规则审查：输入、算法结果、诊断、构建和实际处理器条件一致；两个批次都具有同条件的 A/A 与 B/B 进程对照；各批次版本配对中位差的绝对值不超过本批次两类同程序进程差的绝对值 P95，且两个批次均未出现超出该控制范围的稳定同向差值。同程序 P95 必须不超过 0.01 ms，否则说明环境太粗糙，不能用较大噪声隐藏微秒差值。必须列出全部进程差、块差、方向和控制范围，结论限定为“在已记录条件及分辨能力下，无版本相关证据”，不宣称数学等价或跨机器无回归。缺少控制、环境不稳定、超过微秒范围或持续可辨认的差值仍保持未关闭。此关闭路径与查明原因并修复并列，不要求为不可分辨差值猜一个根因。

**Probe 开关集合。** `diagnostics-off` 固定 `EnablePassEvidence=false`、`EnableTopologyValidation=false`、`EnableTopologyPairEvidence=false`；`diagnostics-on` 对照固定为 `true/false/false`，对应原普通基准的证据设置。每帧使用的三个值写入原始 CSV，运行元数据保存完整集合及协议版本 1；缺少任一值或与模式不符即拒绝分析。其余设置、策略及线程数量由同一场景和显式策略绑定，不能随模式改变；计时外网格正确性校验始终执行并单列成本，不计入 `BuildRenderData` 包络。

## 4. 定位顺序与分支判断

### 步骤 1：保留版本，补全测量身份

在任何拓扑或性能改动前保存 `7522db7` 的完整应用、符号、构建参数和源码；继续使用原 `2dac3ea` 归档。固定资产、工作目录、参数、诊断设置和运行顺序，逐进程记录实际亲和性、环境起止和失败状态，保存原始 CSV。

把当前 25 项触发项映射到唯一计时包络，保留别名与相关性；核对中位数、P95、绝对/相对差和各次原值。新增工具采用显式字段清单或已知 CSV 头契约，未知非计时字段不能被默认忽略，`cpuUtilizationPercent` 单独列为环境观测。

### 步骤 2：先分离环境与诊断开销

1. 在两后端对原六配置先各做一次预热、五次独立计量的新旧交替，保留原调查规则；优先解释此前仍有疑问的三个配置。
2. 对 OpenGL 主要疑问配置保留同程序 A/A 对照，并在机器实际报告的各三级缓存分组内分别执行新旧对照。每种亲和性都是独立条件，不能选最快分组去覆盖原条件。
3. 新调查目标用同一公共设置、清单和冻结相机分别驱动旧/新源码的 CPU `BuildRenderData`。三个诊断开关全关与原基准设置分别运行，固定外层包络；结果核查在包络之外并记录成本，两版本协议完全相同。它是诊断关闭的 CPU 调用对照，不冒充 GUI 帧率或原普通基准。
4. 旧版本需要以相同调查驱动在隔离构建目录编译，不借当前新测量实现执行旧程序冒充旧源码。记录驱动、被测源码与构建的独立身份；禁止链接一半旧、一半新的算法后称为完整旧版本。

初次控制实验固定一次预热块和五个 ABBA/BAAB 计量块，进程顺序运行；如同程序波动足以覆盖疑问版本差值，只允许在明确修正环境条件后完整复测一轮，不无限追加直到出现期望方向。环境仍不稳定则保留“性能尚未验证”，转入有针对性的调度观测。

### 步骤 3：定位剩余差值，形成具体修复

| 观测 | 下一项检查 | 可以支持的修复方向 |
| --- | --- | --- |
| 仅不限制处理器时异常，控制条件下版本方向消失 | 对代表性旧/新进程采集线程调度、迁移及可用频率信息；记录实际采集能力和限制 | 修复性能采集的环境约束及元数据；不能直接给生产应用绑核 |
| 证据开启时异常，关闭后消失 | 分析现有 `CollectPassEvidence` 的排序、哈希、分配热点；用独立归因运行分段，不挪动验收计时边界 | 只有定位到实际版本变化或冗余工作后才提出证据路径修复；开启诊断后的固有成本不能伪称 PREP-04 新退化 |
| 建堆差值在控制条件下仍稳定 | 核对完整调用目标、对象与链接符号、函数和输入地址布局；以隔离链接/构建对照测试具体假设 | 证实构建或代码因素后提出相应窄修复；当前三个函数的主体匹配不能替代调用链审查 |
| CPU 时间接近但墙钟差异明显 | 检查调度等待、线程唤醒和同步，核对实际工作线程及同程序控制 | 仅修复证实的等待来源，不根据墙钟差值盲改评分和拓扑 |
| 结果或工作量不一致 | 先定位行为与输入差异，停止速度解释 | 转交相关正确性规划；不能将不同工作量下的较快值计为修复收益 |

分析工具可使用本机已有 WPR/ETW 或等价采样能力，但先检查是否已有采集会话；不能中断用户的采集。跟踪仅用于归因，采样扰动的耗时不能混入最终性能比较。运行环境或权限不足时明确保留缺失证据，不编造调度/频率结论。

本步骤结束须形成“已证实原因 → 对应文件/设置 → 修复行为 → 对照实验”的明确记录，或按第 2.4 节形成受控复测支持的“无版本相关证据”记录。原因不明且未满足不可分辨条件时，不能用强制对齐、降低诊断、改变并行下限或扩大噪声阈值试到通过。

### 步骤 4：修复后闭环验收

实施经 Review 的具体修复后，重新运行原矩阵、受影响热点和诊断关闭对照；同时对比本修复前版本与原始 `2dac3ea`。两后端分别报告，不能以另一后端的改善抵消局部恶化。

如果是测量环境缺口修复，应在明确的新环境中重测保留旧版本和新版本，同时保留原环境下的未解释记录。环境改变不会自动让旧的 25 项变成通过项；需要逐项说明复现结果与归因证据，不能用较宽的新噪声范围替换原规则。无法追溯历史具体原因时如实记录，是否接受新的受控验收口径由本规划 Review 明确。

## 5. 性能基线、命令与预算

贯穿每个实现子步骤：先保存该步骤前报告，再使用同条件复测，独立记录工具成本和生产成本。不得等所有工具及生产改动完成后才采集第一份基线。

主矩阵继续使用：

```text
<old-or-new-exe> --benchmark --algorithm dod --profile <standard|budget-saturation> --pass-policy <default|serial-incremental|maximum-parallel-incremental> --csv <new-output>/frames.csv
```

两个后端使用既有 `RelWithDebInfo` 预设，完整命令、二进制和资产摘要写入元数据；主矩阵每组一次进程预热、五次独立计量。同步记录 `buildWallMilliseconds`、`cpuUpdateMilliseconds`、`passEvidenceMilliseconds`、评分/建堆/拓扑/网格子项、进程墙钟/CPU 时间和峰值内存。计时别名不重复累计；诊断关闭探针使用单独模式和报告。

新增工具按本次 144 个进程记录的规模验证完整读取、语义核对、统计与中文报告，建议本机预算 30 秒/256 MiB，测量包含文件读取及摘要核对，排除应用执行时间和解释器启动。实现前先用当前调查脚本记录相同数据规模的处理基线，保存脚本身份。超限单独分析，不能缩减核查字段。测试不在 CI 中以此墙钟阈值作断言。

原调查规则保持：原五次独立运行级统计中位数恶化超过原极差即调查；同时报告其他项实际变化。该规则不是允许回归额度，也不是 CPU 策略交叉的胜负阈值。控制实验用于解释原因，不得挑选更快块或只报告显著改善的条件。

所有产物保存到 `benchmark-output/prep-04-performance-fix/{before,after,comparison,diagnosis}/<attempt>/`；规划前 144 次调查保留在 `benchmark-output/prep-04/planning-performance-diagnosis-20260910/`，不覆盖原报告。

## 6. 测试、风险与两项修复的关系

工具测试覆盖完整字段、坏 CSV、缺失/不一致身份、配对顺序、A/A 标签、进程失败及亲和性恢复；探针验证相同相机/资产/策略、诊断开关与连续包络，比较有效几何与结果，不能只检查返回成功。发生生产修改时运行受影响专项与双后端完整构建/CTest，逐文件核查注释和职责。

主要风险是小包络对调度与布局敏感，调查本身也可能扰动环境；因此原始数据、控制条件和归因运行必须分开。没有证据时保留不确定性，不能用一项调度设置的收益给算法下结论。

[拓扑等价性修复](prep_04_split_topology_equivalence_fix_plan.md)会改变并行安排数量，必须保持独立版本。先完成本规划的原版本定位，再进行拓扑修改；两条线完成后追加联合版本对照。已有不等价的跨策略数据只用于正确性归因，不参与性能胜负解释；同版本性能问题也不能用拓扑修复后的新工作量掩盖。

关闭条件：测量身份和诊断关闭路径完整；疑问指标有可复现原因与对应处理，或满足第 2.4 节不可分辨关闭契约；相同工作量、相同计时边界的复测支持结论；原 25 项逐项有结论；阶段报告、性能分析、代码事实和架构审查同步。若仍不能判断，则保持阻断状态；是否继续其他阶段需要用户明确决定。

## 7. 已批准的具体决定

用户批准：先补测量工具与诊断关闭对照；将处理器分组视为显式实验条件，保留默认环境主矩阵；重点调查建堆剩余差值和链接调用链；生产优化由定位证据确定，再补具体修改供 Review。第 2.4 节落实本轮三项 Minor Revision，不改变主体文件边界。不能将本规划理解为已确认“只需绑核”或“只需优化堆”。
