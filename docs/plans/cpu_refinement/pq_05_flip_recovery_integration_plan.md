# PQ-05：净零翻边恢复的受控接入与持续轨迹验证

2026-09-15，小规划；代码基线`eebf9bd`。用户已确认实施，按一个小阶段自主闭环并独立提交。范围是在既有事务化流水线中增加一种有限恢复事务，不新建更新框架。虽需同步配置、计数和输出等多个入口，但沿用已确认的状态所有权、阶段划分和发布链路。

## 1. 目标与依据

[PQ-03](../../research/cpu_refinement/pq_03_fit_counterfactual_results.md)定位到同连接下Fit选值偏保守；[PQ-04](../../research/cpu_refinement/pq_04_local_recovery_results.md)另找到一个净零连接恢复正例：frame8的AB翻边保持旧点几何和三角形数量，却将q2当前误差从1.348412降至1.114554px，固定frame15投影从2.351050降至1.943430px。原E/F/H在该状态全部形状失败。

本阶段只回答：**把这种2→2连接恢复作为原目录的有限兜底，接入真实持久状态后，是否能够改善原24机会轨迹的恢复，并维持结构、预算、确定性和可计费的续接？**

必须区分三个出口：接入正确、持续质量收益、运行成本。前者通过不自动代表后两者通过，不要求本阶段追平DOD质量或性能。

### 前置阅读与源码事实

已阅读开发规范、规划规范、PQ-02/03/04规划与结果及[PQ-04代码事实](../../codebase/cpu_refinement/pq_04_local_recovery_facts.md)，并扫描当前配置、候选、认证、预留、提交、样本/网格续接、平台回放及诊断入口。直接影响接入的事实：

1. `TransactionalReservation::Plan`先并行处理相同全局前缀的原目录，再按优先级顺序做不可回退预留；预算命名基于每个接收方净+2。
2. `TransactionalCommit::Prepare`明确拒绝接收方不是净+2的批次。因此不能把净0提案伪装成已有空额度细分。
3. `Proposal.Free`可以为空，提交器的几何写入循环也允许为空；但`Fit`直接访问`Free[0]`，且其仿射基准来自旧曲面。翻边不应调用Fit。
4. `PreparedTopology`已按旧支持/新面构造邻接、活动数组、身份和局部记录；`Samples::Prepare`与`Mesh::Prepare`消费该差分，没有按净+2才能运行的公开前提。这是复用候选，仍需定向验证。
5. `Footprint`已记录旧面、旧/新边和高度资源；共享邻接由提交准备阶段统一合成。是否足够覆盖新提案的读取前提需逐项核对，不能只凭旧函数存在就宣布冲突正确。
6. 原追溯中的“非donor必有新点”假设不适用于翻边，需要按明确事务类型记录，而不能伪造新点。

## 2. 范围和冻结策略

新增`EnableFlipRecovery=false`配置，沿`TransactionalLodSettings → Configuration`传入；默认关闭。首版只支持`PreserveSurvivingHeights=true`且`HeightGuard=false`的组合。不支持的组合明确拒绝，不能静默改动用户设置。

政策属于种子生命周期身份：公共适配器已有完整Settings比较，切换时Reset并重新初始化；`SetView`禁止直接更改该政策。B/C对照各自从同一个旧种子开始，不在运行中切换政策。

本阶段不修改：

- 原E/F/H顺序、拟合选值、新点源高规则及general one-ring回收；
- 全局评分、前缀160、donor池160、.25/.10阈值、最小角和硬预算50000；
- 既有命名额度与同批不重新分配规则；
- 相机路线、自然输入或恢复机会数量。

不加入翻边后立刻细分的复合操作，不连续翻多条边，不2-ring、不新HeightGuard、不前缀扩张、不冷却/滞回政策、不新的并行调度。PQ-03选值优化继续保持独立。

## 3. 执行语义

### 3.1 何时尝试

仍从同一快照取得原精确全局前缀，按原顺序处理每个根的E/F/H。

- 原目录成功：保持原接收提案，完全不构造翻边。
- 原目录实际尝试非空、耗尽且**全部返回`shape_infeasible`**：政策打开时，进入翻边兜底。
- 原目录因质量、近面、数值、配额或无可见样本失败：本阶段不启用该兜底。
- 预算配对或批次冲突失败：也不返回前端再选翻边。

这个范围针对PQ-04已定位的问题。负结果只约束此兜底策略，不能推广为所有连接恢复无效。不得对`frame8`、根`-111`、AB身份或q2坐标硬编码生产触发条件。

### 3.2 有限翻边目录

根的三条边按稳定点身份排序，每边最多尝试一次。每个候选只取两侧面、四个旧点：

1. 边必须有两侧活动面、不同对面点；四边形严格凸。
2. 新对角线不存在于当前全局边表；同一有向外边界保留。
3. 两个新面正方向、原最小角判据成立，所有旧点UV/高度逐值不变。
4. 新面数=旧支持面数=2，无新增点、无删除点、`Free`为空。
5. 通过本节质量认证后，选择**固定边顺序中的第一个合格项**；不按未来视图收益重排，不选最大收益项。

当前阶段一个根至多产出一个原细分或一个翻边恢复。不同根可能提出同一条边的重复翻边，交给共同资源冲突预留拒绝，不额外建立全局边扫描/去重平台。每批最多3r次局部尝试，r=160；本批新面只在下一批可见。

### 3.3 质量目标复用生产数值契约

翻边只改变连接，不进入`Fit`或PQ-03高度搜索。为避免复制第二套微像素算法，从`TransactionalCertification::Fit`中定向提取现有的“选择旧见证并求进展阈值”纯职责，建议接口：

```text
SetProgressTarget(state, samples, proposal, work) → 原原因或成功
```

原Fit在原位置调用该方法，保持原样本顺序、比较、精确算术、计数、舍入与原因。新翻边在几何前提之后调用同一方法，再对实际固定高度执行`Measure/Accepts`；不改变旧Fit内部其余逻辑。

支持S始终为原两面闭区域；可见样本取既有`VisibleSupport(S)`。沿用生产算法：由浮点评价确定旧见证w，再精确计算其误差，得到

\[
\tau=\lfloor 10^6 e_{old}(w)\rfloor-10000.
\]

新S最大采样误差须被原认证器证明不超过该微像素目标。即使浮点评价选到的w不是精确最大点，`e_old(w)≤E_old(S)`，接受条件仍要求旧S最大值至少减少0.01px；可能保守漏解，不能因此放宽阈值。

PQ-04诊断使用“旧S误差上下界落在同一微像素格”的目标。本阶段不复制其全支持旧测量到正常路径，而是复用现有生产见证阈值；两者在冻结AB正例上的对应必须在定向验证中记录。若本例出现差异，先解释，不修改目标追求正例。

保持原当前视图/固定Q质量含义。q2与未来视图只用于观察；不能成为运行时选择输入。局部最大值下降允许逐点退化，`EnableFlipRecovery`不提供新的全域高度或跨视图保证。

### 3.4 混合批次与预算

在`Exchange`中新增明确的类型标记，如`ExchangeKind::Refinement`与`ExchangeKind::ConnectivityRepair`；原默认是`Refinement`。标记附加在原聚合字段之后，保持旧构造默认含义，不能用`HasDonor=false`区分两类事务。

接收阶段保留每项原全局前缀位置。细分接收数和命名额度仍只对原净+2项计算：

\[
C=\min(\lfloor(B-N)/2\rfloor,\ N_{refinement}).
\]

按**混合项的原全局优先级顺序**预留：

- 细分项按其在细分子序列中的序号使用既有命名额度或原donor规则；
- 翻边项只检查自己的资源与已预留项冲突，无donor、不消耗或归还额度；
- 高优先级已预留翻边可以阻止低优先级细分，反之亦然；不把全部翻边放到批首/批尾；
- 任何项预留失败都不回退重选，不同批的状态仍由实际发布结果决定。

`Receivers/Need/Feasible/Executed/FreeExecuted`保留原细分/预算交换口径，另记翻边的触发、尝试、认证、冲突与实际执行数量。必须满足：

```text
batch.Exchanges.size() = Executed + FreeExecuted + FlipExecuted
finalN = oldN + 2 * FreeExecuted
```

原四层预算交换分母不能被净0恢复稀释；翻边与预算交换分别报告。已有`Exchanges`集合可容纳两类事务，但报告字段不能继续把集合长度全部称为预算交换数量。

## 4. 冲突、提交与续接

翻边读取旧支持面、四点几何、旧边使用和新对角线不存在性；写入旧/新边关联及两面替换。旧点高度只读。优先复用`Footprint/Conflict`，核对上述每项均被资源键覆盖。共享顶点的incident列表、候选资格、样本和输出派生状态继续由已批准批次统一合成；不新增并发容器写入。

提交器按类型验证：

- `Refinement`仍严格要求接收方净+2、可选donor净−2；
- `ConnectivityRepair`严格要求无donor、净0、两旧面/两新面、旧点集合和几何一致、无自由高度，拒绝伪造类型；
- 两者均检查旧快照代际、未解决冲突、最终预算和形状，之后共用`PreparedTopology`。

续接验收必须覆盖：

1. 复用旧面槽但生成规范逻辑面身份；`NextVertexId`和活动顶点集合不因翻边变化。
2. 外部邻面关系、四点incident列表及边表完整一致；共享顶点的独立事务合成顺序不影响逻辑结果。
3. S内样本归属/插值误差和受影响接口面的优先级刷新；不能因为面数不变就跳过。
4. donor索引与接收候选的受影响邻域失效；无需全局重建或重新导入种子。
5. 两个新面产生真实网格/法线/索引脏块；未消费Pending继续累计，不能因净0而错误报告空上传。
6. 准备失败或配额到期不发布半份状态；开关Reset、暂停、消费和再次更新仍沿原生命周期。

不直接改写真实面数组跳过`Prepare → Samples/Mesh Prepare → Publish`。本阶段不重构状态表示、分配器、预留算法或渲染资源。

## 6. 运行模式与记录

### 6.1 同一24机会上的两个政策

- **B**：现有固定旧点政策，翻边关闭；保持旧轨迹对照。
- **C**：固定旧点政策加本规划的形状失败兜底，从第0次正常规划即启用；不只在frame8注入一次有利翻边。

唯一自然输入仍为Peking547²、尺度80/12、深度20、预算50000、r=m=160、原24次相机机会，原材质、1280×720、OpenGL/NO、关闭VSync。C相对B的轨迹、批次、面身份和工作量允许改变，不能要求逐帧与B相等；必须证明同一初始种子。

C一线程和八线程必须得到相同决策、逻辑结果及实际网格。该对照验证执行确定性，不因新路径几何合法就略过。

平台回放沿既有入口，仅附加可选`--flip-recovery`；要求事务化算法和immutable模式。视觉模式复用`GraphicsBackend::RequestFrameCapture/TakeFrameCapture`与`ExperimentVisualArtifacts::WriteCapturedFrame`，不改后端。若有可复用的同输入B捕获则直接复用；无匹配来源时补一次B视觉回放。

### 6.2 诊断账本

正常路径只保留必要有限统计；详细记录由探针输出，不混入正常平台计时：

- 原目录全形状失败的根数；翻边尝试、凸性/形状/投影/数值/质量拒绝数、认证数、冲突数、执行数。
- 原预算交换四层分母、空额度、实际N和新恢复数分别列出。
- 每个执行翻边的四个稳定点身份、旧/新边、旧/新支持、旧高度、视图、证书目标及误差。禁止依赖不断变化的面ID识别翻回。
- q2逐帧高度、当前可见性/误差、固定frame15投影；沿用原q1等既有见证，不只追踪变好的点。
- 同四点旧边→新边→旧边的次数，区分相机、四点高度和支持是否改变；不把视点驱动的合法反转自动称为振荡错误。

原`Recovery`诊断重建E/F/H失败时，也要明确当前是否曾尝试翻边，避免新政策下仍错误归因为“没有接收提案”。复用已产生的批次记录优先，不再跑一遍生产规划得到解释。

## 7. 实施步骤与验证

### 步骤1：冻结与局部接线

保存`eebf9bd`来源、旧探针/平台程序、配置、资产和基线身份。PQ-04默认q2进程4.453036s及完整B轨迹可作为探针对照；平台旧B正常计时只有身份和环境匹配才复用，否则在改码前补一次旧B。

实现生产翻边组件、进展目标提取和类型化净0提交。先验证解析几何以及PQ-04冻结AB候选：同旧点/连接、阈值、证书与预算；数值目标提取不得改变关闭路径的Fit结果。该案例是局部对应夹具，不是持续C轨迹的强制触发点。

### 步骤2：混合预留和续接

加入默认关闭政策、严格形状失败触发及原全局位置预留。选择风险相关夹具：

- 净0翻边在N=B时仍可运行；净+2没有额度/donor仍拒绝。类型伪造、附带donor、旧点改高、同边/共享边冲突拒绝。
- 高优先级翻边与低优先级细分、相反优先级、独立翻边/细分混合；原命名额度不因翻边错位。
- 批次正序/反序，允许共享只读顶点的独立事务；逻辑拓扑、邻接、样本、候选与网格一致。
- 局部续接对照同一目标上的全量重算oracle，检验样本归属、误差、优先级和donor资格。全扫只在测试，不成为正常修复路径。
- 连续两批不消费后再消费Pending、过期批次、准备失败、Reset和政策切换。
- 相同视图、相同四点高度和支持中，接受一次翻边后立即请求反向翻回，进展认证应拒绝。若不成立先审计阈值/样本对应，不加cooldown掩盖。

只运行相关新夹具及被进展目标提取/净0路径实质影响的原认证、提交或适配夹具；不跑全CTest、后端矩阵或更多线程档。

## 10. 架构决策摘要与当前状态

- **目录**：新增一个核心`TransactionalFlipRecovery`组件、一份定向测试和一个阶段脚本；其余均为现有边界的必要接线。

- **核心变化**：原E/F/H全形状失败→有限翻边兜底；明确事务类型，恢复与预算交换统计分开。
- **实验边界**：同一24机会B/C；不采用PQ-03高度政策、不扩原语、不改渲染、不扩大矩阵。
- **备选方案未采用**：所有根优先翻边会混入新调度政策；另设翻边后置批会改变相同快照下的全局优先预留；直接修改面数组会跳过现有续接保障。因此首版均不采用。

当前状态：**实现与验收闭环；接入及本冻结轨迹持续改善通过，默认关闭。** 对生产质量政策的更强保证仍属于后续独立问题。
