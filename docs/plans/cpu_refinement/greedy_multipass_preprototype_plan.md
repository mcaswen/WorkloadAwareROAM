# 全局优先级驱动的事务化 CPU LOD：原型前大规划

> 日期：2026-09-14。类型：**Major Plan，研究契约与原型准入**。状态：**GMP-01 已提交，GMP-02 已完成组合推导与有限续接检查；提交后进入 GMP-03，GMP-04 尚未启动**。
> 基线：`8af1a41`；事实：[原型前能力基线](../../codebase/cpu_refinement/preprototype_capability_baseline.md)；自审：[规划审查](../../reviews/cpu_refinement/greedy_multipass_preprototype_plan_review.md)。
> 本规划止于“具备编写并评审原型实现规划的证据”。仅允许后续获批阶段制作有限离线核查工具，不启动持久 C++ 新算法、真实并行提交或生产接入。

## 1. 研究定位、目标与范围

研究对象是**将 ROAM 拓扑更新内部逐次决策、立即修改的串行反馈循环，重构为全局优先级驱动、事务化、数据导向的 CPU 动态 LOD 执行模型**。核心变化是将全局优先级决策与拓扑修改解耦（decoupling global priority-driven decision making from topology mutation through a staged transactional execution model）。

原循环可概括为“选择请求 → 强制细分/合并 → 修改拓扑 → 修复队列/依赖 → 选择下一请求”；目标流程为“快照候选/评分 → 全局需求 → 局部提案/认证 → 冲突/资源预留 → 批量提交 → 局部续接/物化”。**multi-pass 是执行形式，不是主要创新本身。** 本工作不声称消除所有串行性：全局顺序预留仍可能串行，反馈仍存在于批次之间；其工作量、关键顺序和成本必须显式计入。

一般 one-ring 回收是拓扑阶段的预算重分配原语，用于提高 planner 决策的兑现能力；它和多边形 DP 不承担独立 remeshing 创新的叙事。

这是一条在[现有 CPU ROAM 主线](../formal_experiment/cpu_roam_research_definition.md)下待验证的算法扩展。本规划记录用户提出的贡献层级，不追改历史研究结论，也不提前把新候选称为严格 ROAM 的等价实现。

原型前要回答四个问题：

1. 脱离二叉层次后，priority、greedy 顺序和质量各自是什么意思？
2. planner 能否直接从当前网格形成可认证事务，提交阶段不再执行目标发现或 forced propagation？
3. 在共同的真实输入和预算需求上，一般回收是否比三价回收多兑现了有价值的决策？代价在哪里？
4. 安全提交后，下轮候选、质量缓存和增量输出需要维护什么，是否已有完整可计费规格？

不要求原型前证明普遍质量进展、优于 Legacy 或实际多核加速。也不把“批宽非零”当成完整算法成立。

**范围**：执行语义、现有局部引理的组合、有限快照兑现审计、成本与依赖规格、已有工作差异表、原型准入判断。

**非目标**：2-ring / 多点任意重网格、新 closure/传播算法、重新优化 NativeTargetPlanner、GPU/CBT、生产开关/渲染上传、通用 profiler、全矩阵实验、完整连续误差求解平台。MPR/NMP、已有生产算法和历史报告保留。

**实施原则**：大规划是最大工作范围，不是必须完成全部设施的瀑布流程。每阶段先写小规划并 Review；理论反例、成本或自然证据已足以作判断时提前停止。推导保留问题、假设、尝试、失败例、修订和证据，不只留最后结论。

2026-09-14 用户进一步授权：本大规划执行及后续小规划由 Agent 自主完成规划、实施、验证和审查，不再逐阶段等待确认。随后明确按“完成一个小阶段 → 验证与审查 → 单独 Git 提交 → 开始下一阶段”的顺序推进。本授权包含各阶段本地提交，不包含远程推送，也不扩大原语、原型或生产接入范围；发生停止条件时记录证据并作阶段决策。

## 2. 当前基础与缺口

| 能力 | 已有基础 | 原型前必须补齐 |
| --- | --- | --- |
| 输入 | 冻结 DOD 来源和阶段观察入口 | 中立当前网格快照，不能通过 `MaterializationDodBridge::Capture` 顺带运行 Legacy 取得 J |
| 决策 | 局部交换、条件匹配/独立选择推导 | 一个完整、确定且直接产生本轮事务的全局 planner 规格 |
| 几何 | 有界接收补丁、d→d−2 回收、精确有限 DP 和正负例 | 当前原语集合的统一入口、数值前提、失败分类及完整读写支持 |
| priority | DOD 层次误差、公共屏幕投影 | 任意当前/拟合三角形可重新计算的 P；不能借用旧 variance/path 的语义 |
| 质量 | bilinear 主参考、sampled maximum | 局部证书与全局固定样本的对应；采样接受和连续保证分开 |
| 状态 | DOD/MPR 各自完整状态及 oracle | 新一般网格的状态/缓存/候选/输出义务；旧 Lean 支持集定理不自动迁移 |

当前没有完整的新 planner 或自然兑现率探针。以下“将测量”均为规划，不能写成已经能直接运行的实验。

## 3. GMP-01 要冻结的算法契约

### 3.1 保留什么，推广什么

| 语义 | 建议契约 | 不继承的结论 |
| --- | --- | --- |
| 全局优先级 | 批次开始时全域合格候选按 P 和稳定身份全序处理 | 不能仅因排序相同就声称逐请求轨迹等于 Legacy |
| greedy | **批次快照上的全局优先级顺序贪心预留**，具体规则见下文 | 批内新候选只进下一批，可能偏离逐步重算 greedy |
| 预算 | 每个已发布网格 N≤B；预算与临时内存分别管理 | 预算利用率/质量最优性不自动成立 |
| 共形性 | 参数域完整覆盖、无悬挂点/重叠，共享边界位置与高度一致 | 允许一般连接，不要求仍为原 binary hierarchy cut |
| 质量 | 独立 bilinear reference 下的明确误差契约 | P 不等于独立 E，Legacy 不是 E 的质量最优 oracle |
| 持续更新 | 新稳定身份、版本和局部缓存支持；回收保留存活顶点当前高度，接收拟合只修改已认证支持内的高度 | 不复用不适用的 ROAM path 历史、旧高度回滚或原生 Γ 定理 |

正式策略名称为 **batch-snapshot global priority-ordered greedy reservation**。下文的 global greedy 均指以下规则：

1. 在不可变快照 M_j 上，按冻结的有限候选生成规则形成全部 `RefinementIntent`，不预先按回收后端的成功结果过滤。全域指该规则覆盖完整快照，不意味着枚举任意几何位置；若因资源上限未完成生成，必须标记不完整。
2. 按紧迫性 P 降序及稳定身份同分规则，形成 `I_1 > I_2 > … > I_m` 的全序。分区或线程数量不能改变这个顺序。
3. 按全序逐个处理需求；只在其预冻结的接收提案列表和 donor pool 中，按固定顺序寻找第一个通过认证、空间兼容且资源可预留的方案。
4. 成功时原子地预留该完整交换的资源；高优先级请求已取得的预留不被后续请求抢占，不回退重配以最大化总交换数。单独使用空余预算的接收分支及其规则在 GMP-01 同时冻结。
5. 失败时撤销该请求尚未成功的临时尝试，记录不可认证、无合格回收、冲突或资源限制等原因，继续后续需求；上限内搜索失败不能称为整个类别无解。
6. 扫描期间只更新规划预留账本，不应用拓扑修改，也不根据其他提案应用后的状态重新构造当前批次成员。完成或达到预冻结限额后封闭批次。
7. 本批应用产生的新候选、几何与资格仅在下一快照可见；不得回插本批排序。

**global** 指完整同代快照上的需求形成与排序，区别于各线程/空间分区独立决定优先级；**greedy** 指按此顺序不可回退地尝试预留。它不是固定预算全局最优三角剖分，不是最大兑现数/最大独立集，也不是动态串行 `NextRequest` 的严格复现。

例如 A(10)、B(9)，A 执行后出生 C(9.5)：批次 A/B 与动态串行 A/C 不同。GMP-01 保留这个反例，固定候选覆盖、同分、搜索顺序、停止和空预算规则，不重新开启动态严格模拟器。顺序预留的扫描、重复提案尝试与失败工作进入成本账本，不因提交并行而省略。

### 3.2 紧迫性 P、接收证据 G、回收代价 C 与独立质量 E

| 量 | 角色 | 与其他量的边界 |
| --- | --- | --- |
| P：urgency | 当前区域值得优先处理的程度，形成需求全序 | 不依赖哪个回收后端最终找到方案，不等于事务实际收益 |
| G：receiver gain / acceptance evidence | 具体接收提案的旧误差见证 L_r、新误差上界 U_r 及改善证据 | 可以是结构化证据；P 高不保证该接收提案能改善 |
| C：donor damage / reclamation cost | 具体回收提案对质量的代价证据及几何条件 | U_d 是回收后误差上界，不是误差增加量；若另报 damage 增量，应保留旧/新误差及定义 |
| E：独立质量 | 相同 reference、采样与视图下对实际几何评价 | 不由需求排序或后端成功率定义，不把 Legacy 自动当质量最优解 |

G、C 不必各压成一个标量。最大误差不可加，不能把 `G≥C` 或“收益减损失”替代 `max(U_r,U_d)+η≤L_r` 的质量组合条件。第一轮只分离这些角色，不新增收益优化目标。

建议首轮离线规格使用固定公共样本 Q 和实际当前三角形，定义

\[
P_Q(t)=\max\{E^{sample}_{screen}(t),\ \beta\,\ell_{screen}(t)\}.
\]

这保留“投影失真加细节密度”的优先思想，但不是 DOD 原 score 的等价替换。GMP-01 冻结 β、排序/同分规则、无样本面、不可投影/跨近面处理及计算费用。无样本不得被解释为连续误差为零；未覆盖或无法认证的区域标记未知。

共同主参考仍为 **raw height samples + bilinear interpolation**。Q 由固定参考域产生，不依赖候选顶点、选中事务或被测结果；局部证书必须覆盖 Q 在完整修改区域中的全部样本。当前 mesh 的存活拟合高度必须来自当前状态，不能重新吸附到 source。

第一轮只对采样契约作接受保证；绝对 sampled screen maximum、height maximum及最大点保留。独立更密一层只作预先指定的小规模敏感性核查，不把经验稳定写成连续保证。RMS、配对 Dmax 和连续屏幕证书按需要另列工作，不预先建设整套 evaluator。

### 3.3 上层需求必须先于后端可行性

定义 `RefinementIntent`：快照版本、接收区域稳定身份、优先级/排序、期望增加的面数、允许质量规则。先冻结原始需求，再检查接收方案与各回收后端，避免仅统计已经知道能成功的事务。所有后端共用 P、接收提案/认证 G 以及同一原始需求；后端只改变回收方案及 C，不反向改变需求 population。

首轮只比较净 **+2 / −2** 的内部预算交换；已有面内/共享边/完整邻域接收构造均在现有原语集合内，GMP-01 固定有限提案顺序和每区域数量，不枚举无限几何位置。移动旧点的接收必须覆盖其完整邻面。边界需求与不同面数增量单列为未覆盖范围，不静默删除。

建议为每个需回收的接收需求冻结同一有限 donor pool：由当前内部顶点和不依赖新重剖分结果的代理次序生成；候选数量上限、同分规则和结构过滤在测量前写入小规划。三价与一般回收看到相同中心池，不能各自挑输入。代理排序、池外候选与接收原语失败都单列；有限搜索没有找到解不等于不存在解。

这个简单选择规则不是最优配对：高请求先拿最便宜 donor 可能减少总兑现数，已有反例必须保留。首轮固定它以分离后端能力；只在少量小池用枚举审计选择器损失，不新增全局匹配研究。

## 4. 目标数据流与职责边界

```text
FrozenCurrentMesh + SourceReference + View + Budget
    → Candidate / Priority Refresh
    → Ordered RefinementIntents                 全局需求，尚未承诺执行
    → Read-only Local Proposal + Certification  原语构造、误差/形状和预算代价
    → Pairing + Conflict Resolution + Reserve   形成已认证、资源互斥的批次
    → Private Patch Preparation
    → Publish + Local State / Mesh Maintenance
    → next snapshot                            新生机会只在此后可见
```

| 组件 | 输入/输出及所有权 | 禁止承担的职责 |
| --- | --- | --- |
| 来源适配器 | 借用只读 DOD，输出自有中立快照、输入摘要 | 不调用旧拓扑阶段取得新算法目标；不让研究内核依赖 DOD 控制器 |
| 候选/priority 阶段 | 读取同代几何和 reference，输出自有候选数组 | 不修改拓扑、不把 oracle 结果伪装为便宜评分 |
| 全局 planner | 有序需求、池限制、确定策略和预算账本 | 不携带整份最终网格/邻接作为提交阶段的答案 |
| 局部事务生成与认证 | 固定边界、局部替换面、质量证据及完整访问集合 | 不读取前一事务应用后的状态来扩大本批 |
| 冲突选择/资源预留 | 不可变提案，输出批准事务及拒绝原因 | 不用“removed faces 不交”替代全部状态冲突审计 |
| 提交/维护 | 私有结果、唯一输出槽位、局部变化列表 | 不再发现目标、求全局 closure、临时寻找替代 donor |

这是待验证架构，不要求原型前实现上述持久模块。离线工具只实现足以审计契约的单轮切片。

概念记录限定为 `Snapshot`、`RefinementIntent`、`LocalProposal`、`CertifiedExchange`、`BatchDecision`、`StateEffects`。提案持有快照版本及逻辑身份，不保存悬空节点地址；不可变输入持续到该轮检查完成。新 ID 按确定的事务/局部顺序分配，物理槽位不进入 priority 同分规则。

采用**不可变快照、值类型事务、薄来源适配、纯规则与编排分离**，为同代观察和审计服务；首轮不引入虚拟插件层、通用任务图或运行时策略注册中心。

### 4.1 与 DOD 五个 pass 的对应关系

**保留 DOD 的阶段化执行思想与可复用基础能力，使用新状态引擎实现事务路径；不把一般回收直接插入旧节点状态的 `SplitTopology`。** 这是本大规划的接入边界，具体生产接口在后续规划中 Review，不是本轮代码变更。

现有生产顺序为：

```text
DOD Prepare
 → MergeScore → MergeTopology → SplitScore → SplitTopology → MeshEmit
 → DOD Validation / History / Stats
```

五个阶段并非接受任意三角网格的独立插件。它们共享 `DataOrientedRoamState` 的二叉节点、菱形资格、持久队列、路径历史和增量网格状态。一般连接产生以后，这些表示前提不再自动满足。

| 原 DOD 阶段 | 新流程中的对应职责 | 可复用部分 | 必须更换或重新证明的部分 |
| --- | --- | --- | --- |
| `MergeScore` | 回收候选的低成本代理评分；局部回收质量认证单列 | 只读数组分块评分、线程派发和排序/归约技术；纯投影数学 | 候选由原合并菱形转为当前内部点/邻域；不复用 `MergeQueue` 资格、原生层次误差或把 DP 隐藏在“评分”中 |
| `MergeTopology` | 回收提案、与接收需求配对后的回收子事务 | 先确定工作再提交的职责划分、局部脏状态维护方法 | 原节点/菱形合并执行器不能应用一般 one-ring；当前预算交换中的回收必须由联合事务规划决定 |
| `SplitScore` | 当前接收区域的全局 P 刷新与接收需求排序 | 数据并行、稳定全序、分块执行及公共几何公式 | 输入改为当前实际面/高度和新误差契约；原 hierarchy variance、`SplitQueue`、path/depth 抑制不可直接沿用 |
| `SplitTopology` | 全局需求、局部提案、配对/冲突、预算预留及批量应用 | 保留规划/执行分离与串行/并行策略比较 | 不调用旧 strict controller、forced split 或预算交换函数；本阶段不再单独拥有所有拓扑决策 |
| `MeshEmit` | 已提交新面与脏属性到 CPU mesh 的增量物化 | 预分配槽位、脏面分块填写、区间合并，以及公共 CPU 输出类型/寿命契约 | 新面到槽位映射、变化记录和顶点写入逻辑需适配；实际拟合位置不能被 `SampleTerrainWorld` 覆盖 |

这里的“复用”有三个层次：公共纯函数/值类型可以直接复用；不依赖拓扑的调度能力可经薄适配复用；原节点/队列耦合的 pass 函数只作为参考，不用同名函数伪装兼容。不会为统一接口强迫 Legacy 热路径经过新状态抽象。

### 4.2 新旧阶段顺序与组合边界

对于本轮固定预算交换，新的一批建议组织为：

```text
New Prepare / Freeze M_j
 → [接收 priority refresh | 回收 proxy refresh]   共同读取 M_j
 → 全局需求 / 局部构造与认证
 → 配对 + 冲突筛选 + 预算/输出资源预留
 → [回收子补丁 | 接收子补丁] 私有准备
 → 联合发布拓扑 + 修复局部状态
 → 新 MeshEmit → 发布公共 CPU mesh
```

两个评分职责可以独立分块，但都必须看到同代状态；认证读取的也是该代，不能沿用旧 `MergeTopology` 修改前后的两份分数混成一批。回收和接收属于同一预算事务，不能先跑一个无关的旧合并阶段，再把新接收当作等价替换。

**旧 `MergeTopology` / `SplitTopology` 在新引擎中对应一个联合拓扑事务阶段的两类操作，而非两个必须保持原顺序的旧函数。** 子操作、准备、发布和维护可以分别计费；不得为了维持“五个槽位”把联合规划重复计入两侧，或漏掉配对/认证成本。

现有 `SplitTopology` 自身就可能为预算执行合并。未来性能比较应使用实际完整阶段包络，不按函数名字推断操作类别；旧报告中的 crossover 归账与新细分计时也不能直接相加当作更新总时间。

**生产覆盖缺口**：当前 Gate 主测 +2/−2 交换，并不已覆盖低误差区域单独粗化、预算上限下降、边界增量或所有无空闲预算的更新情况。GMP-01 列出这些行为及“不支持”的明确出口，GMP-04 安排原型/生产后续工作；未补齐前只称实验更新策略，不称完整 DOD 替代。不能让新网格下一帧再调用旧 `MergeTopology` 来补齐这些行为。

### 4.3 状态、入口与旧/新选择

建议未来在 **`ITerrainLodAlgorithm` 的算法实例/完整更新入口**选择旧 DOD 或新事务引擎，分支发生在各自 Prepare 之前。旧 DOD 保留 `DataOrientedRoamState` 和五阶段；新引擎拥有自己的当前网格、身份/版本、候选、证书缓存和输出槽位。算法选择与线程策略是不同维度，不把新算法藏在现有 `ParallelAssisted` action 内。

共享接口限于高度场输入、相机、尺度、预算与公共 CPU mesh 输出等有共同语义的值。`MaxDepth`、原 split/merge 阈值、路径历史及原质量评分参数不能未经映射直接解释为新算法的约束；新契约参数和算法身份必须随报告记录。

旧/新选择保留供对照，但**不提供任意帧之间共用同一拓扑状态的热切换承诺**。推荐切换时重置相应引擎，或使用显式、单独计费且验证过的导入；初始化、冷启动和必要全量上传单列。正常运行时新引擎直接持有前一帧自己的状态，不每帧复制 DOD、不跑 Legacy 产目标、不转换回原二叉层次。

原型前的 `SplitTopology` 前快照捕获只是一次性输入接口：旧 MergeTopology 已经执行这一事实要写入来源身份。它不能被宣传为未来每帧“旧前三阶段 + 新拓扑 + 旧网格提交”的生产组合，也不证明新算法已承担完整更新。

未来文件落点建议为：独立实验原型放 `src/experiment/greedy_multipass/`；经另行批准的生产引擎/适配层放 `src/algorithms/greedy_multipass/`，面向 `ITerrainLodAlgorithm`。本轮不创建这些目录或接口。若最终选择作为 DOD 对外模式呈现，内部仍保持上述独立状态所有权，具体枚举/GUI 名称留生产接入规划。

线程池可在实验调度适配层包装现有 `DataOrientedRoamThreadPool::ParallelFor`，由新引擎拥有自己的实例；纯事务内核不依赖 DOD 状态或线程池。若生产阶段需要提取通用调度组件，单独 Review 后实施，不在本轮重构 Legacy。

### 4.4 网格与渲染接入

新 `MeshEmit` 的输入是已提交面、当前顶点高度/位置、属性变化及自有面到槽位映射。几何位置必须反映拟合结果；法线采用当前几何还是 source 梯度属于需要明确的显示契约，不能假定旧写面函数语义合适。Debug 中旧路径/强制来源等不适用字段应明确标注，不伪造。

输出沿用 `TerrainMeshData` 与 `TerrainLodRenderPacket`：网格所有者、`UntilNextBuildOrReset` 借用寿命、generation、全量更新标志和顶点/索引区间必须一致。保留“逻辑顶点身份”与渲染复制顶点/物理槽位分离；即使沿用每面三个渲染顶点，也不代表可直接使用 DOD 的 `SlotOwners`。

OpenGL 和 D3D12 从公共 CPU mesh 边界消费结果，各自管理上传/资源；本路线不修改后端渲染模型。正式接入时分别验证 generation、切换后的全量更新和区间生命周期，不合并两套 uploader。GMP 阶段不做这些图形测试。

### 4.5 阶段证据与接入验收

- **计时**：保留评分、事务构造/认证、排序/配对/冲突、提交、状态维护、网格提交和完整更新各边界。准备、来源导入、验证/收尾也要有完整计费出口；实际完整包络是端到端比较依据。
- **身份**：新算法的阶段记录带独立契约/算法身份；可作职责对应表，不能把不同任务硬写为旧 P5 的五个严格配对 pass。现有 `TerrainLodPassTrace`/CSV 是否扩展，由后续实验接入规划决定，本轮不改历史 schema。
- **同任务核查**：相同快照、相同新规则和同一批准批次下，串行/并行检查当前网格、预算、脏输出与下一轮候选一致；不要求新算法和 Legacy 最终拓扑相同。跨算法采用同输入/预算/独立质量与完整耗时比较。
- **Gate 责任**：GMP-01 冻结五阶段对应、参数/状态边界及未覆盖的生产行为；GMP-02 给出提交到下一轮评分/网格提交的变化清单；GMP-03 只核查只读来源与有限应用；GMP-04 必须列出未来算法适配、开关/reset、公共输出、计时和生产覆盖任务后才能形成原型实施建议。

这使已有 DOD 的阶段拆分、数据并行和增量输出经验继续成为新算法的执行基础，同时准确区分“复用执行模型”与“复用原生拓扑状态实现”。

## 5. GMP-02 的必要证明与续接清单

### 5.1 局部到批次

1. **原语与预算**：内部 d 面回收成 d−2 面，接收增 2；固定边界、高度连续、域覆盖和最小角条件逐一验证。不能因局部拓扑存在就声称质量可接受。
2. **质量组合**：沿用 `max(U_r,U_d)+η≤L_r` 时，L 必须是旧状态真实见证，U 必须覆盖同一完整修改域。明确保证的是冻结 Q/view 下全局最大值不增，可能其他区域固定住最大值；不保证 RMS 或每点都改善。
3. **几何冲突**：定义 F_v 为待删除中心 v 的 incident-triangle / removed-face set。不同内部中心的 `F_u∩F_v≠∅ ⇔ uv 是当前网格边` 只描述两次回收的面重叠；接收—接收、接收—回收及完整交换的冲突必须另算。
4. **状态冲突**：共享保留边界点可能共写度数、邻接入口、法线、候选和脏标记。逐项选择唯一所有者、确定归约或保守冲突；需读邻点坐标/高度的证书依赖也属于访问集合。
5. **组合与发布**：对合格小批次用不同应用排列与独立几何验证器比对逻辑结果，不比较物理槽位；证明分配、预算预留与局部替换兼容。整批原子可见或先回收后细分，但消费者不得看见未完成网格，失败不得发布半个交换。

纸面一般命题与脚本有限检查分别标注。只机械检查容易犯错的组合，不为形式化率扩建 Lean。旧三价独立性、b/57 等条件常数不迁移到一般回收。

**完整读写契约**：对 `CertifiedExchange T_i` 定义 R_i 为认证与执行依赖的逻辑状态集合，W_i 为改变的拓扑、元数据和缓存集合。包括删除/插入面、边关联及不存在性条件、顶点度数/邻接入口、候选资格、priority 缓存、样本归属、法线/输出属性、脏标记、槽位所有权，以及证书读取的邻点坐标/高度。按逻辑资源键描述，不要求逐条 C++ 字段读取插桩。

在没有另行解决共享操作的情况下，若

\[
W_i\cap(R_j\cup W_j)\ne\varnothing
\quad\text{或}\quad
W_j\cap(R_i\cup W_i)\ne\varnothing,
\]

则不把二者直接接纳为独立事务。这是保守的充分独立性判据，不把拒绝解释为数学上必不可并行。所有证书读取同代快照；共享不可变 reference/view 只有读，没有由其产生的写冲突。

全局预算、分配器和新 ID 先由协调阶段统一预留，得到唯一配额/输出槽位，再分析执行事务的资源集合。不能给每个事务独立使用旧余额，也不能把未分解的同一个全局计数器放入所有普通 W_i，制造全图冲突。活动预算、临时内存和发布峰值分别核查。

少量共享写可采用明确的交换归约，例如脏标记 OR、带唯一贡献身份的整数增量；必须同时固定结合律、贡献次数、溢出边界及读取时机。可将事务产生的增量在屏障后统一归约，再重算受影响资格/缓存；事务不得读取归约的中间结果。浮点加法不自动满足逐位排列一致，必要时固定归约顺序。归约规则未证明的共享访问仍按冲突处理，不建设通用事务系统。

GMP-02 的目标命题为：**局部事务各自合法、同代认证、批准集合不存在未解决读写冲突、资源预留有效且共享归约满足上述规则时，不同合法应用顺序得到等价逻辑拓扑及续接状态。** 等价覆盖下一轮候选/缓存和输出几何，不要求物理槽位编号一致；反序检查只是这一命题的有限审计，不能替代完整支持证明。

### 5.2 续接状态是原型准入的一部分

必须形成“字段—来源—失效支持—修复动作—代价”的表，覆盖：

- 活动面/顶点、边关联、边界、稳定 ID 和版本；
- 当前高度、局部法线/输出属性，禁止历史高度回滚；
- 候选资格、priority、采样归属及证书缓存；
- 预算账本、槽位生命周期、脏面/区间和消费者可见代；
- 无进展/拒绝状态的寿命；它们不能意外成为永久屏蔽。

固定视图下可局部维护的项需给出支持证明。相机变化可能要求全域候选和样本误差刷新，应计入实际工作，不能仅写 O(N) 而漏掉样本评价。原型前只要求规格闭合及小例下一轮重生成检查，不构造完整持久队列。未能解释续接义务时不得以“最终三角网格正确”通过准入。

**样本归属的目标维护模型**：Q 固定于参数域，维护 `sample → active triangle` 与 `active triangle → owned samples` 双向关系；边/顶点样本采用确定的唯一归属规则。相机变化不改变这种参数归属，重新剖分只需重分配完整修改区域中的样本；仅改变顶点高度也可能使误差失效，即使归属本身没有变化。所有受影响邻面与边界样本都必须纳入支持，不能靠唯一归属漏掉移动旧点的影响。

正常实现的目标为按归属聚集样本并归约当前面的误差，计

\[
W_{refresh}=O(N_{candidate}+|Q_{evaluated}|),
\]

不采用“每个面扫描全部 Q”的 O(N|Q|) 默认方式。该目标前提是归属/反向索引有效、单样本投影求值按所列原语计费；相机移动可能使 `|Q_evaluated|=|Q|`，不承诺视点变化后次线性更新。

初次定位/索引构建、O(N+|Q|) 级归属存储、局部重新定位、索引/缓存更新与全局排序另计。例如对含 s 个样本、O(d) 个新面的补丁，直接逐面定位可能需要 O(sd)，不能一概记为 O(s)。不同接收/回收提案对同一样本的重复认证仍计入 `W_certificate`，不由当前网格的唯一归属自动消除。

GMP-01 固定归属、失效与空样本语义，GMP-02 核对局部维护支持和下一轮全量参考的一致性。原型前可使用全扫独立验证器，但须标记诊断实现、完整计时，不作为未来正常路径的复杂度或性能基线。

### 5.3 最小角与拓扑度数不变量

广义拓扑后端要求初始网格及所有批准输出都满足同一**二维参数域**最小角 θ₀；内部点周围角度总和为 2π，故

\[
d(v)\le D=\left\lfloor\frac{2\pi}{\theta_0}\right\rfloor.
\]

θ₀=30° 时 D=12 仅为数值例，实际参数由 GMP-01 在自然后端运行前冻结；不能用三维高度曲面角度套用 2π，也不能为通过 Gate 放宽角度。边界点按对应边界几何另行处理，不套用内部点证明。

这一不变量支持单个 one-ring 的拓扑记录和最终面/边写入 O(D)，固定层数局部邻接维护可计 O(D²) 等明确界。它不保证合法回收必然存在，亦不使样本数、源栅格相交或 `W_certificate` 成为常数。

事务冲突图的度数还依赖每面/点的提案重数及配对规则。大量接收提案若共用一个回收点，即使网格度数为 6 也可形成大冲突集合；需限制提案重数或先固定配对，才可另推冲突邻域界。GMP-02 不提前沿用旧分支的常数界。

## 6. GMP-03：最小后端兑现审计

### 6.1 输入、工具与范围

冻结一个小规模自然快照面板：两个已有场景 `test129-a-b4096`（30/4）、`peking547-a-b20000`（80/12），各取 2～3 个预先指定 sample index，总计 4～6 个快照，不增加预算/线程/压力矩阵。`sample14` 可保留为历史锚点，其余时间点及全部选择理由在 GMP-03 小规划、运行任何新后端之前一次性冻结；可依据已有时间协议或既有执行前特征，不能依据新算法成功率选点。

全部在 **SplitTopology 执行前**捕获当前活动叶，相机/分辨率/资产摘要沿用原冻结清单，不调预算、原阈值、地形尺度或高度比例。来源是新算法初始几何，不是必须复现的目标；此时可能尚未更新的 mesh 输出不能当作当前网格。多时刻只减少单帧偶然性，仍只有两个场景，不当作独立场景样本或完整统计重复。

以一个薄 C++ 导出入口取得中立快照，Python 离线审计消费快照。旧规则二叉 UV 可导出精确逻辑坐标键，避免 epsilon 焊接改变拓扑；适配器验证共享点高度一致、关联与边界。只导出几何/身份/环境，不导入原队列或求目标 J。

面板中每个快照各做一轮共同输入比较；保持逐快照结果，包括无需求、失败、未知和较慢结果，不只汇总成功帧。对事先固定的高优先级选择规则产出的事务做少量副本应用，核查组合结果与下一轮候选重新生成；明确这是单轮审计及有限续接检查，不是持续算法原型。诊断副本、全量验证与导出成本单列，不承诺未来运行时复制状态。

这里确实需要少量新的单轮参考执行代码，不能宣称只重排已有结果就能测量。它以验证器可检查的几何值和诊断副本为出口，不实现跨帧状态所有权、持久队列、线程调度或生产增量消费者；这些是后续原型的边界。若单轮审计也必须先建设完整运行时，提前 Review，缩回可以回答问题的有限范围。

不增加压力矩阵。若冻结面板全部没有 `D_need`，结论为 **当前冻结自然输入没有覆盖预算竞争**；保留零工作证据并结束本面板采集，不临时添加时刻、改变预算/阈值或切换压力路径寻找正结果。

### 6.2 分母、分层与失败状态

统一保存四层集合：原始高优先级需求 `D_raw` → 接收侧已认证且需回收的需求 `D_need` → 在共同 donor pool 中找到合格交换的 `D_feasible` → 经冲突/资源选择并验证应用的 `D_executed`。

`D_need` 不能用“回收方案成功”定义。各后端先共用接收认证结果、快照余额以及预冻结的空余预算归属规则，形成同一个预算需求基准；不能根据某后端较早请求实际成功/失败后产生的余额，重新分类分母。GMP-01 还须固定空额度释放/复用规则及其与该共同需求基准的对应；若真实执行出现空额度再分配，另记流转和无回收提交，不用它改写原分母或冒充后端交换成功。

空余预算满足的接收、接收侧本身不可行/未知、边界或原语未覆盖分别统计。`D_executed` 在这里仅计固定 `D_need` 中经认证回收交换提交的请求；它是 `D_feasible` 的子集。局部可行性在同一池上不扣除其他请求的预留，实际 donor 复用冲突属于后续执行流失，不能反向降低 `R_local`。两类比例分别报告：

\[
R_{local}=|D_{feasible}|/|D_{need}|,\qquad
R_{execution}=|D_{executed}|/|D_{need}|.
\]

分母为零写 N/A，不能报 100%。另给相对 `D_raw` 的总流水线流失，避免隐藏接收证书过滤。相同需求可能有多 donor，按需求去重，不用成功 pair 数冒充成功请求数。

| 必须输出 | 解释 |
| --- | --- |
| 三价、一般快路径、一般快路径加 oracle 的兑现数 | 同一需求/池/质量/形状规则的后端能力消融 |
| fast miss + oracle feasible | 启发式漏解；记录实际可构造证据 |
| exact shape / quality infeasible | 限于已完整求解的 one-ring 类别、固定边界与声明误差 |
| unknown / cap / invalid projection | 资源上限、数值不确定、池外机会或未认证；不并入 infeasible |
| 被一般回收解除的高优先级阻塞 | 保存需求 ID、priority rank、原阻塞原因与新证据；不能仅报总交换数 |
| conflict / donor reuse / budget / metadata 拒绝 | 区分后端能力、选择器和提交模型限制 |
| N、B、N/B、回收和接收面数 | 净预算、实际利用率和中间发布峰值 |
| d 分布、完整事务支持大小、批宽及工作不均衡 | 不能用平均 d≈6 掩盖高价点/大证书成本 |

快路径建议固定一种合法耳切顺序，失败后不无限换启发式。DP 只用于预先指定的有限失败子集；记录度数、候选三角形数、采样数与资源上限。未审计其余失败仍为 unknown；有 unknown 时给兑现数的已证下界与剩余可能范围，不推算完整总体成功率。

有限浮点 DP 的“精确”还需要数值契约：组合穷尽并不等于算术认证。小夹具复用有理数/独立穷举；自然样本若比较有未消除的数值区间，输出 unknown，不能凭一个 epsilon 判数学无解。

三价回收是**原语消融**，不是有竞争力的传统 ROAM 基线；规则 ROAM 网格可能本来就几乎没有三价中心。一般回收优于三价只证明能力扩展。原型比较还必须保留 Classic/DOD 或自然逐事务参考，不能据此宣称比 Legacy 更强/更快。

### 6.3 成本账本

分别记录输入恢复/导出、几何索引、priority refresh、需求排序/扫描、局部构造、认证、配对、冲突筛选、私有填写、发布/状态维护及独立验证。诊断 oracle 与拟议正常快路径分开，二者都不漏计。

逻辑量至少包括：面/候选扫描数、reference/sample 访问数、样本归属初建/重分配量、尝试的 donor 对数、局部三角形评价数、DP 状态/转移数、顺序预留/冲突检查数、新旧面/边写数、缓存失效量、分配量与峰值临时字节。受限候选池的范围限制进入报告；不能把候选读写合并成一个无法解释的总时间。

成本模型至少保留

\[
W=W_{refresh}(N,Q)+W_{order}(m)+W_{proposal/cert}
+W_{pair/conflict}+W_{commit}+W_{maintenance}.
\]

每个回收完整费用写成 `W_ring + W_geometry + W_certificate + O(d³) + W_reconstruct`；朴素实现可能有 O(d⁴+d³s) 工作。不同提案可独立准备不代表准备便宜。只报告当前选择器找到的可行独立工作和模型成本，离线 Python/导出时间不能称为 CPU topology speedup。

**原型准入的必要条件**：

- 当前网格到需求、事务、批次的语义完整，不需要 Legacy 产 J；指定有限原语可构造并能解释失败。
- 共形性、活动预算、声明质量契约及完整读写/续接义务没有未处理的正确性缺口；一般命题和有限检查界限清楚。
- 至少有自然输入的已认证预算交换被完整应用，并在冻结选择规则下出现包含两个及以上不冲突事务的批次；这是可执行性信号，不是吞吐量结论。未出现只能说当前输入/模型证据不足。
- 有完整成本和资源账本，没有未登记的全域工作；oracle 不能被默认为每帧免费的目标发现器。
- 已有工作差异能落到具体执行契约/组织/工作量假设与后续消融，不只剩“删点、DP、独立集、SoA”。不要求预先证明论文可发表。

一般回收的自然增益若已存在，可据此纳入原型；若三价已足够，则可简化原型，不为扩展 primitive 而扩展。若主要需求持续被 one-ring 形状/质量否证，或认证/选择成本使直接目标来源失去意义，先 Review 后决定停止当前后端或调整范围，**不自动扩展 2-ring**。

没有覆盖预算竞争、unknown 太多、只观察到宽度 1 分别记为“缺少证据”的具体原因，不能否定整个 CPU 主线。按四层实际流失决定后续范围：`D_raw→D_need` 检查接收证书/预算覆盖，`D_need→D_feasible` 检查回收类别/搜索及认证，`D_feasible→D_executed` 检查冲突/资源/选择；不要把任一层失败都归因于几何原语不够。GMP-04 可以以“不进入当前原型”结束，无须补齐剩余工具。

| 参考 | 契约与用途 | 不能作出的解释 |
| --- | --- | --- |
| **A：Dynamic serial greedy** | 相同新原语、P/G/C/E 与资源规则，每提交一个事务后按更新状态决定下一请求；允许正确的局部候选/缓存维护 | “重新决定”不意味着每步全域扫描/重建；不能为迁就参考而人为拖慢 |

| **C：Batch parallel commit** | 与 B 相同批准结果，实际并行准备/提交，维护与发布完整计费 | B→C 才支持同任务 multicore speedup；不能只测局部填写而称完整更新加速 |
| **D：Classic / 当前 DOD** | ROAM 家族的完整性能、独立质量、预算利用率与行为基线 | 不要求与新一般网格最终拓扑一致，不作为本算法动态串行参考 A 的替身 |

B/C 同时区分给定批次的应用时间与含目标发现/认证/选择的完整更新时间；共享离线 batch decision 可用于提交配对，不能免除完整运行的规划费用。A 的停止/重试/空额度规则和 B/C 的批次规则在 GMP-01 明示，跨语义比较同时报告实际工作与质量，不仅报告耗时。

| 风险 | 处理与结论边界 |
| --- | --- |
| 快照 greedy 严重偏离动态 priority | 先明确新生延迟/跳过规则，后续量化质量/利用率；不以全局排序宣称 strict |
| 几何/证书比真正修改昂贵 | 全流程计费；限制 oracle 在审计，保留 fast miss；不预支 2～5 倍收益 |
| 旧顶点拟合与形状约束导致停滞 | 保留 CR 反例和完整邻域接收规格；不回滚历史高度或无限加新原语 |
| 选择器低估后端能力 | 少量同池精确审计；仅称当前找到的 feasible batch |
| 共享边界状态使几何独立不等于可提交 | 明确状态所有权/归约和检查排列；负结果限定当前实现边界 |
| 小面板仍来自两个 DOD 场景 | 多时刻减少偶然性，只支持种子状态现实核查；不证明一般网格长期行为或场景泛化 |
| 已有方法本质覆盖组合 | 定向比较 greedy terrain refinement、固定预算插删点、并行简化与误差约束重网格；只核查契约差异，不泛搜 parallel terrain |
