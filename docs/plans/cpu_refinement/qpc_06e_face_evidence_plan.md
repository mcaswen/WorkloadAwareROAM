# QPC-06E：提案面证据复用的同结果消融

2026-09-17，基线`a508870`。用户在06D及剩余空间评估后确认继续。本阶段只落实面/边不变量准备，不调整质量政策、旧Fit或任务调度。

## 1. 问题与范围

06D消除了固定接收块的不均衡，但P的原生接收仍为41.92/29.90ms，Sierra最慢根包含8次Fit和7次逐点认证。06C源码与perf已发现面覆盖、重心插值反复恢复面端点、边差和面积。现有SampleEvidence缓存的是单样本参考/投影，ProposalEvidence服务于旧Fit，均不能直接替代两域逐点证书的面事实。

本轮限于`PointwiseQuality::Certify`内旧/新面覆盖及高度求值。每个表示域建立私有面证据，区间与精确系数按需构造，支持多个样本复用。保持原边/面序、区间表达式树、精确回退、样本集合、损伤与进展判断。`ValidateBatch`、旧Fit/Measure、接口认证、视图、预留和持久状态均不改。

非目标：跨提案/帧缓存、全Q缓存、裸double替代区间、更紧误差界、提案选择变化、删减认证、并行目录、数值库重写、05预留、持续质量修复。此次只是普通执行优化，没有新增Lean或一般几何算法。

## 2. 文件归属与架构

已阅读开发/规划/审查规范、06A/06C/06D计划与事实，核查`QualityEvaluation`、`QualitySampleEvidence`、`PointwiseQuality`、`ProposalEvidence`、测试/CMake及已有运行归约入口。

| Extend | `TransactionalQualitySampleEvidence.h/.cpp` | 增加消费已准备面集合的覆盖入口，仍惰性提供精确样本坐标；旧入口保留为对照 |
| Extend | `TransactionalPointwiseQuality.cpp` | 每域拥有面证据数组，将原覆盖/插值替换为同式求值；局部物理计数在样本循环外归并 |
| Extend | `cmake/TransactionalLod.cmake`、`tests/CMakeLists.txt` | 登记新组件及独立数值专项，沿用严格浮点选项 |

依赖为`PointwiseQuality → SampleEvidence/FaceEvidence → QualityEvaluation`，低层不反向依赖证书或实验层。面对象拥有冻结点值；每次认证、每个域、每个线程独立，析构包括在认证/完整计时内。新对象不进入持久证书。不会增设配置开关或通用缓存系统。

## 3. 形式推导义务

令冻结面的点为a,b,c，样本坐标为q。缓存原公式的子表达式，例如`b.u-a.u`、`c.v-a.v`及`area=(b.u-a.u)*(c.v-a.v)-(b.v-a.v)*(c.u-a.u)`。不是代数重排，也不能用反向边差取负替代原区间减法。

1. 区间构造与每次基本运算顺序不变，缓存子表达式端点与原计算逐位相等；精确域缓存同一binary64有理值，按需产生。
2. 按原面序、每面原三边序检查，保留闭包含及歧义才回退；因此首个覆盖面相同。只缓存值不更换覆盖谓词。
3. 高度插值保留原w0/w1/w2及最终加法树；除法保留原零分母路径，不将area倒数代换为不同算法。区间/精确高度相同推出原质量分支与累计相同。
4. 两域各自来自原Faces结果，不共享float与核心参数域的系数。样本参考和投影复用沿06A，不能重新采源高代替被测高度。
5. 新物理计数可变，逻辑Touch/求值人口/停止与发布验证不变。时间期限触发仍是失败，不混入正常同结果提速。

设面数d、边查询数e、高度查询数h。原面内不变量在每次查询计算，本轮将其变成至多每个被触达面/数值域一次；总覆盖仍最坏O(ud)，未消除样本数u或有理位长。按实际准备数记录成本，早拒绝也可能让准备成为额外工作。固定差分运算计数及系数内存另列，不把少一次有理操作当作固定CPU时间。

推导过程/拒绝方案写进结果原文并更新推导索引和数学总览。边界样本、正负零、输出舍入、小面积和区间跨零须有oracle核对；不以最终网格哈希代替数值专项。

## 4. 实施与验证顺序

1. 保存06D的FP/Tracy/Windows二进制与源身份，复用06D四配置96机会前测。记录`benchmark-output/cpu-refinement/qpc-06e/run-01/`，不覆盖基线。
2. 实现面证据与数值专项，先做有限内核对照再接入；完整计入准备/析构。数值不等价即停止该候选，不改断言，不靠更好质量接受差异。
3. 运行新面证据专项、既有逐点政策与核心持续测试；不全CTest，不重跑未改变曲面的密集质量评价。
4. Linux FP四组、原生D3D12四组各一次正常后测。沿06D的L/P、50k预算、r=m160、8线程、96机会，主分母frame3～31。Sierra实际约9千～1万面，不能误写饱和50k。
5. 仅Sierra P补一次perf和一次Tracy，并保留同Tracy构建未连接对照，核对函数占比、根内时间与捕获扰动。复用06D观察入口，不新增逐样本事件；Tracy每次认证末尾导出一次面构造/消费聚合数，关闭宏无此事件。全部运行顺序执行，与编译/分析隔离。
6. 一次归约全部96帧行为、移动/返回/静止均值/中位/P95、逻辑与物理工作。正常轨迹只具工程证据；微测内部短重复不充当独立进程。

内核目标为含准备的同输入几何求值下降至少10%；至少一个P移动完整均值下降5%，其余P和未修改L无超过工程门槛的持续回退。达不到完整目标则诚实记录有限收益；无实质收益或空间/早拒绝代价抵消时撤回生产接入，不无限追加机制。目标不是承诺追平DOD或修复持续质量。

采集预计15分钟内、单进程180秒；仅出现具体回退时按`max(0.05ms,5%,已知波动)`至多补一次受影响旧/新配对，不扩矩阵、不追静止微秒。06D静止残余继续保留，不因本轮新增机制混淆归因。
