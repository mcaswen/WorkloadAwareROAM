## 1. 问题、目标与有限范围

成本审计确认：Sierra/Canyon完整暖CPU相对04D分别为2.89×/2.00×，接收阶段净增量为67.114/46.061ms。实际检查根数只增加约3.4%/0%，不能用请求总数解释开销。旧Fit、新逐点认证、失败后的目录继续尝试同时存在；没有同提案对照，不能为各函数预填耗时百分比。

性能修复分清三个不同问题：

| 问题 | 当前证据 | 处理归属 |
|---|---|---|
| 同一认证反复恢复参考、坐标和投影；快速进展累计也构造有理数 | 源码调用链与现有组计时明确 | **本阶段：同输入等价降本** |
| 同状态、同视图空批仍重复旧Fit/形状失败 | Canyon末端31机会、34,720次失败 | 条件QPC-06B，先选定政策并证明完整输入/失效；本阶段不建跨帧缓存 |
| 旧Fit最大值门槛与新逐点目标错配 | 04G的28项见证与有限无进展证据 | 单独算法修订，不能伪装为等价优化；本阶段保持Fit |

目标：在相同状态、提案、政策与浮点环境下，保持认证理由、接受集合、批次和公开曲面一致，减少真实参考重建、重复投影和快速路径有理构造。完整计入准备、内存、精确回退、发布复核及析构；先解决认证内部的可审计重复，不同时修改所有热点。

非目标：更换Fit/目录、放松E*/H*或最小角、减少支持Q、取消核心/float双域、取消发布前复核、放大前缀/预算/线程、资源索引、层次视图算法、线程池改造、通用profiler。默认仍为`legacy`，ATT暂停，QPC-05/06B没有因此获准启动；拟合目标修订仍归QPC-04。

## 2. 当前事实与拟修改的数据流

规划前已阅读开发/规划/审查规范、04F/04G规划、GWR-04与04F事实，扫描`PointwiseQuality`、`QualityEvaluation`、`ProposalEvidence`、`Reservation`、`Pipeline`、相关夹具、CMake及原运行脚本。

当前逐域逐样本路径：

```text
Cover(old)：Reference/Coordinate，边界分支再计算精确Reference
Cover(next)：重复上述工作
CheckSample：再Reference → VisibilityAgrees → 两次Screen
快速通过：double区间端点 → cpp_rational → 2^128定向整数累计
歧义：精确参考/插值/投影/质量比较
```

`ProposalEvidence`只缓存旧Fit的可见样本覆盖与double权重，不能直接替代新证书完整闭支持、精确权重或float曲面证据。`SameInterface`、两域支持枚举及批次共享贡献仍有真实义务，本阶段保持其顺序和语义。

拟改为：

```text
已拟合提案 → 原双域接口检查/支持枚举
→ 单个样本证据上下文（坐标；参考高度/投影按需）
→ old/next覆盖与损伤/进展共用该上下文
→ 相同数值分支与理由 → 相同证书 → 原ValidateBatch
```

上下文只在一次认证的一个样本、一个表示域内存活；拥有已计算值，借用冻结State/Samples。不同提案、两个表示域和线程不共享可变上下文，不增加全Q×提案缓存。精确值按需创建，不因复用反而提前为所有样本支付精确算术。优先保留区间运算顺序，不能通过代数重排改变保守界。

## 4. 必须先落纸的等价推导

本阶段不扩Lean工程；纸面推导、独立数值oracle、有限生产对照分别标注，未经检查不称机械证明。推导原文与索引在实施时同步维护。

**QCOST-01：不可变证据复用。** 定义输入`X=(State实例与代次, Source/Q, Config, sid, domain, 实际提案几何)`。列出每个缓存量读取的字段、区间/精确域及生命周期。冻结X且保持表达式求值顺序时，复用相同值应保持原覆盖面选择、可见性、区间端点与精确值。先坐标后源高的惰性拆分不得改变原参考表达式；共享边仍按原面序选面。证明局部owner限制排除了跨相机/曲面/提案的过期值。

**QCOST-02：定向累计等价。** 对有限binary64值x，唯一精确值表示为`x=(-1)^s m·2^e`，其中m为整数有效数，次正规数单独处理。目标是直接得到

\[
L(x)=\lfloor 2^{128}x\rfloor,\qquad U(x)=\lceil 2^{128}x\rceil=-L(-x),
\]

且与当前`AddBounds(R(x), R(x))`逐整数相等。正负、余数、整除、±0、次正规、极小进展和最大有限输入都必须覆盖。使用位分解/整数移位，不用可能溢出或双重舍入的浮点乘`2^128`；不以epsilon判断正进展。精确有理分支保留原`AddBounds`作为生产路径及独立oracle。非有限值保留原失败/未知处理，不静默截断或接受。

**QCOST-03：认证及流水线等价。** 原样保留完整候选支持与排序去重、域顺序、接口、拒绝顺序和进展整数累计。逐项相等推出相同理由与证书支持；确定目录/选择和发布规则下，再以逐机会对照确认相同事务与实际曲面。实际计算计数允许下降，逻辑请求/尝试/接受/配对及质量结果不能变化。参与`CheckLimit`的既有逻辑访问计数与检查点不能当作纯诊断随意删除；减少的参考构造另记物理工作，资源超限/取消保持未完成而非普通拒绝。若更紧的界导致原unknown变成accept，即使数学安全，也不属于本阶段等价修改，须停止该候选。

**QCOST-04：复杂度与未处理项。** 令s为实际闭支持、c为公开域包围框候选、d为局部面数、b为精确操作位长。复用把同一样本反复参考构造降到每域每种数值表示至多一次，覆盖仍最坏`O((s+c)d)`；有理回退、接口及支持排序保留。快速累计消除通用有理规范化/除法，但整数位成本不能冒称为任意精度O(1)。新增上下文同时存活数随线程数，精确对象内存另按位长计费；不声称消除Θ(s)、全部旧Fit或静止重复。

### 6.3 配额与性能出口

开发快验预计采集/归约10～20分钟，上限30分钟，不含必要编译；单平台进程180秒、8GiB，超限保留为censored。同提案微测固定顺序，一次预热、三次短内部重复仅用于内核定位，每项至多1秒、合计120秒；不能把内部重复当独立进程样本。冻结前若身份/环境不匹配，先解决基线问题，不直接跑后测。

本阶段工程目标：同提案认证中位成本争取下降至少25%，Sierra或Canyon移动段完整CPU争取下降至少10%，其余代表输入不出现超过工程门槛的持续同向退化。这些是预置判断目标，不是性能承诺，也不宣称10%就修复了2～3倍差距。

出口分开：

1. **等价性通过/失败**：证书、批次及曲面必须一致；失败即停止候选，不以更好误差或更快时间抵消。
2. **认证降本成立/未成立**：用同提案、真实工作和包含准备/析构的时间作证。
3. **完整成本有限改善/未改善**：必须单列移动段，不能仅靠静止比例变化达标；即使内核改善也可能整体无收益。
4. **04F成本退化是否消除、持续恢复是否成立**：各自保持OPEN，只有对应同条件证据才更新。本阶段不以它们为已完成前提。

没有达到工程目标或仅内核有收益而完整移动段受旧Fit/失败链主导时，结束P专属性能修复，以L作为后续回退性能对照，不自动微优化到达标。达到成本目标也不解除P的恢复阻塞：必须单列质量收益与应用是否需要逐点保证，不能只看时间晋升P。策略回退从同seed、新政策身份和完整旧规则开始，保留旧点固定，不在同批或同一演化状态中关闭证书继续接受。L若不满足声明质量，后续只能是受限成本研究；不能称质量修复成功。06B或Fit改写仍需各自小规划与阶段验收。
