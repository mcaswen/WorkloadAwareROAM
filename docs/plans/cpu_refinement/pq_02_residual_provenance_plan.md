# PQ-02：冻结旧点策略的残余质量追溯

2026-09-15；小规划，修改前版本 `474841d`。用户已确认继续追溯；沿用独立诊断边界自主闭环，完成后按当前任务授权提交。本轮不修改生产算法或质量策略。

## 1. 问题、范围与出口

PQ-01 的 B 策略在 Peking/50k 的 frame15 仍有 sampled Emax=2.3510499813968333px，最大点为 `(0.97985345125198364, 0.94871795177459717)`。本轮只追溯这个已经冻结的残余见证，保留原两个见证作为兼容对照，不扩大自然输入或寻找新正例。

要回答：首次几何恶化发生在哪个事务；来自接收新点赋高还是回收删点/重连；当前可见证书为何允许；重新可见后的优先级、前缀、认证和执行处于哪一层。不能把最终误差变大直接归因为拟合，也不能把当前目录失败写成所有局部操作数学不可行。

依据：[开发规范](../../standards/development_guidelines.md)、[规划规范](../plan_guideline.md)、[PQ-01规划](pq_01_quality_provenance_plan.md)、[事实](../../codebase/cpu_refinement/pq_01_quality_provenance_facts.md)、[结果](../../research/cpu_refinement/pq_01_quality_provenance_results.md)。已阅读追溯类、原生探针、启动/汇总脚本及生产提案、认证、回收路径。后续代码事实/审查按对应目录规范记录。

## 2. 冻结测量契约

- 沿用 PQ-01 的 Windows/MSVC、Peking547²、尺度80/12、深度20、预算50000、阈值.25/.10、前缀160、8线程、NO、1280×720、原24视图序列。
- 只测 B：`PreserveSurvivingHeights=true`，新点继续原一维拟合，HeightGuard关闭；不更改种子、目录、预留或进展门槛。
- 见证坐标直接来自原 `quality-15/quality.json`，保存其SHA及原始完整精度；不能用四舍五入后的UV重新挑点。
- 每次运行从相同种子独立执行24批；全帧网格哈希及已有工作字段必须与 PQ-01 B 对齐，五关键帧实际输出文件核对身份后复用原独立质量，不重跑全Q评价。
- 只读诊断允许计算固定未来/返回视图误差、局部反事实插值；这些不是新算法决策，不反馈生产状态。

## 4. 实施与验证

1. 在修改前复制现有原生探针并记录身份，执行一次原B两见证诊断，核对其24帧与旧结果，保存本机诊断费用基线。
2. 扩展可选见证与局部几何记录；原两个见证仍保留相同编号。旧点高度不变、批前预测与批后实际曲面检查继续执行。
3. 只构建原生追溯目标；原参数执行一次作为兼容及费用对照，再追加新见证执行一次。不构建其他后端或跑完整CTest。
4. 新旧默认诊断应有相同帧字段及见证数值；追加见证不得改变24帧算法结果。非法/非有限UV在启动运行前拒绝。
5. 从完整轨迹定位新见证的首次改变，检查受影响事务的几何与证书，再按实际恢复记录分层归因；必要时只补该事务的局部只读证据，不增加修复策略。
6. 完成结果、事实与审查后提交；本阶段以“残余来源已解释或明确未解释”关闭，不以质量下降或性能胜负判定调查是否完成。

## 5. 性能、资源与停止条件

修改只进入独立探针，生产路径复用源码/程序未变的已有证据，不重复平台计时。修改前与修改后各一独立进程、同两个原见证，对照完整诊断耗时；新增第三见证费用单列，不把诊断费用当CPU-ready。基线在修改前取得，若出现明显差异，最多一次同边界复测并说明来源，不追逐微秒波动。

原始输出在显式忽略的 `benchmark-output/cpu-refinement/pq-02/run-01/`，不覆盖PQ-01。原生进程沿用180秒/8GiB，总采集目标小于5分钟，首次上限10分钟，构建和离线归约另计。若身份不一致先停止归因；若恢复只能由更一般操作解释，记录当前模型边界，不自动扩原语、扩大轨迹或启动性能优化。
