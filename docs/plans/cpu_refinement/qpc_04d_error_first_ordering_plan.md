# QPC-04D：同一候选集合内几何误差优先的有限策略对照

日期：2026-09-16。类型：QPC-04下的小规划。基线：`644bbf7`。状态：**实现与有限实验完成，工程验证通过；Peking/Sierra有限质量正面，Canyon混合，默认不变。按授权提交后等待用户验收。** 对应[大规划](transactional_quality_performance_closure_major_plan.md)、[04C结果](../../research/cpu_refinement/qpc_04c_quality_target_results.md)及[本轮结果](../../research/cpu_refinement/qpc_04d_error_first_results.md)。

## 1. 问题、目标与非目标

04C已经证实：Peking50k/frame15前160项有158个根没有根内可见样本，最坏误差根复合排名194、同人口误差排名1；Sierra48有类似错位。Sierra95的坏区域却未通过当前4px触发值，前缀并未截断。Canyon还说明最大值下降允许其他可见点明显变差。

本阶段只验证一个因果候选：**保持接收资格和局部操作规则，在相同状态上将接收方前缀从复合紧迫性排序改成几何误差排序，是否能把已有误差需求转化为真实事务和有限持续质量改善，完整代价是什么？**

这是不同的贪心选择政策，不是等价性能优化。目标不是一次解决绝对E*、采样一致性、目录能力和恢复时限，也不预设最终质量/速度胜出。阶段可以以“策略正确实现、效果混合或没有兑现”闭环。

术语区分：本规划的A/B两臂指排序政策；“B原语”专指04B接入的单侧边界细分，二者不是同一个开关。

本阶段保持：候选资格公式、原阈值、r/m、预算、源数据和尺度、相机轨迹、Q_runtime/Q_eval、形状界、旧点不可变、提案目录顺序、0.01px进展认证、捐赠排序、冲突与不回流规则。仅接收方前缀顺序改变；由此导致预算命名、实际事务和后续状态变化属于被测政策的结果。

不新增原语/保护/拟合策略，不修采样对角线，不把密度需求从人口删除，不调低门槛，不补更多恢复机会，不做200k预留优化，不宣称连续曲面或长期恢复保证。默认保持原复合排序和B关闭。

## 2. 已扫描的实现边界与设计判断

已阅读开发规范、规划规范、QPC大规划、04B/04C规划与事实/结果；扫描`TransactionalSamples.*`、`TransactionalPriorityIndex.h`、`TransactionalReservation.cpp`、`TransactionalPipeline.*`、`TransactionalTypes.h`、公共设置/SeedBuilder/适配器、ExperimentCase/Replay、schema/runner/catalog/suite及相关测试。

当前需要注意四项事实：

1. `_priority`既参与接收资格，也参与捐赠中心的邻面代理评分。**不能把它整体改成E，否则同时改变两个变量。**
2. 每次初始化、换视图和局部续接，Samples已经归约得到纯几何`maximum`，随后才合成P。目前这个maximum未单独持久保存，不能从`max(E,0.2L)`反推E。
3. `TransactionalPriorityIndex`已经按256槽分块存完整候选并查询精确前缀；无需新建堆、树、第二套排序器或每批全排序。
4. `TransactionalQualityProvenance::Rank`目前硬编码复合P顺序。若只改生产排序却沿用此排名，会制造错误的拒绝归因；诊断必须同时明确政策身份。

**架构选择：复用现有索引，分离资格值与排序值。** 在既有样本归约处生成接收键，键内保存所需排序值，避免新增一份长期E数组或在Prefix时重新扫描Q。索引拥有键、Samples拥有评分/键构造、Reservation继续只消费有序根，不认识新的几何评价器。

## 3. 精确策略契约

### 3.1 相同状态上的候选集合

对同一已发布状态S及当前视图，定义：

```text
E²(t) = 当前参考可见、属于闭三角形t的运行时样本误差平方最大值；空集取0
P²(t) = max(E²(t), 0.04 × 最长投影边长平方)
C(S)  = {活动面t：P²(t)有限，且P²(t) > SplitPixels²}
```

新旧政策都必须使用同一个C(S)。无根内可见样本、E低于门槛但密度越线的根仍留在集合；P无穷的根仍排除。不额外筛掉无证据根，也不把E>阈值另建资格人口。

### 3.2 两种全序与确定性

| 政策 | 升序比较键 | 对外名称建议 |
|---|---|---|
| A：原复合排序 | `(-P²(t), stableFaceId, slot)` | `composite`，默认 |
| B：几何误差优先 | `(-E²(t), stableFaceId, slot)` | `error-first`，显式实验政策 |

取各自全序的前`min(r,|C|)`项。**B不增加P作为第二比较键**，与04C已有反事实完全对应；E相同仍按原稳定身份和槽位次序。比较平方值，避免开方、量化或新epsilon。空证据的E=0根在正误差根之后，但仍可填满不足的前缀。

全局的含义仍是完整快照上的全序；批内新候选只进入下一快照。认证并行完成顺序不参与选择；Reservation按新的前缀序收集成功提案、命名空额、尝试原共同捐赠池并不可回退预留。

捐赠池仍按原相邻面复合P代理值和稳定中心身份排序；相同S上两政策的`PrioritySquared`、`RawCount`、完整C(S)及DonorPool必须一致。不同的是接收顺序及其下游决策。

### 3.3 “同一候选集合”的时间范围

相同S上的人口相同是硬验证义务。**持续A/B从同一种子独立运行，第一批分叉后网格、C(S)、实际N和捐赠池可以不同**，不能强迫它们继续保持相同人口，也不能把不同工作量下的时间比称为同任务多核加速。

04C三个完整根CSV作为同状态排序证据复用；它们只证明排序机会，不伪装成新策略已经执行的历史。新轨迹仍从第一次更新启用B，不在原frame15或48临时换策略。追踪见证使用冻结UV/采样身份并重新定位覆盖面，不强行沿用原root编号。

## 4. 设置、键构造与完整续接

### 4.1 设置与生命周期

在公共`TransactionalLodSettings.h`中定义两值枚举`TransactionalReceiverOrder`，并添加`ReceiverOrder`，默认`Composite`。核心Configuration引用同一数据类型，不复制两份枚举；这是无行为的算法设置依赖，不引入平台/渲染依赖。

共同实验字段建议`receiverOrder: composite|error-first`，缺省为旧政策；未知值显式拒绝，非Transactional不得启用error-first。新设置经`ExperimentCase → ExperimentReplay → TransactionalLodSettings → SeedBuilder::ConfigurationFor`传入核心。非默认值纳入taskId；默认缺省/显式composite归一化并保持旧任务身份，suite不向Classic/DOD/CBT泄漏。

公共SeedKey已包含完整设置，切换排序通过原Reset/重建生命周期生效；核心`SetView`拒绝中途变更此字段。不为实验新增热切换索引、克隆生产状态或隐藏旁路。核心直接初建也要拒绝非法枚举。

### 4.2 Samples只生成一种实际接收键

在Samples内部复用一个纯键构造步骤：输入冻结政策、P²、E²、身份和槽位；先以P²判断资格，再返回相应`optional<PriorityKey>`。它不投影、不定位样本、不修改状态。

- **Initialize/Refresh：** 在原闭面样本归约完成时生成接收槽记录，原P数组不变；BuildOrders接收已准备记录并重建原接收索引，捐赠索引继续读取P。
- **PrepareView：** 在原按面划分的评分任务中同时生成目标接收槽记录；线程写唯一槽。全部投影/归约成功后构建目标索引，沿原PublishView移动发布。没有每面第二次扫描Q或生产全排序。
- **Samples::Prepare：** 旧面删除先写null；在新面和保留接口面的原maximum归约处构造目标键。槽复用必须使用新稳定身份；不能只在复合P改变时更新键，因为P不变时E仍可能改变。共享边贡献更新范围沿用原完整接口修复。
- **Publish/失败：** 接收记录并入已有`ReceiverIndex::Repair`；所有容量/分配在prepare计费，noexcept发布保持。丢弃准备结果、配额失败、其他组件失败时，旧P、索引、样本与Pending仍一致。

持久E不另建一套缓存：新排序的E已经包含在索引键中，诊断若需要分量仍从既有贡献只读重算。允许新增准备期槽记录/局部写集，但应替代原BuildOrders中的接收记录构造，不叠加重复全量缓存。

### 4.3 诊断与参考路径

新增政策身份写入resolved/manifest和诊断元数据，旧字段`priority`仍指P，不悄悄改含义。Provenance排名在B下必须对应真实接收索引；可在一次观察中读取完整`Raw()`建立排名表，诊断单独计费。独立验证另从全根CSV按公式排序，不用同一键helper自证。

04C的原分析脚本及旧报告保持原契约。新薄分析显式读取政策，分别记录实际排名与原复合排名，不把旧`scoreAndIndexExact`断言套到B。默认A的原输出格式/数值保持；只在新政策输出必要的额外身份或旁表。

旧`TransactionalDynamicReference`不作为本阶段竞争基线；若收到新政策，先显式拒绝不支持的组合，不在本阶段扩写动态参考控制器。Classic/DOD/CBT实现和渲染资源模型均不修改。

## 6. 有限实验协议

### 6.1 先验证同状态，再测持续效果

同状态层复用04C的Peking15、Sierra48/95评分CSV和原资格人口，用独立排序核对期望；原生专项夹具再检查新实际索引。必要的自然追溯对新轨迹自身状态导出一次评分分解，核对其真实索引，而不是要求它复现旧frame15的状态。

持续层每对A/B使用相同DOD种子、完整输入和后端。种子只创建一次用于初始化，后续由各自政策独立更新；不让Legacy提供逐帧目标。新轨迹种子hash必须与A一致。

### 6.2 冻结三个50k输入

| 输入 | 两臂共同B边界政策 | 轨迹 / r与m | 独立全域质量帧 | 用途 |
|---|---|---|---|---|
| Peking50k | **开启**，沿04B候选 | `pq-return24`，24机会，160/160 | 2、15、16、23 | 检查误差根进入前缀后是否真正兑现，避免已知边界原语缺失遮盖排序作用 |
| Sierra50k | **关闭**，沿FER/04C | `reveal-return`，96机会，160/160 | 2、48、80、95 | 区分排序获益、触发不足及实际面数差异 |
| Canyon50k | **开启**，沿04B候选 | `reveal-return`，96机会，160/160 | 2、48、80、95 | 监测局部最大值下降伴随的误差转移与返回质量 |

每一对内部只变`receiverOrder`，不做B开关×排序的完整矩阵。Peking/Canyon开启B是显式固定的实验背景，**不是默认开启或认定04B质量通过**。同表保留FER的B关闭和DOD历史质量参照，不能因新策略好于有退化的B开启基线就宣称整体质量修复。

沿原D3D12、1280×720、neutral材质、3机会预热、8线程、源资产和原数值。Peking尺度80/12、split/merge为0.25/0.1；Sierra尺度80/10.38941992187497、4/2；Canyon尺度80/11.973810546875、4/2。以冻结resolved及其SHA为准，不重生成相机或提高样本配额。50k是预算上限，Sierra实际约9k的角色必须如实标注。

不增加200k、额外线程/地形或长期恢复矩阵。本阶段验证选择语义；200k高预留成本保留为后续风险，50k结果不外推规模性能。

### 6.3 最小采集与复用

1. 修改前保存程序/源码和环境身份。原政策关闭新功能的前后性能选Peking50k、B关闭一组；可复用同环境、同身份的已有基线，不匹配才补旧运行。
2. 上表A/B各一组正常运行，共六条轨迹，顺序执行。A的新输出若与历史hash/工作/视图完全相同，复用原12个独立质量点；B只新增表中12份实际float网格评价。A分叉先按默认兼容失败处理，不能覆盖旧基线。
3. B各一条诊断/视觉运行，复用原追溯及输出核对；正常与诊断的完整mesh、决策和工作量必须一致，观察费用不计入正常CPU时间。捕获使用原平台实际输出，能合并即合并，不重跑全FER。
4. B的1/8线程自然对照只选Peking24机会一条；无实际事务则报告自然证据不足，以有限夹具完成线程正确性，不换场景追求正例。
5. 全根诊断限每场景两个帧：Peking15/23、Sierra48/95、Canyon48/95。旧见证沿原UV集合，加04B已知新增退化点，追踪覆盖根而非固定旧身份。

测量不能把诊断模式完整pair枚举与正常模式提前停止混用。`D_raw→D_need→D_feasible→D_executed`保持原定义；Free、配对和净零翻边分列，不拿总事务数冒充独立可行需求。

## 7. 实施顺序与逻辑门禁

### 步骤1：冻结输入与政策接线

保存基线和旧程序，接入默认composite的两值设置，核对schema、C++解析、suite隔离与taskId。验证默认/显式composite身份一致，error-first身份不同但workloadId不变，非法/不适用值明确拒绝。公共切换触发重新建种子，核心SetView不允许半途切换。

### 步骤2：接收键、增量修复与独立oracle

实现§4的单一键构造入口；原P数值和捐赠索引完全保留。定向夹具必须包括：

- 高密度/低误差与低密度/高误差竞争；有限P刚好等于阈值、无穷P、空可见支持、E同分稳定身份，前缀不足r。
- 同一S的新旧完整资格集合、复合P及捐赠池一致，而接收顺序符合各自独立全排序。
- **P不变但E改变**时键仍更新；新增/删除/槽复用、保留接口共享样本、全局换视图均与全量独立重算一致。
- 准备后放弃、局部修复失败、过期批次和Pending累计消费不破坏旧状态；新键写入不移入发布分配。
- 同政策1/8线程得到相同有序意图、目录结果、预算、事务及实际网格；只比较相同政策，绝不要求A/B结果一致。

选新排序专项、受影响的原核心/边界续接和公共适配生命周期用例；公共输入只跑相关解析/身份检查。索引容器未改则复用既有索引算法证据，不因为可用而跑全CTest、DOD或CBT矩阵。

### 步骤3：有限自然A/B与失败链

仅硬门槛通过后跑§6。每条B逐帧记录实际N/U、根/前缀人口、接收认证、配对/Free/翻边、原失败类别、PairChecks、冲突、样本触达、索引更新、真实写入和全部阶段时间。

原坏点进入前缀后，要继续追到目录/认证/命名/捐赠/冲突/执行，不能到“排名升至1”便算修复。新极值和超额簇同样保留；既有坏点改善不得掩盖新增坏点。Canyon需完整共同可见误差分布与`excess>0.25px`连通簇，而非只看最大点。

### 步骤4：回填、审查和提交

## 9. 复杂度、风险和停止规则

令S为分配的面槽数量、N为活动面数、C为闭面样本贡献总量、r为接收前缀、b=256为索引块长、g=ceil(S/b)为块数、f为本批需修评分的面数。

- P和E均由既有归约得到，选择排序分量只加O(1)/面的键构造；不新增O(C)样本遍历或O(NQ)定位。
- 准备期接收槽记录O(S)，复用原记录形状和所有权；持久索引规模不变，不额外长期保留两种全序。接收索引重建仍为O(S+N log b)上界，前缀沿块合并为O(g+r log(g+1))上界；完整view成本仍另有投影、样本归约和捐赠索引维护，不能只计接收索引。
- 局部键修复随f及触及块数计费，原样本续接依赖实际贡献/接口，不因本次改排序成为常数。
- 同状态捐赠索引工作定义不变；持续B的认证数、实际修改量与冲突图可变化。预留仍可能出现r×m配对及随已批准批宽放大的冲突扫描，不预支改善其上界。

高误差根可能长期卡在目录而反复占据前缀；纯误差排序也可能使密度需求饥饿。当前不新增aging、跳过失败缓存或混合配额，观察到即报告政策限制。样本错位、形状目录、不可回收边界及局部误差转移均仍存在。

出现以下情况停止相应准入，保留负结果并收口：

1. 相同S的资格/P/捐赠集合被改变，或默认路径、原子发布、同政策线程一致性失败：实现不合格，先定位，不以质量收益抵消。
2. 排名改善但未形成事务：沿目录/质量/预算/冲突归类，不自动扩大目录或配额。
3. 形成事务但独立质量无改善或新增明显退化：策略出口为未兑现/混合，保持默认，完成预注册有限面板后交Review，不追加场景找正例。若发生结构/数值无效则停止后续依赖运行。
4. 成本/资源明显失控或超限：留存失败/删失，不移走认证/维护计时，不进入无限优化。

最终报告必须分别写明：**策略实现正确性、已有需求兑现、有限持续质量、默认路径成本、候选策略代价、用户视觉验收**。不存在一个可以替代这些维度的总PASS。
