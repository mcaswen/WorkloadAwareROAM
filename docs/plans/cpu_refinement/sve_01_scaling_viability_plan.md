# SVE-01：20k→200k 规模扩展可行性实验小规划

> 日期：2026-09-14；类型：小规划；状态：实施与实验已完成；性能/质量出口见 §9。英文实验名：Scaling Viability Experiment。
> 冻结算法基线：`7425736`。依据：[GWR 最终结果](../../research/cpu_refinement/gwr_final_results.md)、[当前算法与复杂度](../../research/cpu_refinement/transactional_algorithm_overview.md)、[GWR 审查](../../reviews/cpu_refinement/gwr_final_review.md)。
> 本轮由用户明确提出 20k→50k→100k→200k，是 GWR 关闭后的独立有限实验；不重开其失败的按需视图候选，也不把旧“小范围不扩矩阵”解释为禁止本次实验。

## 1. 问题、目标与非目标

判断固定版本在更大活动网格上，完整 CPU 更新成本、B1/C4/C8 并行收益和相对 DOD 的工程距离怎样变化。当前 Peking 20k 的 C4 均值约 11.226ms、DOD 默认 8 线程约 2.858ms，仅为历史背景；不能直接拼入新曲线，也不能由两种语义的时间比证明同任务加速。

回答三个有限问题：

1. 预算从 20k 增到 200k，实际活动面和必要更新工作是否真的增长？
2. 全 Q、候选索引、认证和局部续接各按什么量增长，哪项决定完整时间？
3. 固定批次额度与随预算增长的额度，分别是否出现值得继续研究的规模趋势或实测交叉，同时质量/预算/响应欠账是否恶化？

按用户补充，两组各测一轮：固定额度组与增长额度组；每组都测 B1、C4、C8，分别保留单线程参考、4 线程和 8 线程执行。只按 §3.2 的预注册表改变需求/回收池上限；不优化算法，不改变 Q、优先规则、提案顺序、拟合/数值认证、回收原语、线程池或高度保护规则。线程矩阵仅增加本次要求的 C8 和对应 DOD8，不扩到 16 线程；不增加场景、长轨迹、平台接入或新的 profiler。也不为达到预算利用率临时降低阈值。

本轮是快速可行性筛查，不是最终论文实验。正结果支持下一步设计，不构成普遍性能保证；负结果限制当前实现与配置，不证明事务模型的复杂度下界。

## 2. 已核对的实现与职责

已阅读开发规范、规划规范、持续原型/GWR 规划、MPR-03 压力协议及 GWR 结果/审查；扫描 SnapshotProbe、两个 Transactional 探针、Input、Types、Samples、公共相机和 DOD 线程选择入口。

当前接口有三项真实限制：

- `TransactionalInput::Load/Views` 只接受两个旧场景，视图来自严格 trajectory A 清单。
- SnapshotProbe 在 sample14 的 split 阶段输入处捕获；FamilyProbe 则从公共完整更新入口运行，二者初始化边界并不完全相同。
- 原 formal 清单不允许 50k/100k。不能改旧 CSV 的名字/预算绕过约束，不能把 20k 网格只改为 200k cap 当作大网格实验。

额度接入无需修改批次算法：B/C 的 Reservation 已读取 Configuration::PrefixLimit/DonorLimit，SetView 则要求额度与旧配置一致。因此在初始化前选定组参数，后续每个视图沿用；不在一条轨迹中途更换额度。独立动态参考 A 另有硬编码 64 步停止，本轮不测 A，也不顺手修改它。

现有 MaterializationExecutor/TransactionalExecution 已支持任意正线程数，当前 C4 是探针构造参数写死为 4；C8 只在探针通过显式 8 接入同一执行器，不复制线程池或改变分块规则。报告中的 C8 指 8 个执行线程；实施前核对 WSL 可用逻辑 CPU、主机物理核/SMT 映射，不能未经确认将 8 个线程写成 8 个独立物理核。

复用 `RoamMaterializationProbe.cpp::StressCamera` 的已冻结 64 点环绕几何公式和 `BuildCameraView`。不调用 MPR 目标生成/物化器，不复制其 5+30 计量协议。新协议只负责实验输入，不能进入正常发现/更新的热路径。

### 3.1 预算标签与真实规模

记录每档种子/逐帧的 N、顶点数、实际槽容量、U=N/B、空额度、深度/阈值停止情况。预算只给 cap，主图必须同时提供按 B 和按实际 N 的横轴。

预注册规模覆盖检查：四档种子均 U≥0.9，且 N_200k/N_20k≥8，才称“四档近饱和网格规模覆盖”。这个 90% 是输入覆盖标签，不是质量或预算正确性放宽。未达时仍运行安全可执行的原四档并保留结果，标记“cap sweep、实际规模覆盖不足”；不补点、改阈值或重新挑快照。

Q 固定意味着 q/N 随网格增加而下降，单提案覆盖样本可能减少。若认证因此便宜，这是固定地形/Q 下的成本效应，不能推成资产分辨率增长时同样可扩展。

### 3.2 两组额度：各测一轮，不做参数搜索

| 预算 B | 固定额度组 `fixed64`：r / m | 增长额度组 `scaled`：r / m |
|---:|---:|---:|
| 20k | 64 / 64 | 64 / 64 |
| 50k | 64 / 64 | 160 / 160 |
| 100k | 64 / 64 | 320 / 320 |
| 200k | 64 / 64 | 640 / 640 |

增长规则冻结为 `r=m=64×B/20000`。采用预算 B 而非每帧 N 计算，避免把输出状态反馈到额度；每个进程内额度固定。记录实际 r/N、m/N 和候选不足时的实际返回数量，不填充虚拟候选。

两组各对应不同问题：

- 固定组：在更大的状态上维护同一有限决策额度的完整成本。
- 增长组：当可处理需求与可用回收池一起增长时，认证、预留、冲突和续接能否支持更多实际工作。

r=m 是本次固定取舍，不能据此判断 r 或 m 的独立最佳值。两组同时改变它们，无法独立辨识各自因果；不另开 r×m 搜索矩阵。增长的是工作额度，不保证实际需求、可行 donor 或事务数同步增长。

20k 两组参数、输入和执行方式完全一致，只采一次 B1/C4/C8 及诊断，作为两组共同锚点；报告显式标注共享数据，不算两次独立重复。DOD4/DOD8 不消费 r/m，每档每种线程设置各测一次，供两组共同对照；4/8 线程基线分别保留，不能混用或取较慢者。

## 4. 比较对象与时间契约

| 配置 | 角色与冻结策略 |
|---|---|
| B1 | 现有 batch-serial；同一输入、优先级、预留和发布语义，串行执行 |
| C4 | 现有 batch-parallel，4 个执行线程；在同一额度组/预算下，与 B1 的逐帧意图、批次和逻辑几何一致 |
| C8 | 与 C4 完全相同的输入、额度和算法，执行线程数设为 8；同组逐帧意图、批次和逻辑几何必须与 B1/C4 一致 |
| DOD4 | 现有生产 DOD 公共 BuildRenderData；保留默认各阶段动作、自然回退和增量 mesh，只把现有五项 PassPolicy 线程请求设为 4 |
| DOD8 | 同一 DOD 实现和阶段动作，五项线程请求设为 8；作为 C8 的同线程额度工程基线 |

按匹配线程额度固定 CPU 集合：C4/DOD4 共用同一 4 CPU 集合，C8/DOD8 共用同一 8 CPU 集合，前者是后者子集；B1 使用共同子集内一个 CPU。优先不同物理核，实际映射与可用性在采集前冻结。记录主协调线程、执行线程数量和实际参与情况，不把配置值当作核利用率。记录硬件拓扑、请求/有效线程数、WSL CPU 配额与 affinity；若只能确认 vCPU/SMT，按实际资源标注。不得强迫 DOD 的串行特化路径变成并行重建，也不得按旧默认 8 线程数字冒充本轮同资源对照。线程额度相同不代表任务、质量或操作数量相同。

主计时边界：

- 新算法 `T_ready = SetView + Update + ConsumeMesh`：包含发现、拟合/认证、预留、所有准备/发布、续接、mesh 生成、实际派发/等待和临时对象释放。
- DOD `T_ready = BuildRenderData`：完整 CPU 渲染包就绪。新算法消费增量包的成本计入，外部 JSON/校验/独立评价不计入。
- 另保留新算法历史 `frame_update` 与 `consume` 分项；不把新的 T_ready 直接与历史只含 update 的数字混比。
- 来源、解析、状态/样本/mesh/线程池初建、首次视图备用分配、最终销毁、RSS 峰值分别报告。冷启动不摊薄进未冻结的长运行，也不隐藏已知初始化问题。

`S_p(g,B)=T_B1(g,B)/T_Cp(g,B)`（p=4,8）是同组同批次任务的并行收益；另报 `S_4to8=T_C4/T_C8` 与效率 `S_p/p`。`R_p(g,B)=T_Cp(g,B)/T_DODp(B)` 是匹配线程额度的不同算法工程成本比，g 为 fixed64 或 scaled。C4、C8 都必须对照对应 DOD 基线；B1 同时列入完整时间表，不能只展示 C8/C4 的相对倍率。组间时间差同时包含工作额度、选择结果和状态演化变化，不能称为多核加速。静止 round1/2、变化视图 round3..7、首轮 round0 分列；总体八轮均值保留，但不得用静止轮掩盖移动视图瓶颈。

### 4.1 服务额度与质量响应

两组分别记录合格候选总数、配置 r/m、实际检查前缀/回收池、是否截断、执行事务数、未兑现需求及样本访问配额失败。固定组最多考虑 64 项，增长组最多考虑当档额度；用满额度均不等于所有该帧需求已处理。增长组若只增加尝试却未增加执行，应定位局部不可行、donor 复用、冲突或资源限制，不能只凭更大的 r 宣称释放了并行工作。

不能直接用“每秒事务数”把不同语义的 DOD primitive 与新算法预算交换等同。可分别报告每项自身吞吐，主要判断仍为完整时间、质量与响应。若较低成本来自更少更新、较差质量或严重前缀欠账，不能判为性能胜出。

本轮不追加追平质量的循环或动态收敛测试。八轮与一次返回只提供短程恢复证据；无法确认质量可比的时间交叉，称“成本交叉、质量解释未完成”，不叫同质量性能交叉。

### 5.2 质量与正确性

对相同参考、相机、Q，分组离线评价每帧的 sampled screen maximum、现有 terrain-domain sample RMS、sampled height maximum；不能把当前 RMS 改称 screen-space weighted RMS。增加基于同一 Q 的逐点 `Dmax_sample(Cp,DODp)=max_q(e_Cp(q)-e_DODp(q))`（p=4,8），共同可见域由参考和相机确定，记录无可见样本情况。

绝对误差不由 Dmax 替代；同时保留返回视图与新可见区域的现有诊断。这里只能报告 sampled 质量，不能声称连续上界或“不可感知”。不在本轮新设视觉可接受阈值。来源 DOD 与新算法并不需要最终拓扑相同；B1/C4/C8 在同组同预算内必须相同。除共同 20k 锚点外，两组的意图、批次和最终几何允许不同，必须分别评价，不能要求跨组轨迹相等。

每个不同额度/预算配置做一次 B1 诊断，复用全量结构/归属/mesh/Pending 及首批反序校验；20k 共用，合计 7 次。计时输出保留每帧几何和批次身份；验证 C4/C8 与 B1 同逻辑结果，再在离线评价中复用同几何证据，避免重复同值全 Q 验证；验证覆盖全部八帧，不能只看最后一帧。DOD4/DOD8 各帧输出另作独立质量评价；只有几何与视图身份一致时才复用评价，不能默认多线程结果相同。不拿算法自身 score 作质量。

### 5.3 复杂度与趋势

以当前复杂度页为依据，不从四个数据点“证明”渐近复杂度：

- 换视图仍有 Θ(q) 投影、a 级关联归约及按面/点槽的索引准备；K=256 固定，建序项近似 O(N log K)，不能把整个 SetView 简写 O(N)。
- 前缀需要访问 Bidx 个块首，再归并 r/m 项；按实际额度完整计费，固定组也不能把发现写成 O(1)。
- 认证主要随被尝试提案样本规模 s_i、支持关联 a_i 和数值分支增长。拓扑度数有界不保证这些量有界。
- 配对尝试上限包含 r×m。增长组从 64/64 到 640/640，组合上限从 4,096 到 409,600，增长 100 倍；PairChecks 是实际次数，每次足迹/冲突检查与已预留批宽还可能增加成本。不得将 O(rm) 写成整个预留阶段的完整成本界，也不能为了隐藏增长临时截断配对搜索。
- 续接计入样本重新定位 z、s_delta、a_delta 及 h 个脏块重排；固定组的有限批次也不保证局部维护常量。增长组另外报告已执行批宽、每事务样本访问和脏块修复放大。
- 精确算术位复杂度与空间峰值另列；禁止忽略大整数成本或仅用 primitive 数反推时间。

画实际 N→T_ready、N→阶段时间、N→R_p/S_p、N→实际事务/样本访问/质量四组图，每图同时保留 fixed64/scaled 的 B1/C4/C8 曲线和共享 DOD4/DOD8；匹配资源的工程比值与同批次线程倍率分开画。附同预算的组间增量：多检查/认证/执行了多少项，额外花费多少时间，以及质量/未兑现需求如何变化；执行增量为零或负数时不计算伪造的每新增事务收益。输出相邻两档的描述性弹性 `beta=log(T2/T1)/log(N2/N1)`，只有 N 实际增长时计算；分别用于两组 B1/C4/C8 及 DOD4/DOD8，附原始点，不强拟合复杂参数。

四档 q 不变，无法辨识随 q 增长的系数或给出 general terrain scaling；报告明确将全 Q 固定税摊薄、每提案样本减少和真实多核收益分开。

## 7. 实施顺序、最小测量与资源停止

1. 保存 `7425736` 源码/原二进制/构建身份；实现协议与窄探针扩展，单独核查旧入口。四档来源依预算递增生成并一次冻结，先检查实际规模与合法性，随后不得换源。
2. 先测 fixed64 四档一轮，再测 scaled 三个新增配置一轮；增长组 20k 引用共同锚点。每个新配置先做 B1 诊断，再分别运行 B1/C4/C8 各一个独立计时进程。固定组 20k/100k 顺序为 DOD4→C4→B1→C8→DOD8，50k/200k 用逆序；增长组 50k/200k 为 B1→C4→C8，100k 为 C8→C4→B1。DOD4/DOD8 已在固定轮各测一次，增长轮复用；环境出现实质变化时标记原对照不适用，不拼接失配数据。算法之间不同时运行，记录实际次序/时间和环境，披露顺序可能带来的漂移。
3. 每进程只执行该协议的前缀/初建和八轮；没有额外 5+30、全轨迹或重复收敛帧。去重后为 7 个不同额度/预算配置×3 种执行方式=21 个新算法计时进程，加 4 档×2 个 DOD 基线=8 个，共 29 个；另有 7 个 B1 诊断进程。两组每配置都独立初始化，不能复用上一配置最终状态；共享锚点/基线不增加独立样本量。
4. 如实报告逐帧、轨迹均值/中位数/最大值及静止/变化视图区分。八帧不是八个独立样本，不报告稳定 P95/置信区间。只对决定 Gate 的可疑读数或潜在交叉补一次反序独立对照，最多两个“额度组/预算/线程数”配置；只有需要核实与 DOD 的成本比时才复测匹配线程额度的 DOD。其他已有证据充分则停止。
5. 复用 FPR：保留共同 20k/C4 一份 Tracy，并在 fixed64/200k、scaled/200k 分别采 C4/C8 配对时序，合计至多 5 份。确认 C8 实际任务参与和短任务分布，不把 8 个线程存在等同于有效并行。若现有分段与时序不能解释关键增长，再对 scaled/200k/C8 补一份有限 perf 采样；该配置失败则保留失败，不自动换成有利配置。采集与关闭观测计时分开，重放只用于采样量，不能当性能重复。不到足够样本就标注有限证据，不自动扩大 profiler。
6. 对照账本、质量、源码/规划形成报告、事实、审查；不因任何性能结果顺手优化实现。

所有命令在同一 WSL Ubuntu 存活会话，Release、编译器、Boost、严格浮点开关固定。记录 CPU/内存、频率策略与负载、affinity、库/二进制/输入 SHA。初建和缓存预热按真实运行保留，性能任务期间不并行构建/采样/评价。

单进程外层上限 180s，已有内部 120s 与 SampleVisitLimit 不放宽。RSS 达 8GiB 或系统进入明显换页时停止该进程并保留证据；实施前若可用内存不足，先登记更低安全限额，不提高上限。预算不保证工作增长，超时/配额是截尾结果，不是耗时等于上限，也不是质量不可行。

加入 C8/DOD8 后，主矩阵和来源生成预估 12～30 分钟量级，增长组认证成本尚未知；整个采集首次固定最多 40 分钟，超限停止剩余运行并说明未覆盖项；构建时间单列。这是资源预算而非性能承诺。对失败输入不自动重试、更换场景或提高算法配额。某组超时/配额耗尽只截尾该配置，在总资源限制内继续另一组；不得因 fixed64 慢就跳过用户要求的 scaled，或因 scaled 慢删除其结果。总时限耗尽导致未完成时明确列出，不能称两轮都已测完。正确性错误立即停新算法测量，归档定位后再决定修复。

## 8. 验收、比较门槛与退出

按 fixed64/scaled × 4/8 线程分别报告四条曲线的各档及组级出口，不使用无类型 PASS。继续/停止信号不能在同一曲线上挑不同组/线程的快点拼接，也不能用 C4 失败替代 C8 结论：

| Gate | 判定 |
|---|---|
| 输入规模覆盖 | 按 §3.1 检查实际 N/U；不足则本轮不能回答完整 20k→200k 网格 scaling |
| 同任务正确性 | 每组 B1/C4/C8 各档逐帧批次/逻辑几何一致，结构/预算/续接成立；错误或证据未覆盖的档不参与性能主张 |
| 多核扩展证据 | 给出 S_4、S_8、S_4to8 与真实工作/线程；区分 8 线程比 4 线程加速、持平或退化，不预设线程翻倍收益 |
| 工程交叉信号 | R≤1 的实测点需一次独立复核，并同步审查质量、预算利用率和工作欠账；否则只能标“初步成本交叉” |
| 继续研究信号 | 覆盖有效时，100k/200k 都在 R≤5 的工程距离内，R_200k≤0.75×R_20k，最后 100k→200k 没有超过实测波动的明显反转；仍须质量/欠账没有提供相反解释 |
| 性能路线停止信号 | 有效覆盖下，100k/200k 均明显 R>5，且比值缩小不足 25%，没有已测质量/能力补偿：关闭该组当前 scaling 候选，不自动扩到 500k/1M 或加线程；两组×两档线程均满足时，才形成已测范围的共同负面出口 |
| 证据不足/取舍待评估 | 实际 N 不增长、配额/超时、工作欠账大、质量有取舍、趋势处在两种条件之间或复测矛盾；如实结束当前实验，不强判方向生死 |

本表的 R 使用匹配线程的 R_p，按额度组与线程数分别计算，统一取五个变化视图轮次 round3..7 的 T_ready 均值之比；八轮总体比、静止比与首轮另报，不可择优替换 Gate 口径。

5× 和 25% 是预注册的工程投入筛查数，不是发表门槛、统计显著性或视觉阈值。即使 R 缩小，也不能保证在更大 N 会交叉；即使四档均未赢，也不能推断任意规模不可能赢。只有当前样本的质量与时间均有证据，才讨论质量—成本 Pareto；不通过事后定义“可接受损失”构造胜出。

不以提高并行倍率替代完整时间下降；不以某帧最快结果替代完整轨迹；不把固定 Q 下这两种额度策略的测量称为任意地形/任意更新强度的扩展性。原冷启动、视域外高度退化和局部维护风险继续逐项报告。

### 开发改动的前后对照

本阶段只改实验入口/输出。以 `7425736` 为算法前基线，在原 Peking trajectory A 输入上各跑一次旧/新 C4 八轮，检查几何/决策及原 frame_update 分项，防止测量设施改变算法或侵入热路径。按开发规范 `max(0.05ms,5%,已知波动)` 判断工程回归，必要时仅一次定向复测。新增压力入口没有旧四档数据，不能伪造前版结果。

测试只覆盖新协议解析/身份/固定矩阵、旧输入兼容和四档必要诊断；原算法未修改的单元证据复用，不运行渲染后端/全项目 CTest。计量设施引入的回归优先撤回该设施，其他新性能修复另列事实与建议，不在本轮扩大算法范围。

### 实施边界细化

为避免两个探针各维护一份逐点质量导出，新增探针专用 TransactionalQualityReport.h/.cpp，统一摘要和公共 Q 误差文件；只链接实验目标，不进入核心热路径。该文件属于既有离线评价职责，未新增质量规则。当前只实现实验输入、参数和报告扩展。

### 实施时的计量细化

- `T_ready` 包含算法内部临时对象及 ConsumeMesh 返回包的释放；为计时外 JSON 审计保留的返回 `CertifiedBatch`，和 DOD 返回渲染包一样，属于调用方持有的结果，其序列化和最终释放不在窗口内。不能把该边界称为整个探针进程的全部成本。
- 家族离线全 Q 评价推迟到八轮结束后；每帧公共网格导出仍在窗口外，可能影响后续缓存，因此这是相同公开就绪边界的工程筛查，并非无观察真实应用。
- CPU affinity 根据 WSL 暴露的 core/sibling 拓扑选取 0,2,…；目前仅确认 vCPU 拓扑，未获得主机物理核调度保证。
