# QPC-06H 认证准备与旧证据复用小规划

## 1. 问题、目标与范围

06F提前拒绝仍在证书几何复制、完整支持排序及面证据构造之后。本阶段尝试减少被拒绝提案的准备，并审计同根提案的旧证据复用；不得跳过结构检查、当前支持资格、当前失败重证或成功提案完整双域认证。

## 2. 职责与候选设计

- Extend `TransactionalPointwiseQuality.cpp`：用局部样本列表累计认证结果，只在完整成功后创建并绑定成功证书。几何拷贝不参与求值，不能提前发布部分证书。
- Reuse `TransactionalSamples::FaceSamples`：核心提示成员资格可直接查询支持面列表；只有确认和完整集合成员关系严格等价时，才将提示重证移至全量整理之前。公开域仍独立收集，不套用核心列表。
- Reuse `QualityFaceEvidence/QualitySampleEvidence`：单次调用仍独占；优先省掉明显无用准备。
- 条件Extend根内认证上下文：若实际同根、相同有序支持被多次消费，则缓存旧面和支持集合，严格绑定state、version、domain、支持序列；新几何不得命中旧系数。需要独立类时放同算法目录的`TransactionalQualitySupport.*`，只由根任务持有，结束即销毁。先核对复用人口和维护成本，不默认实现跨提案全样本对象缓存。
- Extend受影响认证/源高测试；不将缓存放入Reservation的几何算法或跨帧Pipeline。

## 3. 证明义务及失败边界

证明`sid∈sort(unique(∪FaceSamples))`等价于存在一个支持面含sid；面序及提示重证仍相同。提示失败回到原完整次序，成功证书仍覆盖全部样本。延迟几何复制只改变失败路径分配，没有改变最终绑定内容。根内复用需证明输入依赖完整；支持不同、视图变化或公开域混用均为反例，不能共享。

资源配额按实际访问计费；省掉排序不应虚构省掉数值认证。自然触限视作不完整。成本分别列准备、提示、完整认证，不能把旧准备费用全部当成可消除。

## 4. 实施与退出

在06G提交后补充直接调用链和实际方案。先实现延迟证书/提示成员检查，保持独立结果；再决定是否值得根内支持复用。使用前阶段冻结程序进行两个源高自然输入同任务快验，受影响旧分支至少一个代表。专项覆盖错提示、支持变化、公开域、证书篡改与并发确定性。完整输出变化为硬失败；复杂复用无明显减工则撤回，报告原因，不叠新全局缓存。

交付研究报告（含推导、代码因果与工作量）、事实、审查和数据，每阶段单独提交。

## 5. 实施结果

06G已提交`3ae5a8e`。直接核查确认旧面读取只依赖当前state及有序Support；同根F/H可能反复读取相同闭面集合。首版选取最小复用单元：核心域去重样本集合，`TransactionalQualitySupport.*`由每个根独占，仅保存最近一个支持；成员、实例、代次变化即重建。不开跨根/跨帧缓存，不保存完整样本对象和成功证书。完整旧面数值证据暂不共享，避免其中账本指针跨调用悬空；其成本与更重缓存收益列入最终核查。

提示查询前仍保留结构/接口和面证据，成员查询使用原FaceSamples线性查找，不要求未证明的有序前提。只有需要完整循环时才整理样本。支持缓存只做完整集合复用，不能绕过当前提示重证。证书绑定在两个域全部成功后复制。自然对照复用06G after为基线；全部原路径/模式保留，无新增实验开关。

最终闭环：根内支持缓存仅1次复用，已按退出条件撤回其组件/签名/登记。只保留提示检查先于排序、完整成功后绑定证书。支持整理少7,838次，证书分配11,234→1,495，数值样本与96帧结果保持。Sierra首轮波动经一次定向参考复测未形成持续退化，最终107.427ms、Canyon62.544ms；不宣称完整性能突破。见[报告](../../research/cpu_refinement/qpc_06h_certification_preparation_results.md)及[审查](../../reviews/cpu_refinement/qpc_06h_certification_preparation_review.md)。无新增生产文件，进入06I。
