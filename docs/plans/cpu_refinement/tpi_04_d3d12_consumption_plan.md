# TPI-04：D3D12 消费与双后端边界

> 2026-09-15；前阶段 `a4f4fd9`；依据 [TPI 大规划](transactional_platform_integration_plan.md)自主实施。

## 目标与源码事实

已读开发规范、TPI-03 事实、D3D12TerrainRenderer 的 Update/Rebuild/UploadMeshForFrame/Render、帧资源结构和 GraphicsBackend::BeginFrame。D3D12 复用帧之前 WaitForFrame，再重置 allocator/list；每个网格帧持有自身映射缓冲和待消费范围，CPU 借用仅用于当次同步。接口/注册已共享，持续调度和设置尚需接线。

本阶段只完善相同 CPU 输出的 ZO 输入、生命周期、范围恢复及各帧追赶，不提取共同 uploader，不修改核心策略。

## 文件职责与处理

- Extend `D3D12TerrainRenderer.cpp`：与 OpenGL 相同的公共配置/调度/失败包规则，保留 D3D12 自身 PendingFullUpload、区间合并、版本和 fence。初始化/设置延迟到有效相机机会；重置先清借用。
- Extend 帧容量恢复：当前增长会先释放旧资源；分配失败后容量必须归零，不能下一次依据旧容量向空映射地址写入。任何范围积累失败使所有帧要求全量，防止部分帧遗漏已经消费的算法范围。只在成功复制后清除该帧待消费状态。
- Extend Render 的延后同步统计/错误：补齐真正 Render 才发生的上传费用，不能用 CPU 更新的零字节覆盖它。失败保留恢复标志，不绘制失配资源。
- 暂停后的资源恢复只同步最新输出，不额外执行算法批次；此共用契约同时补到 OpenGL。D3D12 有限诊断入口可请求下一次网格分配失败，触发点位于释放旧映射之后，验证失效容量不会继续使用；该开关默认关闭，非设备移除模拟。
- Reuse `TransactionalPlatformProbe`：相同暂停/单步/重载/预算和窗口序列，增加足够帧轮转与一次资源失效检查。若需要有限诊断钩子，归属图形消费者检查入口并默认关闭，不放入算法。
- Extend `CMakePresets.json`：事务 D3D12 预设继承各自后端，公开相同 Boost 要求。不更改旧默认配置。

## 验证、性能与停止

1. 先在当前原生同配置保存旧 DOD 八帧参考，构建/运行日志单列。第三算法在接线完成前不运行。
2. 实现上述接线；复用 TPI-02 NO/ZO 数值测试，不重复完整核心矩阵。
3. 原生 D3D12 有限公共图形检查，至少跨两个帧槽多次轮转；首次全量、后续无字节、窗口尺寸改变、数量缩短、重载、暂停后单步、主动恢复与失败后恢复。调试层有告警则保留，不能把编译成功代替运行证据。
4. 同一原生 D3D12 旧名单八帧后测，新算法单独短自然回放。一个进程/配置；10 分钟采集上限、单次180秒，不拼 OpenGL/WSL 时间比值。
5. 输出事实/审查、性能分析和未验证边界，提交后进入 TPI-05。设备移除若无法安全恢复则明确关闭该会话，不重导入算法伪装正常恢复。

## 实现结果

已完成接线、真实双帧轮转、暂停恢复和有限分配失败核查；旧 DOD 前后无实质性能回归。默认短回放零事务，持续交易和质量未据此通过。见[代码事实](../../codebase/cpu_refinement/tpi_04_d3d12_consumption_facts.md)与[审查](../../reviews/cpu_refinement/tpi_04_d3d12_consumption_review.md)。
