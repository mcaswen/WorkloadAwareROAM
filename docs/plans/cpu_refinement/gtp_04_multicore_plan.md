# GTP-04：有限多核对照与原型出口

> 2026-09-14。承接 `74d7762`，依已授权大规划自主完成、审查并提交。本阶段仍为独立原型

## 1. 任务与硬边界

B/C 均执行同一批快照全局优先预留：相同输入、前缀、提案目录、认证、命名额度、donor 池、预留顺序和最终事务。B 为单线程，C 固定 4 线程。并行只覆盖只读接收/回收认证、换视图投影和面评分、独占目标面记录与输出块填写；共同索引、邻接、分配、预留和最终发布仍串行。没有新增几何原语、阈值、保护规则或生产入口

所有线程完成后才消费结果，按原输入顺序归并。回收认证在存在预算需求时预先处理共同池：原 B 为统计局部可行分母本来就会遍历该池，工作集合不扩大。各线程拥有私有提案和计数，不能并发修改共享 map、计数器或浮点归约顺序。任务失败必须排空，潜在失败点位于发布前，旧逻辑状态和 Pending 保持有效

## 2. 架构与文件归属

| 判断 | 文件 | 职责与理由 |
| --- | --- | --- |
| Create | `TransactionalExecution.h/.cpp` | 同步分块回调、局部账本归并与诊断线程证据；调度与几何规则分开，不建立新线程池 |
| Extend | Pipeline / Reservation / Samples / Commit / Mesh | 显式注入执行配置；各自只划分已有独立循环，保留默认单线程调用 |
| Reuse / Wrap | `MaterializationExecutor` | 仅测试/探针包装现有排空异常的 DOD 线程池适配器；核心不依赖 MPR 或 DOD 控制器 |
| Extend | probe / tests / CMake | B/C 模式、真实线程证据、失败原子性、相同批次与结果对照 |
| Create | `GreedyTransactionalLodFamilyProbe.cpp` | 隔离 Classic/DOD 自有轨迹测量，作为家族上下文，避免把不同任务混入 B/C 比值 |

执行配置为值对象加同步 Dispatch 回调，不引入多态业务层。每段分块数量不超过配置线程数。计时包括局部账本、分配、派发、等待和归并；线程内墙钟和不是 CPU time，也不是该阶段墙钟。全局配额在归并后再次检查，超额不可发布

## 3. 最小验证与测量契约

复用 GTP-03 的两场景及八轮 `14,14,14,15,16,17,18,14`。每场景 B/C 各一诊断进程、一计时进程，不增加样本、暖机或重复矩阵。保存修改前二进制与输入/编译来源。诊断逐轮核查全量状态、样本、输出、Pending，以及 B/C 的请求、尝试、批次、几何与计数一致；实际线程身份只在诊断收集。计时关闭全量核查和线程身份追踪

解析测试覆盖真实 4 线程、分块异常排空、失败前旧状态保留、无 Dispatch 配置拒绝、同批串行/并行续接。只构建原型和相关家族探针，不运行全套 CTest 或图形后端

报告完整 frame update（含视图、发现、认证、预留、修复和 mesh）、各阶段墙钟、事务量和实际线程证据。相同任务 B/C 才可称多核加速。GTP-03 B 是修改前参考；明显回归按开发规范仅做一次定向复测，不追逐微秒

Classic/DOD 各场景一次独立进程，使用冻结参数/相机。从各自初态回放 0～13 作为初始化，再计同样八次视图更新；它们未导入新原型的半阶段状态，历史、任务和质量不同，时间只作家族上下文。返回帧另评公共 Q 的绝对质量，评价和文件输出不进入算法计时

源码核查发现 Formal 清单加载器强制历史串行配对动作及单线程。因此家族上下文显式恢复默认 `TerrainLodPassPolicy{}`、`EnableParallelSplit=true`，保留场景尺度/阈值/深度/预算；线程数由默认运行时选择，不能保留清单的强制串行来削弱 DOD。该口径在家族运行前冻结，实际使用线程数逐行输出

## 4. 出口与接入后分析

正确性通过且真实多线程执行即形成原型证据；完整时间无收益时明确串行成本和当前边界，不扩充算法或自动进入平台。持续质量风险沿用 GTP-03，不把数值等价等同于质量问题已解决

完成并提交后，另写接入前性能空间分析：按实际成本给出工作量参数、时间/空间复杂度、可并行与串行部分、平台状态/输出适配成本、不同负载下胜过 Legacy 的必要条件。目标发现与认证始终完整计费，不承诺尚未实测的倍率；论文性能结论还需同预算、可比质量和持续轨迹实验

### 最终环境核查补充

阶段及分析提交后，进程核查发现 WSL 在工具调用之间重新启动，已有短计时可能混入启动后台负载。因此追加且仅追加一组同一存活会话内的核查：等待启动 40 秒后记录 CPU 活跃度与进程快照，随后每场景旧 B / 新 B / C 及家族各一次独立进程。冻结顺序为 test 旧 B→C→新 B、Peking 新 B→旧 B→C，家族保持各一次；不重跑诊断、样本或线程矩阵。新旧数据全部保留，启动风险和本次修订先于结果登记。只有这一具体环境新证据触发复核，不以追求更好的数字为由重复

核查已完成，测前 CPU 空闲 99.984%，B/C 完整比值 1.940×/1.470×；旧/新 B 分别 290.752/285.557ms、376.958/343.800ms。此前 +12.07% 和内部认证差值未复现，关闭为无稳定版本相关证据。所有决策/工作/网格保持，家族质量保持；结果 §7 与接入分析已同步，无后续重复
