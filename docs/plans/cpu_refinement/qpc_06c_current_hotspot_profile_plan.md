## 1. 目标与范围

回答Sierra/Canyon的50k移动段：真正消耗CPU的函数是什么；旧Fit、新逐点认证、数值与数据结构各自位于哪条调用链；墙钟由总工作还是最长任务、串行尾部主导。保留L=`legacy+error-first`和P=`pointwise-target+error-first`，两者不是同任务，费用差异必须同时报告工作人口与曲面差异。

输出是有当前版本证据的优化优先级、复杂度解释和收益边界，不是实现性能修复。质量规则、目录、前缀、任务划分与线程数不改；不重启一般profiler建设，不进入05或新的Fit算法。

## 2. 已核查事实与采集边界

旧FPR为GWR前的4线程八轮，不能替代本次50k/8线程输入。现有`run_experiment.py profile`、`profile_adapter`和`ExperimentCpuReplay`已经能够运行完整资产/相机输入，调用真实平台算法适配器的`BuildRenderData`，无需重新实现算法。`ProfileSession`目前只支持Linux；本次perf和Tracy先在同一WSL核心路径采集，Windows06B正常计时作为原生参照，不能把Linux函数占比直接乘Windows毫秒数。逐帧核对两平台实际输出与工作人口；不一致时明确限制或停止对应归因，不默认为同一行为。

现有Tracy已有Fit、Measure、任务、派发、等待、视图、修复、提交等区间，但`PointwiseQuality::Certify/ValidateBatch`没有独立区间；仅补这两项，每样本数值叶函数由perf观察，不逐样本发事件。

## 4. 冻结协议与实施顺序

1. 保存当前提交/源码、工具/构建身份和06B两场景L1/P2实际配置；保留原96机会、前三暖机、50k、前缀160、8线程、immutable、翻边、原边界设置、原相机与D3D12深度约定。Linux没有渲染/上传，不声称等同原生整帧。
2. 补两个静态区间，按现有FP和Tracy预设构建真实`parallel_roam_experiment_cpu`。不全局禁内联，不改严格浮点，不更新依赖/内核/权限。复用已验证工具能力，实际捕获失败再定位能力问题。
3. 四配置各一正常FP进程、一perf进程、一Tracy未连接计时进程、一Tracy捕获进程，顺序运行，不与编译或其他性能任务并行。每次最多180秒/单产物512MiB；原始捕获原生缓存落盘后归档到`benchmark-output/cpu-refinement/qpc-06c/run-01/`。预计正常采集15分钟内，构建另计。perf移动有效样本不足2000时至多一次定向补采，不为美化排序重复。
4. 冷/暖、移动/返回/静止分开归约。主要结论只使用暖移动窗口，初始化不得占热点分母。函数报告同时给自身/含调用加权比例、样本量、缺栈/未知/丢失及调用边；不能把采样数叫调用次数。Tracy报告逐帧完整边界、真实调用数量、任务起止/最长块/任务和/等待/派发尾部，父子时间不相加。
5. 同一构建采集/未采集逐帧比对实际网格、逻辑/物理工作与序列。跨构建/跨系统相等单独核查；任何差异保留首帧和具体字段。性能数字保留扰动，不用采集时间宣称优化收益。
6. 将主要路径映射到源码责任、循环人口和成本表达式。优先级按当前绝对墙钟可影响范围和工作削减机会排序，区分已实测瓶颈、源码解释、仍需消融的机制。完成报告与审查后收口，不直接改算法。

## 5. 验收与停止

必须得到当前两个场景的函数和线程证据，而不是仅重跑阶段计时。报告包含所有有权重符号/调用边的明细、主要函数解释、逐帧任务表及移动重帧示例。检查窗口完整性、结束标志、实际线程及二进制一致性。辅助统计处理耗时单列；现有通用解析器复用其既有测试，新增分析只做必要计数恒等/边界检查，不跑全仓库。

静态区间关闭宏不产生运行时代码；正常原生基线沿用06B，不把无算法改变说成新提速。Tracy扰动以同构建未连接对照报告，单进程不能推出稳定尾部结论。若Linux与Windows工作显著不同，报告明确不能据此定量指导Windows瓶颈，优先解决代表性问题，不以旧报告填空。
