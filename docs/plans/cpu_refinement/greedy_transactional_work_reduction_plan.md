## 1. 问题、目标和结论边界

本轮只验证：在保留已经声明的事务、预算及认证语义时，能否通过减少发现、认证与视图维护的工作，使持续原型进入值得继续研究的成本区间。论文定位仍是全局优先级驱动、分阶段、事务化、面向数据的多核 CPU LOD 执行，不新增独立重网格化主线。

当前四线程八次更新的平均成本如下，单位 ms；阶段划分互不重叠，子项不能与完整时间重复相加。

| 项目 | test129 | Peking |
| --- | ---: | ---: |
| 完整更新 | 18.397 | 29.226 |
| 视图刷新，含评分及建序 | 2.379 | 26.626 |
| 接收与回收提案/认证 | 10.721 | 1.892 |
| 其余成本 | 5.297 | 0.709 |
| DOD 家族上下文 | 0.589 | 2.977 |

Peking 的主要入口是视图工作；test129 即使视图刷新免费仍约 16ms，必须同时处理发现、认证与局部维护。当前数据证明现实现缺乏竞争力，没有证明这些成本全部是可删除冗余，也没有证明事务架构存在不可消除的同等成本。

目标产物为：

1. 每项削减对应的语义义务、真实减少的工作及完整时间对照。
2. 精确前缀选择、惰性提案和局部不可变证据复用的有限实现候选。
3. 对按需视图评价给出明确的证据机制；能保留原决策才实施，不能则记录当前方法的失败位置。
4. 逐场景性能可行性出口，以及未解决的持续质量和真实平台成本限制。

不承诺快于 Classic/DOD，不承诺 2～5 倍。四线程相对自身串行的已有收益不能替代绝对成本验收；找到自然批次不等于便宜地找到批次。

## 2. 范围与非目标

范围限于 `src/experiment/greedy_transactional_lod/` 及其现有测试/探针。保留原始双线性参考、公共 Q、场景/相机、预算、阈值、E/F/H 目录、一般 one-ring 耳切、旧中心改高范围及当前视图认证。改变数据访问方式，不改变用于决定前缀和事务的输入问题。

本轮不做：生产算法注册、GUI、OpenGL/D3D12 上传、更多线程档位、新线程池、2-ring、新几何原语、改写 greedy 预留、扩大自然输入、寻找大负载交叉、长期恢复算法、新通用 profiler 或一般理论库。精确 DP 仍是离线 oracle。拓扑/网格记录填写不列主要优化项目。

如果只有换 urgency、减少认证人口、改变拟合自由度或放松接受标准才能获得收益，应单独提出契约修订；不得借本规划实施。连续质量风险继续开放，本轮精确复现旧结果不代表旧结果的质量已通过。

## 3. 三类变更及同任务契约

### 3.1 保持决策的工作削减

默认要求同输入下保持：原始候选资格、精确优先级键、接收前缀、共同回收池、已尝试提案次序及结果、首个成功交换、预算命名与不回流规则、批准事务、实际 binary64 几何、下一轮可观察状态、网格和 Pending 语义。

允许改变物理索引排列、临时分配、计数及未影响选择的诊断访问。削减的是重复或不参与决策的工作，不是减少有效请求或事务。资源配额仍检查实际工作；因新增预算门禁、配额耗尽或未认证而退出的样本不能列为成功加速。

接收键沿用 `(-PrioritySquared, stableFaceId, slot)`，包括当前有限值筛选与阈值规则；回收键沿用 `(incidentPriorityMaximum, stableVertexId)`。原 `PrioritySquared=max(sampledErrorSquared, 0.04*projectedLongestEdgeSquared)` 不变。同分、空可见证据和密度项主导的需求不能被过滤后补取尾部。

### 3.2 有证据的按需精确查询

视图加速推荐仅走此类：为尚未详细计算的候选维护包含当前规范计算结果的上下界 `L_i≤P_i≤U_i`。只有剩余上界无法进入当前精确前缀时才能停止展开；相等情况按完整稳定键继续判定。前缀内仍输出精确值，回收最小前缀另用相应的下界排除规则。

上界必须覆盖当前浮点评分结果，不只覆盖理想实数几何误差；投影分母、可见性和非有限数分支也属于证明义务。对无法判断的节点下降，最终复用原规范样本评价。允许最坏情况回退至全 Q，不能声称一般次线性保证。

惰性状态不要求每个物理缓存列随时与稠密基线逐字节相等，但要求所有算法观察点返回相同结果。诊断可以展开全部缓存后与独立全量 oracle 比较，该展开不得提供正常路径的先验答案。

### 3.3 不在本轮范围的语义修订

直接按保守上界排序、换层次误差 urgency、减少 Q、只认证部分可见样本等，可能保持某个质量界，却不能保证当前前缀及交换一致。它们属于另一个明确标记的算法版本，本规划不授权实现。

如果 GWR-01 发现精确查询没有可用跳过证据，关闭的是所考察表示/查询机制；不写成“任何运行时误差表示都不可行”。同时不得自动开启另一套误差系统以延续本轮。

## 4. 已有能力及目标架构

现有 State/Commit/Mesh 已提供局部状态、失败前私有准备与完整输出；Execution 提供同步分块和异常排空的接入契约。它们继续复用。Samples 当前同时拥有样本关联、视图派生值及全序索引，本轮按真实新增职责定向拆分；不重写活网格表示。

```text
探针：输入、运行配置、诊断 oracle、计时与文件
  ├─ 动态串行参考 A：独立反馈控制
  └─ Pipeline：批次 B/C、生命周期和共同发布
       ├─ Samples：参考/Q、owner、闭面关联、局部修复
       │    ├─ PriorityIndex：确定性前缀及持续索引
       │    └─ ViewEvidence（条件阶段）：视图界、按需评价
       ├─ Proposals：按冻结次序逐项产生局部提案
       ├─ Certification → ProposalEvidence：拟合/认证与不可变事实
       ├─ Reservation：顺序预留及配对，诊断另列
       └─ Commit / Mesh：复用已批准批次的准备、发布和输出
```

依赖规则：几何证据不依赖 Reservation；候选索引不决定认证、提案或预算；视图查询不选择事务；Pipeline 不吸收这些算法。由 Samples 拥有的新索引/视图组件只接收只读值、区间或窄访问器，不反向持有 Samples/Pipeline 对象，避免所有者与被拥有组件形成循环依赖。Input/Validation 只属于实验入口。生产库仍不反向依赖原型，不引入 MPR/DOD 状态或新的第三方库。

采用值对象、明确所有权、只读借用、顺序游标和同步执行配置。前缀索引采用归并摘要以支持局部修复；不建设通用缓存框架、虚函数策略树或任意组合的运行开关。

## 6. 确定性前缀与持续维护设计

GWR-02 以完整精确评分为输入，先不同时改变视图采样。目标是消除换视图的逐项树节点分配和全排序，并保留同视图局部更新能力。

推荐表示为连续记录、固定物理槽块、每块接收 top-r / 回收 bottom-m 摘要及确定性归并摘要树。叶块还保存合格接收数量；父节点合并计数和前缀。全量重建按块扫描，沿用固定键；局部更新只重建脏块及其祖先。现有身份映射复用，不新建任意位置堆删除所需反向索引。

块大小 `b` 在 GWR-02 实现前冻结一个值，不做参数搜索；令前缀尺度 `R=max(r,m)`，应满足块内空间与摘要复制成本可明确计费。对已分配记录数 `n*`，预期完整重建工作为 `O(n* log R + (n*/b)R)`，固定 R 后对 n* 线性；修改 h 个不同块的保守界为 `O(h b log R + h R log(n*/b))`，共享祖先可合并。空间 `O(n* + (n*/b)R)`，读取根前缀 `O(R)`。回收代理计算及受影响邻域另外计费。

这些是建议结构的目标界，不是已实现结论。不得将 n* 写成活动 n 以隐藏空槽，也不能将固定 r 的线性描述成与 r 无关的线性选择。若该摘要结构实际维护成本超过旧局部树，保留旧路径并报告；不追加多套堆/分页结构搜索。

全局阈值数量 `D_raw` 在此阶段仍精确维护。GWR-04 引入区间后，精确人口统计另见 §8，不能借精确前缀推断完整人口。

## 7. 惰性提案、证据复用及诊断分离

### 7.1 提案与证据

逐项构造保持：排序后的边 E → 原规则的见证点/重心 F → 排序后的内部中心 H。可能影响目录的见证选择仍用当前规范值；首项成功后不为未尝试后项收集支持样本、构造点表或计算几何。计数分别记录目录项存在、实际构造和实际进入 Fit，不能继续用原 `Proposals` 一项代表全部工作。

同一提案内保存样本身份、首个规范覆盖面、插值关系、参考值、与该视图绑定的系数及已验证固定前提。共享边选择次序保持；参数坐标/连接变化必须重建，视图变化使投影证据失效。普通浮点系数、包含真实值的区间和精确有理证据分开，不能互相冒充。

最终认证仍针对实际 binary64 存储高度；可复用已成立的覆盖/插值前提，不要求每步从头恢复同一事实。独立全量重算属于诊断 oracle，不提供运行时答案。证据随提案/批次释放，初始化、内存峰值、销毁和缓存失效均记账；暂不引入跨帧全局提案缓存。

### 7.2 回收和配对

同一快照/提案的 footprint 构造一次。预留仍由高到低按冻结共同池顺序取第一个合格交换；已成功后可停止该需求的运行时配对，不更改成功之前的判断、命名额度和不回流规则。

当前回收池预先全部认证，配对早停不会自动节省这些认证。首轮保留此并发准备边界，明确区分两笔收益；按需回收认证仅在 GWR-03 小规划有成本依据并明确固定批块顺序时作为同阶段一个候选，不叠加多套调度策略。未达到该条件就不实施，不以早停后的 pair 数声称减少了回收拟合。

运行时报告必须区分精确值、已知下界和未收集项：`D_need`、已执行数、实际批准事务保持精确；成功交换已证明对应需求可行，未执行需求的全部局部可行性可能需额外审计。诊断遍继续输出精确 `D_feasible` 和完整拒绝分布；不得把未检查按不可行或零填写。诊断和计时都选出相同事务，额外检查无副作用，不进入正常发布路径。

### 7.3 两自由高度拟合的有限消融

先用最小计数确认 H 实际进入次数、每次裁剪前后顶点数、去重比较数与总阶段贡献。只有它是剩余实质成本时，尝试一次保持首出现次序的去重/复用临时存储方案，不引入新 LP 求解器。

当前最终高度来自顶点均值。去掉重复点或改变次序均可能改变数值，故解析验证覆盖退化多边形、重复交点、signed zero、舍入和最终存储值；不能仅凭最终认证通过认定是等价削减。无法保持声明语义则撤回该候选并记录，不在本阶段顺便修订拟合策略。

## 8. 视图证据的先行审计与条件实现

GWR-01 只推一个推荐机制：**在当前面—样本关联上建立可局部修复的参数域样本块层次，保留参考/当前曲面范围证据，换视图时先投影块界，再对不能排除的块细化。** 这不是 ROAM 二叉层次，不要求将一般网格重新映射到旧 cut。

首先给出纸面/小型可执行证据，不先搭完整 C++ 视图系统。审计必须覆盖：

| 义务 | 要求及不能隐藏的成本 |
| --- | --- |
| 上下界正确性 | 同时覆盖 sampled error 与边长项，包含规范 binary64 运算结果；下界来自真实已评价见证，上界不能遗漏局部尖峰 |
| 视图域 | 参考决定可见人口；参考可见、被测越过近面和非有限数仍须被识别。范围无法判定就下降，不能跳过整个块 |
| 接收前缀 | 排除所有可能越过截止键的剩余候选；前缀输出精确键，同分按稳定身份 |
| 回收前缀 | 中心代理为 incident 面最大 priority；最小前缀有独立排除证据，不能只解决接收排序 |
| 目录与拟合观察 | 最大误差见证、空可见支持及被尝试提案的样本全部得到当前视图值；旧缓存不混用 |
| 全局人口 | `D_raw` 如保持运行时精确，必须证明整块全部在阈值同侧或继续下降。若仅诊断取精确值，运行时使用显式未收集/区间标签，不能更改实际接收人口 |
| 续接 | 局部换面、H 改高、共享边 owner 和关联变化均修复相关证据；相机变化不重建参数域归属 |
| 代际与并发 | 几何/关联 revision 与视图 generation 分离；按需计算结果由唯一任务拥有，跨 root 共享写须消除或在 barrier 后归并 |
| 输出完整性 | 调试/UI/报告若要求全 Q 当前值，显式走诊断展开；正常消费者不能通过直接 `Values()` 读取未求值列 |

全局投影有效性检查尤其不能推迟到“恰好尝试该提案”才发生，否则改变 SetView 对非法视图的拒绝语义。可以用块证据一次证明大区域合法，也可以在不确定处精确检查；无法获得有效跳过时，回退成本就是该方法的结果。

证明和账本应采用 `W_view=O(n* + v + s + W_select + W_domain)` 一类参数化表达：v 为实际证据节点访问，s 为真正求值的样本，选择与域检查各自明确。初始化/局部证据更新另列 `W_build/W_repair`；块存储、闭边重复关联与峰值内存均计费。未求值列用代际或有效区间表达，不每次清零/复制全 Q 临时数组再宣称仅访问 s 个样本；必要的密集写回必须另列，不能藏进发布或帧外维护。不能直接承诺 `O(k)`、`O(log q)` 或无条件次线性。

进入 GWR-04 前须在 GWR-01 结果中冻结：一个具体块划分、证据字段及公式、失效支持、数值域回退、前缀/人口处理、复杂度及字节预算。若只能按新上界 urgency 排序，或必须每次全量重建证据，标记当前精确视图机制未通过；不自动创建 ViewEvidence 文件。仍可完成有限 GWR-02/03 并对已验证工程削减收口，但不能声称 dense-Q 问题已解决。

## 10. 测量、正确性与最小成本账本

### 10.1 冻结输入和环境

- 沿用 `test129-a-b4096` 与 `peking547-a-b20000`；尺度分别 30/4、80/12；Q 分别 98817、1790881；前缀/池均 64，目录至多 8，角度及所有认证规则不变。
- 初始化来源仍是 `benchmark-output/cpu-refinement/gmp-03/run-01/capture/<scene>-14.json` 及其来源文件，八次视图为 `14,14,14,15,16,17,18,14`；之后不再导入 Legacy 状态。
- WSL Ubuntu、现有 Release 构建、GCC/Boost 及浮点开关保持并记录版本/SHA。所有命令通过 Ubuntu；性能任务串行，不与构建重叠。
- 针对已知 WSL 启动干扰，在一次存活会话中完成前后测量。启动后等待稳定并记录进程/CPU 活跃度；沿用约 40 秒启动间隔，超过 60 秒的等待拆分且提供进展。环境不一致时重测旧二进制，不与历史最佳值拼接。

正常代码阶段每配置默认一个独立进程、八次更新，无额外预热或内部重复。每阶段选择受影响的 B/C 和诊断组合；公共索引影响 A 时，加一次对应的最小 A 前后检查，不每阶段重跑全部家族。阶段结果足够则复用。独立进程是统计单位，八个不同视图不是八次独立重复。

探针沿用快照、模式、输出目录三个入口参数；新增受控模式名及完整命令在对应小规划运行前冻结。旧命令入口例如 `parallel_roam_transactional_lod_probe <snapshot> trajectory-c-timing <fresh-output>`，不能在本文假称尚未实现的新模式可运行。保存修改前二进制及源码身份；自然单进程外部墙钟上限建议 180 秒，单轮沿用现有 120 秒异常配额，超限保存证据后停止。构建/初建/诊断耗时单列，预计分钟级开发快验，不运行小时级矩阵。

### 10.2 边界、统计和诊断

主要工程门槛沿用历史完整 `frame_update`：SetView、发现、拟合/认证、预留、准备、发布、续接及 mesh；暂存分配/释放属于调用内成本。另报 Consume、初始化、最终销毁和峰值空间。不得将原来计入的重复检查移出窗口后改名为免费必要认证；科研额外审计才允许移到诊断遍。

前后原型比较优先同策略、同 1/4 线程及相同结果。动态 A 不与 B/C 当成同任务加速；C/DOD 仍是不同历史/语义/线程资源的家族时间量级。DOD 默认实际 8 线程这一事实继续显式标注，正式同资源研究以后另定。

报告每轮、八轮总量/均值、静止与换视图子集、最大观测值；中位数/P95 可按固定八点描述，但必须注明只是异质轨迹摘要，不是稳定延迟分位数。不得删除较慢帧、把未执行事务当速度收益、用旧环境结果证明本次回归不存在。

普通工程回归按开发规范 §7.3 的 `max(0.05ms, 5%×基线, 已知波动)` 筛查。跨线或新风险只对相关输入追加一次复测；没有波动估计则明确缺失，不为几微秒继续分析。统计不足时写“待验证”，不强行判 Pass。

诊断全 Q 的绝对误差/RMS/高度误差和返回视图逐点 excess 保留。优化路径需与稠密基线独立诊断结果及事务轨迹一致；按需缓存允许通过外部全量展开验证观察语义。原始几何合法、预算、R/W 冲突、槽复用、Pending 和失败排空等不因工作削减放宽。

### 10.3 最小新增账本

| 范围 | 记录量及解释 |
| --- | --- |
| 选择 | 全量/脏块记录数、比较/摘要归并数量、重建/修复时间、分配和实际容量；选择不能藏在准备外 |
| 提案 | 可枚举目录项、真正构造项、Fit 进入数、成功/失败和采用 ordinal |

产物存 `benchmark-output/cpu-refinement/gwr-xx/`，按 before/after/diagnostic 隔离，Git 忽略；报告、事实和审查归现有 `docs/{research,codebase,reviews}/cpu_refinement/`。每阶段的小规划和大规划结果写明未执行项，不覆盖 GTP 数据。

## 11. 工程门槛与退出机制

以下为**待随本规划确认的建议门槛**，不是用户已确认的性能承诺。

### 11.1 分开三个出口

| 出口 | 判据 |
| --- | --- |
| 正确性 | 原决策/实际几何/可续接观察一致；或明确说明失败并停止对应候选。诊断访问数允许减少，不允许漏认证 |
| 机制有效性 | 明确减少预期工作，构建/失效/空间/析构计入后有实质完整收益；不能只有局部小循环更快 |
| 性能可行性 | 按下方逐场景时间目标与质量/能力边界判断，不能用前两个出口自动批准生产替代 |

参考当前 DOD 家族时间，建议阶段性门槛为 `T_new≤5×T_DOD`，对应 test129 约 2.95ms、Peking 约 14.88ms。实际判据使用本轮冻结同环境家族结果，历史数字只作距离说明；不选择较慢 Legacy 样本降低难度，也不人为限制旧路径。

每场景单独列达标/未达标/证据不足。达到工程门槛也只支持继续研究，不能称胜过 DOD、同质量收益或具备论文完整证据。相同预算上限仍要报告实际 N、事务与返回质量；当前质量没有已证实整体优势，不能以更强保证为慢路径辩护。

### 11.2 阶段停止与最终决定

- GWR-01 没有可审计证据机制：不实施 GWR-04。可完成已限定 GWR-02/03 后收口，不自动扩展层次/近似策略。
- 一项优化因更少事务、陈旧视图、不同选择或弱认证而更快：正确性不通过，不计入保留候选。
- 结构修改没有减少预期工作或新增维护抵消收益：记录原因，至多处理该阶段已确认的一个候选，不继续堆局部优化。
- 有实质收益但仍越过 5× 线：记录工程进展和剩余成本，不降低门槛。若只某个场景成立，只讨论该范围，不以另一场景抵消。
- 有限结构削减完成后仍明显越线，且没有已验证质量/能力回报：停止将“绝对性能优于 DOD”作为默认下一步；提交实际成本与机制失败位置供后续讨论，不自动进入平台、扩大工作负载或重设误差系统。
- 没有新工作负载数据时，将交叉点写为“未测”，不能以不存在交叉作否定证明，也不能以可能有交叉获得无限续期。

当前视域外高度退化、返回视图恢复不足，以及 priority/receiver 错位独立列为开放风险。即使达到时间目标也不关闭它们；若未来解决这些问题需要新增工作，须重新计入完整性能，不能预支本轮收益。

## 12. 风险、取舍与确认事项

| 风险 | 处理/备选 |
| --- | --- |
| 精确前缀要求迫使大量样本展开 | 保留回退及实际访问账本；关闭当前视图机制，不自动换成按上界 greedy |
| donor 代理或 D_raw 迫使全域精确评价 | GWR-01 优先检查；人口统计可明确迁至诊断，但决策所需回收顺序不得省略 |
| 块摘要加快换视图却拖慢同视图/A | 同输入前后对照；保持旧实现可追溯，必要时不采用新索引，不能削弱参考 |
| 缓存复制量和失效成本超过重算 | 局部提案生命周期复用，报告实际字节；不为命中率长期保存所有提案 |
| 去重改变实际高度 | 保留首出现顺序及规范算术；不满足则撤回，另议拟合契约不属于本轮 |
| 正常/诊断分离造成漂亮分母 | 使用完整性标签，诊断保留精确四层分母；不以缺失值充零 |
| 视图检查延迟漏报非法状态 | 全局域证据或明确回退须在共同发布前完成；认证最终局部提案不足以替代此义务 |
| 继续陷入无边界性能修补 | 固定输入/线程/一个结构候选，逐阶段退出；不实现额外调度或平台设施 |

需要后续讨论确认的关键架构决策为：本规划仅保持原 priority 的精确查询路线；持续分块前缀索引；提案局部证据与视图证据分别归属；诊断完整性显式化；5× 家族工程线及逐场景出口。视图证据具体公式/存储布局在 GWR-01 证明后再写 GWR-04 小规划，缺失核心义务时不进入实现。
