## 1. 目标与冻结范围

从 GMP-03 四个原始中立快照直接建立自有网格，计算完整原始优先级，认证前 64 个需求，使用共同前 64 个内部中心和固定耳切寻找预算交换，冻结批次后直接写入自有状态。不得借助 Legacy 目标、预先求好的事务或 Python 认证结果。

本阶段为独立实验的单批串行内核，不实施动态参考、真实多线程、完整持久样本/网格消费或生产接入。单批几何应用必须局部准备和发布；初始化、独立全量验证及下一轮全量再生成分别计费，后两者不得冒充正常增量维护。

实现前已阅读开发、规划、审查及代码事实规范，大规划、GMP-01/02/03 契约与实现；扫描四份 Python 核心、来源探针、测试构建、公共依赖和 MPR 执行适配器。当前没有新持续 C++ 状态或精确数值依赖。复用旧数据和有限 oracle，不将旧 Python 控制器搬入生产调用链。

## 3. 数值、依赖与执行契约

### 3.1 实际发布值

固定 C++ 数值标签 `gmp-v1-binary64`，参数坐标与高度均为 binary64，原输入整数身份精确读入 64 位整数。新点先舍入再生成局部面、做形状和质量认证；不复用理想有理新点的证书。禁止 fast-math 与隐式浮点收缩改变冻结运算顺序。

定向/包含和角度使用浮点过滤及必要有理回退；质量使用向外舍入的区间判定，不能确定时对实际二进制值进行有理复核。拟合仍只是提案生成，任何浮点拟合失败记 `fit_bound_failed`，不是数学不可行；证书覆盖完整可见闭补丁，未知拒绝。记录过滤和精确回退访问及时间，不能默认为全 Q 使用精确算术。

锁定 Boost 1.90.0，Ubuntu 包 `libboost1.90-dev=1.90.0-6ubuntu1`，SHA256 `7b89698c907fd5d33ccd439674fa53803139923822181c87b910579827aca379`；来源为 APT 已索引的 Ubuntu 官方归档，许可证 BSL-1.0 及包内版权记录保留。仅在用户目录解包到 `/home/mcaswen/.cache/roam-gtp-boost-1.90/root`，不修改系统包或把完整依赖加入仓库。配置显式给头文件路径并检查 `BOOST_VERSION==109000`。Multiprecision 用于精确回退；同包 PropertyTree 仅在输入/诊断适配读 JSON，不增加另一套解析器依赖。若已索引版本无法取得或身份不匹配，停在依赖门禁，不自动换源/版本。

### 3.2 v1 单批

P/G/C、β=0.20、θ=atan(1/3)、η=0.01px、目录及 pool/prefix 均保持原冻结规则。`no_screen_samples` 高优先级需求仍保留在前缀与失败分母，不补取尾部。E/F 只改新点，H 仅指定旧中心和新点，donor 固定存活环高度。全 Q 高度保护不进入本阶段基线。

新接收点身份由快照和提案次序确定，面身份在批准后按逻辑连接确定；应用排列不能改变结果。冲突至少覆盖被移除面、读写的边关联、旧点高度；邻接/样本等派生共享写由发布后的明确合成承担，不把只读旧高度共享误当成独立写。每批预先命名空额度、不回流；账本结束即失效，实际 N 是下一批唯一预算来源。

State 连续槽与逻辑 ID 分离，准备阶段可扩大容量但不修改已发布逻辑状态。提交所需的局部邻接和身份记录先建立，失败不部分发布；修改支持外的记录直接保留。工作按真实局部访问计数，不通过全网格重新排序/复制来实现单批写入。

## 4. 验证、性能及停止

1. 先复用 GMP-03 原始数据/代码 SHA 作为诊断参考；记录本阶段基线源码、构建配置及已有来源探针身份。在实现前运行现有无捕获来源的一组独立进程短基线，结果写 `benchmark-output/cpu-refinement/gtp-01/before/`，不覆盖旧报告。
2. 解析验证覆盖：33 样本/38 闭面贡献、正交/透视误差平方 2500/1600、边界共享样本、近退化/舍入、六价耳切、旧点完整支持、非 dyadic 坐标、接口边冲突、重复预算、过期批次和拒绝后状态不变。对新代码按风险测试，不跑全项目 CTest。
3. 四个既有快照各一遍诊断，前后实际几何输出由独立检查器核对；v1 与 Python 的需求/提案/接受差异逐层定位，不能将差异笼统归为浮点。计时遍关闭独立全量诊断，仍含发现、认证、预留、准备、发布，输出与导入单列；每快照一独立进程，不额外预热或正式重复矩阵。
4. 单自然进程上限 120s，局部样本认证访问上限 1,000,000；全 Q 初建不纳入局部访问配额但全额计时。到限保存部分结果，不降低阈值或扩大配额追正结果。若数值实现无法承受此最小规模，按成本门禁分析停止，不先建多核设施。
5. 完成后只对受影响来源短路径同配置复测一组，按开发规范 §7.3 的实际影响门槛比较；没有显著影响证据不追加。新内核无旧 C++ 同任务时间，单独报告绝对成本，不能以 Python 速度作为性能胜负。编译与性能任务不并行。
6. 全量几何/样本核对为诊断费用，既不计作已实现的局部续接，也不隐藏在 C++ 完整更新中。合法性、预算、数值认证和目标独立性通过后可以进入 GTP-02；不以快于 DOD、达到某倍数或高度保护通过为本阶段正确性条件。

## 5. 实施顺序和架构自审

先冻结依赖与基线，再实现数值/状态/样本；接着提案/认证、预留/提交、薄编排/输入验证。完成解析检查后才执行自然快验，逐层定位差异；形成结果、实际代码事实与 Critical/Major/Minor 自审，提交本阶段后开始 GTP-02 小规划。

阶段自审重点：没有生产反向依赖、没有外部 J、没有借 oracle 认证、没有全状态复制发布、局部支持和预算完整、未知未当不可行、正常时间与诊断时间分开。若必须改变大规划的重要边界，先说明并记入规划；普通实现细化按现有自主授权处理。
