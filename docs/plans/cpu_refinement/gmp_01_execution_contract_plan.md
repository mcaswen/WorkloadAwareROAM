## 1. 目标与出口

把 Major Plan 的七步 `batch-snapshot global priority-ordered greedy reservation` 落成一份**可以独立解释每个请求、失败和预算去向的有限算法契约**。该契约供 GMP-02 验证事务组合、GMP-03 制作单轮离线审计使用，不是持久 C++ 原型。

核心产物是 `greedy_multipass_contract.md`，以 `gmp-contract-v1` 标识规则身份，包含：输入/输出、P/G/C/E、有限提案目录、确定预留伪代码、共同需求分母、样本归属、状态失效与成本边界、四类参考角色，以及手算过程。

完成条件：同一合法快照和同一冻结配置交给两位实现者，不需猜测候选身份、搜索顺序、空额度去向或停止规则，就能生成相同的需求和批准批次；数值不可判定的地方有统一 `unknown` 出口。不能把“调用某个未定义的最佳 receiver/donor”留作核心步骤。

## 4. 需要锁定的具体规则

### 4.1 输入、身份与有限接收目录

输入是当前合法参数域三角网格 M、实际共享顶点高度、固定参考/Q/视图、预算 B 和冻结规则配置；不携带 Legacy 目标 J。新输出是需求、局部提案证据、预留批次和原因账本，不输出完整最终状态作为“规划答案”。

推荐**每个当前面最多一个主需求**，priority 来自该面当前几何；共享边插点、面内插点和完整邻域旧/新高度共同拟合作为有限接收提案，按固定类型/稳定身份顺序尝试。相邻需求可能引用同一共享边提案，该提案用逻辑键识别与复用证据；实际只能预留一次，冲突跳过不自动删除原始需求。成功请求数、受改善的面数与提交面数分别记录。

GMP-01 需为每类已有原语写出：提案键、q 的单一确定选法、可调整高度、完整支持和面数增量。若选最高误差样本作为 q，必须处理它落在旧顶点、内部边或域边界上的情况，不能把不适用的位置静默当作内部 1→3。旧/新双高度方案仍限已有的完整邻域构造，不新增“换一种边细分再共同拟合”的未证明原语。

所有位置、类型顺序和有限数量在查看 donor 结果前确定。不枚举无限位置、不自动扩邻域；缺少适用原语或数值证据时分别记 `unsupported` / `unknown`。原始需求生成覆盖完整快照的声明域，局部认证是否成功不影响它的存在。

### 4.2 P/G/C/E 与一次性参数冻结

P 只负责紧迫性；G 保留接收区域的旧见证 L_r、新上界 U_r；C 保留回收后上界 U_d 及其证据类型。交换仍采用 `max(U_r,U_d)+η≤L_r`，不使用可加收益假设。对原始面、扩大接收支持及回收支持的误差域分别命名，避免扩大支持后不声不响地改变该请求的 P。

契约正文形成唯一冻结配置表，至少包含：

| 配置项 | 本阶段的定案依据与边界 |
| --- | --- |
| Q 与参考 | 建议复用既有 k=0 公共参考域采样及 bilinear reference；不是按被测面顶点采样。独立更密评价只作诊断，不改变本批接受域 |
| β 与紧迫性阈值 | 以公共 0.20 长边权重及场景原数值阈值为起点，明确新 P 的语义不同；禁止为了未来成功率事后调参 |
| θ₀ 与 D | 在自然运行前固定唯一角度，明确是参数角。先用已有形状反例核查提案目录是否会全部失效，再定数值，不把 30° 示例自动当最终选择 |
| η | 固定正像素余量，说明其防止零进展的作用与拒绝范围；不是视觉不可感知阈值，与算术误差容差分开 |
| 同分/空样本/投影 | 固定稳定身份全序、空样本标记、近面/无效深度与非有限值出口；不把未知质量当成零 |
| 拟合/认证规格 | 固定误差阈值而非先求全局最优拟合；返回合法高度/证据或失败类别。数值不确定不能当数学不可行 |
| 提案与 donor 上限 | 各取唯一有限规则和上限；只限制声明的搜索，未遍历部分保留 `cap/unknown`，不报告整个类别无解 |

特别记录已知几何限制：内部 1→3 若要保持最小角 θ₀，原三角形各角必须至少 2θ₀。因此 30° 下只有原三角形各角均为 60° 才满足这一必要条件，45°/45°/90° 来源上的面内插点及该类双高度接收不可用；共享边 2→4 属另一已知类别。不能等自然 Gate 失败后才发现这个配置效应，也不能为绕开它新增原语。

本阶段结束前配置不能还写“任选一个合理值”；应留存所选值、先验理由、被放弃的选择与影响。若现有原语和硬约束之间发生关键冲突，报告具体反例并 Review，不通过增加参数矩阵延长阶段。

### 4.3 样本归属与当前 priority

固定 Q 的物理存储唯一归属及反向样本列表；同时明确 P_Q(t) 使用闭三角形内样本还是仅使用其唯一归属样本，二者在共享边上不等价，不能由容器实现偶然决定。

推荐保留闭面评价语义：样本误差按当前曲面求一次，共享边/顶点样本向实际关联面的摘要贡献。需要把这些贡献数单列，固定度数界下再化简复杂度；不能为得到 O(N+|Q|) 而漏掉边界面的 urgency。唯一存储归属服务于局部取样，不自动限制证书的几何覆盖域。

列出初建归属、仅高度变化、连接变化、相机变化四种情况的“归属是否变化/误差是否失效/处理哪些样本/代价”。本阶段只定义支持和操作计数；GMP-02 验证修复规则。正常路径禁止每面全扫 Q，独立诊断允许全扫但另计成本。

### 4.4 共同 donor pool 与空预算账本

回收池由当前内部点和一个**不依赖回收后端求解结果**的固定代理次序形成；建议以当前邻域紧迫性摘要和稳定中心身份排序。三价与一般回收看到相同有序中心列表，后端不同之处仅是可实现的回收方案/证据。低代理值不被宣称等于低实际 damage。

先对所有主需求完成共同接收认证，再按同一优先级建立预算基准，明确哪些进入 `D_need`。推荐首版采用**预编号的空额度**：按共同顺序向前若干合格需求分配初始余额，每个名额对应 +2；这些需求失败时额度本批不转让，下一批重新分配。这样同一快照的 `D_need` 不受后端执行成败影响；代价是可能少用预算，应记录未用额度及原因，不能归因于回收能力不足。

如果选择允许本批额度回流的版本，契约必须另给共同分母定义、实际流转与无回收提交的对应；不能只写“余额足够就直接细分”而破坏后端配对。本阶段只定一套规则，不并行维护两套主策略。

共享预算、输出槽位和临时内存由规划账本统一预留；失败尝试不泄漏额度，已成功预留不被低优先级需求抢占。无需定义分配器实现；需要明确分配前后责任及实际未用预算。

### 4.5 预留、停止与有限续接规格

给出结构化伪代码：完整需求 → 共同接收证据/预算基准 → 逐需求按有限次序找交换 → 原子预留成功或写失败原因 → 封闭批次。将认证、池查询、冲突查询和资源预留分别列为可计费操作，禁止把它们都藏入无费用的 `FindBestExchange`。

正常停止包括完整顺序扫描结束、没有可接受事务；研究配额用尽则为不完整/上限停止，不等于局部最优。单个失败只暂缓该需求，不永久屏蔽它；下一快照依赖的连接/高度/视图版本改变时须允许重新评价。

列出 `StateEffects` 的逻辑类别、输入依赖、下一轮重算支持和数据所有者：当前面/边/顶点、资格、P、证书、样本归属、预算、脏输出。这里只形成续接义务清单；R/W 组合、共享归约和完整修复正确性留 GMP-02，不声称已实现可持续状态。

## 5. 实施顺序与验证

1. 建立契约正文和定义表，引用已有引理，逐项列出本阶段选择与失败语义。
2. 确定有限提案目录、P/G/C/E、Q 边界和参数表；先核查形状/深度反例，不采集自然数据。
3. 写共同预算分母与七步预留伪代码，固定 A 动态串行、B 批次串行、C 批次并行、D Classic/DOD 四类参考及完整计费边界。A 可局部维护，不能每步强制全量重建。
4. 按下表手工演算，保留初始表、每步观察、预留/回滚、结果和原因。发现矛盾先改规则/记录选择，不新增运行设施。
5. 按验收清单自审，填写本规划实现结果并同步索引；通过才进入 GMP-02 小规划。

| 最小检查 | 必须回答的问题 |
| --- | --- |
| A(10) 产生 C(9.5)，已有 B(9) | 快照预留为什么可以选 A/B，动态参考为什么下一步选 C；不得写为严格等价 |
| 两接收阈值 5/10、两回收代价 1/7 | 顺序贪心可能少兑现，为什么不声称最大匹配；与原有反例单位/η 对齐 |
| +2 空额度仅一个，先获额度者失败 | 共同 `D_need`、剩余额度、后端实际提交和未用预算如何记录 |
| 高优先级请求不可认证或 donor 已预留 | 失败继续、旧预留不被抢占；没有候选出生于本批应用结果 |
| 样本在公共边/旧点，随后只改高度或改变相机 | 单一存储归属不漏 priority/证书贡献；归属与误差失效分别解释 |
| 45°/45°/90° 输入与角度约束 | 面内及共享边类别的能力差异；不能为形状无解伪造自由高度收益 |
| 一个完整 ±2 已知几何交换 | 复用 CR-04 几何证据，从需求/G/C 到资源预留逐步追踪；高度解析例不冒充自然透视像素实验 |

验证只使用已有解析结果与本阶段手算，不复跑旧 Python、Lean、CTest 或两图形后端。若发现必须新增可运行求解器才能回答语义问题，停止并报告缺口，避免提前进入 GMP-02/03。

## 6. 性能与验收边界

纯文档阶段没有运行时版本差异，因此不运行性能基准，不伪造“实现前后无退化”。验收成本表必须完整包含候选扫描、样本及共享边贡献、提案认证/拟合、顺序预留、局部状态修复和输出；初建/复制/全扫独立验证另列，原型性能为未验证。

通过条件：配置表没有影响结果的未决项；有限目录与搜索/预算规则确定；四层分母一致且没有把未知写成不可行；上述手算无矛盾；完整支持/数值计算等尚待 GMP-02 的证明义务被准确列出，没有当成已证明结论。

停止条件：只能靠运行 Legacy 取得需求/目标，有限目录无法在声明条件下定义，或预算/续接规则必须引用未定义的中间状态。记录具体缺口，不宣称整个研究方向不成立，不自动增加原语或一般性理论分支。
