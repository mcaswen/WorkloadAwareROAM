## 1. 背景、目标与已有证据

依据：[FER-02 总报告](../../research/experiment_infrastructure/fer_02_overall_results.md)、[12项问题及派生数据](../../research/experiment_infrastructure/fer_02_validation_questions.md)、[PQ-05结果](../../research/cpu_refinement/pq_05_flip_recovery_results.md)、[GWR既有规划](greedy_transactional_work_reduction_plan.md)、[平台接入规划](transactional_platform_integration_plan.md)、[CBT共同实验规划](../experiment_infrastructure/cbt_experiment_infrastructure_major_plan.md)。

FER-02已建立真实平台、持续执行、有限同任务多核收益与四算法共同实验。当前阻塞项分属不同层：

- Peking50/100/200k转向采样Emax均为1.996557px，卡在同一边界见证；增加预算改善分布但不解除最大点。峡谷、山地还存在更广泛的逐点退化。
- Peking200k暖CPU约501.469ms，其中reservation约432.271ms；三重复单次峰值约3.5秒。前缀、池宽、批宽与实际N同时变化，尚不能把它归为N的单变量复杂度。
- 山脊、山地的大头主要在发现/认证和视图更新；大量无拓扑事务机会仍有明显成本。预留优化不能替它们解决问题。
- 9个CBT质量点存在覆盖歧义；DOD既有工程性能变化原因仍OPEN；实际图像还有法线/面片明暗问题。三者必须独立归因。

总体研究目标保持：**在预先声明的持续质量要求下，争取实际50k及以上代表负载的完整CPU成本优于竞争性DOD，并准确解释相对Classic/DOD/CBT的质量、成本和适用范围。** 50k上限不等于50k实际活动面数；不承诺所有输入胜出或特定加速倍数。

本规划要交付的是可审计结论与有限有效改进。审计完成、修复成立、性能改善、达到竞争目标分别标记，不能统称一个PASS。

## 2. 范围与非目标

### 2.1 纳入范围

1. 持续质量来源、候选流失、局部恢复与预算利用的联合审计；由证据支持的有限修复。
2. 固定质量契约后的reservation工作削减、规模因素分析、无事务帧成本削减。
3. 同任务多核、完整成本、峰值、冷启动及条件性的真实时间恢复验证。
4. 三项独立审计：CBT质量有效性、DOD参考成本、实际画面属性。
5. 统一的质量—数量—成本归因报告；原始数据、失败、无效点和历史报告保留。

### 2.2 不自动纳入

- 新GPU算法、CBT算法研究、渲染后端统一或uploader重构。
- 无证据的2-ring、多点任意remeshing、扩大几何操作目录、放松最小角或重新放开旧点高度。
- 修改前缀/预算/阈值/恢复轮数来替代质量原因定位；用更少有效工作制造性能收益。
- 通用事务框架、新线程池、通用profiler平台或旧Transactional代码的全量风格重排。
- 500k/1M矩阵、寻找有利新地形、全后端全CTest或每阶段重复完整FER-02。
- 宣称优化空间耗尽、算法不可并行、CPU实际时间达到理论下界或几何误差有连续曲面严格保证。

QPC-01之前不预选质量修复原语。特别是外边界操作若需要净+1面，而现有普通细分/回收按±2计费，属于需要重新明确预算与事务类型的关键设计，不能作为普通边界补丁直接加入。

## 5. 目标架构、数据流与所有权

```text
冻结资产/相机/算法政策/旧版本
          ↓
独立研究编排（runner、有限probe、离线归约）
          ├─ 正常性能运行：现有公共LOD入口
          └─ 诊断运行：只读观察、实际mesh、有限反事实
                               ↓
Transactional：SetView → snapshot候选/提案/认证
                         → 顺序reservation → CertifiedBatch
                         → topology/sample/mesh准备 → 统一发布 → Pending消费
                               ↓
独立质量评价＋进程统计＋视觉审阅 → 阶段报告/决策

Classic/DOD、CBT参考 ──各自的适用执行与证据边界──→ 同一分析层
```

依赖保持 `experiment → algorithms`、`benchmark/app → 公共LOD接口`、`render → RenderPacket`。生产算法不依赖experiment、文件输出、质量评价器、perf控制脚本或未来相机。共同分析层不硬编码QPC样本；具体研究协议调用共同工具。

### 5.1 质量证据

见证/误差簇记录绑定source/Q/mesh/pose/projection身份；区分当前可见误差、固定未来投影和世界高度。候选流失记录first blocking reason、稳定身份、snapshot generation、rank及预算/资源状态。

有限反事实仅在私有数据上运行，不写回生产State。质量修复输出仍是已有Proposal/CertifiedBatch和完整续接状态，不能只生成一个最终mesh绕过owner、priority、dirty范围和Pending。

### 5.2 预留表示候选

首选待验证机制是**批内资源索引**，不改变贪心控制器。获批事务的读写集合分别聚合为 `R_used`、`W_used`；候选只有在以下条件成立时才可预留：

```text
W_candidate ∩ (R_used ∪ W_used) = ∅
R_candidate ∩ W_used = ∅
```

这与现有逐个reserved事务的读写冲突判定对应；receiver/donor内部冲突、质量接受、donor reuse、命名额度与no-reflow仍单独遵守。查询可分别遍历receiver/donor足迹，避免为了查询先复制联合集合。

资源索引只属于一次Plan，获准后才写入，批结束销毁；拒绝、异常不得留下半预留。共享读允许，读写/写写拒绝。先采用可审计的集合/索引实现，构建、插入、清理和峰值内存完整计费；不先引入并发预留、通用锁管理或跨帧资源缓存。

新机制须以当前暴力Conflict为独立oracle，核对相同proposal序列下的选择、理由类别和最终状态；若第一冲突来源是观察契约，也需保留或明确诊断差异。它是条件候选，不预支O(f)实测或完整时间收益。

### 5.3 重复失败与持久证据

优先复用现有 `InvalidatedRoots/InvalidatedDonors`、ProposalEvidence和样本修复信息。若QPC-06需要新增缓存，必须先列完整依赖：topology、view、quality policy、预算与资源代际；给出owner、容量、失效support和重用前提。

structural failure可以与view-dependent failure有不同生命周期，但不能用一个bool跨视图缓存所有失败。批内冲突结果原则上不跨批复用。无法给完整失效依据时保留现行计算，不能用少做合法查询换速度。

### QPC-01：质量来源与恢复阻塞

**目标/范围。** 联合回答V01/V02/V08，先诊断，不改生产选择、原语、高度、角度或阈值。

**独立实验。** 复用24个T–DOD有效配对及locations；先Peking50k边界点，比较200k同点与局部连接，再看峡谷48、山地48/95。以事先写定的连通规则选择最大超额簇/最大样本簇，避免仅挑能修的点。现有证据不足才补一次定向追踪；固定未来view不参与选择。

**实现归属。** 参数化现有Provenance/RecoveryAudit与薄probe，增加必要first-reason/identity/version输出；不得将历史frame8或新见证UV写入生产分支。

**验收。** 给每个目标形成“种子已有/事务新增→是否进入priority/prefix→proposal/认证→预算/冲突→执行/进展”的链；UNKNOWN、上限退出与数学不可行分开。核对诊断关闭时原批次/mesh/工作量不变；必要默认路径短性能对照，纯离线归约则计离线成本。

## 8. 每个小阶段必须独立闭环

大规划确认后，执行每个小阶段仍必须遵守下面的顺序，不能拿本表代替小规划，也不能把阶段验收推迟到09：

1. **独立规划。** 阅读当时规范、上游结果和相关源码；写清问题/假设、文件归属、Reuse/Extend/Create、接口、冻结输入、预期工作量、正确性/质量/性能验收、资源上限与退出。内容应足以让下一位Agent执行，不能只有待办标题。
2. **独立实验与修改前基线。** 先保存源码/程序/配置身份及当前输出。复用有效旧数据；新采样必须有判别目的和计费边界。诊断先于依赖该诊断的实现，不先假定原因再选有利实验。
3. **独立实现。** 仅处理本阶段已确认机制，必要时先做最小反事实/私有原型。诊断型阶段的实现可以是工具、归约和证据，不强制修改生产算法。重要边界变化先更新设计并Review。
4. **独立验收。** 同条件前后对照、逻辑/质量/续接/性能及必要视觉检查；分别报告PASS、有限成立、No-Go或OPEN。没有实现变化的阶段不为形式要求重跑无关生产基准，记录离线新增成本与复用依据。
5. **回填与架构审查。** 小规划实现结果、research报告、实际代码facts（有代码变化时）、按Critical/Major/Minor组织的review，以及本大规划状态同时更新。审查重复职责、依赖方向、生命周期、诊断关闭开销和规划偏离。
6. **独立提交与用户验收。** 当前任务获得实施/逐阶段提交授权后，完成一个就提交一个，向用户报告完成项、结果、限制及提交身份；停在当前阶段等待验收和继续指示，不自行编写或实施下一小阶段。提交标题沿`feat/fix/update/chore: 中文内容`，正文只写修改和影响，不写测试通过。原始大文件进入忽略目录，精简数据/脚本/报告保留来源，不留悬空产物。

## 9. 实验、验收和成本契约

### 9.1 输入与证据冻结

FER-02作为历史问题基线保持只读；新阶段使用独立输出目录和policy/evaluator版本。记录资产原始samples、尺度、深度、视口、Q、相机、参考规则、seed、预算、prefix/donor、线程、诊断集合、编译/硬件/后端/驱动和二进制身份。

Peking优先50k与200k既有路线；100k用于解释规模，按需要复用/补测。峡谷/山地/山脊依各自问题选有限输入。诊断见证由已有证据预定，不在新结果出来后挑换。所有新失败、超时和未知保留，不补一个更容易的输入替代。

命令编排沿WSL Ubuntu；Windows平台运行仍调用同一已冻结原生程序，不把Linux核心时间与Windows平台时间直接拼接。环境变化时需匹配前后基线。性能测量期间不并行构建、离线作图或其他性能任务。

### 9.2 正确性与质量

- topology合法、hard budget、固定旧点和声明shape invariant继续为硬约束；未来view与独立evaluator不提供生产作弊信息。
- 等价性能修改固定proposal/选择/预算/续接/实际输出；质量修复允许声明的行为变化，采用独立质量评价，不能继续标为同任务提速。
- Primary reference保持raw height samples＋bilinear；Emax sampled、RMS参数域等权、Hmax全域、Dmax逐点。质量无效点不填0、不用于排名；必要可见域与投影身份核对。
- 不将0.1/.25/.5/1px称视觉不可感知值。QPC-01提出可审核的质量操作点与目标，QPC-04修改前冻结具体验收；未选定允许退化契约前，只报告各操作点是否满足，不能自选最宽一档宣布目标通过。
- 连续质量证据须覆盖目标局部、其他冻结关键视图与后续恢复；全局Hmax不变、返回Emax下降不能替代同点几何恢复。四帧质量不推广成全轨迹严格上界。

### 9.3 性能与复杂度

完整CPU含view、discovery、proposal/认证、reservation、准备/发布、samples/mesh续接；初始化、最终销毁、upload和帧包络分别明确，不移出窗口隐藏成本。记录均值/中位数、P95/最大值和原进程值；小样本尾分位只作描述。

开发快验默认每配置一组独立进程前后对照，短序列、明确预计耗时；正式统计另行预注册，不机械复制FER矩阵。沿开发规范§7.3用`max(0.05ms, 5%×基线, 已知波动)`筛查工程退化，具体风险才至多补一次定向复测。它不是性能论文显著性门槛，也不是质量门槛。

账本按N、q、关联a、prefix r、donor m、批准b、足迹f、证书样本s分解；记录配对/资源查询/样本触达/分配与空间。r/m变参会改变决策，须单列。固定degree不代表s、q或完整事务成本有常数界；源码上界不等于实测增长率。

正常性能关闭详细诊断、full audit、mesh全量读回和perf/Tracy；必要公共证据/hash的计时外缓存影响要说明。诊断与正常输出/模式等价需核查，新增账本自身开销单列。GPU录制、GPU计算、绘制、代次尾部缺测与CPU更新不混成一个计时量。

### 9.4 验证规模与停止

每小规划明确最小充分测试及复用结果，不全跑CTest/所有后端；共享CPU逻辑默认一个适用后端，确实改变后端资源/生命周期再增加覆盖。原生正常进程默认沿FER的180秒/8GiB限制、独立质量每帧180秒；特定离线诊断在小规划冻结更适用的上限，触限记录UNKNOWN并停止，不自动加资源追正结果。

纯规划阶段只核对覆盖、依赖、文件路径与文档一致性，不构建或运行算法。每个代码/工具阶段必须有自身性能对照；性能问题按对应review单列原因、承接或撤回，不用新退化版本覆盖历史基线。

## 10. 类型化门禁与退出机制

| 门禁 | 通过含义 | 未通过后的边界 |
|---|---|---|
| 参考有效性 | 比较的mesh/质量/计时来源明确 | 受影响比较保留空值/限制，其他独立调查可继续 |
| 质量原因 | 来源与恢复流失位置可追溯 | 不实施针对猜测的质量修改 |
| 有限质量修复 | 冻结操作点、结构/预算/续接及成本满足声明 | 撤回或明确受限政策；不称持续质量已解决 |
| 等价工作削减 | 相同决策/结果下确实减少目标work | 撤回候选，不用改变需求掩盖失败 |
| 完整执行可行性 | 完整时间、尾部、初始化与资源满足所声明使用范围 | 缩小适用范围或停止性能候选，不单靠局部speedup续期 |
| 竞争性证据 | 质量与实际N条件明确、竞争性参考下有优势 | 只报告architecture/characterization或部分Pareto价值 |
| 视觉验收 | 实际图像、属性更新与声明政策一致 | 不用几何指标代替画面结论；用户签收单列 |

总规划允许提前停止：质量修复不能以有限机制成立；合理质量约束下事务机会/性能价值消失；预留替代没有减少主要工作；新增维护/空间抵消收益；参考无法支持目标比较。停止依据必须对应冻结范围，不证明所有Transactional算法无价值。

相反，已确认的Peking50/100k成本优势也不能抵消200k或转向质量失败。不沿用旧GWR的5×距离线充当本轮“优于DOD”标准，不把“还有潜力”当无期限继续理由。

## 11. 关键决策、风险与待确认边界

| 决策/风险 | 本规划处理 |
|---|---|
| 质量改变后旧性能工作负载失效 | 04冻结新政策，05/06重新记账；FER旧数字只作问题基线 |
| 边界残差可能需要新预算粒度 | 01先证据；04如涉及事务/预算语义需专门设计Review，不预授权 |
| 聚合资源索引漏掉读写依赖 | 暴力Conflict oracle＋分支/批次/续接对照；不并发发布共享容器 |
| 失败缓存过期导致漏掉候选 | 完整依赖revision/失效证明；不满足则不实现 |
| CBT评价器改动改变所有算法质量口径 | 新评价版本，受影响双方重评；历史表保留 |
| DOD性能原因仍不明 | 报告竞争结论受限；不通过放慢或修改参考选择策略制造优势 |
| 同预算、同N和同质量混淆 | 分别报告cap、actual N、质量操作点和预算利用；CBT容量不当hard cap |
| 小阶段越写越大 | 每阶段最多一个主要机制，追加独立研究需Review，不以补指标扩大成新平台 |

当前可供Review的架构决定是：生产状态与诊断隔离；质量先定位再有限修复；性能阶段保持既定质量/选择语义；资源索引归批内资源组件；三项参考/视觉审计独立闭环；共用实验基础设施不另造平台。

仍须由后续证据决定的内容是具体质量修复机制、允许退化操作点、CBT歧义修正规则、DOD回归原因及缓存依赖集合。这些不是默认已解决的前提；各依赖实现必须在相应小规划冻结后才可开始。
