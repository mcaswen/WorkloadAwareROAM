## 1. 研究目标与04实施后的事实

依据：[FER-02总报告](../../research/experiment_infrastructure/fer_02_overall_results.md)、[问题清单](../../research/experiment_infrastructure/fer_02_validation_questions.md)、[平台接入规划](transactional_platform_integration_plan.md)、[GWR规划](greedy_transactional_work_reduction_plan.md)、[CBT共同实验规划](../experiment_infrastructure/cbt_experiment_infrastructure_major_plan.md)。

研究主线仍为全局优先级驱动、分阶段、事务化、面向多核CPU的数据组织与执行。目标是在预先声明的持续质量要求下，争取实际50k及以上代表负载的完整CPU成本优于有竞争力的DOD。预算上限不等于实际活动面数；不承诺所有输入胜出，不把较少有效更新称为同任务加速。

### 1.1 QPC-04结账：能力、损伤控制、恢复与成本分开

| 阶段 | 已建立的证据 | 未建立的结论/后续归属 |

这条链不是逐轮逼近一个已证明可行的修复：它表明当前请求、旧Fit与新接受条件存在目标错配，而当前目录与约束也有真实恢复边界。损伤非增允许停滞，正势能进展也不保证最大误差下降。04已有成果保留，但不再不断增加04后缀来容纳所有性能问题。

两组性能倍数的比较政策、状态和采样不同，**不能将04D与04F倍数相乘，宣称已测得累计退化**。04F暖完整CPU分别为：Peking 104.241→103.046ms，Sierra 33.161→95.838ms，Canyon 41.708→83.595ms；它们是单进程历史快验，不是同质量速度排名。

### 1.2 当前未决事项

- 持续恢复未通过。既有高误差可能保留，也可能在旧质量政策下新增退化；不能因安全拒绝或返回视图误差下降宣布恢复。
- 新政策额外成本主要在接收/认证；预留时间净下降，不能直接用旧FER的预留占比解释它。
- 原FER的Peking200k预留仍是独立大负载风险：完整暖CPU约501.469ms、预留约432.271ms；这些不是新政策当前200k实测。
- CBT的9个质量无效点、DOD参考竞争力、实际法线/属性和用户视觉签收仍分别未决，不随04结账自动通过。

## 2. 策略分层、选择与回退

### 2.1 明确定义“旧策略”，不使用含混A/B

| 名称 | 具体语义与来源 | 当前角色 |
|---|---|---|
| 原排序参照C | `legacy + composite`；对应04D的A，保持该组已冻结其他开关 | 用于判断误差优先排序本身的收益/代价，不与04F的A混淆 |
| 旧质量对照L | `legacy + error-first`；对应04F的A及04D的B | 新质量政策的直接回退对照，也是后续可选择的性能研究基线 |
| 新质量候选P | `pointwise-target + error-first`；对应04F的B，`E*=0.5px`、`H*=HeightScale/256` | 受限实验候选；不是必须保住的最终方案，不准默认晋升 |

这三条自然对照均固定存活点高度、原翻边能力、相同预算/前缀/源与相机；Peking/Canyon边界细分开启、Sierra关闭，这是历史冻结输入，不是可在后测任意更换的设置。C/L/P仍可能演化成不同网格、面数及事务量，跨政策只报告质量—实际N—完整成本，不称同任务加速。

源码默认是 `Legacy/Composite`，但 `TransactionalLodSettings`与核心 `Configuration` 的 `PreserveSurvivingHeights` 默认值仍为false。**“恢复默认设置”不是本规划认可的回退方式。** 后续实验必须显式写出 `heightPolicy=immutable`、排序、质量政策、翻边、边界等全部设置，不能回到PQ-01之前的自由旧点拟合。

### 2.2 当前选择：撤销新策略的必选地位

1. P保持显式实验候选，保留源码、抽象证明、只读审计与历史数据；不删除成果，也不把它升级为生产推荐。
2. L作为明确回退对照保留。其已知离屏损伤和恢复限制继续列出，**回退不是质量修复通过**。
3. C保留用于单独评价排序政策。若需要进一步退回原排序，必须登记独立政策分支，不能同时关掉边界/翻边/固定旧点并把时间变化归给一个开关。
4. 06A只允许一轮有限的新认证等价降本，用来判断新义务中的重复成本；不是为P无限续期。也可依据已有质量需求判断直接不做P专属优化，选择L继续有限执行成本研究。
5. 改Fit、放宽逐点约束或改变恢复原语仍属于QPC-04的算法决策，需要具体新机制与独立小规划；不因06性能实验无收益而自动开启。

### 2.3 保留、回退与停止规则

| 观察/条件 | 决定及准确含义 |
|---|---|
| 同政策优化改变接受理由、批次或公开曲面 | 撤回该优化；不是通过放宽数值/质量获得速度 |
| 06A未达到冻结的工程目标，或降低内核费用但完整移动段无有意义收益 | 结束P专属性能修复，不自动追加数值核/线程/缓存候选；后续以L为回退性能对照 |
| P降本有效，但仍无满足任务要求的持续恢复 | 只记“认证降本”，P仍不成为最终质量策略；不因更快而宣称质量通过 |
| L已能满足未来明确声明的独立质量要求，而P成本明显更高、没有任务所需的附加收益 | 采用L，不为更强但非必需的逐点契约继续支付成本 |
| 应用明确要求P的逐点损伤保证，而L不满足 | 不允许静默改用L接受原来被拒的事务；P不可用时，该应用范围仍阻断 |
| C/L/P都不满足冻结质量要求 | 仅允许带限制的执行/成本表征，停止预设“高质量且快于DOD已可实现”；不挑更宽阈值重新签收 |
| 只有相对DOD收益、实际N或质量比较口径未明确 | 保留未知，先完成03及相应质量评价，不据速度单项决定政策 |

当前还没有足够证据签发L或P的完整持续质量合格结论。06A的25%认证/10%完整移动段目标只是有限工程收益门槛，不是P晋升或论文竞争力标准；正式质量容差须在新政策比较采样前独立冻结，不能事后选最宽操作点。

06F已实施的有限补充：成功接受、实际提案、批次及续接仍必须一致；仅允许提示检查先发现一个同样足以否决提案的高度损伤，使失败诊断中的首个理由不同。提示拒绝必须由当前输入重证，并在诊断遍重放原认证确认其也拒绝；原理由与提示理由分列。该补充不追改06A～06E的原理由等价要求，不允许更改形状失败、翻边资格或用触限差异签发等价性能收益。

**回退执行方式。** 后续实施若决定P→L，应建立新的显式运行配置与政策身份，从相同冻结seed重新开始，恢复完整旧质量语义，包括请求资格及接收/捐赠接受规则。不能仅关闭证书而保留其他新语义，不能在P已经演化的状态上热切换来取得所谓配对基线，不能逐提案遇到拒绝就改走旧政策。运行时设置变更沿现有Reset边界；原始日志、失败与程序身份保留。这里是配置级研究回退，不是Git回滚整个QPC-04实现。

## 4. 架构事实与职责边界

规划依据包括[开发规范](../../standards/development_guidelines.md)、[规划规范](../plan_guideline.md)、[审查规范](../../reviews/review_guideline.md)、[04F事实](../../codebase/cpu_refinement/qpc_04f_target_quality_facts.md)、[04G事实](../../codebase/cpu_refinement/qpc_04g_proposal_feasibility_facts.md)与[GWR-04事实](../../codebase/cpu_refinement/gwr_04_lazy_evidence_facts.md)。本轮另核对生产配置默认值、Samples请求入口、PointwiseQuality、Reservation、Pipeline及原04F配置；不是重新建设一套算法。

| 组件 | Reuse / Extend / Create判断 | 责任边界 |
|---|---|---|
| Pipeline/State/Samples/Mesh | Reuse，必要局部Extend | 持续状态、视图、准备/发布与Pending；不读研究结果或未来视图 |
| Proposals/Certification/FlipRecovery | Reuse；算法变更归04 | 目录、拟合、几何可行性与恢复；性能阶段不改目标 |
| QualityEvaluation/PointwiseQuality | 06A局部Extend | 数值事实与双域损伤/进展认证；不得减少支持或跳过精确义务 |
| QualitySampleEvidence | 06A条件Create | 单样本单域取证复用，局部生命周期；不持久复制全Q |
| Reservation/Conflict | 05 Extend | 全局顺序、预算、捐赠唯一与冲突；不堆数值认证 |
| ResourceReservations | 05条件Create | 单批资源占用索引；不改变选择或并行化预留 |
| IdlePlanCache/Pipeline | 06B Create/Extend，已实施 | 同实例同代次完整空结果复用；不保存成功提案、不跨视图/拓扑变化复用 |
| 实验追溯、WorkLedger、perf/Tracy | Reuse，缺口才Extend | 只读取证，正常与诊断分离，不让统计改变生产决策 |
| 共同runner/evaluator/report | Reuse | 来源、质量/数量/成本对照；算法不依赖实验层 |

依赖保持 `experiment → algorithms`、`benchmark/app → 公共LOD接口`、`render → RenderPacket`。数值取证下层不反向依赖高层认证；渲染层不负责修复LOD。新代码按DOD风格，避免紧凑多职责控制器。

## 5. 数据流、复用与关键证明义务

```text
冻结政策C/L/P、seed、配置和程序身份
→ Samples：请求资格 / 全局前缀
→ Proposals：原目录与Fit
→ 按已声明政策认证
→ 顺序预算/冲突预留
→ 准备拓扑、样本与网格
→ 发布 / Pending / 下一轮
→ 独立质量、正常性能、诊断账本分别归约
```

### 5.1 认证内部复用（06A）

局部取证上下文只拥有单次调用的坐标、参考/投影结果与惰性精确值。输入绑定状态实例、代次、Q、配置、样本和表示域；不同提案/线程不共享可变上下文。保持闭支持、稳定面序、区间求值顺序、两个域、拒绝理由与发布前绑定。

快速定向累计如需改写，应证明有限binary64值的直接整数结果与原有理数实现完全相等，保留精确分支作为oracle；不能用更宽容的epsilon换速度。这些属于等价求值，不是新的质量理论。详细文件/公式/消融见06A小规划。

### 5.2 重复失败（06B，条件）

先列几何、源/Q、视图、质量政策、预算/资源、槽位/逻辑身份等完整依赖。相同理由字符串或相同最终mesh哈希不足以证明输入相同。结构失败与视图相关失败分开；批内冲突原则上不跨批缓存。

优先复用现有失效列表。不满足完整失效证据就保持重算；不先建全状态副本或一般缓存框架。重复失败复用只减少重复求值，不会让没有合法提案的区域恢复，必须另报停滞状态。

等价优化要求请求、目录顺序、实际提案、接受/拒绝与预算、批次、公开曲面/续接一致；允许实际工作计数下降，不允许削减任务制造加速。跨政策比较允许轨迹不同，但必须保留所有质量与工作分母，不能用新的较差质量换时间后说性能问题已修复。

回退到L不再主张P的逐点损伤保证，旧坏例保留。若实际任务需要P保证，则回退只能作为对照、不能作为合格交付。未来视图和独立评价器不得进入生产选择。四个质量帧、Hmax不变或返回Emax下降不证明全轨迹恢复，用户视觉签收也不由Agent代签。

### 9.3 成本与统计

完整CPU含视图、发现、生成/认证、预留、拓扑/样本/网格准备发布及续接；初始化、最终析构、上传和帧包络单列。计数按N、q、关联a、前缀r、捐赠m、批准b、足迹f、证书样本s及精确位长分解。度有界不令样本工作为常数，源码上界不等于实测增长率。

正常性能关闭详细捕获、全审计、离线求解、perf/Tracy；原正常账本边界保持。任务墙钟和不当作总线程CPU时间或完整帧时间。开发默认每配置一组独立进程前后对照；仅具体风险时至多一次定向复测，采用开发规范7.3工程门槛，不追微秒、不复制正式重复矩阵。

降本既与当前同政策版本比较，也保留退化前政策参照。跨政策历史毫秒数只作定位，声称恢复到旧成本需同环境实测；不得把新慢版当唯一基线。正式统计以独立进程为单位另行冻结，不用内部重复假装显著性。

### 9.4 规模与退出

每小规划写明有限输入、预计耗时和配额。正常原生运行沿180秒/8GiB上限，特殊离线任务另冻；触限记未知/删失，不换容易输入。只跑相关测试，共享CPU改动默认一个后端，资源/后端接口改变才补覆盖。

纯规划只核对代码事实、政策表、路径、依赖与出口，不构建、跑性能或重绘不变曲面。质量候选没有可用性时可停止专属优化；不能用“还有潜力”无限续期。
