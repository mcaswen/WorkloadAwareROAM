# QPC-06D：接收根动态领取的同结果消融

## 1. 问题、目标与出口

06C表明P政策接收阶段占原生移动时间80.0%/66.8%；Linux接收阶段47.232/35.481ms中，最长连续块46.971/35.256ms。当前160根按8个连续块处理，每块20根，但认证工作不均。这里检验能否在逻辑工作不变时缩短该实现长尾，不主张降低几何认证工作量或语义必需span。

目标：同一快照每根仍执行相同目录、旧Fit、新认证、失败分支；最终按原全局前缀收集。质量、预算、前缀、捐赠方、预留、线程数和渲染接口均不变。只让先完成的任务领取下一根，避免人为等待整个固定区间。

保留门槛预先冻结为：两个P移动段接收均值至少下降15%、完整CPU均值至少下降10%；L不得出现超过工程噪声门槛的完整回退。所有正常成功输出与整数工作计数必须相同。无收益则撤回生产调用，保留证据；若单根已主导，记录其边界，不在本阶段追加数值/质量机制。有限单进程快验不代表正式统计。

## 3. 正确性与成本推导

令快照为S，原前缀根i的纯准备过程为`F_i(S)`，独占输出位置为i。前提是根间只读共享State/Samples，提案/游标/证书写入各自私有对象，账本由当前同步任务独占。原子`fetch_add(1, relaxed)`只决定唯一索引归属；输入发布与输出可见性由既有Dispatch/排空屏障保证，不依赖原子索引发布业务内存。

成功完成时，每个`i∈[0,r)`恰执行一次，因此输出数组仍为`(F_0(S),…,F_(r−1)(S))`。串行收集与预留未改，故最终批次/曲面/完整整数工作相同。浮点计时汇总和线程诊断可不同，不当作逻辑差异。所有先验须由直接源码核查、针对性测试和自然逐帧对照共同支持；没有把抽象推理称为新增Lean定理。

成本新增`O(r+p)`原子领取，局部账本仍O(p)，不创建r份map。几何/认证work不变。固定分块的`max_j Σ_{i∈C_j}T_i`改为根粒度动态领取；理想列表调度近似受`Σ_i T_i/p + max_i T_i`约束，但真实缓存、原子竞争、线程调度和计时侵入均须完整测量，不承诺达到该界。

串行和不超过一项路径调用原Run，避免无意义原子调度。多线程保留p个外层`gtp.task`，内部增加`gtp.item`及phase/index文本，仅Tracy开启时发生。计时包含派发、领取、原认证、同步、账本归并；原子初始化等极小外围仍在完整CPU边界内。

## 4. 配额、异常与生命周期

- 每个外层任务继续持有原WorkLedger，沿用Deadline/VisitLimit；join后原全批CheckLimit不能删除。正常成功时非负工作总量不变，因此不会因更细领取放行超额批次。
- 异常继续由同步执行器等待全部已派发任务结束后传播；没有任务可借用已销毁的索引/回调。事务准备失败不进入生产发布。多异常时不承诺哪一个逻辑根先报告，当前接口本就只保证排空后异常；失败诊断的已完成人口可随调度变化。
- 期限受真实时间影响，不要求超时帧与旧版本逐指令相同；不得把失败/限额帧计入同结果提速。正常自然输入必须没有超限。
- 原子领取不改变VisitLimit为每根额度；仍是每任务保护＋全批保护。专测“各局部均未超额，但总和超额”必须拒绝。
- 领取计数、任务账本只活在一次同步RunIndependent内；Reset、Pending、视图/拓扑代次规则不改。
