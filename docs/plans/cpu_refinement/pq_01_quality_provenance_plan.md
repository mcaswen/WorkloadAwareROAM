# PQ-01：持续质量来源追溯与存活点高度消融

2026-09-15；小规划，修改前版本 `01ecf96`。用户已授权本规划编写后自主实施、验证和审查，无需再次确认。一般性能优化暂停；实施授权最初不含 Git 提交；开发闭环后，用户于同日另行授权提交本阶段。

## 1. 问题与出口

TPI 的 Peking/50k 连续回放出现 66.081137px 最大误差，返回后仍为 31.125805px。首要目标是解释两个固定见证的几何来源及恢复阻塞，再验证仅冻结存活点高度是否改善同一轨迹。不是扩展平台或承诺质量修复成功。

依据：[开发规范](../../standards/development_guidelines.md)、[规划规范](../plan_guideline.md)、[TPI-05](tpi_05_platform_evidence_plan.md)、[TPI 事实](../../codebase/cpu_refinement/tpi_05_platform_evidence_facts.md)、[TPI 结果](../../research/cpu_refinement/tpi_platform_results_and_headroom.md)。已定向阅读公共适配/种子、提案/拟合/预留、样本/提交、平台回放、独立评价及测试构建。

出口分别记录：来源复现是否成立；具体退化原因；恢复阻塞层；高度消融质量/执行效果；默认路径兼容；同质量性能仍待什么证据。完成负结果及原因记录也构成本调查闭环，不把单帧接受定理写成已被反证。

## 2. 冻结输入和比较

- 原生 Windows/MSVC/OpenGL 为平台对照；所有命令由 Ubuntu WSL 编排。独立追溯程序使用同一 MSVC 核心、公共种子及相机公式，无图形时序主张。
- Peking 547²、尺度80/12、深度20、预算50000、细分/合并阈值 .25/.10、r=m160、8线程、1280×720、NO、原始双线性参考，HeightGuard 仍关闭。
- 24次更新为 `[14,14,14,15,16,18,22,26,30,34,38,42,46,50,54,58,14,14,14,14,14,14,14,14]`。一次当前视图 DOD 种子，不复制旧历史、不追加恢复轮次。实际约49999面。
- 固定见证 UV：`(0.96336996555328369,0.7967032790184021)`、`(0.020757021382451057,0.11965811997652054)`，来自既有离线评价。不能混用评价器与核心 Q 的样本编号。
- A：原有限局部拟合；B：存活点保持批前高度，仅新点沿用原一维拟合及最终认证。E/F/H 顺序与完整支持保持；H 不删目录项，但其旧中心不再是自由变量。回收重连仍允许，故 B 不是持续质量定理。
- B 不同时改成新点固定参考高度，不开启 HeightGuard。第二种策略不属于本轮必做项；若 B 失败，保留失败而非叠加策略直到通过。
- 独立全域评价只取既有关键帧0/2/15/16/23，报告实际 float 输出的 sampled Emax、Hmax、RMS、Dmax 与返回恢复。没有人为设定视觉可接受阈值，也不以全局最大值相同替代逐点比较。

## 4. 实施顺序与诊断契约

1. 保存修改前原生程序身份及副本。提取协议，先建立 A 的独立追溯，核对24帧实际网格哈希与既有平台输出；不一致先定位，禁止拿不同状态解释旧见证。
2. 两见证分别记录批前/批后高度、参考高度、当前视图误差与可见性、固定暴露/返回视图误差。原始几何和实际 float 输出分列；屏幕定义域无效写明，不能强制记零。
3. 对每个覆盖见证的已批准接收/回收提案，记录支持、面连接、旧/新顶点高度、自由变量、认证样本数、误差区间及接受阈值。两成员独立于共同批前状态评价，不通过依次执行给后者额外信息。
4. 逐帧定位覆盖见证的候选：全局优先值/排名、是否进入前缀、目录拒绝原因、是否为已批准根、是否有其他根的完整支持覆盖见证。必要时在单独诊断中重建对应提案并检查共同回收池，以区分认证、局部可行、冲突/回收复用和执行后进展；诊断成本单列，不改变正常选择。
5. 来源复现成立后实施 B。逐批检查存活点确实不改高，正常/导出/独立核心结果一致；新增夹具防止改成事后回写高度。随后仅跑同一 Peking 轨迹。
6. 汇总 A/B 的关键帧质量、实际交换、分母、配对/冲突、冷/静/动完整 CPU 成本及预留/上传。B 与 A 改变任务结果，不能把耗时比称为同任务并行加速。DOD 复用同平台冻结轨迹作质量参考，必要时一次正常重测只控制机器时差。

## 5. 最小验证、资源与停止

开发快验仅本次高度策略夹具、必要公共适配/协议检查和 Peking24帧。初始正常基线一进程；改后默认 A 一进程并核对身份；B 一进程；导出/追溯单独。默认路径出现实质退化时至多追加一次受影响对照，按开发规范7.3处理，不追微秒。构建与测量顺序执行，不与其他负载并发。

单进程上限180秒、8GiB，正常/追溯采集总上限20分钟，构建及离线质量计时分列。不得跑完整 CTest、更多平台、500k/1M、更多线程或更多自然场景。追溯程序中的全域定位/排名是诊断费用，不混入 CPU-ready；原生正常性能仍来自平台入口。

若两见证不能由当前原生核心重现，则关闭归因主张并记录身份/表示问题；不能猜测原因。若 B 的质量仍差，或有效事务近乎消失，按相应负结果结束。若质量明显改善且有事务，标记有限消融有利，仍不宣布所有视图保证或同质量胜过 DOD。默认算法仍保持 A，B 为显式消融入口。

## 7. 实现结果

已完成，2026-09-15。来源追溯和高度消融闭环，持续质量修复未完成；默认策略保持A，未提交Git。

### 7.1 实现与计划对照

- 完成共享只读相机协议、独立见证追溯、原生公共高度策略、H自由变量限制、定向夹具及汇总脚本。
- 追溯在冻结批次上读取，诊断全扫/额外认证不进入普通核心。补充freeVisibleSupport，定位新自由变量在可见约束中的非零系数数。
- native_run仅扩展可选argv，复用已有原生超时/内存/隐藏启动能力；文件表已同步。
- 审查删除After未使用mesh参数、修正注释和模式提示；没有改拟合器、预留算法、新点规则或HeightGuard。
- 计时所用程序保存在measured/；审查后源码清单与每次真实二进制身份分列。

### 7.2 核心发现

A的两次严重退化均来自H接收的新点：frame5/9的新点在27/3个可见认证样本中系数全部为0；原二维拟合取可行多边形顶点均值，把绝对高度选成6。旧中心仅小幅改高，不能把主要原因写成旧点高度大幅漂移。

q0暴露后排名很高，但后续目录全部shape_infeasible；q1先受预留冲突阻挡，返回时执行一次极小改善，然后同样受形状目录限制。原局部Q与独立评价模板不同，不能把覆盖面优先值低于独立见证误差直接当作缓存错误。

B相对DOD仍有frame15的2.320578px逐点超额，返回后为0.101125px。B返回期没有交换；质量改善不能解释成证明了恢复速率。冻结旧点还把H拟合切至原一维分支，不能把消融归因简化为“所有旧点调整均有害”。

### 7.4 验证与停止

- 高度策略夹具返回0；24批B全部存活顶点高度保持；初始/最终拓扑检查完成。
- A修改前后及历史TPI的24帧网格、决策和记录工作计数一致；独立A/B与平台对应输出一致。
- B正常/导出一致；五关键帧独立质量及Dmax完成，无缺失/无效几何。
- 默认性能42.916909→43.430074ms，+1.20%，未越过开发规范5%筛查门槛，不追加微小差值测试。
- 最终定向原生构建和Python入口检查完成；构建失误与修正日志保留。
- 原生采集约29.86秒，单进程配额未触发；未扩场景、后端、线程或完整CTest。

按照原停止条件，本调查以“有限消融有利、持续质量尚未修复”关闭，不再叠加策略。报告记录残余新见证，但未扩大来源追溯。一般性能优化继续暂停。
