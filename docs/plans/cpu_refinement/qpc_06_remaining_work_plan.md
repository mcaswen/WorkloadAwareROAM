## 3. 共同验证与交付

使用06F冻结可执行文件作首阶段参考，每个后继阶段以前一保留版本为参考。相同96帧比较`frames.csv`的逻辑字段、完整网格哈希与工作量，复用既有分析器的比较函数；不同输出立即停止，不用相似Emax替代。选择逐点、面证据、高度拒绝、源高和持续状态测试中的受影响子集，不跑全项目。完全同曲面时复用06F/04H视觉及质量证据，不伪造新视觉验收。

普通性能记录完整CPU、接收、视图、捐赠、样本修复，分移动/返回/静止的均值、中位和P95。小于规范7.3门槛的波动不扩测。需要诊断时用现有`--recovery-trace`、perf/Tracy，不新增通用profiler；诊断工作不混入普通时间。原始证据置`benchmark-output/cpu-refinement/qpc-06g`等忽略目录，精简JSON及完整命令身份进入报告数据目录。

推导记录等价表达式、生命周期、复杂度和失败尝试，声明纸面证明/有限检查，更新推导索引。报告必须把源码操作、工作计数、时间及因果限制连接起来。架构不改变Pipeline→Reservation→Certification→Evidence和Pipeline→Samples的方向。
