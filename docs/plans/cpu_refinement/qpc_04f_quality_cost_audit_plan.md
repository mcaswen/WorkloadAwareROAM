已阅读开发规范、规划规范、04F/04G规划与结果，扫描Reservation、Proposals、Certification、PointwiseQuality、QualityEvaluation、ProposalEvidence、Execution、Pipeline及RecoveryTrace。现有正常平台阶段时间和B诊断子阶段账本足以完成第一轮定位，缺少同快照交叉消融和细分函数计时的部分明确保留未知，不凭源码估计百分比。

## 3. 有限步骤与验收

1. 核对A/B配置和初始种子；B正常/诊断的几何哈希、面数、请求、执行及配对等逐帧一致。确认正常时间不含只读追溯和离线评价。
2. 按原前三机会暖机掩码计算完整时间、阶段净增量及事件分层；同时报告实际根数、成功接收、执行及样本访问。不能把全域请求数量等同于真正遍历的前缀数量。
3. 单独归约B诊断账本。明确旧认证、逐点认证和阶段墙钟的包含关系；任务墙钟和既不是串行时间也不是总CPU时间，不能与正常平台墙钟相加或直接相减预测加速。
4. 检查静止且无修改的后缀，量化重复费用和末帧目录失败。结合源码判断是否改变状态/视图，不能仅凭拒绝字符串推出跨帧缓存正确。
5. 审计两域支持、覆盖定位、参考重建、区间/有理运算和证书生命周期。每项区分已测组成本、代码确定工作、未测函数份额。
6. 报告明确修复方向及前提，交用户决定；不在调查期间改Fit、跳证书、增加失败缓存或恢复轮数。

验收为原始归约可复现、表格账目闭合、正常/诊断边界无混用、原因可定位。用已有216个B机会核对及聚合恒等式验证脚本，不新增镜像实现测试或全CTest。只读归约预计数秒、上限120秒；无生产代码修改，复用04F性能基线，不为文档重跑平台矩阵。记录新脚本实际处理时间，图表需实际目视核对。

## 4. 出口与实现结果

已完成[性能问题分析](../../reviews/cpu_refinement/qpc_04f_quality_cost_analysis.md)及可复现归约。24个原始输入文件登记SHA256，共同配置/种子一致，216个B正常/诊断机会逐帧离散核对；阶段净增量闭合。标准库归约约0.166s，复用已有绘图环境生成并目视检查一张四面板图，没有新增运行矩阵。

实际新增发现包括：Sierra实查根只增加3.4%、Canyon不变；新增证书与旧认证任务成本都显著；Canyon末端31个静止空批没有进入新增逐点认证，仍重复34,720项旧目录失败；快速质量路径也调用有理数/大整数，原回退比例不是全精确计算比例。性能结论仍为未修复，缺少同快照交叉消融及证书内部细分计时，不编造函数百分比。

未修改生产源码、接口或算法契约；性能基线复用04F，未重复平台/CTest。报告第10节记录实现自审与限制。此出口不代表性能问题已修复，不自动开始下一小阶段。2026-09-17，用户授权提交本轮调查产物，并准备性能修复阶段；修复方案另行规划，本调查不承担生产实现。
