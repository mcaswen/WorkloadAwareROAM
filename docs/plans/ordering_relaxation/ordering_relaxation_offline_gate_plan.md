## 1. 目标、范围与交付判定

### 1.1 要解决的问题

在同一冻结拓扑状态上，固定批次选择器、操作能力和资源规则，仅改变细分请求的优先级窗口，是否能以较小的独立几何误差变化获得更多可行独立工作；这些机会是否被预算利用率下降、长依赖闭包、串行维护或额外工作抵消。

首版具体研究的是 **保留严格头请求的有界排序松弛（head-preserving bounded relaxation）+ 不相交读写足迹独立模型（disjoint-footprint independence model）**。它没有覆盖先跳过头请求、可交换共享写或共享强制闭包去重。正结果说明这个保守子空间已存在机会；负结果最多否定当前模型和投入方案，不能否定一般 ordering relaxation 或 constrained bulk refinement。

本 Gate 先建立可信的单线程反事实执行和并行潜力模型，不实现新的多核拓扑提交器。有效并行潜力必须来自同一批次开始状态的资格、依赖与资源证据，不能来自单线程应用过程中新增的机会。

### 1.2 首版建议范围

1. 复用已冻结的轨迹 A、场景、输入重建及正确性验证。
2. 仅对 `SplitTopology` 中的细分根请求顺序进行松弛；合并完全按严格 `S` 执行，原合并/细分阶段先后、评分、资格、预算交换、迟滞和停止规则保持。状态因细分顺序产生变化后，`S` 在新状态上的合并决策可以相应变化，但规则不变。
3. 必要的强制细分属于根请求内部闭包，可以分析新节点创建；不再将当前“只能复用子节点且无需强制细分”的限制当作算法并行上限。
4. 由同一快照产生操作描述和保守读写足迹，构造批次，然后单线程确定性应用并验证。
5. 对最终输出网格运行独立离线质量评价，报告实际预算利用率、经验 Pareto 前沿与有条件的成本模型。
6. 保存单批次、单变体和完整尝试的来源、失败、排除与成本。

### 1.3 非目标

- 不更换原研究问题、评分函数、地形资产或默认 Classic/DOD 行为。
- 不实现 GPU/CBT 移植、OpenGL/D3D12 上传重构或新的渲染流程。
- 不放宽拓扑合法性、预算上限或旧 P4/P5 的等价断言。
- 不实现在线质量预算控制器、学习模型或完整连续轨迹稳定性研究。
- 不宣称视觉不可感知、连续域严格最大误差、全局最优前沿或实测多核加速。
- 不建设通用事务运行时、恢复服务、参数搜索平台或完整正式实验框架。
- 不研究合并排序松弛、跨阶段重排、两侧同时批处理或新预算交换策略；不恢复 PREP-06，也不因负结果自动扩大范围。

### 1.4 交付完成与研究继续分开

完整采集交付要求协议冻结、程序可重放、零松弛与原基线一致、正确性和采样可靠性有证据、已启动采集的输入与配置都有结果或明确失败状态，并形成可追溯报告。提前停止也可以形成完整的阶段交付：保存已得证据、停止原因、结论适用范围和未实施项；不要求先做完全部工具或取得完整 Pareto 图。

继续算法设计的建议必须同时考虑独立质量变化、实际预算利用率、可行独立工作和额外工作，并结合依赖关键路径、负载不均衡与成本敏感性；单独批宽增加不构成通过依据。没有有利区间、只有局部机会、或受实现/采样限制仍无法判断，均可完成 Gate 交付。任何结论都不自动授权改写研究主线或开始正式并行算法。

### 1.5 实施原则与阶段停止条件

**本大规划是工作范围上限，不是必须完成 GATE-01～05 的瀑布流程。** 用户本次要求优先快速验证问题，不以长期可维护性、抽象数量或基础设施完整度作为 Gate 的交付目标。保留正确性、信息隔离和可复核证据，允许固定输入、小型驱动、局部辅助函数和够用的报告格式。

每个小规划写清本阶段要回答的问题、最少实现、开发/运行投入上限和停止条件。先完成低成本证据检查，再决定是否建设剩余能力；触发停止条件时直接停止扩建并记录 `stopped_current_model`、`model_limited` 或 `evidence_incomplete`，不为“阶段完成”继续堆工具。恢复或扩大范围再由用户决定。

GATE-01 先验证少量真实闭包能否可靠描述；GATE-02 先做参考一致性校准；GATE-03 先跑小规模筛查。GATE-04/05 只有前面仍有值得验证的信号时才启动。依赖模型过于保守导致停止属于当前建模/投入边界，不自动等于研究假设被否证。

## 3. 拟冻结的实验契约

### 3.1 身份与比较单元

建议使用单一契约标识 `ordering-gate-v1`，在一次配置中写明松弛规则、选择器、足迹范围、粗计数口径、参考/采样和审计限制，并绑定源码/程序身份；第一版不建设多层协议版本注册。这里描述待实现的记录约定，不代表已有 schema。

一个逻辑输入由资产字节摘要、场景/相机身份、分辨率、来源阶段输入哈希和实现身份确定。一个变体由逻辑输入、松弛家族及参数、选批规则、操作模型和终止配置确定。一次进程运行单独记录 `RunId`。

每个变体从同一 `SplitTopology` 开始状态复制，真实更新自己的队列、候选、闭包与预算，应用结束后执行已有网格提交与必要收尾，导出独立几何；不能重排串行 trace 代替反事实状态演化。它是单阶段反事实结果，不称完整自主轨迹。阶段模型与包含其他阶段的模型分别标明覆盖范围，均只报告模型估计的执行收益。

### 3.2 第一版松弛家族

推荐第一版只实现 `priority-band`，归一化排名窗口记录为后续对照候选，不同时展开两套参数矩阵。

正松弛参数 `α∈(0,1]`；在 `S_j` 的严格控制器允许下一项为细分请求时，先按既有资格和比较器形成 `C(S_j)`，然后取：

\[
C_\alpha(S_j)=\{t\in C(S_j):P(t;S_j)\ge(1-\alpha)P_{\max}(S_j)\}.
\]

`α=0` 单独定义为严格控制器，不进行多成员选批；同分依旧使用 `SplitPriorityPrecedes` 的分数降序和 `PathId` 升序。正松弛允许考虑同分成员。分数统一来自冻结状态的既有评分；比较使用明确的提升精度和包含等号规则，不改写生产 `P`。

建议参数扫描为 `0, 0.001, 0.005, 0.01, 0.025, 0.05, 0.1, 0.25, 1`。这组数是待 Review 的工程扫描建议，不是质量阈值。非有限参数或分数直接拒绝；无候选按严格控制器停止；最高分非正时退到严格单步，不临时更换归一化公式。

每批记录候选总数、带内数量、检查数量、带宽对应分数范围、实际排名跨度和窗口占比。松弛参数不保证 `ΔE`、可行批宽或模型收益单调变化。

### 3.3 控制器、资格和终止

控制器在收敛入口保存原 `maximumIterations`，之后不得随每批重新计算。一个根请求计一个原迭代单位；其强制子操作不是额外根迭代。失败后的预算交换、队列清理和屏蔽沿用原控制流。

首先尊重 `S` 的下一步选择：优先合并或停止时不创建细分批次。严格头请求无法形成完整成功闭包时，执行真实严格单步，保留部分成功和失败后的预算语义；不把失败试算改成生产回滚。

首版为避免停滞，成功批次必须包含严格头请求，即 head-preserving relaxation。随后按既有比较器遍历带内成员，确定性地跳过冲突、未知足迹或联合预算不足项；不越过优先级带找更容易的候选。头闭包阻挡全部后续候选时，也不会尝试先处理后续成员；记录这一限制，不增加跳头主矩阵。

拟设每批最多检查 64 个带内根请求、接收 32 个根请求；二者都是独立于 `α` 的执行限制，记录截断原因。达到检查上限不声称已经分析整个优先级带，负结果不能外推到未分析成员。

应用过程中可以忽略新出现的更高优先级细分请求直到下一批，这正是排序松弛的对象；但每个根操作边界仍检查严格的优先合并、停止、失败和迭代限额。触发其中任一条件即终止当前计划，剩余成员撤销；已应用部分按串行执行记录，整批不能继续计作成功独立批次。不得利用新信息扩大成员或将自适应截出的前缀追认为预先成立的并行批次。

工具时间、内存或记录上限不属于算法收敛条件。被工具截断的结果标为 `resource_limited`，不是低质量但成功的 operating point。

### 3.4 分离排序松弛与依赖处理能力的对照

除 `α=0` 的严格串行参考外，增加独立配置 `strict-prefix`：使用与正松弛完全相同的闭包观测、资源模型和 64/32 限制，只从当前严格顺序的连续前缀选取成员；遇到第一个不满足条件的项即结束，不能先过滤再把不连续成员称为前缀。

该对照仍在单线程中验证计划。每个成员应用前，严格控制器的下一项必须正好是该成员；如果新细分候选、合并或停止插入，立即结束计划，原计划按串行处理并交回严格控制器，不扩大批次。完整结果和决策语义必须复现 `S`。

`strict-prefix` 只用于测量相同能力下、保留严格顺序的批处理潜力，不是新的松弛参数值，也不宣称已实现并行提交。正松弛相对于该对照的变化，才支持在所选模型内归因于排序放宽；仅优于原 P4 受限实现，不能作这种归因。

### 3.5 窗口与批次选择器分离

`C_λ(S_j)` 决定哪些候选允许考虑；`B_j=F(C_λ(S_j),S_j)` 决定从中选择哪些操作。首版固定第 3.3 节的确定性 greedy selector：包含严格头请求，按既有比较器检查后续带内候选，遇冲突跳过，达到固定容量结束。扫描 `α` 时不改变 `F`、操作模型或 64/32 限制；`strict-prefix` 是单独标识的严格顺序对照。

正式结果称为“当前选择器找到的可行批次”，不能把其宽度称为该松弛级别的最大并行度。只有负结果可能来自选择器而非已明确的头闭包冲突时，才使用有上限的小子集选择器审计：对相同带内候选子集，使用同一足迹与联合资源谓词搜索包含头请求的子集。分别比较批宽和按实际基础操作计的可行工作；不建设通用搜索器。如果全部已检查成员均与必选头请求冲突，直接保留证据即可，不为证明批宽为 1 再穷举。

审计必须报告子集身份、大小、greedy 在该子集上的结果、搜索是否完整以及两种目标下的差距。完整搜索最多给出该子集在声明模型下的最优值；它不证明完整窗口或真实算法的最大独立集合。发现更好集合后仍按第 4.5 节验证；验证失败时不能把它列为已证实可行潜力。搜索截断时只报告找到的更好可行解及未决差距。

该审计不读取质量结果，不选择新 `α`，不将更强集合写回主变体，也不重跑完整矩阵更换选择器。选择器确实低估潜力时如实形成限制或继续投入建议，不能把选择器失败直接解释为排序松弛无效。具体审计规模见第 8.3 节。

## 4. 快照批次与依赖模型

### 4.1 构造和应用分离

`BuildBatch(const S_j&, config) -> BatchPlan` 不修改来源。每个根请求从同一 `S_j` 的独立工作副本试算，使用共享生产操作逻辑形成必要闭包，不把前一请求的结果作为下一请求输入。

`ApplyBatch(state, immutablePlan) -> BatchApplication` 只消费已封闭成员及描述，固定按 `P`、`PathId` 顺序应用。批次携带输入身份、根成员、闭包、预留、读写足迹和拒绝原因；输入身份不符即拒绝。

初版允许完整状态副本作为离线试算载体，逐候选释放并控制峰值内存；这项高成本如实归档。它证明可获取信息及局部依赖，不证明同样昂贵的构造能够在生产中获益。局部覆盖层或可撤销日志只作为后续优化候选，不在 Gate 中提前建设通用事务系统。

### 4.2 操作观测与共享实现

优先在现有拓扑实现内增加窄实验入口及局部观测，复用细分/合并操作和单步控制助手；不先整体提取操作层，也不复制简化 ROAM。普通路径不收集实验足迹。只有局部复用确实受阻时才提出必要的小范围提取，不为长期扩展提前改造 DOD 数据结构。

读取足迹必须覆盖影响结果的节点资格、父子/邻接、深度、历史子节点、局部评分依赖及调用到的局部资格检查；写入足迹覆盖新增/激活节点、链接变化和局部状态。只比较操作前后差异能发现写入，不能代替读取足迹。共享只读高度/方差数据与公共配置只绑定身份，不制造虚假写冲突。

**依赖足迹和成本计数分开。** 足迹是去重的逻辑资源读写集合 `R/W`，用于批次正确性；允许在必要分支入口或操作边界声明保守超集，而不必为每一次 C++ 字段读取建立事件。GATE-01 对调用链的资格判断、递归闭包和修改路径建立覆盖清单，说明每类依赖由哪个集合覆盖；实际读写不能遗漏，纯状态差分仍不能代替读依赖。

成本计数只在基础操作、节点创建、邻接更新和队列操作等少数已有边界记录粗粒度次数。不同集合的重复访问次数与足迹去重大小不混为一谈；首版不要求精确 `W_touch`，不为此把所有直接数组访问包装成 instrumented accessor。无法可靠覆盖的依赖标 `footprint_unknown`；若主要真实闭包都未知，或必须侵入大量热路径才能覆盖，触发 GATE-01 停止检查，而不是降低正确性要求或继续全局改造。

记录内部 `PathId` 作为逻辑位置，新节点在试算中使用局部标识；两个副本碰巧分配相同数组下标不构成真实冲突。应用时确定性映射到实际节点。Gate 不实现生产并发分配器，只明确未来可实现的统一预留与互不重叠节点区间模型。

### 4.3 冲突、资源和串行维护

对两个根请求 `a,b`，只有已覆盖的逻辑足迹满足 `W_a∩(R_b∪W_b)=∅` 且 `W_b∩R_a=∅`，并且联合资源条件成立，才认定拓扑内核可独立。闭包重叠在第一版保守拒绝，不擅自合并共享工作或计算最大独立集合。

这是保守充分条件；已验证集合给出逻辑内核独立机会的保守下界，不是实际加速的下界或所有可能并行方法的上界。共享写即使可能可交换、共享强制闭包即使可能去重，首版仍拒绝。大量 `shared_forced_closure` / `coordinator_dependency` 应优先标为当前模型边界，不能解释成一般排序松弛无价值；本 Gate 不实现可交换共享写或闭包去重。

预算必须使用操作执行过程中的最大预留需求及实际净变化，不能只累加最终叶数量。第一版不在细分批内借用未来合并释放的预算；不足时由原严格控制器完成预算交换，之后重新构造快照。记录内存分配准备、峰值资源和失败状态。

共享堆、活动索引、统计、路径集合及网格修改日志由协调部分处理。依赖观测不能简单忽略这些共享写入：将其明确划为串行维护工作；如果某项共享状态会反过来影响本批操作资格或结果，则它是依赖，不能仅当成事后归约。

共享操作分离后的局部拓扑、派生索引维护和控制器必须与完整串行操作对应。未证明可以推迟的维护保留串行，不计为可并行工作。

### 4.4 批次证据等级

| 状态 | 处理 |
| --- | --- |
| 成员同源、足迹完整、资源成立、应用吻合 | `validated_batch`，仅表示模型下的独立拓扑工作 |
| 信息不足或共享状态无法分离 | `footprint_unknown` / `coordinator_dependency`，按串行计 |
| 应用中触发优先合并或停止 | `control_interrupted`，保留状态，整批按串行计并重建下一批 |
| 计划与应用的闭包/资源/局部效果不一致 | `plan_mismatch`，停止该变体并保留证据，不能静默修补 |
| 排列间逻辑结果或控制合法性不一致 | `dependency_model_mismatch`，按第 4.5 节撤销资格并暂停同模型正向结论 |
| 拓扑或预算违规 | `invalid_result`，停止该变体，不进入质量前沿 |

验证包括固定应用顺序、完整副本差异、共享正确性检查，以及第 4.5 节的定向排列审计。闭包内部顺序依赖不计为多个独立任务。`validated_batch` 仅表示模型及已执行检查下成立，另附排列审计覆盖状态，不能暗示每批都已穷举排列。

### 4.5 逻辑等价与排列审计

从相同 `S_j` 的独立副本应用同一封闭集合的预定排列；每个请求仍以批次开始状态的描述为约束，不为适应排列重新扩展闭包或增加成员。排列审计对象是被模型声明独立的集合，因此某排列不合法或触发不同控制语义也必须保留，不能只筛出成功排列后比较。

GATE-03 小规划先冻结逻辑等价投影，至少比较：

| 比较项 | 等价条件 |
| --- | --- |
| 逻辑拓扑与后继状态 | 按 `PathId` 规范化节点域、父子/邻接、活动叶和会影响后续操作的历史子节点、屏蔽状态；实际三角形数量相同 |
| 预算和资源 | 相同最终剩余预算、未释放预留及资源所有权；每种排列的过程峰值均不超联合预留，不要求不同时间点的瞬时曲线相同 |
| 队列与新候选 | 有效候选的逻辑身份、资格、评分、比较器顺序及新增/失效集合相同；堆内数组布局和无语义的懒清理布局可不同 |
| 根请求及闭包 | 按根逻辑身份对齐成功/失败、强制操作及其逻辑效果和必要依赖；根失败后留下的部分成功也纳入；不要求跨根日志顺序相同 |
| 控制和停止 | 所有排列都不越过优先合并、停止、失败或迭代边界；最终严格控制器的下一项/停止原因及已消耗迭代相同 |

新节点数组下标和内存地址不作等价要求，通过逻辑路径映射；评分等决定执行的数值沿用既有确定性比较，不事后加容差隐藏差异。原完整输入哈希不能直接当作跨分配顺序的逻辑等价判据。耗时与纯诊断日志不属于逻辑等价，但工作量差异继续记录，不能连同日志一起丢弃。

小批次在上限内枚举排列；较大批次使用固定顺序、逆序和预定相邻交换/循环排列，保留排列身份与覆盖。它审计的是批内可交换性及控制约束，强于“存在一种串行执行成功”；有限排列通过不是一般可串行化或并发正确性证明，也不替代足迹完整性论证。

排列审计只临时置换已经选定的细分根顺序，不放松合并、资源和停止约束。`strict-prefix` 对照的逐步 `S` 一致性另外按其规定顺序验证，不把审计时主动交换根顺序本身误报为依赖漏边。

任一排列出现逻辑差异或模型未预见的非法操作，标为 `dependency_model_mismatch`，撤销该批次的独立工作资格，停止该变体并保留最小差异证据；同操作模型版本的正向 Gate 结论暂停，不能只删除失败排列后发布其余正结果。先区分局部依赖漏边、资源建模错误和控制边界遗漏，再修复并作定向复核；不得通过放宽等价条件关闭问题。

### 4.6 候选未入批的原因与统计分母

对每次批次开始状态的候选暴露记录唯一 `principalBlockingReason`，可附已观察到的原因集合和冲突对象。候选指既有资格/队列规则下的 `C(S_j)`；过期队列项清理另计维护，不能混入优先级拒绝。检查流水线及主原因优先级预先固定，首个未通过条件作为主原因：

| 层次 | 主原因与语义 |
| --- | --- |
| 窗口 | `priority_window`：不在当前优先级带；不为统计该项额外试算闭包 |
| 检查覆盖 | `inspection_limit` / `batch_capacity`：达到检查或批次容量后未继续检查；明确属于实现限制，依赖未知 |
| 操作描述 | `dependency_unknown` / `dynamic_prerequisite_unresolved`：足迹不全或必要前置条件无法在当前快照闭包内解决；已知正常强制细分本身不属于未解决前置条件 |
| 与已选成员的依赖 | 按 `shared_forced_closure`、`write_write_overlap`、`read_write_dependency`、`coordinator_dependency` 顺序判定；只读/只读重叠不拒绝 |
| 联合资源 | `budget_reservation_conflict` / `node_resource_allocation_conflict`：联合峰值预留或节点/内存需求不成立 |
| 其他明确失败 | 记录具体操作失败码及部分成功证据，不能笼统归入排序限制 |

主原因表示在固定选择顺序下首先观察到的阻塞，不是唯一因果。按层记录 `total / outsideWindow / insideWindow / inspected / notInspected / accepted / rejected`，入批后控制中断和审计失配另计应用状态，不回写成窗口拒绝。缺少完整候选遍历时将总数或带内数标未知，不能用已检查项反推完整分布。

严格头请求失败或控制条件直接阻止构批时，记录头项/控制原因，其余成员标未检查，不凭空分配依赖原因。`α=0` 没有选择器，其窗口拒绝字段标不适用；`strict-prefix` 首次拒绝后的未检查项标为 `strict_prefix_boundary`，不伪装成已经检测到的闭包冲突。

报告 `RejectReasonDistribution(λ)` 时，同时给出相对完整候选暴露的窗口拒绝率、带内检查覆盖率、已检查候选中的原因数量/比例，以及未检查项数量；已检查主原因的分母与所有未入批项的分母分别标明。按输入先汇总，附原始计数和确定的跨输入权重；同一候选反复暴露不算独立统计重复。两种 `λ` 的轨迹可能不同，因此分布变化用于解释已观测瓶颈，不直接当作对同一状态的因果证明。

## 5. 独立几何评价设计

### 5.1 已确认的主参考曲面

**最终锁定（2026-09-11）：`Primary reference = raw height samples + bilinear interpolation`。** 最小参考校准已通过；完整质量评价能力按需暂停，RMS、Peking 收敛或配对 D_max 的缺口不阻塞 GATE-03 的最小独立工作筛查，也不被当作已完成能力。

2026-09-11 经用户确认，primary reference 改为原始 height samples 与冻结双线性插值规则定义的连续高度场。每个原始 cell 内 `h_*=(1-s)(1-t)h00+s(1-t)h10+(1-s)t h01+st h11`；参考身份包含资产 SHA-256、解码/归一化、行列方向、边界、尺寸/高度比例和 evaluator 版本。具体规则见 [GATE-02 第 8 节](gate_02_mesh_quality_evaluation_plan.md#8-双线性主参考与单项重跑修订)。

旧 `TerrainMeshBuilder` 固定对角线三角曲面保留为首轮 reference-mismatch 证据，不再承担主质量 ground truth；其 UV/索引可继续作为算法无关的采样模板。最细 ROAM 表示仅为可选 secondary diagnostic。生产节点的 float 求值不变，评价器独立用原始解码样本在 double 中计算 source；三角网格逼近连续双线性曲面的非零残差不自动表示参考失效。

被测网格使用最终 `TerrainMeshData` 的位置、UV 和索引建立查询结构，按同一域位置插值高度。质量模块不引用 DOD 状态或 `ComputeScreenErrorScore`。复用坐标数据和矩阵，独立计算投影位移，不读取算法维护的保守分数。

### 5.2 指标和异常

主要指标及 RMS、`H_max` 数学定义沿用[讨论记录第 5 节](ordering_relaxation_discussion_record.md#5-几何质量的数学语义)。记录字段使用 `sampledScreenMaxPx`、`screenRmsPx`、`sampledHeightMax`，均附采样身份和评价状态，不省略 `sampled` 含义。

- 最大屏幕误差：参考点落入固定 NO 视锥时纳入；被测点投影移出视口仍计算未夹紧坐标的偏移，不能删点。
- 屏幕 RMS：对参考可见地形像素中心射线确定最近正向表面交点；参考确定对应域点和等权像素集合，不按被测网格重新选点。
- 最大高度误差：覆盖固定完整地形域，使用统一世界单位；第一版仍为采样最大值，不借用高度场形状宣称精确极值。
- 被测曲面在参考有效点处缺失覆盖、投影非有限或穿越相机/近裁剪边界时记录独立异常；该配置不作为具有完整屏幕质量证据的操作点。不通过丢弃异常样本降低最大值。
- 参考视图没有地形像素时 RMS 为 `not_applicable`，不能写 0；高度指标仍可计算。参考采样为空、几何退化及未知状态单独报告。

拓扑验证与投影评价异常分开，后者不能自动等同于拓扑非法。

补充逐点超额退化 `D_max(R,S)=sup_{q∈D_c}(e_R(q)-e_S(q))`，有限采样字段为 `sampledPointwiseExcessMaxPx`。两侧使用同一参考、相机、域和公共样本，保留符号及异常，不隐式夹零；它不是两个全局最大值相减，不替代绝对 `E_max`、RMS/高度，也不保证表示误差代数相消。本次单项校准没有 relaxed/serial 配对，只冻结契约，不实现或填充该数值。

### 5.3 采样与收敛检查

最大值采样以固定规则三角形的 UV 模板为单元，包含顶点、边中点和重心，使用确定的嵌套重心细分序列；去重标识来自模板三角形/边与有理采样坐标。模板高度不参与 reference 求值，每个 UV 的参考位置和视锥域均按双线性 source 重算。每一级必须覆盖全部参考单元，不能只加密被测误差较大的区域后称为公共样本。

RMS 使用参考像素集合，允许先低密度估算成本，但正式 `screenRmsPx` 使用冻结分辨率的完整参考地形像素中心；稀疏近似须另标字段。参考射线交点必须属于双线性 source，不能直接沿用旧三角参考命中；查询及缓存只依赖参考、相机和分辨率，可供所有变体复用。

GATE-02 小规划在解析几何夹具上预先确定采样级数、`η`、最大样本数量及成本上限；建议 `η` 显著小于最小报告质量预算。正式结果至少报告三层公共加密值和连续两次变化；达到资源上限仍未稳定则标 `evaluation_unresolved`。即使变化小于 `η`，仍只称经验稳定，不称严格连续域误差界。

高梯度/窄峰几何夹具及预定代表输入执行一次额外敏感性检查，结果保留。候选输出驱动的自适应加密不进入第一版正式指标，避免样本选择依赖算法。采样层间变化是敏感性证据，不冒充统计置信区间。

以上 evaluator 范围足以支撑本 Gate。验收聚焦公平、算法无关、可重复和局部尖峰敏感性；不新增严格连续最大误差证明、复杂感知模型或完整时间跳变模型。资源不足按既定异常/未决状态处理，不临时升级评价器研究范围。

### 5.4 参考一致性校准：先于完整质量采集

GATE-02 首先以最小投影/高度查询和公共样本完成 `reference consistency calibration`，不等完整评价工具建成后才检查参考选择。首轮三角参考只执行 test129/DOD/sample5 后暂停；用户随后批准双线性主参考，完成同一自然项的 k=0 校准，再明确授权 test129 同一输出的 k=1/2 与 Peking/DOD/sample9 的单项 k=0。原两地形/两实现完整矩阵保留为历史范围，不据此自动扩大运行。

优先复用已有最细网格；需要生成时使用现有构建能力和受控校准设置，不新增正式算法模式。记录实际深度分布、叶数量、深度/预算/停止限制及资产、相机、分辨率、样本身份；生成前检查节点规模和阶段资源上限。没有真正达到所声明的最细表示时，标为“当前可达细化残差，校准未完整”，不能声称已测到完全细化的误差底。

`E_reference-floor` 是表示与参考的一致性校准残差，不是数学误差下界或随机噪声。表示不匹配和排序误差也不保证可以标量相加，不能从 `E_max` 中直接减掉校准值后称为排序误差。保留分地形/相机的残差，与拟报告的 `0.1/0.25/0.5/1 px` 操作点和采样精度一起比较。

例如 `0.01～0.05 px` 与 `1～2 px` 仅说明需要关注的量级，不作为自动通过阈值。批准双线性 source 后，合法有限三角表示的残差即使与目标变化同量级，也不自动否决参考；须结合残差位置、绝对质量和未来逐点超额退化解释。输入/几何/求值错误、成本超限或最细表示不可获得则停止，不无限增加细化深度；完成当前小规划第 9 节的三个指定评价即结束。

确定性的几何与批次记录不为增加样本量重复生成。需要计时的配置以独立进程为统计单位，按第 11 节执行；几何采样点、闭包成员和相邻输入不当作独立统计重复。

审计不新增主配置，先用定向排列和已知冲突证据；确有选择器/依赖疑问才使用额外审计。完整 Gate 的审计最多采用以下上限，并计入总墙钟及内存预算，GATE-03 只取足够判断的少量项：

- 定向人工夹具至少覆盖独立三根、故意漏掉读写依赖、资源峰值冲突和 greedy 非最佳选择；属于实现验证，不增大自然输入矩阵。未发现可审计自然小状态时保留覆盖缺口，不能不断追加场景找正例。

## 9. 成本模型和 Gate 判断

### 9.1 三种成本必须分列

1. **离线实际成本**：来源重建、完整副本、访问取证、选批、单线程应用、质量评价和文件输出，分别计时并保存总墙钟与峰值内存。
2. **算法工作量**：实际反事实执行的根请求、基础操作、粗粒度结构操作及串行维护，按下表分别记录；失败和部分成功不可省略，不能只计算批次内成功成员。
3. **模型执行成本**：已验证拓扑工作在 `p=1,2,4,8` 上按固定规则分配；共享维护、控制失效和回退按串行处理。模型权重和没有计入的硬件因素明确列出。

| 口径 | 必须冻结的计数语义 |
| --- | --- |
| `W_root` | 实际发起的根细分请求次数，包含失败与重试；强制子操作不另算根，合并根请求单列 |
| `W_primitive` | 已实际完成的基础二分细分和合并次数，按种类分列；菱形操作展开为其基础修改，根失败前已完成修改保留。同时必报基础尝试和失败次数，不能只用成功数量建模 |
| `W_coarse` | 在少数稳定操作边界计节点创建/复用、邻接更新、活动集合和队列查询/更新次数，按类别分列，标明覆盖和未观测成本；不声称是所有字段读取次数或硬件 load 数量 |
| 依赖足迹规模 | 分别报告去重的逻辑读/写资源数量，仅描述依赖覆盖与结构规模；不代替访问次数，不把集合大小字段命名为 `W_touch` |
| 闭包与共享维护 | 每根闭包长度、强制细分、新建/复用节点、失败工作，以及队列/索引/日志维护量；局部内核与串行协调分开，不重复归属同一次访问 |
| `W_feasible` | 通过模型验证、未中断的多成员批次中可独立局部内核的基础操作量，附根数量和粗工作量；每次实际操作只计一次，共享维护与单根内部串行链不能凭根宽归入多个独立任务 |
| `W_extra` | 相对同初态 `S` 的工作差向量：各口径分别给 `W_relaxed−W_S` 和比例；基线为零时比例标未定义并保留绝对差。正增量和工作减少分别可见，不合成单一分数 |

实际执行、候选试算、排列/搜索审计使用不同计数命名空间。离线副本和审计重复不能膨胀 `W_primitive` 或 `W_feasible`；但选批准备、试算总量及其实际成本必须单列，并在未来执行模型的准备成本假设中显式处理，不能借此免费化。现有 `SplitCount` 等聚合量只能复用其已核对语义，不能代替尚未实现的逐根闭包或访问计数。

首版报告 `W_root`、`W_primitive`、`W_coarse` 及失败/维护，不要求精确 `W_touch`。只有存在有利区间且精细成本确实影响判断时，才另议更细访问计数；缺少精确字段计数不阻断当前 Gate，缺少正确性足迹则不能接受独立批次。

先用基础操作、闭包长度和粗工作量检查明显的工作膨胀/不均衡，足以停止时不再校准时间模型。继续分析才引入简单权重敏感性，分别展示原始口径，不通过调权隐藏额外工作；没有计时校准时字段不能叫毫秒。

若引入时间模型，必须有独立进程内聚合的操作类型成本校准，包含准备、串行维护、网格提交及额外工作；避免依靠逐个微秒操作的噪声计时。固定批次按确定性列表调度计算负载，不以批宽直接除总耗时。权重无法可靠校准时保留工作模型，不强求一个看似精确的时间收益数值。

依赖关键路径按已验证执行轨迹建模：根闭包内部串行，批次之间有状态演化屏障，控制器和共享维护为串行节点；模型关键路径包含每批最长闭包及必要串行工作，不能将跨批新候选提前。另报闭包工作分布、每批最大/平均工作、固定 `p` 下的最长线程负载与负载不均衡。它是当前轨迹及模型的关键路径，不是所有可能调度的理论下界。

报告只使用可行批宽、可独立工作、模型依赖关键路径和模型估计的执行收益。即使模型校准为时间单位，也不将结果标成实测“更新时间收益”或 `Speedup`；后者只适用于未来真正多核实现的完整墙钟 `T_serial/T_parallel`。

全副本试算的实际成本不可隐藏。可另绘“未来局部计划构造成本为 0/不同占比”条件曲线来判断可承受的准备成本，但零成本图只表示条件性潜力，不是已经找到可实现的快速计划器。

### 9.2 建议判定

进入正式算法设计的正向建议必须联合展示 `ΔE_max`、`U=N/B`、`W_feasible` 与 `W_extra` 四个方向，同时检查依赖关键路径和负载不均衡。理想信号是在明确质量预算操作点内、利用率接近 `S` 时，相对同操作能力 `strict-prefix` 的可独立工作明显增加，且相对 `S` 的基础操作/粗工作增量没有抵消模型收益。不能把 `α=0` 不构造批次导致的零批宽当作唯一分母。

提前停止不要求先取得四个方向的完整数据：若已证明当前模型下几乎没有独立工作，可只报告这一失败条件，其余指标标未测。所有结论都限定为 **head-preserving + disjoint-footprint** 模型；小子集搜索仍强制包含头请求，不扩展这个适用范围。

质量与资源条件不合并为分数；近似同数量的容差、模型敏感性和覆盖要求在采集前冻结。报告在全部既定质量预算下同时展示通过/不通过各条件的点，不事后挑选一个宽松阈值使 Gate 通过。

| 结论 | 所需证据与后续边界 |
| --- | --- |
| 建议进入局部并行算法设计 | 硬约束及预定审计成立；跨所选地形/预算存在四个方向共同有利的区间。相对严格前缀的独立工作增长未被长闭包、不均衡、额外工作或串行维护抵消，公共采样加密与合理成本权重下仍保留非零准备成本余量 |
| 只支持窄范围继续 | 联合有利信号仅局限于特定输入或成本余量很小；明确缩小主张，由用户决定后续投入，不在本轮追加范围 |
| 停止当前模型/投入方案 | 所选输入上当前保留头请求模型没有足够独立工作，或已测质量、预算利用率、额外工作抵消机会；记录已测/未测维度，可以在 GATE-01～03 提前停止，不否定一般排序松弛 |
| 模型边界主导 | 大量 `shared_forced_closure` / `coordinator_dependency`、头闭包阻塞或保守足迹冲突主导拒绝；优先解释为当前模型边界，可停止建设，不作一般 constrained bulk refinement 的否定证据 |
| 证据不足 | 足迹覆盖、必要排列审计、选择器低估、参考不匹配、采样或资源限制使判断不可靠；说明缺口，不将未知记成无并行度或无质量代价 |

不预先以某个像素数宣布“可接受”。完成质量采集时给出每个质量预算下的可行点、被支配点和未完成点；提前停止时提交有限证据及其结论边界，不强求 Pareto 图。若保守模型已出现有利区间，它提供该受限方案可行的正向证据；仍不自动外推到实际多核加速。

负结果不触发自动扩大松弛范围、增加场景、更换选择器或修改评价规则。证据不足也不等同于获准无限补实验；只提交有边界的缺口及建议。当前计划到离线报告和投入判断为止，不包含正式多核算法、PREP-06 或 GPU/CBT 路线。

首版使用一个现有 `relwithdebinfo-fetch` CPU 构建环境验证。新 Gate 不使用图形资源；D3D12 和 OpenGL uploader 没有修改时不重复渲染矩阵。共享源码集变更需核对两后端构建接入，只有实际依赖/后端风险才追加定向编译。

### 11.2 修改前和修改后

每个代码/工具小阶段必须保留自己的 `before/after/comparison`。已有可追溯且环境兼容的报告可直接复用；不为相同源码重复建立同一基线。初次共享提取先保存当前程序、源码身份与结果，不能只引用历史微秒分析作为同期基线。

共享拓扑阶段建议代表集合：`standard × serial-incremental/default` 与 `budget-saturation × default`。使用既有命令：

```text
<before-or-after-exe> --benchmark --algorithm dod
  --profile <standard|budget-saturation>
  --pass-policy <serial-incremental|default> --csv <new-output>/frames.csv
```

实际命令、程序路径与资产在小规划中展开冻结。按开发规范：一次预热、五次独立计量进程，版本交替；比较进程级中位数/P95、绝对与相对差、工作量和结果。工程调查门槛为 `max(0.05 ms, 基线统计值的5%, 原五次统计值极差)`，超过后至多一次完整复测。研究质量预算不使用该工程阈值。

离线工具没有旧能力可比时，明确标新增成本，同时复测被复用的既有路径；不能虚构“新增 evaluator 修改前耗时”。工具秒级耗时和内存使用小规划事前成本预算，不机械套用 0.05 ms。

### 11.3 诊断与时间包络

生产关闭 Probe 的具体集合冻结为 `EnablePassEvidence=false`、`EnableTopologyValidation=false`、`EnableTopologyPairEvidence=false`，操作观测使用空策略；其他策略/阈值固定。正确性取证在独立执行或计时外进行，不由零违规计数推定已经检查。

来源重建沿用 `MakeCpuSourceSettings` 的校验设置；依赖观测运行必须开启新访问记录，不能拿其耗时冒充关闭诊断的生产时间。质量评价、序列化、全副本试算各有包络。若未来移入实际在线算法，不能继续把必要构造与验证成本留在计时外。

### 11.4 性能问题处理

达到现行工程门槛的稳定新退化，在 `docs/reviews/ordering_relaxation/` 单独记录现象、分析过程、原因和未决假设，由用户决定新增修复小规划或修改后续规划。未经确认不自行延期或修复。旧 P4 性能问题保持用户关闭状态，不重新追究几微秒波动。

已实施阶段对照小规划、本文及开发规范作简洁审查，确认操作语义未复制漂移、依赖足迹未漏项、质量未反向参与调度，并记录停止条件与实际成本。提前停止也记录已有改动及必要工程验证；不为长期架构整洁追加与 Gate 问题无关的重构。

## 12. 风险、替代方案与实施前冻结项

| 决策/风险 | 本规划建议 | 备选与边界 |
| --- | --- | --- |
| 先松弛哪一类操作 | 已按评审限定仅细分根请求，合并与停止仍受严格控制器约束 | 合并排序、跨阶段重排和新预算交换不在本 Gate 内 |
| 松弛参数 | 首版优先级带，零值严格单步 | 归一化排名窗口以后独立比较，不同参数不可混作同一横轴 |
| 操作真值与访问足迹 | 原实现的窄接口、内部助手及局部逻辑集合 | 大规模提取不是前置要求；覆盖成本过高可以停止 |
| 选择器低估潜力 | 固定 greedy 与独立窗口参数，小子集有界审计 | 不把当前可行批次称为最大批次；不回填更强选择器制造主矩阵正结果 |
| 依赖模型漏边 | 预先定义逻辑等价并做定向排列审计 | 有限排列通过不代替依赖论证；失败撤销资格并暂停同模型正结论 |
| 全副本试算成本 | 首版离线使用、流式释放、完整报告 | 局部覆盖层成本更低但实现更重；若成本阻塞先报告，不静默扩成事务框架 |
| 参考曲面 | 原始样本的连续双线性 source；test129 三层及 Peking 首层已校准 | 旧三角参考留作 mismatch 证据；Peking 尚无收敛证据，残差不直接相减 |
| 公共采样与成本 | 固定参考全域嵌套采样，参考像素等权 | 输出驱动加密只作补充，严格上界以后单独研究 |
| 近裁剪/投影异常 | 独立状态，无法完整评价的点不进入质量前沿 | 不能删除异常后宣称低误差；后续可设计专门的有界可见性度量 |
| 批次控制失效 | 不扩批，整批按串行计，保留已应用状态 | 允许跨合并/停止边界提交会扩大松弛语义，需重新确认 |
| 候选检查截断 | 固定 64/32 建议值并报告覆盖 | 若全部因限制无法判断，则结论为证据不足，不宣称排序无效 |
| 有利前沿可能来自少用预算 | 同 cap 全量和同实际数量子集共同报告 | 不补满、不调阈值，不以事后数量匹配掩盖总策略代价 |
| 宽批次来自额外工作 | 根请求、基础操作、粗计数和长闭包负载 | 精确 `W_touch` 非前置要求；失败/维护工作仍要保留 |
| 负结果解释过度 | 限定 head-preserving + disjoint-footprint 模型及已测输入 | 大量共享闭包/协调拒绝先解释为模型边界，不否定一般问题 |
| Gate 变成科研平台 | 每阶段有投入上限与停止条件，GATE-03 小驱动先回答问题 | 取消长期维护导向的预建抽象；工具不足与假设失败分别记录 |
| 研究外推 | 限定输入、阶段与操作模型 | 正式多核加速、连续轨迹、感知质量均需要后续证据 |

用户进一步明确以验证问题为主、避免过度工程化，前期评审据此缩减模块和阶段前置要求。GATE-01 小规划已固定旧特征选样和依赖可观测性检查，并完成其最少接口；完整采集仍只在前面证据支持时启动。具体实现若必须改变已明确的硬约束或扩大范围，再说明并确认，不把“可继续”解释为必须做完所有组件。
