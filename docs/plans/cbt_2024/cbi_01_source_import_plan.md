# CBI-01 来源冻结与模块迁入

2026-09-16；依据[大规划](cbt_2024_integration_major_plan.md)。用户已授权自主实施与逐阶段提交。

## 目标与边界

迁入已有 CBT 核心、着色器及测试，冻结文件来源，建立当前工程的编译门禁。当前阶段不接 GUI / renderer，不运行新 GPU 算法。DOD 是新增/适配代码的风格参考；来源核心保持原有清晰排版，逐文件检查注释与职责。

## 文件归属

- Reuse 来源 `cbt_2024/` 核心和 `d3d12/` 六组文件、着色器、七组测试。先迁入完整文件集，D3D12 适配器在 CBI-02 接通编译；不为提前编译它而绕开公共接口规划。
- Create `TerrainLodCbtTypes.h`：来源容量、模式、时间阶段枚举及集中设置/统计声明。Extend `ITerrainLodAlgorithm.h` 持有 CBT 设置/统计区块，已有 CPU 哈希与行为保持。
- Create `TerrainLodGpuOutput.h`：借用 GPU 描述，公共 packet 的消费和验证在 CBI-02 启用。
- Extend `HeightMap::Values()`：返回现有归一化数组的只读 span，供来源 GPU 上传和几何夹具复用；不改加载、采样或原始整数参考语义。
- Wrap 来源宏调色板为模块内 `CbtDebugVisualization.shared.h`，仅供 CBT 程序化顶点着色器使用，不重定义当前 CPU 调色规则。
- Create `cmake/Cbt2024.cmake`：核心对象库、七组定向测试和四容量着色器构建；入口 CMake 只挂接模块，不继续展开着色器矩阵。
- Create `docs/codebase/cbt_2024/source_import.md` 与 `source_manifest.json`：来源 SHA、上游身份、必要适配和公开再分发边界。
- 审查写入 `docs/reviews/cbt_2024/cbi_01_source_import_review.md`。源码/着色器复制不包含第三方工具链、构建目录或旧应用。

## 来源清单与读取范围

源根固定为 `third_party/RoamTesting`，不从相邻另一个 RoamTesting 工作区取更“新”的文件。清单记录来源相对路径、SHA256、目标路径和适配类别，目标代码的后续差异必须能追到这份清单。

| 文件组 | 本阶段检查重点 | 边界 |
|---|---|---|
| Baseline / Support / ABI | 算法身份、四容量、深度单位、布局与能力要求 | Support 设备查询在 CBI-02 编译接通 |
| OccupancyTree / BisectorTopology | 动态槽与基础槽区别、树计数、双邻接状态 | 不将池容量解释为活动网格预算 |
| Classification / SplitPlanner | 原面积公式、父级迟滞、预留及共享前置 | 保留比较方向、阈值及固定顺序 |
| BisectCommit / SimplifyCommit | 四模板、两/四节点简化、外部邻接传播 | CPU 代码只作为来源参考与夹具，不代替 GPU 更新 |
| TerrainGeometry | LEB 解码、双线性高度、父级第四位置、顶点布局 | 复用当前数学/高度图前先核对函数语义 |
| D3D12 六组组件 | include 依赖、所有者和帧顺序 | 完整迁入待接通，不将未编译文件称为运行通过 |
| HLSL / HLSLI 与七组测试 | 着色器入口、宏、共享 ABI、测试主函数依赖 | 实际调用闭包迁入，不引入整个旧工程 |

来源程序的许可证和 `THIRD_PARTY_NOTICES.md` 单独保留；本阶段只做已授权本地研究迁移，不推送或打公开发布包。

## 接口与构建约束

`TerrainLodCbtTypes.h` 只包含声明与轻量标准类型；`TerrainLodSettings.Cbt` 和 `TerrainLodStats.Cbt` 集中持有 CBT 状态，算法专属字段不混入原五阶段统计。来源字段改为访问该区块属于机械接口映射，不能顺带修改计算逻辑。参数默认保持来源的面积 50、128K、验证 Off、几何 ModifiedOnly。

`TerrainLodGpuOutput.h` 定义借用资源描述，不拥有 COM 对象，不 include Windows 头。保留原生 API、资源寿命、四类句柄、容量/跨度、间接命令偏移和两类 generation；本阶段仅检查声明可独立包含，实际发布与验证在 CBI-02 完成。

构建将 CPU 核心与 D3D12 运行层分开：核心依赖当前 GLM、STB、高度图和几何工具；GPU 运行层依赖固定 DXC/Agility 和当前 D3D12 后端。关闭 CBT 时不引入额外对象或编译着色器；开启 CPU 核心测试不要求 Windows。四容量各自编译来源宏组合，不复制四份 shader。

不得替换现有 `ITerrainLodAlgorithm.h`、`CMakeLists.txt` 或原测试清单。新增库统一维护源码列表，测试链接同一核心库；平台动态组件暂不链接，避免为了本阶段构建成功提前建立假的后端接口。

## 实施顺序

1. 冻结当前工作区与来源文件清单；保存修改前 Windows 程序身份、构建 cache 和短 DOD 回放。
2. 对照 DOD 适配器与开发规范，读取来源核心头和算法实现，迁入并记录非算法适配。
3. 公共声明保持原 CPU 默认值；CBT 设置独立区块，不加入原 CPU replay 哈希。
4. 用现有固定 DXC 编译四容量计算着色器，CPU 核心测试使用既有 GLM / STB。GPU 框架依赖留待 CBI-02。
5. 核对源清单与实际文件差异，记录检查、性能、未接通部分并提交。

## 风格与适配审查

参照 `DataOrientedRoamTerrainLodAlgorithm` 的显式分支、换行与命名。公共类型写自然的摘要，复杂循环说明输入/输出和约束，不用密集单行控制流。来源注释逐文件读取；迁入文件的语义调整、注释调整和纯路径调整分开登记，不用脚本全量替换注释。

核心库不能依赖 GUI、实验输出或 renderer。共享 ABI 仍由 `CbtGpuAbi.shared.h` 单一声明，C++ 布局断言与 HLSL include 使用同一源；不在公共 GPU 输出头重新定义内部二分器字段。

## 验证与成本

- 开发快验：已有 Peking / DOD / 24 机会，8 线程，固定返回轨迹，分别保存旧/新程序与原始 CSV。首轮一组进程，不运行正式 FER 矩阵；预期算法运行数秒，构建另计。
- 定向测试：来源七组核心用例覆盖占用树、分类、邻接、规划、细分、简化、几何；公共 CPU 接口选已有结果/输入测试。不是全项目 CTest。
- 成本：DOD 前后按开发规范 §7.3 核对；新增核心测试耗时与 shader 构建成本单列。纯文件迁入不虚构算法运行收益。CBI-02 才具有迁入 GPU 的运行时间。
- 正确性或四容量编译失败时先修复迁移/依赖问题，不改变 CBT 算法。工程退化按大规划记录并调查，不无界复测。

性能基线固定为当前 `3d8b352` 的已有二进制，运行前保存程序 SHA 和 CMakeCache；若程序身份不能对应源码，则先重建旧版本，不能使用无身份历史 CSV。原始产物归入 `benchmark-output/cbt-2024/cbi-01/{before,after,build,tests}`，不覆盖；CPU 热更新取剔除既定前三机会后的均值，逐帧网格 hash / 活动数核对结果一致性。

新核心库先编译再运行七组测试；四容量 DXC 编译只证明入口、宏及 ABI 引用成立，不证明 GPU 执行正确。原 CPU 路径只重跑受公共声明影响的结果/输入契约测试，不展开拓扑历史 Gate。预计基线与用例各数秒，首次构建可能数分钟；构建失败只围绕失败目标定位。

公共输入契约由新增 `CbtIntegrationContractTests.cpp` 覆盖：CPU 输入哈希不受独立 CBT 设置影响，空 GPU 描述无借用资源，顶点和共享 ABI 大小保持来源要求。该用例与七组核心夹具一起构建，不另跑未受影响的历史拓扑矩阵。原始运行与构建产物增加独立 Git 忽略目录，报告只提交聚合证据和来源清单。

## 完成与停止条件

本阶段完成需要：来源清单可核对、每项非注释差异有解释、核心及四容量 shader 构建完成、定向用例无失败、原 CPU 结果一致且无未处理工程退化、审查记录与规划结果回填齐全。完整 GPU 执行、材质、视觉、同代 mesh 采集仍明确未验证。

缺失共享声明时先检查现有等价能力；确需新增则在本规划补列所有者和依赖。若需要改分类/模板/传播算法才能运行，停止该部分并独立记录，不能把算法修复包装成迁移适配。只有本阶段验收并提交后，才编写并实施 CBI-02。

## 实现结果

2026-09-16：CBI-01 完成。46 项来源文件已冻结（含调色板和来源声明），新增公共类型、只读高度数组与独立 CMake 模块。迁入算法 `.cpp` 和计算 shader 未改变算法内容；路径/注释差异逐文件登记。

八个核心/接口定向用例通过，总 CTest 时间 0.04 秒；106 个四容量/公共 DXC 入口编译完成。Windows OpenGL 应用重建完成，GPU 运行文件依大规划暂不编译。当前无 CBT GUI、GPU 执行或视觉通过的主张。

工程快验采用 Peking、50k、8 线程、24 机会，剔除前三机会；两轮所有帧的网格 hash、活动数和 split/merge 均与旧程序一致。独立进程结果如下：

| 对照 | 旧 CPU 暖均值 | 新 CPU 暖均值 | 差值 | 判读 |
|---|---:|---:|---:|---|
| 首组 | 42.502 ms | 48.548 ms | +6.046 ms / +14.24% | 超过 2.125 ms 门槛，触发一次复测 |
| 唯一复测 | 50.687 ms | 48.924 ms | -1.763 ms / -3.48% | 不再同向退化，未超过当前旧值的 5% 门槛 |

复测相同旧程序本身升到 50.687 ms；当前证据不能归因为版本持续退化，也不声称新程序提速或统计显著。按开发快验的一次复测上限停止，不扩大测试矩阵。两轮原始输入、二进制、日志和汇总均保留在 `benchmark-output/cbt-2024/cbi-01/` 并被 Git 忽略。
