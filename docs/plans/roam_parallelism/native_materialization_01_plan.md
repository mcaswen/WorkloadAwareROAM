# NMP-01：严格动态目标决策与生产状态修改解耦

> 日期：2026-09-13；类型：小规划；上层：[原生接入大规划](native_materialization_plan.md)。
> 状态：大规划与本小规划已获用户确认；先提交规划，再开始实施，当前尚无代码与实验结果。
> 源码基线：`602ed48`；保留 MPR 的独立直接物化证据。

## 1. 本阶段问题与出口

验证同一个已评分细分阶段输入 M₀，能否在不写生产拓扑、不复制全状态、不调用旧提交器的情况下，得到与 Legacy 严格执行相同的目标及续接义务：

\[
M_0\xrightarrow{\text{独立稀疏逻辑规划}}(J,\Delta,\Gamma).
\]

本阶段只实现第一箭头。验收分成三个独立结果，不能用一个 Pass 掩盖另一个缺口：

1. **语义解耦**：J、Δ、封闭 Γ、完整严格决策轨迹和逻辑堆投影一致；来源未修改，出口不携带目标生产状态。
2. **局部性证据**：报告实际节点/堆覆盖、读取和义务规模；判断当前自然输入是否仍具有稀疏结构。
3. **成本记录**：测 T_plan 及共享规则提取对原实现的影响。第一版覆盖容器较慢不自动否定前两项。

通过定向测试是该输入范围的实现证据，不等于对所有 ROAM 状态完成形式化证明。NMP-02 才验证出口足以独立恢复完整原生状态；NMP-01 不提前声称生产续接和完整更新加速已经成立。

## 2. 范围、已读事实与实现边界

已核对[开发规范](../../standards/development_guidelines.md)、[规划规范](../plan_guideline.md)、[接入事实](../../codebase/roam_parallelism/native_materialization_integration_baseline.md)、大规划及用户七项评审。定向重读 `DataOrientedRoamTopology.cpp` 的严格步进/预算策略/强制递归/观察入口，`TopologyExperiment.h`、`Queues.h/.cpp`、`Scoring.*`、原型探针的自然/压力来源和现有测试构建。

关键事实：

- 原控制器不仅细分，还先执行低分合并及失败后的预算交换；根失败可保留成功前置。
- 循环头部的 `<`、迭代后增、强制前置的 `forcedFrom` 都有行为意义。当前递归的 guard 达界只结束该 while 条件，随后仍按源码进入后续判断；不能自行新增“guard 达界立即失败”的语义。
- `Q_s/Q_m` 都是持久堆，新成员会在本阶段评分；不能用入口候选列表代替动态队列。
- 现有 `AdvanceStrictSplitIteration` 可观察循环体结果，但不足以完整观察根内部的预算和前置。
- `ExecuteObservedSplitRoot` 每根计算完整输入哈希，`AnalyzeSplitOperation` 还克隆状态；二者均不适合作为本阶段规划器或轻量轨迹的实现基础。

本阶段新增逻辑规划核心与无窗口测试/探针，必要时提取纯规则。**不实现原生物化、网格载荷、GUI、生产新路径派发或并行执行**；不修改 MPR 状态/补丁/参考。

原／新开关仍按大规划保留。NMP-01 固定枚举与 CLI 名称的设计，公开字段/实际派发随 NMP-02 接线，避免当前出现一个可选但尚未实现的生产动作。共形来源标记及新生产载荷也在 NMP-02 接入；本阶段输入由外部诊断认证。

## 4. 规划状态与正常出口

### 4.1 三层数据必须分开

| 数据 | 使用者与寿命 | 是否可以交给物化器 |
| --- | --- | --- |
| M₀ | 只读借用，由调用方持有；整个同步规划有效 | 作为旧状态使用 |
| 私有规划视图、虚拟下标和堆覆盖 | 仅在规划调用内参与动态决策；测试可在销毁前审计 | **不可以**；不保留到正常返回结果 |
| `NativeTargetPlan` | Δ、封闭 Γ、逻辑摘要和纯求值缓存 | 可以；没有目标邻接/活动数组/生产堆布局 |

拟定普通接口为 `NativeTargetPlan BuildNativeSplitTarget(const DataOrientedRoamState& source)`。审计入口另设诊断策略，在返回前向测试只读访问器提供逻辑投影；诊断访问器不能被 `NativeTargetPlan` 持有，也不作为未来物化的输入。

私有目标和轨迹均从独立 schema 1 开始，记录版本与基态输入身份；不序列化为可跨帧发布的生产事务。现有 `DataOrientedRoamPassInputVersion` 保持不变，后续新增生产载荷时另作版本扩展。公开选择名沿用大规划的 `TerrainLodSplitTopologyImplementation::{Legacy, DirectMaterialization}` 和 `--dod-split-implementation`，本阶段不暴露未接线选项。

私有视图按字段借用原池：已有节点域、误差、身份、父子关系首次读取不必创建完整覆盖记录；仅变动项建立覆盖。新虚拟节点保存为决定后续分数所需的域、误差索引/值、身份及必要关系。节点活动资格与 `IsSplit` 分开表示，不能把休眠缓存误当活动叶。

逻辑关系允许保存当前三邻接，因为下一步 forced 前置可能读取它们；但它们属于决策工作区。正常出口提取完成后销毁，最终叶邻接必须在 NMP-02 重新由局部目标构造。

不维护生产活动数组的顺序/反向活动位置、NodeSlots、SlotOwners、CPU 网格和 TopologyEdits。只更新活动数量及受影响节点的逻辑资格；不每帧遍历全池建身份字典。只读量与覆盖量分开记录，防止“没有写全域”掩盖“读取了全域”。

### 4.2 Δ 和 J

Δ 以**三角形路径事件**为单位：排序去重的 `AddedEvents/RemovedEvents`。`k` 是二者之和；不按请求根或菱形组计数。

从实际触及事件的入口/最终逻辑活动状态提取净变化；反复修改回到初值的事件不进入 Δ。J 是基态事件谓词加这份差分，不构造完整 J 集合。外部验证器可以全量展开 J 比较，费用只属于诊断。

### 4.3 Γ 字段白名单

禁止 `std::any`、任意字段快照、目标节点数组、最终叶边/堆/mesh 载荷。使用以下四类有类型的局部记录；实现时逐字段列出写入点、原生后续读取者和无法由 Δ 唯一确定的理由。

| 类别 | 最小语义载荷 | 独立对照来源 |
| --- | --- | --- |
| `CandidateDisposition` | PathId、细分本帧阻塞或失败合并候选最终移除、原控制分支原因 | Legacy 的实际阻塞/移除事件及最终队列；后续重新插入时撤销已经失效的处置 |
| `EpochAndSourceChange` | PathId、发生变化的轮次字段/强制来源/本轮路径记录 | Legacy 前后字段与成功事件；同字段只保留最终必要值 |
| `CacheBirth` | 新缓存 PathId、必要创建轮次 | Legacy 完整前后缓存身份差；不含物理下标、创建槽位、域或整份节点 |
| `InternalRelationChange` | 非目标活动叶节点 PathId、已批准的 Base/Left/Right 关系字段、目标 PathId 或空 | Legacy 前后内部关系与读取者；需要证明其不能从 M₀+Δ 局部推导，不能整行复制三邻接 |

没有续接后果的根失败和每次预算变化只进入决策轨迹/摘要，不进入 Γ。由身份、Δ 或当前环境直接恢复的父子、域、深度、默认轮次不重复编码。新缓存身份可由最终活动结构推出的部分也不重复登记，仅缓存存在性超出该结构的必要义务进入 Γ；`g` 仍独立记录全部逻辑新建节点。

`InternalRelationChange` 是风险最高的一类：**字段名白名单不等于已证明必要**。步骤 1 先完成逐字段理由和小反例；不能说明必要性的字段暂列审计差异，不进入 Γ。若某个旧休眠字段可被未来激活安全覆盖，就不能以“原数组不同”为理由强行保存。

规范化 Γ 的键为“类别、PathId、字段”，同键折叠，最终值等于可恢复值则去掉。`h` 是规范化义务数量；另报每类条目、不同身份、载荷字节和提取前峰值，不按一整个 vector 计一个义务。比较 Γ 时使用固定语义规范化规则，新旧两端各自产生，不把 Planner 输出交给 Legacy 投影器当查询白名单。

### 4.4 纯求值缓存与摘要

可复用 Planner 确为选择计算过的域、几何误差和纯 score，按稳定身份与冻结环境键索引；不携带活动/候选资格、邻接、堆位置或槽位。逐位保持当前共享评分计算顺序，不能利用缓存为未来批量阶段提前做无关计算。

最终预算、停止原因、迭代位置、根/强制/合并成功失败计数属于固定逻辑摘要，不携带事件列表。求值缓存可丢弃后重新计算，Γ 不可被缓存替代。NMP-02 必须验证关闭求值缓存仍可构造相同结果；本阶段仅固定并检查载荷边界。

## 5. 独立严格控制器及堆覆盖

`NativeTargetPlanner` 只管理严格循环、选择与停止；`NativeRefinementSimulation` 管理一个根内部的逻辑前置展开/合并；`NativePlanningView` 只负责存储与局部查询。不要将原 `Topology.cpp` 整段复制后把写者改名为 Planner。

共享边界限于：分数与 PathId 比较、给定局部描述的资格、迟滞谓词、纯评分和索引堆基本算法。原串行入口仍直接访问原数组；不得把 Legacy 套进覆盖访问器。Planner 不调用 `RunStrictSplitStep`、`AdvanceStrictSplitIteration`、`SplitNodeImpl`、生产 AddNode 或原队列 mutator。

每轮保留以下逻辑顺序：先低分合并 → 细分头部停止判定 → 根预留与动态强制前置 → 根据部分结果再次读取队首 → 预算交换或阻塞/停止。新评分、新候选和失败后的状态立即参与下一次逻辑判断，不延迟到整个规划结束。

覆盖堆用 `std::map` 保存变化槽位，另保存逻辑长度、反向位置及代表/伙伴覆盖。读取未覆盖且未被截断的槽位才访问基态；删除再追加不得复活旧尾部。分数、资格变化后即时修堆。正常返回前仅用它完成决策/审计，不输出物理堆补丁。

正确性不依赖覆盖稀疏程度；稀疏程度只影响空间、查找成本和方向价值。生产队列的最终恢复属于 NMP-02，不能靠导出整个覆盖堆提前完成。

## 6. 轻量严格决策轨迹

### 6.1 事件契约

固定事件以稳定路径和明确结果为内容，测试侧定义比较，不纳入生产 CSV：

| 事件 | 需要比较的内容 |
| --- | --- |
| 根选择 | 迭代序号、Split/Merge、根 PathId、选择时分数、普通低分合并或预算交换来源 |
| 前置尝试 | 当前根、当前尝试 PathId、forcedFrom、Requested/Forced、进入及结果 |
| 预算操作 | 预留成功/拒绝/释放、所属尝试、前后余量；合并释放按原 primitive 数量计 |
| 根完成 | 成功/失败、是否发生预算拒绝；部分成功前置单独保留 |
| 处置与交换 | 被阻塞/移除候选、代码分支原因、交换尝试与成败 |
| 停止 | `NoEligibleSplit/BudgetBlocked/IterationLimit`、最终余量、迭代位置和入口上限 |

按严格根决策顺序和根内逻辑前置/预算因果关系比较；不记录堆交换、节点数组赋值、分配槽位和线程时间线，不把此轨迹当必要 CPU 关键路径。首版逻辑模拟遵循原递归前置顺序，不另外研究可交换重排。

失败原因只按实际分支分类，例如深度拒绝、预算拒绝、前置失败或根非预算失败；原代码没有明确区分的原因记录为该原分支，不能为了丰富报告改变控制逻辑。

### 6.2 获取方式与隔离

Extend 原控制器/commit policy 的编译期诊断策略，关闭时是无操作对象，无每事件虚调用、分配或字段观察。轻量 Legacy 入口运行原严格代码，不调用每根完整哈希观察器，也不克隆每一个根。

Planner 由自己的控制器和逻辑模拟独立发事件；两方共享事件格式而非事件发生判定。测试外层从同一 M₀ 产生 Legacy 工作副本，原状态供 Planner 只读借用，比较前后来源与最终参考。外部克隆、完整投影和轨迹存储都不进入普通 Planner 调用图。

解析夹具完整逐字段比对；自然点同样不得只比较根前缀。每条轨迹首版限制一百万个固定事件，不记录完整字段足迹；达到限制则记为“轨迹审计未完成”，保留已知结果并停止扩展，不把截断摘要标为等价。首次不匹配只输出邻近事件与字段，完整原始记录留忽略目录。

诊断开启/关闭的 Legacy 和 Planner 各自结果必须一致。计时仅使用关闭轨迹和全量审计的入口。

## 7. 外部正确性与局部性审计

### 7.1 比较对象

外部 Legacy 参考从同一 M₀ 调用原 `SerialImmediate` 阶段。其状态投影完整枚举缓存、活动事件及队列，独立得出 J、Δ、Γ 和规范化逻辑堆；不得只检查 Planner 宣称变动的节点。

Planner 的完整逻辑堆只在诊断回调中按 PathId/分数/代表/伙伴和抑制状态读取；检查自身 heap/reverse-position 不变量，物理槽位顺序不作为新旧等价条件。分别检查两个方向的成员缺失/多余，避免只比较队首。

源状态只读检查包括节点、活动数组、队列、历史、预算、mesh 元数据、容器长度/容量及数据地址；构造诊断快照属于测试开销。普通 Planner 不得通过 `const_cast` 修改源统计或扩容源容器。

归纳检查按“入口逻辑投影一致 → 当前根/分支一致 → 根结束后的队列/预算/标记一致”组织夹具。它用于定位差异，不引入通用 Lean/符号执行平台。本阶段尚无原生物化，所以不以继续运行一个伪造 M₁ 的方式替代正确性比较。

### 7.2 计数定义

| 字段 | 口径 |
| --- | --- |
| `N`、`Qs/Qm` | 入口缓存数量及两个堆长度；另报入口活动叶数 |
| `a`、`aPeak/aFinal` | 规划期间累计不同被覆盖节点、同时保留峰值及最终存量；旧记录和新虚拟记录分列 |
| `r` | 逻辑节点字段/记录查询的操作次数，重复访问计数；不称为 C++ load 数 |
| `u_s/u_m`、`uPeak/uFinal` | 每堆累计不同被改写的槽位及峰值/最终存量；原槽位和新追加区间分列 |
| `uMembership` | 反向位置、代表/伙伴覆盖单列，不拿它和堆槽位混在同一 u/Q 比值 |
| `L` | 堆槽位访问/修复操作次数，重复访问计数；比较次数另计 |
| `h`、`g`、`k` | 规范化 Γ 义务、全部逻辑缓存创建、净事件差分数量，保留单位差别 |
| 读覆盖 | 诊断额外记录不同旧节点/堆槽位读取数量，识别大范围读取但少量写入 |
| 内存/其他工作 | 覆盖峰值、出口/求值缓存载荷、评分次数、净差分排序量、销毁成本；不凭容器行数推总内存 |

诊断给出 `a_old/N`、`u_s_old/Qs`、`u_m_old/Qm`、不同旧读数量比例、h/N 和 h/k。零分母记不适用，新增虚拟记录另列，比例不能靠删掉中间覆盖项缩小。自然输入中的小比例只是覆盖证据；三个点不能证明普遍 O(k) 或全域规模无关。

## 8. 运行输入与最小验证

### 8.1 解析夹具

一个定向测试目标覆盖：

- 平分 PathId、迟滞阈值边界、停止头部不能越过、先合并 `<` 边界。
- 根预留、强制前置、部分前置成功后失败、释放范围、失败后的新合并头部和预算交换。
- 最大深度、已合并/已细分抑制、非预算阻塞、缓存复用、净差分为空但历史处置非空。
- 堆任意删除、尾部换位、重复追加/截断、伙伴代表变化、空堆与抑制值。
- 迭代上限公式和后增停止边界；人工计数器边界标为控制组件夹具，不冒充自然轨迹。
- 正常出口字段白名单、Γ 规范化、源未变、独立控制器调用边界；诊断不能改变结果。

能够以少量针对性夹具覆盖就不重复全套 MPR 的 2304 对状态矩阵。本阶段不改 MPR 构造，既有 MPR 结果直接引用；共享评分/堆若影响现有路径，选对应旧边界测试。

## 9. 快速性能契约

### 9.1 基线与计量

先完成只包含来源恢复与 Legacy 计时的中性探针并冻结其分支，然后再修改生产共享规则/诊断入口；保留基线源和二进制身份。实现后使用相同 Legacy 分支测共享抽取影响，另测普通 `BuildNativeSplitTarget`。不以 MPR 的逐菱形参考时间代替原生基线。

默认 **三个计量进程**：修改前 Legacy、修改后 Legacy、修改后 Planner；每进程包含上述三个固定点，每点一次热身、两次短计量。另一次后版本诊断进程完成正确性与覆盖计数。没有线程矩阵、5×30 或完整 64 点性能采样。独立进程为统计单位，本轮只做工程筛查，不用两个重复推断稳定 P95 或统计显著性。

每次计时前由测试外层恢复同一旧状态；为了匹配入口内存条件，Planner 也在计时外得到同协议的工作输入。恢复、来源、输入认证和输出文件费用单列。计时中不克隆、不调用旧阶段、不做全量认证。

`T_plan` 包含构造覆盖、逻辑模拟/堆维护、新评分、Δ/Γ 提取及求值缓存整理，直到私有工作区销毁和函数返回。结果所有权返回后的析构另记 `ResultCleanupMs`，以后合入完整新阶段，不将它漏掉。诊断回调的全量投影时间不用于速度比较。

报 `LegacyBeforeMs`、`LegacyAfterMs`、`PlanMs` 及对应身份。`PlanMs/LegacyAfterMs` 仅表示“规划费用相对旧完整细分阶段的比例”，两者输出任务不同，不能称为加速比。`MaterializeMs` 和新完整阶段时间留空。

正式计时调用前将以下设置/入口固定为：

只有具体异常才追加第二组短对照；不追究几微秒差值。共享改动使原参考出现可重复且有工程影响的退化时，记录原因/未知项并由用户决定修复小规划或后续调整。Planner 较慢单独记录，不因此自动开启性能修复支线。

## 10. 实施顺序与中途 Review

1. **字段与基线**：完成 Γ 各字段的写入点/读取者/不可导出理由；冻结出口和轨迹协议；构建中性 Legacy 基线探针。内部关系必要性无法说明时先停在此处，不把整行塞进 Γ。
2. **私有视图与堆**：实现直接借用、虚拟记录和覆盖堆，复用最小纯规则；局部夹具验证来源未变、截断/追加和计数。
3. **独立严格规划与轨迹**：实现根控制与逻辑前置，原控制器只补轻量观察；比较完整语义、J/Δ/Γ 及逻辑堆，不接生产物化。
4. **现实核查与短计量**：按固定三点诊断一次，正确后执行短计量，输出三类结论；不得因 Planner 慢重建整套基准。
5. **边界审查与回填**：审查依赖调用图、Γ/正常出口、峰值覆盖、计费与原参考开销；回填本页并出阶段实现审查，再决定 NMP-02。

| 观察结果 | 本阶段判断 |
| --- | --- |
| 语义一致、出口封闭、覆盖明显局部，Planner 较慢 | 支持解耦与当前输入的稀疏性；保守容器成本另记，可讨论 NMP-02，不要求先赢性能 |
| 语义一致，但 a/u/读覆盖/h 在自然点与压力点广泛接近全域 | 语义实现成立，局部性价值不足；按数据 Review，暂不继续铺集成设施 |
| J 相同但决策轨迹、Γ 或逻辑堆不同 | 严格语义不成立，先定位反例；不能以最终 cut 相同通过 |
| Γ/辅助载荷包含最终生产状态，或必须旧完整执行器取 J | 解耦边界失败；停止并 Review，不通过改名继续 |
| 轨迹达到容量限制或关键字段必要性尚未解决 | 证据不完整，不宣称 Pass；明确缺口及最小下一步 |

不预设一个未经依据的稀疏比例数值作为通过门槛；报告原始覆盖和各点比例，由当前固定输入上的模式作有限范围判断。不能用一个异常点证明所有输入不可能，也不能只报告最小比例点。
