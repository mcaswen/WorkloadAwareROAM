# MPR-03：压缩目标物化事务内的串行工作

> 日期：2026-09-12；实施记录更新：2026-09-13；类型：小规划；状态：**实现与开发快验记录完成；按用户要求停止完整计量矩阵，不作正式性能验收声明**。
> 前置：[MPR-02](target_materialization_prototype_02_plan.md) 已提交为 `d635a9b`，完整物化、续接和真实并行获得强验证，可以继续。
> 上位：[原型大规划](target_materialization_prototype_plan.md)；分析依据：[串行成本与收益空间](../../research/roam_parallelism/target_materialization_serial_costs.md)。

## 1. 问题、目标与边界

目前并行准备已经可用，但局部支持集、重复记录定位和持久状态维护占据大量事务时间。本轮在共同状态表示与三段执行边界不变的条件下，减少临时树构造和重复字典查询，判断能否兑现完整物化事务收益。

用户随后提出复用既有极限压力路径。执行顺序调整为：**先接入 20 万预算压力样本，测当前 MPR-02 核心，再决定是否调整串行优化优先级**。输入扩大属于本次明确提出的补充实验，不能继续将原八项的小工作量范围当成全部性能空间；原结果保留，不以新增样本替换。

只比较给定同一 `(M0,J,Δ)` 的目标应用；不包含目标发现、差分生成/认证、DOD 导入和消费/换轮。后者继续单列。独立逐菱形参考 R 保持自然、局部的更新方式，不为配合物化器增加支持集、排序或全域索引。

本轮不替换持久 map/set，不引入跨事务缓存、内存池、并行容器、并行排序或新线程策略；不改变目标算法、评分、队列资格、历史/Pending/槽位语义，也不写回生产 DOD。修改限于已批准模块的事务内部组织，属于既有架构内的小规划。

## 2. 规划前核对与架构决定

采用两项局部扩展：**A，复用有序差分并以向量组织事务支持集；B，一次定位后传递本事务的稳定记录句柄。** 状态仍归 State 所有，补丁暂存仍归 Patch 所有。线程只读取冻结输入并写唯一记录，参考仍独立执行合法菱形操作。

## 3. 具体修改设计

### 3.0 前置：复用极限路径测量当前核心

**已核对事实：** [运行时路径](../../../src/app/Application.cpp)的 `ComputeBudgetSaturationCameraPose` 为 64 点环绕；[无窗口旧 benchmark](../../../src/benchmark/TerrainLodBenchmark.cpp)的 `MakeBudgetSaturationCameraPath` 使用相同姿态公式，但只有 24 点。它们均不是 formal trajectory A。现有物化探针把场景 ID、sample14 和八案例数量写死，不能仅替换清单或命令行接入。

本次选运行时的 **64 点几何路径**，首轮仍只捕获 sampleIndex=14，来源从干净状态顺序推进 0..14，保持历史；不将单个目标配对称为完整 64 帧性能实验。该点在测量前固定，避免选择初始化巨变或按新速度结果挑样本。后续完整路径分析不在这次前置测量内。

冻结参数：Peking 547×547，TerrainSize=80，HeightScale=12，MaxDepth=20，split/merge=0.25/0.1 px，TriangleBudget=200000。令 `t=i/63`、`a=2πt`，相机位置为 `(58 cos a, 20+3 sin(2a), 58 sin a)`，目标为 `(10 cos(a+0.55),4,10 sin(a+0.55))`，使用旧实现的 float 常量及运算顺序。四点来源预热后重置拓扑，再开始记录轨迹；该预热与每配置的独立计量热身分开。

视图固定为 CPU 的 RH_NO、1280×720、FOV=60°、near/far=0.1/500，复用现有 `BuildCameraView` 的视图构造；压力姿态不冒充符合 trajectory A 的相机清单。新测量复用旧几何路径及地形参数，另存姿态/视图身份，不能宣称重现历史 GUI 的全部投影位模式、执行策略或墙钟。来源采用当前既有严格串行配置，目标仍由现有 Bridge 在 split-topology 输入上捕获。

入口限定为新增 `--cases mpr-stress-01`，案例名 `peking547-budget-orbit64-b200000-sample14`，只产生这一项。原 `--cases mpr-01` 的两份清单、八项输入和校验保持；压力协议只要求 asset-root 和通用计量参数，不通过修改 formal 清单验证器放行任意路径。局部 `PrepareStress` 负责资产、固定姿态和来源推进，继续返回共同 Case；不读取或重构 App，不扩展为通用场景系统。

只修改探针输入组织，**不改 State/Patch/Reference/Bridge/Executor**，不同时加入 A/B 优化或新增计数。沿用 schema 2 与已有 R/A/F/C、Δ+/Δ−、记录新建、实际评分、Pending、分段和完整时间输出；资产 SHA、冻结参数、完整姿态、程序/源码身份与命令存入本地 protocol。旧压力报告中 sample14 的 DOD split/merge 计数各为 16,206，只说明值得补测，不能视为当前净差分 k 或当前 materializer 的工作量。

先作 R/M1/M4 三项诊断，核对相同目标的完整投影、预算、队列、Pending 消费和换轮；确认没有 replay/全域恢复后，按原协议作 R/M1/M2/M4 各一次独立热身和五次独立计量，内部仍为 5+30。记录 k/N、新建记录与并行准备项目，明确大存量是否确实对应大差分。k 小或为零也保留，不临时换点/阈值制造并行负载。

压力入口新增前先保留 MPR-02 程序身份；该输入无历史物化基线，明确标为新增工作负载，不编造旧程序结果。旧八项输入用一次诊断检查接口兼容和来源身份，既有核心正确性证据复用，不重跑完整旧四配置计时矩阵；只重建探针，不运行 GUI、GPU 或生产性能探针。若大输入暴露导入/续接错误，保留失败，先报告根因，不在输入接入中静默修改算法。

产物保存于 `benchmark-output/roam-materialization/mpr-03/stress-before-optimization/`，与原八项分栏。完成后保存此入口版本，作为 A/B 优化后的压力对照；先由数据更新成本分析，再推进后续优化，不能将小样本的 54%–57% 比例外推到压力输入。

**实施中的测量细化：** 压力诊断已确认 k=27,783、缓存记录 745,072。旧探针每次计量后都重复全域比较、消费、换轮和验证，首个独立热身进程在 260 余秒后仍未完成。按开发规范避免冗余检查：诊断及每个计量进程的最后一次结果做完整投影/消费/换轮比较，其他重复仅测同一事务与恢复；5+30、五个独立进程及事务边界不变。CSV 明确标出逐行验证状态，未执行的外围时间留空。首次热身中止并保留，不能计入性能结果；修订后的新旧核心统一使用相同探针重新开始，原 schema 2 历史数值只作背景，不作该测量组织下的严格版本对照。

### 3.1 A：有序局部暂存

直接只读借用 `CertifiedTarget` 已排序且去重的 Δ+/Δ−，用二分查找构成目标事件覆盖；不再复制为两棵 `EventSet`。F/C 使用局部向量收集，再排序去重；按 F 的有序遍历形成 R/A 向量，维持原有稳定顺序。旧边界检查对 R 使用二分查找。

所有暂存建立、排序、容量分配和析构计入事务。只枚举 Δ 的已有有界支持集，不扫描 J、旧全集、队列或 Pending。k=0 仍在构造暂存前返回。预计消除的临时树元素为 `k+F+C+R+A`，但不预设排序更便宜，不将元素数写成实际分配次数。

### 3.2 B：复用当前事务的记录定位

在局部支持描述中记录身份、旧/目标成员判定以及已存在记录的指针；只为 Δ+ 和 A 中实际缺失的记录分配。F 中未激活且未缓存的孩子保持不存在，不为省查找而扩大记录集。

State 的按身份 `SetEvent/SetLeaf` 与新增私有已定位入口共享同一状态修改主体。参考继续按需局部 Ensure；Patch 对已预留或旧状态已有记录直接传递句柄，消除后续 `k+R+A` 次重复 Ensure 的候选工作。局部表的建立/查找必须登记，不能用此调用减少量替代净索引减少量。

旧外部边界在任何拓扑/成员写入前捕获。目标活动位最终恢复仍覆盖全部 F；不得跳过休眠缓存记录的邻接清理。历史、Pending 基线合成、槽位占用与延迟退役照原语义执行，不把目标最终集合等价偷换为中间状态义务可删。

新增叶描述与外部端点携带所属记录指针；连接时同时传递邻接目标指针，避免按逻辑身份再次查找已知记录。仍按精确边键连接、按身份/槽位归组并检查重复写者，最终每条记录只有一个填写任务。候选资格及评分准备规则保持，未被本轮句柄复用覆盖的查询如实保留。

句柄只在本次 `Apply` 中有效，不跨状态克隆、事务或失败状态保存。现有节点 map 插入不移动记录、事务不销毁被引用节点，构成有效期前提；容器修改/分配仍由主线程完成。新记录静态准备完成后才消费其内容，三段执行返回前不得释放输入/异常槽。原失败状态丢弃规则保持。

数据流为：`已认证有序 Δ → 局部支持与旧接口 → 定位/预留记录 → 静态准备 → 原行为的状态修改 → 派生准备 → 携带句柄的边连接 → 唯一记录填写 → 原队列维护/发布`。不合并屏障、不修改线程池，不新增运行时策略分支。

### 3.3 最小计数契约

只扩展现有诊断模式，不计每次 C++ 字段读取，不添加系统 profiler：

- `nodeIndexProbes`：有效 `WorkSession` 内每次实际调用 `_nodes` 的 find/at/try_emplace 等定位操作；包含 Patch 的直接访问和局部表建立，排除计时外 clone/认证。它是字典调用数，不是树比较数或 CPU load。
- 暂存树元素数、局部排序输入项目数和暂存向量载荷：分别计费，不把换容器后的额外工作藏掉；有序向量查询另记调用数，不能当作零成本。
- 队列刷新次数延续 `queueWrites`；另列成员 map 与排序 set 成功插入/删除数、旧新条目相同的刷新数。相同值只作诊断，本轮不改变队列安装算法。

新增计数在关闭诊断时不形成独立计时任务或原子计数。计时表继续区分支持、分配、状态维护、描述、连接、队列/发布与三段执行；保持完整事务时钟覆盖暂存析构，残差保留。旧 `recordsMs` 的重叠关系明确标注，不相加制造重复成本。

## 4. 成本与收益验收

理论界保持 `O(kH+k log N+k log k)` 加实际评分费用；新增局部表最多 O(k) 项，且不能建立 O(N) 的查询加速表。标准容器串行维护和排序仍存在，不宣称本实现已实现理论低 span。

诊断中的候选成本包络约占 M1 的 54%–57%。若净减少其中 10%/25%，且其他费用不变，条件速度比分别约 1.06 / 1.15–1.17；50% 情景约 1.36–1.40，仅作强假设敏感性检查。依据和绝对值见[分析页 §5](../../research/roam_parallelism/target_materialization_serial_costs.md#5-预期收益如何表达)。这些不是预计保证值或硬性通过门槛。

验收先看实际净工作：临时树消除是否确实兑现；重复定位减少是否大于新增局部表查询；必要新建记录、评分、邻接、Pending 工作和完整投影是否保持。再看同配置完整时间；公共串行压缩可能同时改善 M1/M2/M4，不能把全部收益称为多核收益。

本阶段完成需要正确性、局部性、工作计费与前后性能对照齐全。若减少了逻辑操作却没有可辨认时间收益，记录这一结果及残余成本；不篡改基线、不调场景，也不因此撤销 MPR-02 的强可行性验证。确认性能退化时执行 §6 的用户决策流程。

## 6. 验证与冻结测量契约

### 6.1 正确性与工作量

复用 48 个合法 cuts、2304 对的独立参考/直接串行/4 线程完整投影与持续续接；2 线程只覆盖已有定向案例，不再复制一套穷举。重点覆盖 k=0、混合差分、深层合并再细分、缓存复用、共同叶多个外部槽位、非空 Pending、多次合成/消费/换轮、预算拒绝、过期认证与失败后任务结束。

新增定向断言检查局部句柄属于当前状态、缺失休眠孩子不被创建、活动位/邻接清理一致；合法认证的排序输入与原顺序结果保持。自然两项继续检查来源哈希、完整队列、消费及换轮，不用重导入修复输出。

新串行/并行的必需逻辑工作保持对应；查询/描述计数允许因本次优化改变，不能机械要求旧 19 字段全部相同。`primitiveGroups/fullScanItems` 的直接物化边界继续为零。只跑受影响原型测试和注释检查，不运行全 CTest、另一渲染后端或已关闭 Gate。

### 6.2 前后性能与统计

**用户于 2026-09-13 调整本轮执行范围：开发验证应快，不照搬最终实验。** 下述五进程矩阵保留为原协议记录，未完成部分取消，不再执行。实际采用已经完成的压力前两组完整配对，以及已有原八项正确性/单次诊断；第三组仅完成的新 M1 留存但不进入配对汇总。停止是用户对验证成本的调整，不是按结果挑选重复。未来正式采样另定范围，不从本轮自动续跑剩余命令。

旧输入保持 MPR-02 的八项：两项 sample14 自然输入；uniform d8/d12 各 1/16/128 个菱形。根据用户本次要求，另加 §3.0 冻结的压力项，独立标识、分栏，A/B 前后用相同来源，不覆盖旧清单。除该明确增加项外，不按测量结果另选“大差分”；线程仍为 1/2/4。

新 R/M1/M2/M4 各一次独立热身、五次独立计量，内部固定 5 次热身和 30 次从同一旧状态独立恢复；进程是主要统计单位。沿用旧 `--cases mpr-01`、方法/线程参数、RelWithDebInfo、正常优先级、全核亲和性及平衡电源，方法顺序轮换。复用[MPR-02 命令契约](target_materialization_prototype_02_plan.md#54-入口与产物)，只改本轮输出目录和 schema。

原方案以旧 R/M1 的既有五进程结果为历史基线，优先同期补测旧 M1。实施中因 §3.0 的验证组织调整，改为统一探针的同期比较：压力输入旧/新 R/M1/M2/M4，原八项旧 R/M1 与新 R/M1/M2/M4；各配置一次独立热身、五次计量，共 84 个进程。配置顺序按进程轮次轮换，原八项不重复旧 M2/M4。旧核心仅补新计数及相同探针组织，不包含 A/B；不得以历史 schema 2 时间代替修订探针的旧核心基线。

每案例报告进程中位数/P95、配对绝对差和速度比范围：旧 R→新 R、旧 M1→新 M1、新 M1→新 M2/M4，以及旧 M1/当前 R→新 M4。诊断另跑一次完整八项，不从诊断表推断精确 CPU work 或将分段改善替代事务收益。线程池初始化仍单列，事务内分配、排序、队列、dispatch/等待、发布及析构全部计入。

生产核查只保留原 test129/B4096 完整 64 点默认探针：`EnableTopologyValidation=false`、`EnablePassEvidence=false`、`EnableTopologyPairEvidence=false`，计时外校验保留。若生产源/构建目标及旧新二进制哈希不变，按大规划 §8 复用 MPR-02 已完成结果；若发生变化，才做原一次热身/五组 AB/BA。本阶段性能测试以发生修改的原型事务为主，不重复已关闭的生产微小波动调查。

工程调查门槛仍为每案例/指标的 `max(0.05 ms, 5% 基线值, 基线五次极差)`，中位数/P95 分别判断；触发后至多一次受控复测。确认问题后单列分析过程和原因，由用户选择独立修复小规划或调整后续规划。不用容差宣称显著收益，不追究不可分辨的几微秒。

## 7. 风险、替代与回填

首要风险是局部句柄读取了错误代的成员位，或复用行为入口时丢失历史/Pending 义务；必须保持旧接口先捕获、最终成员再应用和同一状态生命周期。若需跨事务句柄、更换持久容器或全量恢复才能实现，停止该项并重新 Review。

向量查找/排序可能抵消树节点节约，更多指针也会扩大描述载荷；须按同边界净工作和时间判断。合并资格的重复查询暂留，队列真实增删结果只用于后续决策。未来是否换队列表示或分配方式，须基于本轮剩余成本另行规划，不自动扩展。

### 实现情况

用户确认后按压力接入、成本诊断、A、B 的顺序实施。压力输入确有大差分：缓存 745,072 条记录，旧/目标叶数 195,367/200,000；Δ+=16,208、Δ−=11,575，k=27,783。完整参考、直接串行和四线程诊断均完成投影与消费/换轮比较，三段均记录到四条实际线程。历史 16,206 次 split/merge 没有替代当前净差分。

A 消除六个临时集合，以认证向量及排序去重的局部向量组织支持集。B 在支持描述、叶输入、端点及槽位更新中携带本事务记录指针，私有按记录修改入口与原按身份入口共用行为主体。没有修改 Reference、Hierarchy、Validation、Bridge 或 Executor，也没有创建新的 C++ 文件。保存了 A 的源码身份，但未单独计时，因此只能报告 A/B 合计时间效果。

压力诊断中，临时树元素由 190,051 变为零；命中缓存的重复 Ensure 从 92,280 变为零；实际节点字典定位由 636,837 减至 275,852（减少 56.7%）。新增 544,280 次局部向量查询，排序输入由 260,758 增至 399,673；向量载荷增加 5,958,064 字节。后一差值不含旧临时树节点，不能当作总内存增量。必要新建记录、评分、队列真实增删、邻接和 Pending 工作保持对应。

最终一次定向测试覆盖 48 个合法 cuts 的 2304 个目标对、串行/四线程的 29 项工作计数、既有 1/2/4 线程边界及两个自然来源续接；新增定向案例核对休眠缓存、乱序输入认证、当前副本指针归属与空差分。`src` 注释覆盖率为 3043/19821=15.4%，六个修改文件的摘要正文及标点核查无异常。未运行全 CTest、其他后端或关闭的 Gate。
