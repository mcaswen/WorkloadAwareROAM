## 1. 评估、目标与边界

**赞成优先验证出生规则，暂不实现 Lazy Queue。** 它有机会减少求出同一严格请求所需的维护，而不只是让原维护执行得更快。但出生完备性不是单独充分条件：还必须覆盖持续存在候选的改键、身份改组、失败后重新接纳，并保持初始化覆盖和每个查询时刻的有效条目覆盖。

本 Gate 回答：在同一已评分输入和当前严格控制器语义下，能否用有限局部规则维护足够的决策信息，使

\[
\operatorname{NextRequest}_{new}(S)=\operatorname{NextRequest}_{Legacy}(S),
\]

同时证明任意位置删除及相应反向位置维护不再是**决策队列**的必要动作。这里的 `NextRequest` 包含请求身份、分数、低分合并/预算交换原因，以及停止结果；根内前置、失败、预算和历史转移仍按当前规格执行。

本轮交付是源码对应的纸面证明或反例、有界原生核查和符号成本账本。**不实现新堆，不修改 Legacy/Planner 算法，不放宽严格夹具，不切换 E1，不补建 Native Materializer。** 不增加通用 profiler、完整状态模拟框架或新的自然性能矩阵。

Lean 的端点 `repair_*_queue_exact` 不作为本证明的前提。目标发现队列正确，不等于生产队列和 Γ 已能端点恢复；后者仍由原生支持集补证及原有 oracle 承接。即使本 Gate 通过，也只允许随后讨论决策队列原型，不代表完整 Tplan 或生产接入已通过。

## 2. 必须先固定的语义

### 2.1 输入和观察时刻

一次调用内冻结高度场、几何定义、相机、分辨率、阈值、最大深度、`BuildSequence`、上一帧迟滞集合及入口迭代上限。调用不跨帧，外部不同时修改来源。自然输入沿用 NMP 的已评分、共形、预算合法契约；现有故障注入、手工队列键和极值夹具单独标明适用前提，保留原断言。

审计状态至少包括：活动/缓存关系、逻辑候选成员及键、轮次抑制、失败缺席状态、预算与在途预留、迭代位置。不能只用当前 cut 表示 S。阶段入口、普通/强制基础操作、整个菱形合并、根返回、控制器查询分别建模；原始字段写入之间不默认共形。

必须列出的查询点：入口迭代保护、低分合并头、细分头及迟滞判断、部分失败后的新合并头、阻塞/失败处理后的下一循环、出口摘要。预算交换发生在部分前置之后，不能复用根开始时的合并头。

### 2.2 “可选择”不能等于“这次会成功执行”

分别定义 `TopoEligible`、`LogicalMember`、`Suppressed` 和 `HeadRelevant`。本规划的 `Selectable_decision` 指 `HeadRelevant`：**必须参与严格极值观察的逻辑条目**，不是全局极值本身，也不是满足 `ShouldSplit`、预算充足或执行前 `CanMerge` 的候选。

源码已经显示三个必须保留的区别：

- `NativeTargetPlanner` 只判断细分头的 `WantsSplit`；头部导致停止时不会继续寻找较低分候选。不能在求头之前用迟滞谓词过滤。
- `SplitScore` 与合并刷新使用有限的 `-float::max()` / `float::max()` 抑制值，抑制成员仍可能存在于逻辑堆中。首版证明保留这些语义条目；若想省略，先单独证明在明确键/阈值域内与原停止、交换和摘要观察等价。不能把哨兵直接当作不存在。
- 队列成员资格与 primitive 执行前复核不同。Legacy 会选出后失败并记录移除的条目，不能因为新验证器判断它“执行不了”就提前弹掉，跳过这次失败轨迹。

原生 `HeadRelevant` 的精确谓词及这些边界是第一步的交付，不预设普通 split 后“没有 merge birth”成立。新形成的组可能只是被本轮标记抑制；这与没有拓扑资格、没有逻辑条目是三种不同结论。

### 2.3 候选身份与键

细分身份优先用 `PathId`。合并先核查固定几何菱形身份到原生成员组的映射；MPR 的 `MaterializationHierarchy::Group/Mate` 只能提供候选映射，不能未经证明导入为原生事实。

当前 `MergeRepresentative` 在 Base 无效**或 Base 为活动叶**时接受单节点候选。因此单节点不自动意味着真实地形边界；需要检查临时单组、成对组及改组是否存在于声明的观察域。

若固定菱形身份成立，优先用它并单独保存原生代表的比较键；若不成立，允许以“类型 + 当前规范化成员 Path 集合”定义组身份，将旧组消亡、新组出生显式建模。不能直接以物理槽位当稳定身份，也不预先承诺分组查询 O(1)。

比较仍使用原生 Score/Path 规则。稳定组 ID 不得悄悄替换原生代表 Path 的 tie-break。需核查唯一性、同分、浮点极值和非有限值的输入契约；不能对全部 float 直接假设全序。

`Key_S` 指该时刻按原生更新规则应被观察的键，不自动等于重新计算的几何分数。纯 `Score` 在冻结调用内不随活动拓扑变化，但成员抑制、组内取最大值、代表变化和已有缓存键仍可能改变决策键。

## 3. 证明义务及 transition audit

### 3.1 主命题

对语义转移 `op : S → S'` 构造可执行的有限局部枚举规则，证明

\[
\{x\mid Selectable_{decision}(S',x)\land\neg Selectable_{decision}(S,x)\}
\subseteq BirthSet(op,S).
\]

允许保守超集，不要求集合完全相等，但必须计入多枚举和多验证的成本。`BirthSet` 不能定义成上式左侧，也不能通过全量比较前后队列算出；全量差分只能在小夹具中作为独立核查答案。

还需证明持续存在候选的发布完备性：

\[
PublishSet=BirthSet\cup RekeySet\cup RegroupSet\cup ReadmitSet.
\]

这里并集只表达覆盖责任，实际实现可去重。对仍可见但键、代表、依赖版本变化的候选，不能只增加 revision 而不重新发布有效条目；失败状态被取消后即使拓扑谓词未变化，也属于逻辑重新出生。

每条规则列明：前置条件、读取字段、实际写入、修改前/后局部种子、受影响身份、出生/失效/改键/重新接纳集合、证明、最大枚举规模及源码位置。旧邻域及旧伙伴必须在被覆盖前取得。不得把原 `Refresh` 的完整工作作为一个免费黑箱。

### 3.2 必须完成的审计矩阵

下表是待证问题，不能在结果中以“通常如此”填成已证明。

| 转移 | 细分出生 | 合并出生/重新接纳 | 失效或抑制 | key / identity 重点 |
| --- | --- | --- | --- | --- |
| 普通 split | 新活动孩子及缓存孩子重新激活；深度/历史抑制分别判定 | 新形成组的资格与 `SplitBuild` 抑制分开；检查旁侧旧失败候选恢复 | 原叶退出；相关组退出或被抑制 | 孩子继承字段、旧新 Base、组内评分 |
| forced split | 逐个成功基础操作的出生；根失败不能抹去成功前置 | 两侧任一 `SplitBuild` 是否足以抑制新组；仍检查侧向重新接纳 | 失败尝试、成功前置、根阻塞分别处理 | 普通/强制路径标记写入是否相同；forced 来源保留 |
| merge | 回到叶的父节点与 `MergeBuild` 抑制分开 | 更高层父组及关系改组；不只检查被合并节点 | 孩子退出、旧组退出 | 整个菱形完成后的代表与伙伴；半组期间的读取 |
| split block | 单独检查是否有解除/反向出生；本调用内没有解除也需证据 | 是否确实无影响 | 轮次阻塞改变键，不自动移除逻辑成员 | 哨兵键、迟滞、最终 Γ |
| failed merge removal | 是否确实无影响 | 移除本身不是出生；登记失败缺席状态 | 区分队列失败移除与拓扑失效 | 后续重新接纳时如何撤销失败义务 |
| failed candidate 重新接纳 | 是否存在对应路径 | `Refresh` 触及但拓扑资格未变化的候选必须覆盖 | 旧版本失效不能导致永久缺席或擅自复活 | 维护触及是否是独立语义触发；旧代表/伙伴的失败记录 |
| cache birth / child creation | 缓存存在、激活、成为成员是三个转移 | 休眠节点不能单凭创建成为候选 | 历史缓存仍可能非活动 | Path 重用、初始化字段、默认轮次；Γ/cache 义务 |
| budget reserve/release/exchange | 纯余额变化是否确实无出生 | 同左；exchange 内真实 merge 另用 merge 规则 | 余额不足不等于候选失效 | 预算影响控制分支，不能靠 pop 删除暂不可负担候选 |
| Base / representative / partner 改组 | 邻接变化是否改变细分键需核查 | 新组身份或持续身份改键；旧新接口全部覆盖 | 旧组和旧代表的版本失效 | 单组↔双组、规范代表 tie-break、失效读取依赖 |
| 入口初始化、轮次/评分切换 | 已有来源堆的初始覆盖 | 已有来源堆及失败处置的初始覆盖 | 跨帧抑制解除不得藏进本调用局部定理 | 本 Gate 按调用初始化，不宣称跨帧零初始化 |

**优先找反例的顺序**：失败重新接纳 → 动态分组 → forced split / 部分失败。普通孩子/父组规则可以作为候选规则，但不能跳过这三个边界先实施队列。

`Refresh` 目前会撤销重新入堆代表及伙伴的失败移除记录。若重新接纳依赖“被旧维护邻域触及”，须给出等价的局部触发枚举并计费；不能用理想 `MergeReady` 推导其已经自动解决。自然样本没有失败不构成证明。若要证明某类失败在合法可达输入上不可达，必须独立给出不变量，并继续保留故障输入的参考核查。

### 3.3 从出生完备到严格请求等价

按以下顺序证明，不能只完成最后一条通用极值引理就宣布 Gate 通过：

1. **初始化覆盖**：来源所有必须参与观察的成员都有正确身份/键对应；读取和构造成本登记为 `Q₀`，不当作免费。
2. **失效与生命周期正确**：验证器只否定语义上已经过期的版本；不能提前丢弃 Legacy 应选择后失败的候选，也不能让失败缺席候选仅凭拓扑资格恢复。
3. **当前条目覆盖**：每个严格查询前，对所有 `HeadRelevant(S,x)`，存在身份、revision、键均与 S 一致的有效条目。不是“以前曾发布过”；若使用待发布集合，必须在查询前完整排空，排空成本入账。
4. **极值一致**：有限条目中弹出过期头后，第一个有效条目等于 Legacy 的同分规则下严格极值。仍有效但改键的旧条目必须通过版本规则失效，不能掩盖新更高优先级。
5. **控制观察一致**：结合相同迭代、阈值、迟滞、预算和失败上下文，推出 `NextRequest` 一致；在相同且确定的 primitive/历史转移下归纳相同 root、forced 尝试、预算与停止轨迹。

第 5 项只消除决策队列的维护方式差异，不凭队首定理证明省略节点关系或 Γ 生命周期正确。生产端点队列恢复继续是另一条证明链。

### CB-01：冻结谓词、身份及观察域

完成 §2 和矩阵所有字段的依赖清单，对应 Legacy 与 Simulation 实际读取/写入。先用纸面小例子检查迟滞停止、哨兵、失效失败和单组/双组身份。

出口：准确的 `HeadRelevant/LogicalCandidateIdentity/Key/NextRequest` 和输入前提。若同一候选无法在有限局部信息下识别，或必须改请求语义才能定义规则，立即 Review；不开始测试框架或新堆。

### CB-02：逐转移推导出生、改键和重新接纳

按 §3.2 的危险顺序给出具体枚举器和证明。允许保守局部支持集，记录确切字段、常数和 Path 查询费用。一个根可能包含多次 forced 操作，根支持集按实际操作并集计费，不能宣称每根 O(1)，也不能只按净 Δ 计费。

“split 不产生可执行 merge”即使成立，也不能替代 `HeadRelevant` 的出生定理。反例如果只否定这条更强的简化规则，先检查有限扩大支持是否仍成立；若只能逐次重做旧完整 `Refresh` 才能给出规则，记录其未消除的工作，不以改名当作结构收益。

出口：全部转移完成证明或明确反例。出现全域反向查询、不可局部枚举的重新接纳，或未计费的候选重建需求时，可直接结束为 Review/No-Go，不必做后续设施。

### CB-03：覆盖不变量与原生有界核查

先完成 §3.3 的证明，再新增上述唯一测试文件。独立答案来自小状态中 Legacy 前后完整逻辑成员/键枚举；局部规则只能使用转移种子及已登记的局部读取，不能读取该全量差分答案。

复用现有同步事件和逐迭代入口。`SplitComplete`、`MergeComplete` 与整个刷新结束不是统一时刻，不能把每个完成事件都视为稳定队列快照。纸面证明覆盖内部子转移；测试在可正确观察的根/严格查询边界比较，并保留根内事件以核对实际操作。成功 forced 修改后根失败的路径必须留在枚举并集中。

若某个关键中间读取无法通过现有接口观测，明确标为“纸面覆盖、未原生逐点检查”或未决；不可伪造覆盖。若它阻止核心命题核查，停止补证并报告所需最小接口，不自行侵入生产热路径。

### CB-04：成本可行性与 Gate 出口

汇总理论和有限证据分别覆盖了什么，给出 §6 的符号费用、可删除动作及仍必需状态；保存最小反例或核查摘要。完成实施审查和与本规划的逐项比对。没有充分证据时不进入新队列实现。

## 5. 最小核查与性能边界

定向用例覆盖：普通/强制细分、部分前置成功后预算失败、普通/成对合并、阻塞、失败移除及重新接纳、缓存复用、改组、同分、迟滞停止、哨兵与入口迭代上限。设置两个核查器自测反例：**漏发一个高优先级出生而旧头仍有效**；**持续成员键改善但未重新发布**。它们应被核查器拒绝，而不是只看旧头验证是否成功。

先运行有限手工合法小状态和有界可达状态；穷举范围、节点/深度/步骤上限在 CB-01 按谓词冻结，达到上限即报告截断范围，不无限扩大。故障注入单列，不能与合法可达状态混称一般证明。规则通过后最多补一个原有 test129 / 预算 4096 / sample14 的冻结输入，只核查前 8 个严格迭代或提前停止；不更换输入追求覆盖或正结果。该例只是现实核查，缺失转移由解析例和证明承接。

## 6. 成本账本与通过条件

记 `m` 为实际语义转移数（包括失败/标记/重新接纳等必要转移），`v` 为局部规则总访问数，`b` 为实际出生/重新接纳数，`r` 为持续候选需要重新发布的次数，`z` 为过期头弹出数，`Q₀` 为初始成员数。另记 `p_push` 为实际追加条目总数，包括保守多发和重复发布。`k=|Δ|` 另列，**不把 m、v 偷换成 k**。

本轮登记：局部枚举与排重、逻辑出生、保守误报、push、revision 更新、过期头、有效头验证/重复 peek、候选最大驻留数、初始化、逻辑成员计数、失败状态、代表/伙伴查找。未实现的 heap 动作仅给模型次数，不称实测。

未来堆模型需计入 `Q₀` 初始化、`p_push` 次发布、`z` 次弹出及每次有效头的验证成本；每个过期条目最多弹出一次的摊还结论需要“本调用中条目不被重复复活”的生命周期前提。最坏驻留可能达 `Q₀+p_push`，不能假设自动有界于当前合法候选数；只有证明发布前验证与去重充分，才可代入 `p_push=b+r`，验证和去重本身仍计费。不把未来压缩/重建免费化。局部查询若需 O(H) Path 运算或索引定位，明确乘入 v 的费用。

潜在删减单列：任意位置 remove、反向位置修复、`SplitPosition/MergePosition` 投影。**代表/伙伴逻辑映射、失败状态和预算用的真实成员计数可能仍需保留**；带 stale 的 heap 长度不能再充当活动叶数。初始 Q 读取和其他节点覆盖也不会因移除 reverse position 自动消失。

历史压力数据仅作动机：CandidateChecks 428207、NeighborhoodAccess 1795522；42977 次延期失效中 25115 次已被现版本恢复，只有余下部分实际删除。不得把这 25115 次再次算成新方案消除的物理 remove，也不把它们当成成功 split/merge 事件往返。历史约 134 ms 不提供本 Gate 的费用系数或收益承诺。

用户在讨论目标发现费用后，确认继续推导“只读旧堆＋新增版本＋按需决策维护”。本轮仅 Extend 现有研究报告 §7 和实施审查，职责仍是队列语义与符号成本；不新增生产模块，不修改严格测试，不替换 Planner。独立 Python 小模型仅存入已有忽略的核查产物目录，不加入 CMake 或维护为新的算法框架。

用户确认同时推导两项工作削减：split/merge 方向性是否允许省去反向候选维护，以及 Δ/Γ 能否在逻辑转移中在线归约。职责选择为 Create 独立的[研究文档](../../research/roam_parallelism/native_target_discovery_reduction_derivation.md)及[审查](../../reviews/roam_parallelism/native_target_discovery_reduction_review.md)，Reuse 本阶段已有出生/登记契约与源码事实；Extend 本节记录。没有新增生产模块或规划新算法实现。

固定边界：保留严格请求、失败与停止观察；不改变 J 的定义，不修改原严格测试。方向性先证明固定前置偏序中的双向集合包含，再核对 forced 标记、合并恢复、Base/组身份与重新接纳；输出部分逐类核对现有七种 Γ，包含默认值随 Activity 改变、缓存存在性及失败尾筛。符号费用明确区分通知次数、不同触及节点数、过程峰值与最终输出规模。
