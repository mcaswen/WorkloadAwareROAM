## 1. 问题、目标与范围

回答：**一次已确定请求的强制细分中，能否识别有必要性依据、又不照搬递归顺序的先后关系，为有条件的并行上界提供证据？**

完成产物限定为一份审计报告：一页模型、三个小例子的图和边依据表、一个自然案例的既有证据核对，以及继续或停止的建议。发现“当前串行关系可以消除”也是有效结果；不以得到低上界为验收条件。

本轮只读源码和已有材料，进行纸面推导与小例子核对。不编写分析器、C++、Lean、测试驱动、CLI 或新数据格式，不运行自然轨迹，不恢复 GATE-03、CPU-CBT、activation-spectrum 或 recourse 推导。评分、合并、预算交换及完整严格收敛只用于标明范围缺口，不展开完整更新 DAG。

- 原操作会预留预算、递归细分底边邻居并刷新邻接；失败根可能保留已完成的强制修改。递归进入和完成顺序不是必要先后关系的证明。
- 现有观察记录根级去重读写集合、基础尝试/完成和预算轨迹，未记录每个基础操作的逐项数据来源。只重排 `CompletedPaths` 不能重建真实依赖。

## 4. 拟审计的执行边界

### 4.1 输入、结果与允许变换

输入为一个合法冻结网格 M₀、冻结几何与设置，以及一个已批准根请求；独立区域例子使用两个已批准根。局部例子预算足以完成其细分，执行期间仍保留硬上限；这隔离了请求选择与预算竞争，不代表自然工作负载预算充足。

外部结果要求相同的逻辑细分事件及叶三角形集合、连接关系和实际三角形数，不要求相同的内存地址、槽位、递归顺序或私有临时状态。结果等价不包含完整严格控制器的队列、停止与失败语义，后者在自然案例中显式列为未覆盖。

拟采用允许提前计算、私有暂存、预分配和联合提交的参考边界：只要信息能够从 M₀ 与已确定输入推导，就不能仅因当前代码晚计算而把它视为必须等待。推导、准备和合并写入都需要计费；不能免费使用未来 greedy 决策、未发生的合并或事后 trace 才提供的信息。

共形性在声明的完整操作发布点检查，不要求每次私有字段写入都形成可消费网格。联合提交是待审计的允许变换，不意味着现有邻接数组已经可以并发安全写入，也不授权实现新的批量算法。

### 4.2 任务粒度与边证据

先用唯一三角形路径识别逻辑细分事件，避免重复计数；再区分事件所需的准备计算和连接/发布工作。菱形伙伴可以联合处理，不能自动把二者的全部计算串成一条边，也不能无依据地把整颗 closure 视为不可分割任务。

每个例子必须明示任务粒度与成本单位。若使用原子菱形模型，只报告该模型的条件结论，并核对允许内部准备并行后是否仍成立。三角形增量 c、工作成本 w 与关键链时长不能混用；粒度或允许变换改变时重新核对 W 和链成本。

边依据表至少包含：前驱与后继、所需信息/状态、来源、必要性论证、可能消除该边的合法变换，以及“必要 / 指定顺序约束 / 实现选择 / 共同包含 / 未知”的分类。每条保留的必要边都须对声明的执行集合成立。变换能消除边时记录反例，不为了维持预期结论收紧模型。

预算容量和可任选顺序的冲突不自动变成固定方向的边。现有 R/W 不相交判据是安全独立的保守充分条件，其失败不能用于证明不可并行。

## 5. 实施步骤与局部停止检查

### 步骤 1：形成一页模型

按第 4 节列明输入、任务、发布点、输出等价、成本和允许变换，区分集合闭包与时间依赖。给出将一条必要链解释为 D_cert 的条件，引用方向记录中的同工作量上界；不重新扩写通用 work/span 定理。

**核查与停止：** 若无法在不预设串行执行的情况下说明任务与合法变换，先记录具体矛盾，停止上界推导。可以完成“模型尚不足”的报告，不创建采集设施。

### 步骤 2：审计三个小例子

| 例子 | 构造要求 | 核查内容 |
| --- | --- | --- |
| 两个独立区域 | 从合法规则网格取得两个外轮廓互不影响的细分区域；局部约束保持启用 | 给出独立处理及组合结果，检查是否错误引入跨区域串行边 |
| 互为底边的叶三角形 | 使用合法菱形，列出两侧子域与最终连接 | 审计“对侧先完成”是否必要；比较递归顺序、共同准备与联合发布，不把共同包含解释为时间链 |
| 多层强制细分 | 从两个根经合法菱形操作形成层级不齐的网格，再指定触发多层补齐的根 | 每条边说明需要新产生的状态，还是可以由冻结路径/几何推出；分开计算、发布与递归控制 |

三例均记录唯一事件、旧/新叶数与共形性依据。小规模允许纸面枚举相关顺序或构造反例，不要求编写穷举程序。有限核对可以反驳过强边规则，但不能替代对全部输入的证明。

**核查与停止：** 三例完成后，如只剩实现顺序或极弱链，立即记录证据不足；不增加更多夹具、全量足迹或场景寻找低上界。若构造第三例需要改 C++，保存缺口并停止该项。

### 步骤 3：核对一个自然反例

固定 `peking547-a-b20000 / splitTopology / sampleIndex=14 / selectionRank=3`，历史阶段输入哈希 `4677929227313376363`。只读上述 P4 分析及其引用日志：`benchmark-output/prep-04/topology-diagnosis-20260910.log` 和 `topology-plan-diagnosis-20260910.log`；规划时已确认两份日志存在。

核对空间安全请求提前提交、剩余预算与最终结果差异，逐项归入第 4 节的类别。它用于检查解释范围，不用于估计自然上界分布。本轮没有足够原始证据时标为未知，引用已提交报告并披露缺口；不重建历史二进制、不运行整条相机轨迹，也不将归档日志的版本冒充当前版本。

若步骤 1/2 已触发停止，本步骤最多保留已有报告的范围说明，不要求把全部内容做完才允许结束。

### 步骤 4：结论与完成审查

继续建议须同时说明：存在非平凡且有依据的必要关系；三例未暴露未处理的反例；未来可从哪些已有信息提取证书及缺什么信息。若借助了完整目标集合或额外推导，明确其来源与成本，不能宣称已有低成本分析器。

出口包括：值得另行规划证书提取；只支持实现层特征描述；当前证据不足、停止本候选投入。较高上界不是失败，较低上界不是自动成功。本轮结论不关闭 CPU ROAM 主线，不证明所有等价算法的上限，也不自动授权下一阶段。

## 6. 验收与验证范围

| 验收项 | 必须具备的证据 |
| --- | --- |
| 对象明确 | 初态、请求、结果、粒度、发布点、允许变换与成本一页内可查 |
| 边有依据 | 必要边有逐条论证；未知、共同包含、顺序约束和实现边分列 |
| 无循环论证 | 不用递归深度、trace 相邻或保守冲突失败直接证明关键链 |
| 三例有区分力 | 独立区域不被强行串行化，菱形处理共同包含，多层例来自合法网格；未完成项说明原因 |
| 自然证据有边界 | 固定案例身份，区分预算/greedy 与拓扑依赖；不由单例声称频率或普遍低并行度 |
| 与已有工作分开 | 复用旧闭包论证和 ROAM / Kremlin 来源；不将最长路径或依赖指导优化主张为新颖性 |
| 文件与状态一致 | UTF-8、相对链接、图和公式定界、修改范围检查；审查与本规划完成情况同步 |

本阶段没有运行时代码、构建、工具或可执行行为变化，因此性能前后测试不适用；不运行 CTest、后端矩阵、P5、此前 Lean 或微秒复测。该判断与[此前理论小规划](../roam_threshold/theory_workspace_plan.md)的纯研究验证边界一致，不以文档检查冒充性能验收。

若后续需要可执行分析器、插桩或脚本，本小规划不包含其实现授权；须先明确新增职责、成本和相应小规划，并依照[规划规范第 12 节](../plan_guideline.md#12-测试与验证)与[开发规范第 7.3 节](../../standards/development_guidelines.md#73-工程性能回归的实际影响门槛)冻结必要的性能对照及问题处理方式。

## 7. Review 要点与实现情况

2026-09-12，用户确认本小规划并要求开始。已确认的关键边界是“单次局部请求 + 允许预计算及联合发布”，用三例和一个历史反例审计必要性；完整严格控制器与真实 CPU 上限不在其证明范围。没有将范围收紧为只能逐菱形发布以制造低上界。

本轮已交付[审计报告](../../research/roam_parallelism/necessary_dependency_audit.md)和[完成自审](../../reviews/roam_parallelism/necessary_dependency_audit_review.md)：

| 步骤 | 实际结果 |
| --- | --- |
| 1：模型 | 明确允许预计算、私有准备、联合发布；区分目标共同包含、发布先后及基本数据就绪要求，三角形预算增量不作为任务时长 |
| 2：三个小例子 | 独立区域得到 32→36 叶的可交换修改；根菱形得到 2→4 叶的共同准备反例；由合法二分构造 8 叶初态，多层补齐得到 13 叶目标 |
| 2 的停止检查 | 多层例在逐菱形发布时有三层前置，但联合发布允许省去两个公开中间态；未得到适用于宽松模型的非平凡长链，不扩展取证或建立分析器 |
| 3：自然案例 | 只读两个既有日志并记录 SHA-256，核对剩余预算、rank、结果和网格哈希；其证据不足以恢复必要依赖 DAG，不重新运行轨迹 |
| 4：结论与审查 | 当前仅支持指定执行方式下的条件性依赖描述；报告未知成本和不可外推范围，不关闭 CPU ROAM 主线或宣布所有算法不可能并行 |

三例的子域、公共边、事件与叶数经纸面核对；未编写或运行计算验证程序，未新增 Lean 证明。文档验证覆盖 UTF-8、本地链接、公式/图定界、冲突标记和五个授权文件的范围一致性。没有源码、构建或运行工具变化，按第 6 节不运行性能、CTest 或后端矩阵；不把文档验证当作运行时正确性或性能证据。

本次实施授权不包含新增 Git 提交；材料保留在工作区等待用户审阅。后续若需要按更严格执行粒度进行工具分析，应另外讨论模型与成本，不自动延续为新实现阶段。
