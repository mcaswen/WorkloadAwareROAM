## 1. 问题、目标与非目标

检验：**在同一个抽象任务上，能否从明确执行步骤推导工作量向量、参数化 span 与有限处理器数下的执行选择条件？** 先验证结果契约，再比较成本，不用现有墙钟数据反向决定模型。

只研究细分评分、细分拓扑、网格提交三个代表阶段。输出须区分：抽象内核、完整阶段、条件定理、纸面对应与机器检查。允许评分和网格提交落在同一类结构中；不预设“评分工作高效、拓扑工作膨胀、网格有交叉”是三个互斥结论。

本 Gate 不证明真实 CPU 时间、不承诺论文新颖性、不证明 ROAM 的普遍并行上限。不开 profiler、不修改 C++/线程池/分配器、不运行 P5 或新自然轨迹、不拟合参数、不重建语义依赖 DAG、不设计新拓扑算法、不恢复 CPU-CBT、activation-spectrum 或 recourse。旧测量方案暂缓，不因本规划通过而自动启动。

## 2. 前置事实与职责判断

已阅读开发、规划、审查规范，当前研究定义、阶段配对事实、必要依赖报告、工作膨胀草案及旧理论工作区的工具链/验证记录；定向核对以下邻近实现：

- `DataOrientedRoamMeshEmit.cpp`：脏槽位写入共用确定性生成函数，计划、容量和维护仍需计费；完整重写与脏写不是纯线程替换。
- `DataOrientedRoamTopology.cpp`：原生串行与并行辅助的候选准备不同；完整严格收敛涉及持久队列、预算及动态状态，不能用冻结请求名单代替整个任务。

架构判断：研究说明与证明代码留在 `roam_parallelism`，不建立生产模块。**先写同任务规格及成本步骤表，再做少量证明检查**；不为形式化覆盖率建设通用语言、内存模型或调度平台。

| 阶段 | 候选输入与合法结果 | 第一组比较及必须补齐的义务 |
| --- | --- | --- |
| 细分评分 | 固定且无重复的活动条目、冻结视图与评分函数；输出相同身份对应的分数及必要镜像状态 | 顺序映射与互不重叠分区映射；同一项采用同一确定性计算。完整阶段另组合相同建堆/维护，明确逻辑队列语义和确定性平分规则 |
| 细分拓扑 | 合法初态、双方同样持有的已确定合法细分目标 J、预算与可用索引；输出相同逻辑事件、最终叶、连接及阶段声明的持久状态 | 优先审计逐项应用与全域扫描后物化同一目标的既有执行范式；每个成功基础事件只计一次，k 包括强制细分，不以根请求数替代 |
| 网格提交 | 固定拓扑、有效槽位映射、去重脏集合、冻结几何函数与旧输出；输出同一逻辑网格更新且非脏内容保持 | 顺序脏写与互不重叠槽位写入；公共生成函数复用。容量准备、脏区间整理和最终维护属于外层步骤，不免费提供或偷偷省去 |

### 3.1 拓扑的公平性检查先于成本代数

本轮首先尝试的是**固定目标应用子任务**，不是完整 strict greedy update。J 必须是双方输入，不得让某一方免费知道未来请求或最终闭包，另一方却承担发现它的成本。它的来源及产生成本分别登记为 `F_S`、`F_A`；子任务可在共同边界外给定 J，但完整更新结论必须恢复这些项。

每个候选至少审计：

1. n 是当前活动域、索引域还是完整潜在层次；双方不能用不同 n 而不说明。
2. k 是唯一成功基础事件数；存在跨层准备、邻接定位、路径展开时，不能直接假设每项只需固定 `c_E`。
3. 串行如何定位这 k 项；已有有效队列、目标索引、映射与证书由谁持有、何时更新。初态必须满足其有效性，跨调用维护不可隐去。
4. 批量方式为什么确实扫描 n 项；这是所比较设计的步骤，不是所有批量算法的普遍下界。
5. 最终连接、队列或供下一次更新消费的索引是否有同等保证。若只输出逻辑网格，双方均不得被称为完成了完整持久状态更新。
6. 共形性与硬三角形预算在同一对外可见点成立；私有准备存储另列规模，不能把活动三角形预算当成任意私有内存许可。

J 合法性可以作为双方共享输入前提；**两算法结果相等不能直接作为前提代替证明**。可以引用已有几何论证并清楚标记纸面验证范围，但有限例子不能替代一般对应。若只能比较三个旧局部例子，或只有假定相等后成立的算术引理，拓扑项未通过。

若达到等价需要新设计一个目标发现、物化或持久状态维护算法，停止该项，记录缺口。本规划不授权通过发明新算法挽救同任务比较。改变公开结果或预算语义，需要另行 Review。

## 4. 最小成本语义与比较规则

### 4.1 工作量向量与符号 span

第一版只使用七类带单位的原语：Q 评分、S 扫描/分类、P 计划/依赖访问、E 基础拓扑修改、M 网格写入、A 分配/维护、Y 派发/同步/归并。每一类在报告中固定粒度：例如一次有限大小记录的写入或一次二元归并；不能将任意大小的分配、排序、屏障或递归闭包算成一个常数原语。必要的子步骤分摊到已有类别，不无限扩充原语表。

采用 `Empty / Primitive / Seq / Par` 四个构造；`Repeat(n,e)` 为顺序重复的缩写，有限并行分区用 `Par` 组合。没有必要新增单独 Barrier 解释器，相关工作在明确的串行位置计为 Y。结构性 `Par` 只表示允许并行，实际分区、派发与汇合成本另列一次，不能遗漏或双计。

\[
\mathbf W(e)\in\mathbb N^7,\qquad W_c(e)=\mathbf W(e)\cdot c,\quad c\ge0.
\]

`Seq` 与 `Par` 的工作量均相加；span 则分别使用加法与最大值，保留为关于 c 的表达式：

\[
D_c(A;B)=D_c(A)+D_c(B),\qquad
D_c(A\parallel B)=\max(D_c(A),D_c(B)).
\]

不得先对各路径的工作向量逐分量取最大再估值；不同参数可能改变关键路径。本轮 span 只描述所写执行表达式，不描述所有正确实现的最短 span。输入大小 n、实际修改量 k、脏写数量 d、脏区间数量 r、块数 b、处理器数 p 分开使用；不得从 `b=p` 的特例推广到任意分块。

同一种原语采用同一 valuation。若单项成本不均匀，保留各块实际符号成本及其最大值，或给出已说明的上下界；不能默认平均分块就平均成本。涉及并发下每项成本改变的扩展不在首版主模型，不能无解释地给串并行的同一个 M 使用不同单价。

### 4.2 有限核数的排除区、保证区与未决区

以等价串行执行 S 的模型成本 `T_S=W_S>0` 为基线，固定 p≥1 和同一 valuation。对于完整列出成本的 A，引用理想同速处理器、无未计调度开销模型下的工作量/span 下界与 greedy 调度上界：

\[
\max(W_A/p,D_A)\le T_A(p)
\le W_A/p+(1-1/p)D_A.
\]

该界是已有调度结果的应用，不是本 Gate 的新定理，也不说明项目线程池达到它。对有代价的原语使用该界时，应声明与单位计算步骤的展开或适用的加权调度条件；不把一个不可分且消耗多核的集体操作套入单处理器任务界。[调度来源及模型](https://www.cs.cmu.edu/afs/cs/academic/class/15210-f15/www/tapp.html)

令 `I=W_A/W_S`、`β=D_A/W_S`，拟检查：

| 条件 | 在声明模型中的结论 |
| --- | --- |
| `I≥p` 或 `β≥1` | 不能严格快于串行；不等于所有替代设计都不可能加速 |
| `I/p+(1−1/p)β<1` | 理想 greedy 调度下保证严格快于串行 |
| 其余 | 单凭这些界未定，不强行赋予胜负 |

若只有串行和并行成本的上下界，则使用 `L_A≥U_S` 排除加速、`U_A<L_S` 保证加速；不把未知成本或一个松上界当作精确时间。空工作、零 valuation、零分母单列，等号不归入严格加速。

### 4.3 三项推导的预期形状，不预设结论

| 阶段 | 从步骤导出的量 | 需要有信息量的判断 |
| --- | --- | --- |
| 评分 | n 次相同评分、分区与汇合；内核 `W=nc_Q+H_W(b)`、`D=⌈n/b⌉c_Q+H_D(b)` 仅在等成本任务假设下成立；完整阶段加入建堆/维护 `G` | 固定块数、正单价且额外工作为低阶时的工作效率；加入 G 后的 span 限制。不得用内核的近似 1/p 声称完整阶段也如此 |
| 拓扑 | 从选定同任务程序列出定位、扫描、计划、唯一基础修改、连接、分配和维护；不先强设 `W_S=k(c_select+c_edit)` | 若明确设计必做 n 次扫描，尝试推出有限 p 下关于 `ρ=k/n` 的排除区。串行每修改项成本及索引维护必须有依据；闭包展开成本未知不能藏进常数 |
| 网格 | d 项生成/写入、r 个区间的整理及 b 块的执行组织；外层公共成本单列 | 从有取整的块执行界给出足够工作量保证加速的条件，并说明无法判断的区域。只有证明 h 与 d 无关才称固定并行税 |

所有简化式均需由步骤表导出，而非为了获得某种分类直接假设。评分与脏写若都是带组织成本的独立映射，就如实归为同类，二者都可能工作高效且存在小规模交叉。若最终只能得到与具体任务无关的 `nc+h` 常识，按第 7 节 No-Go 结束。

## 6. 实施顺序与提前停止

### PCSG-01：同任务与信息公平审计

先形成第 3 节的任务表和拓扑义务清单。给每一对候选写有限且可读的步骤，不追求通用伪代码语言。明确哪些公共结果必须相同、哪些内部顺序可变，证明分区等价及拓扑对应的适用范围。

**停止条件：** 拓扑无法在既有执行范式中得到同任务比较，或公平性需要新算法/大量状态模型，即判对应义务失败；可以直接完成 No-Go 报告。不得先堆评分和网格的 Lean 定理，再以已投入工作为理由延长拓扑探索。

### PCSG-02：步骤计数与参数区域

只对 PCSG-01 成立的任务列完整工作向量、span 表达式及前后状态维护；使用第 4 节统一规则推出排除、保证和未决区。为每个拟议非空区域给出一个合法符号参数实例或解析存在条件，核对实例满足任务前提，不能只给任意正数满足不等式。

**停止条件：** 只有任意 `H_W/H_D` 参数而无步骤来源、必须从 C++ 计时拟合才能决定定理、只能证明“并行有开销”，则记录 No-Go，不扩建证明语言。相同结构的两个阶段允许合并引理，不制造三种互斥标签。

### PCSG-03：必要的机械检查

仅在前两步留下实质结论后创建第 5 节两份 Lean 源文件。优先检查分区结果等价、工作计数的组合和关键不等式；来源几何、完整生产状态对应及调度模型分别保留真实验证层级。

定向反例/边界至少覆盖：n/d/k 为零、p=1、空分区与 b>n、零单价/零分母、整除与未整除、等号不严格加速、将路径向量逐分量最大误作 span，以及仅有并行上界时不能据其越线证明必慢。脏集合重复或目标不合法属于输入前提违反，不作为正确性正例。

**停止条件：** 证明工具缺失、需要新增依赖或形式化规模开始超出两文件职责时，保留已完成纸面与未检查清单；不为凑形式化覆盖率升级工具链。工具失败不是理论命题为假，但不能将未检查项标为 Lean 已证明。

### PCSG-04：出口与完成审查

给每项结果附“任务范围、执行范式、计数来源、valuation 条件、所用界、验证层级、尚未覆盖内容”。检查结论是否比原始假设多提供信息，能否约束后续有限核数的执行选择。回填本规划与研究索引，不自动转入采样、优化或新算法。

## 7. Pass / No-Go 契约

**Pass** 须同时满足：

1. 三个代表阶段都有可审计的共同任务及结果等价论证；拓扑不是仅凭假设结果相同或三个局部例子成立。
2. 工作向量和 span/上下界由有限明确步骤导出，没有免费目标、免费维护、未说明的 n/k 替换或人为串行边。
3. 至少得到能改变执行选择的非空参数区域，并有来自阶段结构的限制；不能只把标准调度定理改换字母。
4. 结果不要求三个阶段类别互斥；若评分与网格属于同类，仍说明规模、区间整理或公共串行维护如何影响适用区域。
5. 机器检查、纸面证明、外部标准定理与未证实现对应分列，完成定向反例与假设审查。

拓扑若只证明固定目标应用，Pass 只能写为**固定目标应用层面的模型 Gate 通过**；这不是完整 greedy 更新、当前 C++ 或实际性能通过。报告必须明确未覆盖的目标发现与跨帧维护，后续不能把窄范围结果改名为全阶段证明。

**No-Go**：同任务义务不能完成、模型需大量实现细节或新算法才能封闭、或者只剩通用“并行有开销”的结论。保留有用局部引理和具体失败原因，关闭本次小 Gate 的继续投入，不否定 CPU ROAM 执行与特征分析主线。不得通过缩窄输出、忽略公共工作或套用 CPU-CBT 旧数据挽救 Pass。
