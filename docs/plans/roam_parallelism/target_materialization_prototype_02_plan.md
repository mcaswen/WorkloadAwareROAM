# MPR-02：目标差分物化的有限并行与事务成本

> 日期：2026-09-12；类型：小规划；状态：已完成，完整状态物化与真实并行获得强验证，可以继续。
> 前置：[MPR-01](target_materialization_prototype_01_plan.md) 已提交为 `d876cea`；上层边界见[大规划](target_materialization_prototype_plan.md) §4.3、§7。

## 1. 目标与前置判断

本阶段验证：给定同一 M₀、合法 J 和完整 Δ，直接物化中的独立准备与记录写入能否取得真实线程收益，以及这些收益能否覆盖完整事务中的串行维护。结果仍是可继续评分、细分、合并和消费 Pending 的完整原型状态。

规划前已阅读开发/规划规范、大规划、MPR-01 小规划、[实施记录](../../research/roam_parallelism/target_materialization_prototype.md)、[阶段自审](../../reviews/roam_parallelism/target_materialization_prototype_01_review.md)及 CPU 阶段配对契约，并扫描原型状态、补丁、参考、桥接、验证、两个入口和既有线程池。

MPR-01 已解决本阶段的正确性准入，但不能据其四段混合计时推断可并行比例。两个自然任务 k 分别为 12、78；部分解析任务有小幅直接串行收益，自然任务没有稳定优势。已有诊断同时包含纯计算与容器维护，需要先明确执行所有权，再作测量。

本轮保持标准有序容器、独占事务、稳定身份和槽位生命周期。目标发现、差分生成/认证、导入、恢复、消费和换轮继续单列。不并行排序、标准容器增删、槽位分配或最终发布；不增加新目标算法、生产 DOD 写回、全域恢复、并行树、通用调度器或大型 profiler。

## 2. 共同路径与三个并行边界

### 2.1 先固定共同任务和对照

保留独立的 `reference-serial`：共同表示上的自然逐合法菱形参考，先合并到交集再细分到目标。不能让它调用补丁，也不能为共享新接口强加批量缓冲、全局排序或额外索引维护。

新的 `materialize-serial` 与 `materialize-parallel` 使用同一支持集、固定缓冲、队列规则和记录补丁；前者内联执行分块函数，后者通过同步执行回调派发。另保留 MPR-01 旧程序，分开衡量“准备方式变化”和“线程带来的收益”。不在新串行对照中继续使用旧算法而宣称只差线程数。

### 2.2 按代冻结输入、按记录确定唯一写者

| 顺序 | 主线程职责 | 可并行部分与完成条件 |
| --- | --- | --- |
| 事务入口 | 检查版本/预算；枚举 FΔ、CΔ；确定旧/新叶并保存旧外部接口 | k=0 直接返回，不派发 |
| ① 静态记录准备 | 仅为实际缺失的记录分配稳定容器位置，形成固定 ID/输出指针表 | 每条新记录独立计算父子、深度、域和伙伴；各写自己的位置，全部完成后才能读取新记录 |
| 目标代建立 | 串行修改事件、叶、槽位、历史和 Pending；准备候选资格、抑制状态、成员 ID/域描述 | 此后该代输入冻结；准备描述的查询和复制全部计入事务 |
| ② 派生值准备 | 预分配新叶边数组和候选值数组；按稳定顺序建立一个组合任务范围 | 新叶各写固定三条边；候选各算同一评分函数及所需成员最大值。输出位置互斥，不读取可变容器；全部完成后进入连接 |
| 连接整理 | 串行排序、分组和验证边；解析相邻记录；将同一记录的多个槽位修改合并为一个补丁 | 不能把同一保留叶的不同边当作可任意抢写整份邻接的任务 |
| ③ 最终记录填写 | 固定每个补丁的目标指针、邻接身份/句柄及修改槽位 | 每条记录一个写者；不读取其他记录正在修改的字段，完成后交还主线程 |
| 事务收尾 | 按原稳定顺序安装队列条目、归并局部计数、核对数量并发布新版本 | 无在途任务才能返回可用状态；临时存储释放也留在完整事务边界内 |

已有缓存记录不重新解码；队列资格由目标代确定，评分结果安装前不再改变该代。保留 MPR-01 的历史与 Pending 合成语义，不通过换轮、清空或重导入规避生命周期。

首版每个非空并行区按索引连续均分，分块数为 `min(请求线程数, 项目数)`；只有一个分块时内联执行。② 合并边准备和候选计算的任务范围，避免为每个微小循环单独派发。首轮不根据计时新增串并行阈值，也不搜索更有利的粒度。

### 2.3 只读、计数与异常契约

当前 State 的部分 `const` 查询仍会增加共享诊断计数，不能直接从多个线程调用。任务只读固定描述及不可变环境，使用分块局部计数；主线程在完成点归并。共享函数仍复用，但静态记录生成、候选值计算须与容器安装分开。环境评分回调必须可并发重入，不能隐式填共享缓存；现有桥接的自有只读环境需按此核查。

每块独占输出和异常槽。任务内部捕获异常，全部已提交任务结束后由调用线程重新抛出，沿用 WorkSession 的不可用状态规则，不发布半个结果。既有线程池不会捕获任务异常，因此异常不得逃出任务函数。

适配器还需覆盖“部分任务入队后提交失败”：在描述、回调和状态仍存活时排空并停止所持线程池，然后抛出并禁止复用该执行器。不能只捕获调用异常便让任务引用离开作用域。不承诺内存不足时的强回滚，也不增加异步取消协议。

## 3. 文件职责与接口

核心目录沿用 `src/experiment/roam_materialization/`。本小规划新增一对薄执行适配文件，供两个入口共同使用；这是对大规划同步回调方式的具体化，已随本规划获用户确认。

| 决策 / 文件 | 修改归属与边界 |
| --- | --- |
| Extend `MaterializationTypes.h` | 同步执行描述、局部计数/阶段证据及环境并发契约；只保存边界数据，不引用 DOD 线程池 |
| Extend `MaterializationState.h/.cpp` | 将静态记录构造与分配、候选值计算与队列安装分开；继续拥有全部容器、生命周期与失败状态。参考可复用纯函数，但其原子步不新增批量准备成本 |
| Extend `MaterializationPatch.h/.cpp` | 扩展 `Apply` 的执行参数，落实三段准备/填写和记录所有权；不另建并行算法副本 |
| Wrap/Create `MaterializationExecutor.h/.cpp` | 测试/探针共用的同步线程池适配器，管理初始化、借用回调、完成和提交失败时的排空；不读取物化状态或实现算法。仅实验入口编译它，核心库不依赖具体线程池 |
| Extend `tests/RoamMaterializationTests.cpp` | 对照新串行/并行完整状态、续接、唯一写者、真实线程和异常退出；复用原夹具 |
| Extend `tests/RoamMaterializationProbe.cpp` | 增加线程参数、并行方法和 schema 2；记录共同事务与准备/维护费用，不实现补丁 |
| Extend `tests/CMakeLists.txt` | 适配文件仅加入测试/探针源清单；不改变生产源清单 |
| Reuse `MaterializationReference`、`Hierarchy`、`Validation`、`DodBridge` | 保留参考高层顺序、几何函数、独立验证和来源接口；若纯函数提取影响参考调用，仅做等义局部接入 |
| Extend 实施记录、规划及研究入口；Create 阶段自审 | 回填既有研究报告，完成后创建 `docs/reviews/roam_parallelism/target_materialization_prototype_02_review.md`，记录实际边界与偏差 |

```text
测试/探针 → 同步执行适配器 → 既有 DOD 线程池
测试/探针 → Patch.Apply(状态, 认证差分, 诊断, 同步执行描述)
Patch → State / Hierarchy / 不可变评分环境
Reference → 原有局部状态操作；生产算法不依赖原型
```

执行描述由入口持有，借用期覆盖完整 `Apply`；同步回调按分块索引调用并等待完成。没有执行器的串行入口内联执行同一任务函数。选择薄适配器，是为避免测试/探针重复关键生命周期代码；不将线程池放进来源桥接，也不在核心增加具体 DOD 依赖。

## 4. 实施步骤与必要验证

1. **冻结基线和共同准备路径。** 保存 `d876cea` 与旧程序身份，确认八项输入/环境；拆分状态的纯计算与安装，先使新串行完成投影和续接对照。保留新旧串行成本，不能等并行成功后才检查参考是否变慢。
2. **加入同步适配与三段派发。** 确认描述/缓冲地址在任务期间稳定，完善异常排空。核心事务无并发容器写入，修改前已确定每条记录的唯一所有者。
3. **定向正确性与真实执行审计。** 覆盖下表，失败先修正当前边界，不用来源重导入或关闭断言。
4. **运行冻结性能矩阵、回填报告和架构审查。** 比较新旧串行与真实线程成本，核对大/小规划和注释规范；按出口结束本轮，不自动扩大并行范围。

| 必要检查 | 覆盖方式 |
| --- | --- |
| 完整结果等价 | 复用 H≤3 的 48 个合法切割/2304 个目标对，比较参考、新串行、4 线程完整投影；2 线程覆盖代表边界与两个自然任务，不机械展开全部笛卡尔积 |
| 续接与生命周期 | 既有深层合并再细分、混合增删、历史抑制、预算拒绝、未消费更新相消及槽位复用链；并行结果继续运行原操作，不恢复快照代替续接 |
| 记录所有权 | 定向覆盖保留叶多条边同时变化、同一合并候选包含多成员、旧缓存重新激活；检查固定输出范围和每记录唯一写者 |
| 失败与存活期 | 非法版本/预算在修改前拒绝；评分异常/非有限值在任务内捕获；受控提交失败检验已提交任务全部结束、结果不可用且调用后没有残留任务 |
| 工作与局部性 | 新串行/并行的逻辑工作一致，派发统计除外；`PrimitiveGroups=0`、`FullScanItems=0`、FΔ≤3k、CΔ≤2k；新增描述、复制、排序和分配按实际计数，不把所有缓存节点带入任务 |
| 真实并行 | 诊断每段请求线程数、分块数/规模及实际线程 ID。分块索引和线程池容量都不能代替实际参与线程；小任务由一条线程取完时如实记录 |
| 自然来源 | 复用 test129/Peking 的 sampleIndex=14，自有来源、预算、旧 Pending 和后续消费一致，来源哈希保持 |

执行器本身可用专门夹具同步验证多线程存活；真实任务不得为制造多线程证据添加等待。若冻结任务始终无法观察到至少两条线程参与有效计算，记录该限制，不声称已获得真实算法并行证据，也不换自然样本。

仅构建两个原型入口及既有运行时探针，运行本轮受影响的原型测试和注释检查。不重复整个 CTest、旧理论 Gate、其他后端或所有 CPU 配对。原桥接不变的既有证据继续适用；新路径仍须在两个自然输入上验结果。

## 5. 冻结测量契约

### 5.1 输入与方法

仍用 MPR-01 的八项：均匀深度 8/12 各细分稳定身份最小的 1/16/128 个内部完整菱形，共六项；另有两项冻结自然输入。不增加轨迹、不改变预算/相机/尺度，也不因工作量小更换输入。

| 自然场景 | 参数与来源身份 | MPR-01 差分 |
| --- | --- | --- |
| `test129-a-b4096` | TerrainSize=30、HeightScale=4、H=14；`18321219815115088613` | Δ⁺=6、Δ⁻=6，k=12 |
| `peking547-a-b20000` | TerrainSize=80、HeightScale=12、H=20；`4677929227313376363` | Δ⁺=44、Δ⁻=34，k=78，旧 Pending=24 |

新版本配置固定 R=`reference-serial/1`、M1=`materialize-serial/1`、M2=`materialize-parallel/2`、M4=`materialize-parallel/4`。每个配置一次独立热身进程、五次独立计量进程；每进程各输入 5 次内部热身、30 次计量。每次从相同 M₀ 的独立副本开始，复制及指针恢复另计，不连续应用同一 J 测 k=0。

独立进程是统计单位。五轮配置顺序预定为 `R,M1,M2,M4`、`M4,M2,M1,R`、`M1,M2,M4,R`、`R,M4,M2,M1`、`M2,M4,R,M1`；所有性能运行串行执行，不同时构建。报告每进程中位数/P95、跨进程配对差和比值、绝对差与波动范围，不把 150 次内部重复当作独立进程。

### 5.2 计费与诊断开关

**完整事务计时**包含支持集/描述生成、必要记录和临时缓冲分配、几何/评分计算、排序连接、所有派发与等待、队列/历史/Pending/槽位维护、最终发布及临时存储释放。线程池在每个进程热身前创建并复用，创建时间和线程数量单列；每次同步成本不能移出时钟。

诊断遍开启逻辑计数、阶段计时、实际线程 ID 和完整结果检查；计时遍关闭这些诊断，只保留外层事务时钟，结果在计时外验证。评分及记录查询不得因为关闭诊断而换算法。全量哈希、导入、目标发现、差分/认证、恢复、网格消费、换轮继续分别计费；事务时间只能称为**给定目标的状态物化时间**。

诊断报告分别列出主线程支持集/描述准备、分配、三个并行区（含同步的区间墙钟）、排序/连接整理、队列安装和发布；标明诊断扰动，不将局部阶段比值代替完整事务收益。分块内部计时如保留，仅作诊断，不能相加冒充经过操作系统测量的总 CPU 时间。

继续记录评分/查询、记录创建/复用、边及邻接写、队列写、Pending/槽位工作，并新增必要的描述项目数、临时存储规模和派发计数。N 沿用完整有序容器规模口径，缓存记录数另列。工作上界保留 O(kH+k log N+k log k) 加实际评分费用；本实现串行容器和排序不能宣称已达到理论低 span。

### 5.3 旧版本、生产基线与退化

修改前复用 `benchmark-output/roam-materialization/mpr-01/` 中已归档的程序、源码身份、五进程原始行和环境，并建立 MPR-02 基线索引。MPR-01 探针位于 `after/implementation/parallel_roam_materialization_probe.exe`；原始参考/直接记录位于 `after/prototype/`，汇总在 `comparison/summary.json`。不覆盖旧证据。

四类比较必须同时出现：旧 R→新 R 检查参考是否受损；旧 M1→新 M1 量化组织变化的成本；新 M1→M2/M4 隔离线程收益；M2/M4→旧 M1 及当前 R 判断是否仅追回新路径额外成本。历史基线与同期配对明确分栏；环境不一致时，先用保留旧程序在新环境重建相同串行基线。

沿用同一 Windows/VS 2022 RelWithDebInfo 配置、9950X3D、正常进程优先级、全核亲和性和原平衡电源配置；记录实际环境并校验，不临时绑定特定 CCD 寻找正结果。线程数固定 1/2/4，不扩展搜索。

生产默认路径仍只用 test129/B4096 的完整 64 点，旧归档与新探针各热身一次、五组 AB/BA。`default`、`diagnostics-off` 固定关闭 `EnableTopologyValidation`、`EnablePassEvidence`、`EnableTopologyPairEvidence`，计时外验证保留。核对旧/新程序哈希和输入身份，不重跑另一后端。

工程调查门槛为每案例、每指标独立计算的 `max(0.05 ms, 5% 基线值, 基线五次极差)`，中位数与 P95 分别判断。触发后仅对受影响案例作至多一次受控旧/新复测；探针可增加精确案例过滤，但默认八项和原输入不变，过滤不得用于删除首次结果。确认退化后先单独分析，再由用户决定修复小规划或后续规划归属。不用工程容差宣称统计显著收益，也不追究几微秒细节。

## 6. 出口、停止条件与回填

**完成条件：** 同任务完整投影与持续续接成立；唯一写者、同步返回、失败存活期和真实线程证据明确；局部工作界与完整费用有记录；新旧串行、线程矩阵及工程对照齐全。正确性完成不以性能为正为前提。

研究出口按证据区分：有稳定完整事务收益，可讨论后续目标发现/集成；仅局部准备加速而完整事务无收益，说明当前保守边界收益不足；串行容器主导，说明当前实现边界，不能据此否定理论物化结构。若并行只追回新串行路径增加的成本，须明确写出，不能作为净收益。两个自然输入只作原型现实核查。

若需要共享容器并发修改、无法建立唯一所有者、异常后无法保证任务结束，或出现未登记全域恢复，停止相关修改并 Review；不扩大成并行容器、调度器或新目标算法。本规划是本轮最大范围，不要求为完成矩阵绕过正确性缺口。

### 实现情况

**阶段判断：获得强验证，可以继续。** 用户在核对结果后明确认可给定目标的直接构造、完整续接、差分局部性和真实多线程执行，授权继续规划性能兑现。该判断指算法可行性，不将尚未取得稳定整体加速改写为性能通过；原始性能表和当前表示边界保留。

用户确认后按三段并发边界、薄执行适配文件与冻结协议完成实现。参考保留独立局部程序；共同串行/并行路径准备固定描述与记录补丁，核心仅借用同步回调。容器、排序、分配和发布保持主线程所有权，未修改生产算法或新增目标发现。

2304 个目标对的新串行/4 线程投影和 19 项逻辑工作计数一致；1/2/4 线程定向续接、历史/预算/槽位生命周期与失败路径完成。两个自然来源保持原哈希、混合差分和旧 Pending，消费/换轮后仍与参考对应。八项诊断无直接重演或全域恢复，静态记录和派生值出现真实多线程参与；极短邻接填写通常由一条线程取完，未人为制造并发证据。

全部八项、四配置、各一次独立热身/五次独立计量、内部 5+30 完成。M1/M4 的配对比在 Peking 为 0.903、test129 为 0.505；最大 d12-128 为 1.023，但范围 0.814–1.119、仅 3/5 更快。当前有限边界没有稳定完整事务优势，不能将相对参考的收益都归因于线程，也不能将结果写成理论物化结构的否定。
