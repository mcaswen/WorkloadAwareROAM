## 1. 目标与冻结边界

本阶段集中压低 `BuildNativeSplitTarget` 的完整串行费用。当前压力输入的规划时间约 1089 ms，明显高于同轮 Legacy 完整细分阶段的约 62 ms；必须先处理这个缺口，再讨论原生物化带来的生产收益。

优化双方解决同一任务：从同一已评分、共形、预算合法且关闭评分镜像的 M₀，独立得到相同的严格决策、净 Δ、封闭 Γ、纯求值缓存及停止摘要。用户已确认性能门槛，并进一步授权测试后直接调整、扩展优化方案；原三个优化包只是首轮实施顺序，不是优化空间或授权上限。未达标时详细记录各子阶段实际费用及复杂度差距。

必须保持：

- Legacy 控制器和生产直接数组访问不变；新控制器仍独立，不能调用旧执行器获得目标。
- 来源只读，不克隆完整 ROAM 状态。首轮使用稀疏覆盖；后续若改用分页索引或仅复制决策堆，必须登记其初始化、复制、容量及销毁费用，并明确增加的 N/Q 相关成本，不能继续声称完全按触及量付费。
- 低分合并、严格头请求、强制前置、部分成功、预算交换、阻塞及停止顺序不变。
- Γ 不增加最终邻接、活动数组、堆布局或物理槽位；工作区在返回前销毁，不转交物化器。
- 同步调用及 Planner/View/Queues/Simulation 职责保持，先压低串行规划 work；MPR 独立参考保持。

不做排序松弛、跳过必要资格复核、改变预算/评分公式、生产开关、GPU 或新拓扑算法。不通过关闭全部计数、缩减结果载荷、挪出析构或改变来源预热制造提速。严格失效的资格缓存、节点/堆采用不同表示及独立准备的并行执行不是原则性禁区，但必须先给出失效/依赖契约、成本依据与定向验证，再按用户已有授权更新规划实施；不能为了追求时间改变候选可见时刻或严格决策顺序。

采样前冻结的出口规则：

1. 四倍优化仅为中途进展指标，历史值对应约 272 ms，不构成继续接入条件。
2. **硬通过线：压力输入完整 Tplan ≤ 同条件 Legacy 完整细分阶段的 80%**，历史值对应约 49.3 ms；理想目标为 50%，约 30.8 ms。以当前同条件实测比值判定，不把历史毫秒值作为新机器的固定上限。
3. 两个普通输入不得有按开发规范认定的明显退化，严格语义和全部计时边界必须保持。
4. 原三个优化包作为首轮范围：覆盖存储；堆修复与收尾；有热点依据的纯评分复用。用户随后授权：测试后有依据的范围外优化可以直接补入本规划实施，无需逐项确认，目标继续争取 50%。每项补充必须先登记触发数据、收益假设和有界验证/停止条件；不降低 80% 接入门槛，不更换输入。最终仍越线或采样不确定则暂停 NMP-02，不能无限追加优化。
5. 临界/明确波动最多追加一组独立对照，两组保留且反转运行顺序，不选最快值；仍不明确则不认定通过。明显远离门槛时不追加。

未通过时仍须完成本规划 §7 的实际成本及复杂度审计，保留有价值的改善。退出限定于当前生产性能接入，不否定已经成立的语义解耦和物化证据。即使通过，完整阶段仍需另验 Tplan + Tmaterialize < Tlegacy。

## 3. 方案与职责归属

整体依赖保持：测试/探针 → Planner → Simulation → View/Queues → 原生只读状态及纯规则。存储优化放在 `materialization/` 内部；Legacy 不经过新覆盖表。

### 3.1 先建立足够用的成本边界

复用现有探针，增加按精确案例 ID 选取单个输入、仅诊断/仅计量、可选成本诊断的能力。默认三点协议仍可用，不再创建 profiler 平台或第二套来源生成器。

成本诊断仅记录以下互不重叠的大区间：工作区构造、严格循环、净出口提取与排序、指标收尾、私有工作区销毁。结果对象清理继续单列。普通 `Tplan` 用原调用外包络直接测量，不能以这些区间的和代替；诊断开销和无法归入的差值单独说明。

`NativePlanningAudit` 扩展一个同步借用的成本接收结构，普通入口不请求它。默认成本遍只记录上述大边界；按用户补充要求，另提供一次详细成本遍，在语义操作边界计时：队列维护、邻域收集、资格复核、纯评分、虚拟缓存创建、私有细分/合并变更及其余严格控制。嵌套区域按互斥自耗时汇总，同时保存调用次数；不在每次字段读写上计时，不把父项包容时间与子项相加。

有限计时枚举、接收结构与作用域放在 `NativeMaterializationTypes.h`，由现有 View/Queues/Simulation/Planner 仅在对应语义入口使用；不新建 profiler 模块。详细遍不开完整轨迹/读集合或回调。分别报告普通、大边界、详细遍的总时间与差额，不把详细计时的扰动硬减成未插桩的精确子项。最终必须具有两层分解，不能只给一个严格循环总时间。

首次定位优先对压力案例的一次正常规划调用做用户态采样，必要时借助 Ubuntu 已可用的 `perf`。采样只用于排序热点；没有权限或工具时直接使用区间、现有计数与逐步消融，不安装大型工具、不反复排查环境，也不把未获得的归因写成事实。采样报告需要区分来源生成和规划调用，不能把整个进程的建场景开销算给规划器。

### 3.2 紧凑整数覆盖表

建议创建模块私有的 `NativePlanningStorage.h`，提供一个**仅供本轮临时整数键覆盖使用**的小型追加式表：连续记录向量 + 开放寻址的“键到记录下标”索引。无有序遍历要求、无物理删除、无并发 API；删除队列成员继续保存显式无效值。

核心约束：

1. 哈希槽保存记录下标的编码，空槽状态不占用合法键值；无效节点/无效位置作为值与“无覆盖”严格区分。
2. 只随实际记录增长，采用统一几何扩容和固定负载上限。禁止按 N、Q、已知冻结答案或案例名预留容量。
3. 查找预期常数费用是哈希模型下的期望，不宣称最坏 O(1)；扩容重建只处理本表记录，费用和瞬时旧/新存储同时计入。
4. 记录下标在追加后稳定，向量指针/引用不保证稳定。跨可能插入/扩容的调用只保存下标，返回后重新取记录；尤其不能跨 forced 递归持有引用。
5. 只枚举已创建记录。容量、扩容搬移、探测次数与最大探测长度在诊断中可见；计量遍不维护昂贵分布。
6. 空调用不分配大表；分配或重散列失败时终止本次规划并由 RAII 清理，不能继续使用部分写入的工作区，来源保持不变。不能通过跨调用常驻容量把费用转移到别处。

首先替换节点覆盖以及堆 Cells/Reverse/代表/伙伴等高频树表，保留各自所有者。求值缓存可复用同一表；低频失败合并集合和诊断用 set 无需为了形式统一全部替换。

Fields 采用值数组加字段存在位图。允许写回基值后继续持有覆盖，净 `ChangedFields` 在收尾按入口基值比较；“曾触及”“持有覆盖”“最终不同”分别统计。首次无效写仍不能凭空制造触及记录。原 `TouchedNodes` 的累计语义、无效关系、虚拟默认值和 Γ 规则保持。

表的 Find/Create 返回记录下标，View 在一次 Write 或一个明确无插入区间复用定位。只重用存储位置，不把会随当前递归变化的邻接值缓存到未来步骤。路径查询仍沿已有孩子下降，不建全域 PathId 字典。

**备选与选择理由：** `std::unordered_map` 改动较少，但仍逐项分配节点；首轮主方案直接处理树查找与记录布局两项成本。全长数组、堆副本、按需分页属于其他存储设计点，暂未实施，不等于没有优化价值。若平坦表仍显著受限，依据覆盖和成本登记下一方案后直接实施；节点和堆可以采用不同表示，不要求为统一容器牺牲热路径。堆副本仅限决策数据，必须完整计入 O(Q) 复制，不得变成复制完整状态或调用 Legacy 求目标。

### 3.3 堆修复改为携带条目、沿洞搬移

在既有 `DataOrientedRoamIndexedHeap.h` 增加静态绑定的条目搬移形式，由 Queues 提供读取、写入和比较；旧交换式接口及 Legacy 保持原状。

修复时保存待定位条目，逐层读取父条目或两个孩子，选择与当前比较器一致的方向，将选中条目填入洞，最后写入待定位条目。每层不再先比较读取、随后为了交换再次读取同一对条目，也不必在每层把待定位条目写回临时位置。

必须保持反向位置在本次修复返回前完整一致。修复中没有外部回调或重入；若内部步骤会查询尚未落位条目的成员位置，必须先消除该依赖，否则不能使用洞算法。严格轨迹不包含内部搬运；最终成员、分数、代表/伙伴及根选择必须完全一致。

删除、分数上调/下调、尾部截断再追加、显式删除覆盖、平分 PathId 顺序均按独立成员 oracle 核查。优化后的内部 heap 读写次数允许下降，不能为了保持旧指标数而继续做无用访问；旧堆覆盖率也不能当不可改变的算法下界。

### 3.4 局部收尾与纯评分复用

先消除 Extract/Metrics 中对同一覆盖记录的重复定位：直接枚举记录，在单节点局部读取入口默认值和最终值，生成 Δ/Γ 并计算净字段数量。必要的输出排序保留，排序项目和载荷数量不得减少。新虚拟区间、最终仍有效的失败移除也不能漏掉；不因 k=0 直接跳过 h>0 的结果。

只有成本诊断仍指向评分时，再启用调用内纯评分复用，作为独立消融步骤：

- 复用已有实际求值缓存，键为本调用稳定节点身份。Domain、GeometricError、视图、地形/高度比例和评分设置在调用中不变；首次计算保持原浮点运算顺序，不引入 fast-math 或近似值。
- `SplitScore`、资格判断、轮次抑制、合并复核和队列刷新仍在原逻辑位置执行；只复用其调用的 `ComputeScreenErrorScore` 结果。不将 ±最大有限数的资格抑制当作纯几何分数缓存。
- `ScoreEvaluations` 继续表示实际计算次数；新增 `ScoreRequests/ScoreCacheHits`，保持 `Requests = Evaluations + Hits`。跨版本比较逻辑请求与严格轨迹，不能再要求优化前后的实际求值数相同。
- 同一来源下缓存开启/关闭的输出、完整决策、Γ 和分数位值一致；不同调用重新计算，不借用上一相机的值。测试变体不增加 GUI 或生产策略开关。

此项不保证足以改变总成本。压力点已缓存身份与总调用数的差只说明重复求值机会，不能直接外推整段时间节省比例。

## 5. 实施顺序与停止条件

### 步骤 1：冻结对照并定位主要费用

保留 `2f04f48` 二进制及构建参数，先只扩展测量入口和大区间诊断；同一核心在新旧探针包络的普通 Tplan 应一致。冻结版本标识、参数与产物协议后，再改存储。

压力输入先做一次区间诊断；有现成采样能力时补一次调用级采样。输出已证实热点、未确定部分、构造/循环/提取/销毁比例及容量清单。若工具不可用则按源码计数开始有界消融，不把取 profiler 作为无限等待条件。

### 步骤 2：覆盖表示与节点访问

实现并验证小型整数表；先接 View，再接 Queues 和实际求值记录。使用统一增长规则，不逐案例调容量。完成组件与严格夹具后，只复测压力输入的一组短计量，与本步骤前基线比较。

若结构正确但收益低，依据区间判断是否继续堆修复；若表自身重散列/探测/分配成为主要负担，先修表内缺陷，不扩展成多容器自动策略。来源全扫、持久借用或返回布局等边界有破坏时立即停止相关修改。

### 步骤 3：堆搬运与收尾

接入值搬移堆修复、单次记录定位和出口汇总，保留必需排序与清理。再次执行受影响组件/严格夹具，压力一组短测对照步骤 2。若有代表性的无收益修改，移除它并记录，不因已经写完而保留额外复杂度。

### 步骤 4：按热点处理重复评分并闭环

仅当评分仍是可观成本且冻结纯值条件成立时启用 §3.4 的复用，单独验证缓存开关等价并记录消融；否则写明未实施理由，不为完成清单增加改动。

最后在三个原输入上完成一次完整诊断与最终短对照，提交原版本→各步骤→最终版本的费用、逻辑工作和容量变化。未解决的主要瓶颈列明已证实部分和推测，形成接入 NMP-02 前的 Review 输入。

各步骤规定首轮顺序，不要求无条件做完全部备选，也不限定后续只能再做几个优化。每轮根据剩余成本选择一个可验证的方案，登记假设、预计能影响的时间占比及保留/撤回条件；无效方案允许撤回，不能把某一种容器无收益解释成 Planner 无法继续优化。达到目标后完成验收；仍未达标时，只有剩余热点没有可信的可实施收益机制、连续证据否定该机制，或需要破坏语义/计费边界，才结束本轮并报告原因。80% 与 50% 门槛保持，不以优化包数量代替退出论证。

## 7. 复杂度、预期收益与结论边界

设 m 为各私有表实际记录总量，L 为实际节点/堆索引访问量，z 为净出口及求值缓存的排序项目总量。当前树表部分的费用可包含 `O(L log m)`；平坦整数表的目标是将该部分降为预期 `O(L + m)`，另保留向量扩容、初始化、清理和 `O(z log z)` 排序。不同表规模实际不同，这只是成本分解，不是全部严格规划复杂度定理。

洞修复仍需沿 O(log Q) 堆路径，不消除全局优先级维护。压力堆覆盖可能继续很广；改善来自较便宜的定位和较少的搬运，不能称为减少了强制依赖或已得到稀疏堆算法。

若实测可优化部分占比为 f、该部分缩短 s 倍，完整收益上限按 `1 / ((1-f)+f/s)` 估计。f 必须来自分区或采样依据，不能预设 90% 费用属于 map，也不能承诺换容器必达四倍。

最终同时报告原/新 Tplan 比、与 Legacy 的绝对差，以及剩余循环/求值/提取/销毁成本。即使优化后的规划比 Legacy 更快，也仍只是目标发现的成本；只有加上未来原生物化后，才能谈完整细分阶段收益。

**未达标必须交付的复杂度审计：** 对每段列出实际时间、调用/访问/记录/排序规模，以及对应的变量与上界。明确区分：算法仍需执行的严格动态工作；覆盖/堆修复新增工作；期望哈希界失效或增长搬移；满足复杂度但常数大；以及原理论前提不适用。MPR 给定目标的 O(k) 或 O(k log k) 局部物化界从来不是本 Planner 的目标发现界；不能因 Tplan 没有达到期望时间就声称违反该定理。若现有三点不足以证明渐近增长率，明确不能证明，不为补复杂度曲线擅自扩展输入矩阵。

1. **索引槽内保留键**：当前碰撞判断每次回读分散记录。改为槽内键加 32 位记录编码，节点键的槽宽可保持 8 字节，较宽键的额外容量如实记录；不改变输入键域或覆盖语义。先实施并测一组压力，与评分包结果对照；未有明显收益则不保留额外复杂度。
2. **热点字段读取的静态内联**：按资格/邻域高频调用，将 View 的薄读取/来源映射保持在同一类内并对编译器可见，允许固定字段消去通用分支；不改编译器选项、评分或计数契约。只移动和核对原函数主体，不改变数据所有权。独立测一组压力，若无明确收益则撤回这部分。

这两项完成后先检查剩余成本，不因此自动结束本轮。用户已指出原“两项后仍越线就停止”的限制过窄，此处撤销该限制；按需分页、堆与节点分开表示、局部字段批量读取及具有严格失效规则的资格缓存均可成为后续候选。仅复制决策堆也可以评估，但须显式增加 O(Q) 成本并修订局部性表述。每次选择仍以真实热点和可审计收益为依据，不同时堆入多套策略。

最终三点和两层成本分解在选定版本闭环时完成。若仍不通过，应解释哪些剩余费用不能被已分析方案有效压低，而不是因为预先用完两个名额。哈希平均/最大探测和容量将用于区分期望界失效、额外工作与常数成本；不能只说“理论复杂度没达到”。

### 9.3 按需分页索引试验

带键哈希槽的压力短测为 Planner 250.217/237.765 ms、同轮 Legacy 74.714/86.766 ms，尚未达标。现有节点/堆键是受验证的 32 位数值下标，百万级反复查询不必始终支付整数混合、碰撞探测及键比较；下一试验改用按键直接定位的页索引，连续覆盖记录仍复用原存储。

- Create `materialization/NativePlanningPageIndex.h`：只负责整数键到稳定记录编码的索引。页长固定 256 个 32 位编码，目录保存独占页指针；读缺失页不分配，首次写才分配并清零该页，记录编码零仍表示未覆盖。
- Extend `NativePlanningStorage.h`：通过编译期索引选择复用记录追加、枚举、显式无效值与容量计费；先对 View、Queues 和求值缓存统一试验，不增加运行时自适应策略。原哈希实例保留为通用宽键组件对照，生产 Planner 的页索引键不得截断。
- Extend 现有 Types/Probe：单列索引种类、页数量、目录容量/初始化/搬移及峰值上界。目录随已写最大页号增长，因此工作界应写为 `O(L + m + B·b + qmax/B)`，B=256、b 为已分配页数、qmax 为最高已写键范围；这不再是完全独立于数值域高水位的 `O(L+m)`。
- 全部记录、页、目录的分配/销毁留在普通 Tplan 内；来源节点与队列仍只读，不复制实际字段到缺失页，也不初始化完整最终状态。
- 定向验证页边界、跨页目录增长、已存记录、显式删除、缺失页只读、宽键拒绝和原严格夹具；只加一组压力短测。若无实质改善，撤回 Planner 的索引选择；若改善但仍未达标，再按新成本定位，不能自动判死。

该试验针对定位常数而非决策算法，预期主要影响队列、资格及邻域区间。它不能消除严格控制、候选资格本身、堆路径或最终出口排序，不能预先承诺单项就达到 50%。

实际短测：仅内联为 258.601/275.308 ms，没有独立提速证据；保留编译器可见读取作为随后页寻址试验的组合基线，不将其单列为有效优化。页版为 168.767/178.571 ms，同轮 Legacy 82.295/77.118 ms，均值比约 2.18；组件及逐步严格夹具一致，完整自然审计在最终候选版本执行。页索引有实质改善但仍未通过，继续定位而非按名额停止。

### 9.4 封闭候选维护区间内消除往返堆修改

源码核对表明 `Invalidate → 私有 primitive 修改 → Refresh` 之间不查询合并队首，也不调用外部决策回调；所有递归前置均在进入此区间前完成。当前却先把旧候选从 heap 移除，再把仍然合格者重新插入。下一项试验保留相同的逻辑失效、刷新顺序与评分时机，只合并区间内最终互相抵消的 heap 维护。

- Extend Queues：增加受检查的合并维护区间。失效仍立即清除代表/伙伴映射，保存待清理旧代表；heap 和反向位置暂留在私有区间内。Refresh 重新接纳相同代表时更新原条目，区间结束删除未恢复者。新代表/伙伴改组仍遵循原映射规则。
- Extend Simulation：只在原 Invalidate/Refresh 包络启用；所有正常及原防御失败出口必须关闭区间。Merge Top、全量验证、Metrics 不得在区间未关闭时使用，正常根选择只见完整逻辑结果。
- 不要求私有 heap 的物理排列相同，但分数/Path 全序、逻辑成员、最终预算、Γ、所有根及停止轨迹必须相同。已有严格逐步投影仍独立于优化后的维护代码，Legacy 不改。
- 工作计数新增延迟移除请求、恢复条目与实际删除数量；既有堆读写按真实行为变化，不能把暂留条目算作少做资格复核。若条目分数未改变且成员一致，允许跳过无意义 Write/Restore。
- 先补区间未关闭拒绝、存活/失效/改组等组件检查，再跑原严格夹具与一组压力短测。目标是减少实际 heap work；若语义不一致先修正或撤回，不放宽轨迹。若省下访问但没有实质时间改善，记录后按剩余成本决定是否保留。

该变化不延迟到下一根或下一帧，不改变“谁可被严格控制器选中”。其依据是封闭区间的观察边界，不是宣称资格或动态依赖可以省略。

实际结果：压力原 42977 次逻辑失效中，25115 个代表重新接纳并保留原条目，17862 个最终删除；25115 次相同位值更新免于修复。合并堆读取 469423→328211（约 -30.1%），写入 221411→145560（约 -34.3%）；细分堆读写不变。逐步夹具和三点完整自然轨迹/投影/Δ/Γ 均一致，压力 156720 事件没有截断。

短测均值 Planner 166.136 ms、Legacy 85.476 ms；后续三点验收进程的压力均值为 179.746/59.634 ms。前后进程波动明显，当前只确认实际 heap work 减少，不宣称该项独立取得稳定完整时间收益；保留为已经通过语义审计的中间候选。压力远离门槛，不追加重复轮次寻找有利比值。

### 9.6 连续决策 heap 槽位

根据 §9.5 中仍超过百万次的 heap 读取和队列详细费用，先仅更换槽位存储，不同时改节点/反向位置或控制器。当前槽查询经过目录→页编码→记录值三次定位；连续 heap 直接按槽位索引，代价是首次真实修改时复制该堆的全部 Score/Node。

- Create `materialization/NativePlanningHeapSlots.h`：拥有连续私有条目及逐槽曾写标记，管理首次复制、后续增长和容量计费。它不决定堆序或成员资格，两个来源 entry 类型通过字段转换导入，不做类型重解释。
- Extend Queues：构造仍借用来源长度；首次 Write 前复制对应堆，之后从私有数组读取。截断保留高水位存储，但下一次追加仍完整覆盖；反向位置/代表等继续使用当前页索引。不得复制 Nodes、活动列表、mesh 或整个 State。
- Extend Types/Probe：复制条目数、数组种类、标记初始化、增长搬移、容量和来源读覆盖单列。首次复制为 O(Q)，诊断必须报告完整来源堆读取，不能把它混成只有少量被写槽位。复制/初始化/销毁全部在 Tplan，未写堆不分配副本。
- 测试复用任意删改/尾部复用/平分/封闭维护和严格夹具，补首次写才复制、只读不复制、复制与累计写数量分离。压力只做一组短测；当前冻结基线为 maintenance/natural.csv 与 maintenance/timing.csv，不另跑整轮旧版本。

本项预期只减少队列寻址常数；即使成功也不会降低资格复核、必要堆路径或出口费用。若收益被复制费用抵消，则撤回，不把连续表示无效泛化为其他优化不可行。

### 9.8 节点字段紧凑编码

当前节点覆盖的120字节记录包含五个本来只有32位的关系以及四个只需少量位的标记。下一项保留页索引和曾写字段语义，仅缩小每条节点覆盖：五个uint32关系、四个uint64轮次（包括blocked）及独立位标记/存在掩码。轮次不能截断；关系仍须通过原NodeCount范围检查后才编码。

修改归 View 私有 Fields 的编码/解码方法和原Read/Write/Metrics，不改Source、Simulation控制或正常结果类型。固定字段读取对编译器可见，通用字段接口仍保留边界校验；flags打包不能把字段不存在和字段值零混淆。预计Fields56字节、含键记录64字节，实际sizeof和容量随Probe输出核实。

验证补高位64位轮次、独立标记组合、无效关系和恢复原值，再跑严格夹具及一组压力短测。该项目标是减少记录移动与缓存占用，不以“位压缩天然更快”作结论；若取位费用抵消收益，恢复原值数组。

### 9.9 固定字段的编译期读取

集中成员版本压力均值151.761ms；紧凑字段版本167.264ms，没有独立提速证据。重新成本遍仍指向资格/邻域，而生成代码确认非Trace的MergeRepresentative有8处、AppendNeighborhood有5处、SplitScore有3处对通用`Read(node,field)`的静态调用位置；该函数约1KB。调用次数不等于动态调用频次，但足以确认“放进头文件后已经全部消去字段分派”不成立。

Extend View：增加固定Field模板读取和对应Baseline映射，运行时接口通过同一映射保持。Extend Simulation：编译时已知的关系/状态字段使用固定读取，只有真正动态字段循环继续运行时接口。仍保留节点校验、来源/覆盖查询计数和完整字段值，不改变编译器选项、不使用平台强制inline属性。固定参数即使没有内联，也形成不含通用字段switch的实例。

### 9.10 热拓扑字段的连续投影

### 9.11 携带稳定排序键与直接填洞

当前堆虽然已改为连续槽位，平分比较仍两次访问View以取得不变的PathId；Upsert和Remove还先写待修复槽、再读取它、再在最终位置写回。下一项同时消除这两类由队列表示产生的额外访问，不改变候选资格或观察时刻。

- Extend `NativePlanningQueueEntry`：私有条目增加稳定Path键，预计8→16字节；来源导入和候选Upsert时从View取得，必须与Node身份一致。比较仅用Score/Path，不更改浮点位值、优先方向或平分规则。副本容量、复制额外Path读取和条目移动全部计入。
- Extend `NativePlanningHeapSlots`：来源按字段及Path转换，仍只复制决策堆；Extend Queues：移动条目携带Path，避免比较时重新读取静态身份。验证器额外比较缓存Path与View身份。
- Extend `IndexedHeap`：已有值搬移原语改为“待定位值已在调用方”的FillHole入口；Upsert/Remove不先把该值写到洞里，最终无论是否移动均填写一次。原Legacy交换式原语不变；清理本轮已无调用的RestoreValue包装，不保留两套新修复接口。
- 洞尚未填满时禁止观察根或反向成员，只有本次同步修复能访问该私有中间状态；异常仍销毁整次工作区，不能继续使用不完整堆。
- 复用任意删改、尾部复用、平分和独立严格夹具，增加缓存身份核查；压力一组短测记录实际读写减少。该项不是新选择算法，暂不扩大跨根延迟窗口。更大窗口仍有独立语义和收益举证义务。

结果：组件和独立严格夹具通过，压力Planner142.391/150.756ms（均值146.573）、Legacy77.205/76.983ms（均值77.094），仍未通过。没有把较慢重复删掉，也没有据此宣称独立稳定提速。

### 9.12 复用局部访问定位

剩余资格、邻域与堆修复中，正常路径仍对同一对象反复进入通用访问边界。下一项只复用一个封闭操作内部的位置，不跨拓扑变更缓存资格或邻接值。

- Extend View：提供短生命周期只读节点游标，一次定位覆盖记录后读取多个固定字段。游标不得跨任何View写入/创建；只保存节点与记录下标，不保存向量元素指针。原Read复用相同取值内核，各字段读取继续计量，不能把一次定位当成一次全部字段读取。
- Extend Simulation：资格复核和邻域种子中采用游标；它们在对应读取区间没有拓扑写入。增加同节点多字段Write入口，一次查表处理给定顺序的字段，逐项有效性、原值过滤、标记与写计数保持；父状态/孩子初始化等本来相邻的写入合并，不跨根或递归调用保存句柄。
- Extend Queues/HeapSlots：修复入口先准备唯一私有堆与所需长度，洞算法内部复用Heap引用，按已证明合法的索引直接读写，保留每次槽位/成员/比较计数。公开At/Upsert/Remove仍验证边界，热内核不重复检查同一不变量；增长与来源复制不能转出计时范围。
- 复用原夹具，补游标对照、批量写回恢复/独立字段及非法输入。冻结三点自然审计和短测用于本组收束，并取得两层实际成本；是否继续扩大资格或延迟维护机制，根据这次剩余费用和可消除工作量决定，不按累计优化包数关停。

4. 后续有意义的机制应减少循环内实际重复维护，或显著降低资格/字段访问成本。跨primitive/根合并队列维护必须证明完整决策、候选可见时刻与评分结果仍一致；资格缓存必须给出所有活动/孩子/底边变化的失效证据。它们不是禁区，但当前没有可转成完整63%降幅的实测证据，不能预支收益或声称一定达到50%。
5. 线程化几何准备或出口也不是原则禁区，但严格决策顺序和新增工作必须单列。仅并行输出约20ms的上限已经不足以达门槛；不能因此把Tplan拆掉一部分或把当前时间称为完整拓扑更新时间。
