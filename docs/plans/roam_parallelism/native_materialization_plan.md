# 原生 DOD 拓扑目标规划与直接物化接入规划

> 日期：2026-09-13；类型：大规划；阶段前缀：NMP。
> 状态：**规划已提交为 `c2cd2d8`；NMP-01 实施与验收完成。固定范围严格语义解耦通过，压力堆覆盖及规划成本需 Review；NMP-02 未启动**。
> 源码基线：`602ed48`；后续未提交实现和验证见 §15，当前没有生产新路径或开关。
> 依据：[接入边界事实](../../codebase/roam_parallelism/native_materialization_integration_baseline.md)、[MPR 原型大规划](target_materialization_prototype_plan.md)、[原型结果](../../research/roam_parallelism/target_materialization_prototype.md)、[理论边界](../../research/roam_parallelism/target_materialization_gate.md)。

## 1. 问题、目标与完成标准

MPR 已验证：给定旧状态、合法目标及完整差分，可以直接物化独立原型的可续接状态，并执行真实多线程准备/写入。当前生产接入缺口是**目标怎样在原生状态上得到，以及物化怎样维护原生续接状态**。

本规划将新算法放进 DOD 的细分拓扑阶段：

\[
M_0\xrightarrow{\text{稀疏严格目标规划}}(J,\Delta,\Gamma)
\xrightarrow{\text{直接原生物化}}M_1.
\]

`M₀` 是本帧细分评分完成后的原生状态；`J` 是严格执行策略决定的最终活动事件目标；`Δ` 是净事件差分；`Γ` 是 §6.3 封闭列举的续接义务。三者在新阶段内部产生，不要求调用方提前提供。规划器的动态堆和临时关系属于内部工作状态，不能直接变成 Γ 或目标生产状态。

完成后应满足：

1. 用户可以选择原实现或直接物化实现，**默认保留原实现**。算法选择和线程数量分别配置。
2. 新路径直接更新已有 `DataOrientedRoamState`；正常帧不复制全状态、不导入 MPR 状态、不调用旧完整拓扑阶段取得目标。
3. 新规划器保留严格动态选择、强制前置、预算交换及停止语义；物化器按最终补丁写入，不再依次提交原 split/merge 历史。
4. 原生叶、邻接、内部状态、长期队列、预算、历史标记和 CPU 网格能够继续使用；原→新→原切换不依赖重新初始化。
5. 串行/并行物化共用一套算法和补丁；记录完整细分阶段、五阶段更新及 CPU 网格输出成本，明确串行规划占比。

**正确性接入成立与性能有收益分别验收。** 规划不承诺新实现已比原实现快，也不把 MPR 事务时间当作生产更新收益。若目标发现仍占主要时间，应直接报告，不靠排除该项制造加速。

## 2. 范围与非目标

本次替换 `SplitTopology` 阶段，包含该阶段内部的预算交换合并；前置 `MergeTopology`、两个评分阶段、网格几何生成及上传策略保持原职责。首版支持当前 0～20 深度、有效高度图、开启局部共形约束的原生 DOD 状态。

接入 GUI、无窗口基准和运行时参数，使两条实现可选；不增加第三个 `TerrainLodAlgorithmId`，Classic 继续是独立算法。CPU 网格输出契约继续供 OpenGL/D3D12 使用，不提取或统一两个后端的上传实现。

不新增排序松弛、质量分配、CBT、GPU、全域层次扫描器、通用事务框架、并行容器库或大规模 profiler。不在本轮优化帧尾所有全局维护，也不改变 P5 的历史配对契约。MPR 保留为独立证据与回归来源，不归档、不改写其结果。

MPR 继续作为“给定目标后直接物化”的独立算法参考。共享纯层次函数不等于共享状态构造器或验证答案；原型状态、顺序参考、补丁、验证器及续接测试保持独立。原生错误须区分物化构造、生产映射、续接字段和网格消费，不通过削弱 MPR 投影来适配生产实现。

## 3. 已确认事实与关键架构判断

详细源码事实见[基线](../../codebase/roam_parallelism/native_materialization_integration_baseline.md)。以下事实直接约束设计：

| 事实 | 本规划的决策 |
| --- | --- |
| 细分阶段持续更新两个堆，还可能先合并、失败后交换预算 | 目标规划必须是动态状态演化；不用初始候选快照或静态排序代替 |
| 失败根可能留下成功的强制细分 | 不将根闭包改成全成或全败；记录实际成功事件与局部失败状态 |
| 原型历史/队列不同于生产 | 使用原生状态及明确的 `Γ`，不做双状态常驻或逐帧转换 |
| 原生堆以分数/`PathId` 排序 | 复用比较规则；稠密活动顺序和网格槽位顺序允许逻辑等价 |
| 缓存节点数参与迭代保护，内部旧关系参与续接 | 保留逻辑创建记录及被修改的内部关系；不只修叶邻接 |
| 网格消费依赖逐操作日志，细分入口可能已有合并日志 | 扩展网格模块接收叶差分，同时保留前置日志；不伪造 split 历史 |
| 两个渲染入口均传递整份 `PassPolicy` | 实现开关放在该公共配置中，避免分别引入后端开关 |

**“不复制”指不做全状态克隆；仍允许与实际触及区域相关的私有规划记录、覆盖项及输出补丁。**

**“不重放”指物化不重放中间生产状态。** 严格目标发现仍需模拟必要的逻辑选择与前置关系，这部分可能串行、可能昂贵，必须计费。若最终只是旧完整提交器换一份容器运行，不能据此宣称已消除旧执行工作。

## 4. 原／新实现开关

### 4.1 配置及行为

在 `TerrainLodPassTrace.h` 中增加语义明确的枚举及策略字段，拟定：

```cpp
enum class TerrainLodSplitTopologyImplementation
{
    Legacy,
    DirectMaterialization,
};

// TerrainLodPassPolicy 内；名称与取值须在 NMP-01 固定
TerrainLodSplitTopologyImplementation SplitTopologyImplementation{
    TerrainLodSplitTopologyImplementation::Legacy};
```

既有 `SplitTopology` 动作和 `SplitTopologyWorkerCount` 继续控制串并行请求，不用“并行 Split”复选框兼作算法选择。

| 实现 | 动作/线程请求 | 实际含义 |
| --- | --- | --- |
| `Legacy` | 当前任意合法设置 | 原串行收敛或原安全前缀辅助，保持现有行为 |
| `DirectMaterialization` | `SerialImmediate` 或线程数 1 | 新严格规划 + 新串行直接物化，不能转回旧算法冒充新串行 |
| `DirectMaterialization` | `ParallelAssisted` 或 `Automatic`，允许多线程 | 相同新规划 + 按独立记录分区的物化；共享维护仍串行 |

首版新路径不自动选择回原算法。无工作或工作量不足只使**同一新算法**串行执行。新物化的并行门槛使用独立 `SplitMaterializationMinParallelRecordCount`，不把旧候选数量阈值当作补丁记录数量。具体默认值在 NMP-03 实施前冻结，不根据结果逐样本调整。现有指定更新号/阶段限制仍约束线程派发。

旧 `EnableParallelSplit` 的兼容转换保持；显式串行动作优先，0 线程表示自动。最终实际动作需能区分 `SerialMaterialization` / `ParallelMaterialization`，不能沿用 `SerialImmediate` 的结果名称掩盖实现差异。

### 4.2 用户入口、配置身份及切换

- GUI：DOD 面板增加“细分拓扑实现：原实现／直接物化”，另保留线程/并行控制；Classic 下不显示该 DOD 选择器。
- 无窗口入口：拟增加 `--dod-split-implementation legacy|direct-materialization`；运行时入口使用对应 `--runtime-benchmark-dod-split-implementation`。显式实现覆盖在策略预设之后统一应用，不能因命令行顺序被预设重置。
- 请求实现、实际实现、请求/实际线程数量和退回原因进入报告。Classic 对这一 DOD 专属字段记为不适用，不改变 Classic 行为。
- 公共构建配置哈希包含实现与新门槛；**阶段输入身份仍区分状态输入和执行选择**，不为了配对把不同状态视为相同。
- 开关在下一次构建入口锁定，仅完整阶段之间切换。共用已有节点池、队列和网格，不调用算法 `Reset`；已有资产/预算/深度重置条件继续有效。

首版 `EnableLocalConstraints=false` 不满足新物化的共形输入契约，必须在规划开始前记录 `UnsupportedConfiguration` 并执行原路径，GUI 明示该限制。不能仅凭当前开关为 true，推断此前关闭约束产生的状态已经共形：增加一个保守的输入来源状态标记，在关闭约束运行后保持“未确认”，直到既有合法重置或显式全量认证；只重新打开约束不清除此标记。未确认时记录 `UncertifiedInput` 并保持原路径，不为启用新算法暗中重建。基准请求新实现却实际执行原实现的行不能计为新算法数据。

旧拓扑配对观察器不能静默拿来验证新路径：组合暂不支持时，诊断入口明确拒绝；NMP 专用对照在外部独立执行。

## 5. 分层、依赖与控制流

```text
GUI / CLI / Benchmark
        ↓ TerrainLodPassPolicy
DataOrientedRoamPassExecution：细分拓扑阶段分派
        ├── Legacy → 现有 CommitScoredSplitTopology
        └── DirectMaterialization → NativeSplitExecution
                    ├── NativeTargetPlanner
                    │      ├── NativePlanningView：借用基态 + 稀疏逻辑覆盖
                    │      ├── NativePlanningQueues：仅供决策的动态堆覆盖
                    │      └── NativeRefinementSimulation：必要逻辑前置演化
                    ├── NativeMaterializationPatch：最终节点/边补丁
                    └── NativeContinuationCommit：原生索引/队列/历史发布
                                       ↓
DataOrientedRoamState + MeshMetadata 的直接叶补丁
                                       ↓
既有 MeshPlan → MeshEmit → 公共 CPU 网格包 → 各后端
```

新增核心放在 `src/algorithms/data_oriented_roam/materialization/`，使用 DOD 原生类型。目录内部依赖已有 DOD 状态、评分、共享层次与线程池；不依赖 `src/experiment/`、GUI、benchmark 或渲染器。

原型中纯路径/伙伴/整数边键能力提取到 `src/algorithms/RoamHierarchy.h/.cpp`。实验原型改为薄包装/类型别名，继续保留自身状态、目标认证和补丁；不将整个实验目录搬进生产。

采用三个明确模式：枚举分派用于选择实现；借用基态的稀疏覆盖用于延迟生产修改；准备—独占发布用于限定线程所有权。只针对本 DOD 阶段，不抽象通用插件策略、MVCC 或事务引擎。

拟定关键接口如下，仅表达职责边界，具体签名在小规划确认：

```cpp
NativeTargetPlan BuildNativeSplitTarget(const DataOrientedRoamState& source);
NativeMaterializationPatch PrepareNativePatch(
    const DataOrientedRoamState& source, const NativeTargetPlan& target,
    const NativeExecution& execution);
void PublishNativeMaterialization(
    DataOrientedRoamState& state, NativeTargetPlan&& target,
    NativeMaterializationPatch&& patch, const NativeExecution& execution);
NativeSplitResult ExecuteNativeSplitTopology(DataOrientedRoamState& state);
```

`NativeSplitExecution` 持有本次计划/补丁并控制销毁；前两个接口不修改来源，发布接口是唯一写原生状态的入口。`NativeExecution` 借用流水线线程池、记录已解析的执行配置，不持有第二状态或创建线程池。目标/补丁不能脱离本次基态作用域使用；`NativeSplitResult` 只输出实际执行及成本摘要，网格载荷由原生网格元数据持有至本帧消费。

## 6. 同任务与续接契约

### 6.1 严格目标规划

共同入口是同一已评分的 `M₀`。正确性参考为原 `SerialImmediate` 细分阶段，不因新表示增加额外扫描、排序或 bookkeeping。原默认辅助路径另外保持回归，不能把它与严格参考混为同一个配置。

新规划器必须逐项保留：

1. 当前合并头部的 `< MergeThreshold` 优先处理、细分头部停止和 `PathId` 平分次序。
2. 迟滞区间读取上一帧路径；最大深度、本帧阻塞、已合并/已细分抑制规则。
3. 根先预留预算、强制前置的动态底边查询、`forcedFrom`/深度/循环保护。
4. 部分前置成功后根失败的保留规则及预算释放范围。
5. 失败后重新取得合并队首、分数比较、预算交换、失败候选移除和根阻塞。
6. 入口冻结的迭代保护及实际停止原因；最终硬预算始终符合原契约。

这些规则属于“目标发现”，不把它们包装为物化器的可并行工作。规划过程中重新计算的新条目分数缓存进规划结果，避免提交时重复评分。

### 6.2 必须比较的原生投影

| 状态 | 比较及恢复要求 |
| --- | --- |
| 活动事件、活动叶、预算 | 按稳定身份一致，最终三角形数一致且不超过 B；根请求成功/失败/停止语义一致 |
| 活动叶三边、外部反向边 | 参数域和方向一致；外部保留叶不能留下旧引用 |
| 父子、内部关系、缓存节点 | 保留原逻辑创建记录、深度、域、伙伴及续接会读取的内部关系；不以只生成可渲染叶替代 |
| 两个长期堆 | 全部逻辑条目、分数、代表/伙伴、抑制状态及队首一致；堆结构和反向位置各自合法 |
| 活动向量/物理槽位 | 原已有节点下标稳定，允许活动向量和网格槽位次序不同；所有反向位置必须自洽 |
| 历史及本帧状态 | `PreviousSplitPaths`、当前路径变化、阻塞轮次、创建/激活/细分/合并轮次、强制来源均解释完整 |
| 网格与调试 | 按身份比较几何/索引绕序、法线和调试属性；代号、脏区间与消费生命周期正确 |
| 逻辑统计与实现统计 | 成功/失败/强制/预算交换操作数保持语义；堆实际写入、线程分发等成本按实现分别记录 |

新缓存节点的存在、稳定身份和创建轮次保留；物化器负责分配实际追加下标。规划器的虚拟下标不作为 Γ 中的槽位安排输出，现有节点下标保持稳定。缓存数量必须一致，不能因只保留最终活动记录而改变后续迭代上限。

已有全状态输入哈希仍用于诊断恢复同一来源，不降级它的含义；新旧结果使用逐字段规范化比较，不能修改旧冻结哈希以“通过”新实现。新增载荷/来源标记需要扩展输入编码时使用显式版本；旧冻结清单继续按旧版本校验，不强制改写。NMP-01 仅增加私有目标/轨迹 schema，不修改生产输入编码；NMP-02 接入新生产字段时冻结双版本边界，不能把忽略行为字段的旧哈希当作完整新输入身份。之后继续真实运行评分、合并、细分、网格消费及换轮，不重新导入正确答案。

### 6.3 Γ 的封闭边界

Γ 仅允许以下有类型、可追溯到原生读取者的语义类别；新增类别需单独 Review：

| 类别 | 允许携带 | 限制 |
| --- | --- | --- |
| 阻塞/失败后的候选处置 | 稳定身份、本帧细分阻塞或失败合并候选最终移除、对应原因 | 只有会留下续接效果的处置；普通失败过程进入测试轨迹，不累计到 Γ |
| 历史轮次与强制来源 | 变化节点的创建/激活/细分/合并标记、强制来源及本轮路径历史义务 | 同一字段折叠为最终语义；由 Δ 已唯一确定的值不重复保存 |
| 必要缓存创建 | 不在旧缓存、且不能由最终局部目标直接恢复的缓存身份/创建义务 | 不含 SoA 记录、物理下标、活动向量位置或网格槽位；全部实际新建仍用 g 另计 |
| 必要内部关系变化 | 已证明会被续接读取、且不能由 M₀+Δ 局部导出的内部/缓存关系字段 | 按关系字段逐项解释；最终活动叶邻接必须由物化器构造 |

禁止携带完整邻接、最终叶边表、活动数组、完整或局部生产堆槽位安排、反向位置、mesh、物理槽位分配和不透明节点快照。也不允许把这些内容改名为“辅助缓存”绕过 Γ 的约束。

规划器确为决策计算过的纯域/评分值可以按稳定身份和环境键作为有限求值缓存复用；缓存不能包含成员资格、邻接或物理布局，且删除缓存后仍必须能从 M₀+Δ+Γ 独立恢复相同结果。缓存条目和字节另计，不混入 h。

`h=|Γ|` 按去重后的“类别、身份、字段”计数，同时报告不同身份数量、各类别数量/字节及 h/k、h/N；k=0 时不做除法，也不能假设 h=0。有限输入中的局部比例是实验事实，不把它写成已经证明 h=O(k)。

### 6.4 严格决策语义审计

NMP-01 在测试入口增加轻量逻辑轨迹，逐项比较根选择、强制前置、成功/失败、预算预留/释放/交换、阻塞及停止原因。身份采用 `PathId`，不比较线程调度、数组写入和堆交换顺序。

Legacy 与 Planner 只共享轨迹格式和纯规则，各自的控制器独立产生轨迹。生产和计时入口编译期关闭轨迹，不逐根计算全状态哈希。最终 J 相同但语义轨迹不同仍算失败；只记录前缀、仅总计数相同或仅摘要哈希相同，都不能称为完整严格等价。

## 7. 稀疏规划器

### 7.1 借用基态，不扫描完整目标

`NativePlanningView` 在同步细分阶段内借用只读原状态。首次访问某个变化字段才建立覆盖；未变化记录直接读取基态。新节点使用虚拟追加下标及稳定路径，保存评分所需的域/误差和必要局部关系。

覆盖层只维护下一次决策实际需要的逻辑关系、活动资格、预算和历史标志，不维护生产稠密活动数组、CPU 顶点、网格槽位或逐次上传日志。新目标 `J` 用“原事件谓词 + 变化覆盖”表示，**不构造整份 J 或复制 I₀**。从触及事件中与初值比较得到 `Δ⁺/Δ⁻`，从覆盖中抽取 `Γ`。

对现有节点的稳定身份定位先使用已有下标和父子链；补丁域内建立局部索引。不能每帧建立整池 `PathId→index` 字典。按身份导航的额外 O(H) 查询计入成本。

### 7.2 堆覆盖的首版选择

首版使用**按堆位置和反向位置记录的稀疏写时复制覆盖**，而不是复制整个堆或建立全体候选排序表：

- 基态提供只读堆数组，覆盖保存被改写的槽位及逻辑长度；追加、弹出和末尾换位更新覆盖。
- 节点反向位置及合并代表/伙伴关系也使用覆盖；删除任意强制细分节点时仍可定位。
- 插入/删除/修堆立即改变逻辑队首；新条目采用相同评分及比较器。
- 覆盖必须处理反复追加/删除、尾部越界和同一槽位被多次重用；不能误读截断后的基态尾部。
- 堆覆盖及反向位置只服务于规划决策；测试可以读取其逻辑条目。正常出口不输出生产堆槽位补丁，规划器退出后释放覆盖。

首版稀疏覆盖采用标准有序容器，复杂度按对数查找计，不承诺哈希平均常数。提取必要的索引堆 sift/restore 原语到 DOD 内部头文件，原访问器保持直接数组访问且静态内联；新覆盖访问器不要求原实现承担间接查找或维护新缓存。分数/资格纯规则共享；严格参考保留独立原控制流，避免测试双方调用同一个新选择器。

### 7.3 规划器出口及停止条件

正常出口限定为 Δ、封闭 Γ、最终预算/停止及逻辑操作摘要、可丢弃的纯求值缓存与成本计数；J 以基态加差分表达。完整逻辑堆、规划中的临时邻接只通过测试审计访问，不能流入后续物化接口。所有记录绑定本次同步阶段的基态；不暴露可跨帧保存/随意提交的通用目标对象。

若必须复制活动数组/两堆/节点池才能继续，或必须执行旧完整提交器才知道目标，NMP-01 就应记录缺口并 Review，不能先铺后续平台再解释。正确性与稀疏性分开判定：有序覆盖查找慢不否定语义解耦；a/N、u/Q 或 h/N 接近全域则是当前稀疏机制的负面证据，应先 Review 再进入集成，不靠扩大场景寻找正结果。

## 8. 原生直接物化与发布

### 8.1 从最终差分生成补丁

以三角形路径事件定义 `k=|I₀△J|`，不用根请求数量或菱形数量替代。沿用叶差分支持集 `Δ∪children(Δ)`；菱形表示转换需显式计入两侧事件。

1. 在基态仍未修改时确定移除/新增叶及受影响内部记录，读取变化区域外接口。
2. 复用共享层次规则生成最终叶边键，排序匹配变化区域内部，继承外部接口；归并为每个节点一份最终邻接补丁。
3. 应用封闭 Γ 中经过解释的历史/内部关系义务。能够由目标局部导出的字段仍在物化器构造，不从规划内部状态复制最终节点记录。
4. 预留所有追加节点、成员、堆、活动向量和补丁消费存储。存在新槽位时先固定下标，再派发写入。
5. 写入最终节点字段，局部维护活动索引；从最终叶/候选支持集和 Γ 恢复逻辑队列成员及分数，使用原生堆接口维护物理位置，再发布历史标记、统计和预算。最终队列布局由物化器决定，不导入规划器堆布局。
6. 将净叶变化及调试变化交给网格模块。生产节点、活动状态和队列只发布最终结果，不调用 `SplitNodeSerial`、`MergeNodeOrDiamond` 或原拓扑提交循环。

规划期为决定 J 已计算的域、几何误差和分数必须复用；不要为了多线程演示再次计算。部分没有净叶变化的 `Γ` 仍可能需要状态/调试更新，`k=0` 不能直接认定完全无工作。

规划期间的动态堆维护和物化期间的最终局部成员维护是两项实际工作，分别计费。首版接受这项成本以守住边界；不得通过输出完整生产堆答案消去后者。NMP-02 应另核查从 M₀+Δ+Γ 恢复队列的支持集是否完整。

### 8.2 所有权、内存和失败

状态由现有流水线独占；阶段调用期间无外部写者。规划和补丁准备使用局部工作区，其容量可由专属工作区复用，但不能逐帧按整池规模初始化。计划只在当前同步调用内有效；用当前构建号及明确的阶段作用域检查误用，不宣称几个大小字段就能认证任意外部改动。

SoA 扩容可能搬移完整旧数组，必须在并行读写前完成。阶段内保存下标，不跨扩容保存元素指针。容量足够时不搬移；容量不足的复制/初始化字节和时间进入完整阶段，不能以“预分配”名义排出。旧状态的预算预留策略继续复用，不预分配完整潜在层次。

所有合法性/容量检查尽量在首次发布前完成。正常成功路径不需要全状态回滚副本。准备失败时不执行新补丁；发布后出现异常或不变量失败时，本次构建失败、停止发布网格并使该状态待重置，不在半更新状态上再调用旧实现。原算法切换是正常完整状态上的操作，不是掩盖提交失败的办法。

### 8.3 有限并行边界

新串行和并行路径共用补丁结构，后者仅改变以下独立循环的执行方式：

- 尚未被规划器计算的静态记录/边描述准备。
- 固定只读描述上的最终边与局部派生数据准备。
- 归并后每个节点唯一所有权的最终字段填写。

排序、标准容器、槽位数量变更、活动向量填洞、队列发布及历史集合维护首版串行；分配和任务队列准备也完整计费。线程池复用现有 DOD 同步执行能力，不增加常驻第二线程池。不并发 `push_back`、resize、共享堆修复或同一节点的多写者更新。

降低写入阶段 span 不等于缩短整个细分阶段；首版线程收益上限受规划、分配、排序和续接维护共同限制。负结果只约束当前原生实现边界，不重写 MPR 的算法可行性结论。

## 9. 网格直接叶补丁与切换生命周期

在已有 `DataOrientedRoamMeshMetadata` 增加本帧可选的直接叶补丁：移除叶、新增叶、仍活动但调试属性变化的叶，以及有补丁标志。不建立第二份 CPU 网格。

首版冻结组合顺序：

```text
消费者上一帧槽位
→ 消费已有 TopologyEdits 前缀（原合并阶段）
→ 消费新细分阶段的直接叶补丁（M₀ → M₁）
→ 合并调试脏叶 → 生成最终脏槽几何 → 范围收尾
```

新细分阶段不追加伪造的逐次 split/merge 日志，也不清空前缀。前缀通过保留的父子身份消费，不依赖已经被改写的最终叶状态；NMP-02 必须用“先合并再重新细分同一区域”的用例验证这一点。

直接补丁先删除消失叶，再为新增叶分配槽位，复用现有尾部填洞和脏槽规则。保留叶可能因填洞移动，必须标脏；未改变拓扑但调试状态改变的叶也必须标脏。范围按实际槽位生成，不要求复现旧算法的槽位次序。

初始化仍允许现有最终活动叶完整建网格；正常非初始化帧不能依赖完整重建恢复正确性。旧路径原有日志失配保护保留；新补丁失配在诊断中算失败，在运行时必须显式记录失配/重建，不能作为新路径成功或性能样本。

`BeginDataOrientedRoamMeshPlan` 只清空上次已消费的本帧载荷；`Apply` 消费后释放它，调试过渡叶按原生命周期保留。切换发生在新帧开始，不遗留旧补丁、不漏掉当帧合并前缀。借用 CPU 网格仍有效至下一次 Build/Reset，渲染器按现有代号/范围处理。

## 11. 成本模型和报告边界

### 11.1 分开登记实际规模

| 量 | 含义 |
| --- | --- |
| N、Q | 缓存节点总量及入口堆规模，作为上下文；不以读取 `.size()` 冒充扫描 |
| k | 最终三角形事件净差分，不等于根请求或 primitive 数量 |
| r、a | 规划中的逻辑记录访问次数、累计不同覆盖记录数量；另报峰值与最终存量 |
| L、u | 堆槽位访问/修复次数、累计不同覆盖槽位数量；两堆、反向项及新增区间分列 |
| h、g | 封闭 Γ 的义务数量、新建缓存身份数量；避免只统计净出口遗漏峰值工作 |
| m_q | 物化阶段实际维护的最终队列成员数量，与规划覆盖 u 分开 |
| R | 真正准备/填写的最终补丁记录数量，包含外部边界及续接义务 |
| `PlanScoreEvaluations` | 拓扑规划中新增评分数量，和前置评分阶段分开 |
| `CapacityMovedBytes`、`FullScanItems` | 扩容搬移及额外全域扫描；正常计划不隐藏全量初始化 |

标准有序覆盖下，规划至少计入 `r log(a+2)` 与 `L log(u+2)` 的查找工作；一次堆维护可能访问 O(log Q) 槽位，不能把它当一次常数操作。还需加入新身份/域构造、评分、去重和差分提取。各项按实际实现给出符号式与计数，不先宣称总体 O(k)。

物化目标成本可写成：

\[
W_{\mathrm{apply}}=O(RH+R\log(R+2)+m_q\log(Q+2)+g)+C_{\mathrm{allocation}}+C_{\mathrm{derived}}.
\]

这是需要代码核查的设计预算，不是当前已证明的生产界；`R` 必须受 `k`、`h` 和实际边界限制。容量扩张的 O(N) 搬移显式进入 `C_allocation`，不能用“差分局部性”抹去。连续帧中实际触及域接近 N 时，也不能称为小差分算法收益。

### 11.2 时间边界

\[
T_{\mathrm{split\ pass}}=
T_{\mathrm{plan}}+T_{\mathrm{patch\ prepare}}+T_{\mathrm{capacity}}+
T_{\mathrm{fill}}+T_{\mathrm{continuation\ publish}}.
\]

每项包含所需分配、排序、派发、等待、汇总及新增局部评分。清理工作区也计入；首次容量/初始化另标，但完整运行时更新仍包含它。

汇总时固定 `T_split_pass = T_plan + T_materialize`；后者包含补丁准备、容量、填写、最终队列/续接发布及相应清理。规划覆盖提取/销毁属于前者，不移到评分或计时外。NMP-01 尚无物化器，`T_materialize` 和完整新阶段时间留空，不填零计算加速。

原生阶段外层直接计时为主要依据。新旧均包含细分阶段内部的预算交换合并，保留原历史兼容统计时要明确其重归属，不能由子项相加构造一个少算的阶段时间。帧尾路径重建、统计、CPU 网格生成仍纳入 `BuildInternal` 完整更新。

三档对照固定为：原生原串行、新原生串行、新原生并行。另保留未指定新开关时的原默认配置回归。分别报告规划、物化、完整细分阶段、CPU 完整更新；只有完整边界可称为对应更新加速。不得把既有原型 `reference-serial` 放进这张原生严格等价性能表。

| 阶段 | 具体交付 | 独立验收与下一步条件 |
| --- | --- | --- |
| **NMP-01：原生严格目标规划** | 按[小规划](native_materialization_01_plan.md)实现封闭 Γ、稀疏逻辑视图/堆、独立动态控制器及测试轨迹；生产仍默认原入口 | 比较 J/Δ/Γ、完整逻辑决策及逻辑堆；另报 a/u/r/L、h 与规模关系。慢而稀疏不直接否定；边界塌陷、语义不符或覆盖近全域则先 Review |

NMP-01 产出是可执行的新规划器，不再做一般理论 Gate。NMP-02 将它接入真实状态；不能用实验桥接长期代替任何一期交付。

## 13. 验证与快速性能契约

### 13.1 逻辑正确性

按阶段选择必要项目，不一次跑全仓测试：

- 规划夹具：平分/停止头部、迟滞阈值边界、根预算预留、部分强制成功后失败、失败后新合并头部、跨预算交换、最大深度、重复缓存使用、迭代保护。
- 覆盖堆夹具：任意位置删除、尾部填洞、多次截断/追加、代表/伙伴切换、阻塞项；对照独立原堆逐步队首和成员。
- 物化夹具：纯细分、纯合并、混合差分、`k=0`、存在独立历史/调试变化、外部反向邻接、内部缓存关系、容量扩张、预算饱和。
- 消费/续接：本帧已有合并日志后再次细分，跨帧调试着色清退，原→新→原，新→原→新；检查不调用 Reset、不重新导入、非初始化不全重建。
- 并行：两线程确实领取非空记录，写集合互斥，线程异常正确等待；完整字段投影和串行相同。

诊断允许在测试外层克隆同一输入并全量验证；这与生产无全状态复制的要求不冲突。验证克隆不得进入新算法调用图，计时遍关闭全量诊断。不能仅比较最终图片或单个哈希。

### 13.2 冻结现实输入

优先复用 MPR 已有 test129/Peking 场景及压力样本。Peking 保持 `TerrainSize=80`、`HeightScale=12`；不统一改成 test129 的 30/4。

快速压力输入复用 [MPR-03 §3](target_materialization_prototype_03_plan.md) 冻结的 `peking547-budget-orbit64-b200000-sample14`：H=20、B=200000、细分/合并阈值 0.25/0.1 px、原 64 点几何轨迹及视图参数。来源从干净状态推进 0..14。此次可在同一条短前缀上做连续原生更新，而不是每帧调用 Bridge 冻结/导入；不将其描述为完整 64 点实验。

普通输入使用既有 test129 冻结设置，至少保留一个低工作量或无变化点；确切点号和少量切换位置在对应小规划、运行前固定。压力之外不临时挑选更有利场景，不因 k 小而换样本。

### 13.3 每阶段实现前后对照

遵循[开发规范 §7.3](../../standards/development_guidelines.md)：每个代码阶段先保留上个版本的必要性能报告，再在相同 WSL Ubuntu、构建类型/编译器、线程设置和冻结输入上运行实现后对照。

开发默认一组短进程对照，采用一档代表多线程，必要正确性另用两线程；不是 1/2/4/8 全矩阵，不默认 5×30 或几十进程。只有明确异常或新修改才追加第二组定向复测。独立进程为主要统计单位，同进程多帧不冒充独立样本。

NMP-01 重点检查共享规则/堆提取是否拖慢原串行，并记录新规划成本；NMP-02 增加完整新串行阶段和网格消费；NMP-03 比较新串行/并行；NMP-04 检查应用开关及完整 CPU 更新。仍适用的上阶段结果可引用，不为文档完整重复所有项目。

计时遍关闭：全量拓扑/队列验证、阶段证据哈希、旧配对回放、操作访问观察和工作量发现探针；保留必要子项直接计时及低成本实际数量。具体开关字段集合在每个小规划列明；不假定 GUI 默认配置已经关闭证据（当前应用设置会打开部分证据）。

首轮数据只筛查明显退化，不以几微秒差值阻断。出现重复且有工程影响的性能问题，单列现象、边界、定位过程、原因或未知项；由用户决定另写修复小规划或调整后续规划，不静默扩大优化范围。原型已关闭/暂停的性能问题不自行重开。

全部命令按用户要求经 WSL Ubuntu 执行。CPU 核心/无窗口检查优先；不默认构建全部后端。共享 CPU 网格接口未变时，以程序化包/范围测试验证；D3D12 原生运行在该环境不可用则明确未验证，不能以 Linux 构建冒充两后端通过。

## 14. 风险、备选与 Review 边界

| 风险/歧义 | 本版处理 | 需要重新 Review 的变化 |
| --- | --- | --- |
| 严格目标规划几乎重做原全部工作 | 只模拟选择必需逻辑，保留 r/L/评分成本；与旧完整维护分开审计 | 需要全状态复制、旧 pass 产 J，或改变严格目标 |
| 净差分无法表达历史义务 | `Γ` 单列并计费，保留缓存创建和内部关系 | 要求丢弃原历史/抑制语义，或改变迭代保护 |
| 原参考被共享抽象拖慢 | 静态直接访问器，旧路径不维护覆盖；阶段前后短对照 | 大范围重写原堆、原状态表示 |
| 原生与原型局部性不完全对应 | 先做完整原生续接验证，R/h/g 单独报告 | 需要全域续接恢复或无法解释的原生状态 |
| 标准容器/规划占据大部分时间 | 首版如实记录，保留原实现默认 | 自制并行容器、并行规划、新目标算法 |
| 网格前缀与净补丁不兼容 | NMP-02 提前验证前缀消费和缓存孩子稳定性 | 必须统一重写所有原网格日志或复制消费者状态 |
| 缓存扩容造成偶发全量搬移 | 计入容量项，区分常规与扩容帧 | 更换为分段节点池等表示重构 |
| 新旧切换需重建才能正确 | 视为续接缺陷，不能宣称原生替换完成 | 接受重置式切换必须由用户修改契约 |

本次建议人类 Review 的核心是：DOD 内部实现开关；严格规划与物化分层；稀疏堆覆盖；包含历史义务的原生续接投影；前置网格日志加直接叶差分的消费协议；四阶段范围。

用户已认可大规划，要求守住“规划器决定目标、物化器构造目标状态”；对应 [NMP-01 小规划](native_materialization_01_plan.md)现已完成独立严格控制器、净出口、三点完整语义和短计量。解耦证据与当前容器成本分开判定，不以语义通过预先承诺性能收益。
