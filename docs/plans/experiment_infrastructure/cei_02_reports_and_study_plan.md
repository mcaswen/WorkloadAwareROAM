# CEI-02 通用报告、视觉与正式编排小规划

日期：2026-09-16。前阶段：`dcfc01a`。关联[大规划](cbt_experiment_infrastructure_major_plan.md)。状态：完成。

## 目标与边界

在CEI-01统一数据上，让四算法直接使用`analyze/report`以及配置化正式实验编排。处理的是统计、展示、文件身份和调用流程，不修改算法、GPU捕获或质量评价器。

当前通用图只有三算法标签，CPU/GPU均会被放到CPU-ready轴；重复进程逐条绘图会产生巨大表和轴。报告把成功退出但质量不完整的原始数值直接展示，也不适合新一轮总体比较。

正式脚本的FER-01固定目录、程序、三次重复和三算法布局仍需保留历史可复现性，新协议应显式传入，不复制CBI专用完整流水线。

## 文件与职责

| 文件 | 处理与原因 |
|---|---|
| `process_statistics.py` | Create：唯一配置级独立进程统计、质量观察与数量配对事实；不作图、不运行算法 |
| `comparison_figures.py` | Create：四算法通用成本/质量/N/时序科学图；与旧历史profiler图职责分开 |
| `figures.py` | Extend：颜色/标签及委托新图，保留FigureWriter和历史perf/Tracy适配 |
| `report.py` | Extend：进程汇总、GPU与CPU口径、质量失败、配对、HTML/Markdown数据表 |
| `visual_report.py` | Extend：相同路线去重，质量失败不参与色标；保留每配置真实帧播放器与见证 |
| `formal_study.py` | Extend：显式config/raw/app/probe输入，保留旧默认值；执行/冻结/验证/分析调用已有能力 |

| 定向测试与阶段事实/审查 | 验证统计单位、无效数据、GPU显示边界与历史入口兼容 |

进程统计依赖analysis事实，不依赖具体FER/CBI目录。科学图依赖统计结果与FigureWriter，不读取未登记的新结果。报告层负责文字/表/媒体链接，不重新计算算法误差。

## 配置级统计契约

仅正常timing且状态成功的独立进程进入性能总体。分组必须核对任务、程序、源码身份、线程与执行平台；同名case但身份不同不能合并。视觉/质量采集仍独立列示，不加入正常时间平均。

每配置保存各进程值、样本数量、均值、最小/最大。帧P95仅表示该进程轨迹尾部，不充当独立重复；不生成无依据的置信区间。未执行、超时、记录错误单列，不隐去缺失重复。

CPU列完整更新与阶段分解；CBT列主机录制、来源代GPU计算和绘制、有效采样/缺测数量。公共平台帧包络可列在同一张表，但明确包含边界和异步性质，不直接称GPU完成时间。

## 质量、数量与成本关联

所有质量点保留状态、实际N、Emax、RMS、Hmax、覆盖计数和见证。无效点绝对指标空白；即使文件里存在部分样本最大值也不用于有效曲线、色标或排序。

逐点Dmax使用CEI-01共同参考域原语。CBT最近数量点按实际N选择，不因质量无效换点；数量比例与无效状态均列。CPU同预算配对也列实际N，不能假设预算都用满。

质量—N图必须同资产、同关键机会、同相机比较。轨迹仅连接预声明观察点；无效点断开，不跨缺失点补线。不同算法/参数实际质量点构成设计点，不证明完整Pareto前沿。

GPU正常进程没有全mesh hash，质量与正常成本最多按配置关联；图注明没有验证两个GPU进程拥有相同mesh。CPU有证据时保留同结果核对，不降低其门禁。

## 图表与视觉组织

通用报告支持少量开发样本，也支持正式多进程矩阵。成本图按设备边界分组；多配置按资产拆分，避免32个子图挤在一行。所有图使用同源统计和FigureSpec。

正式报告包含：配置级时间/范围、CPU阶段、GPU阶段、同视图质量—N、关键质量轨迹、代表重复的成本/工作量时序，以及真实画面/见证。时序固定第一个预登记重复，不挑最快或最好一次。

路线图按源资产/冻结路线身份去重；每配置实际截图仍可浏览。正式面板的见证图在预声明质量帧中选择最大有效者仅用于展示，完整质量表和失败表不减少。显示选点不触发新质量采样。

所有生成图实际打开检查中文、轴、图例、缺口和真实图像；Agent视觉、用户视觉、数值有效性分开记录。HTML本地链接/图像SHA程序检查不能替代实际看图。

## 正式编排接口

`formal_study`允许显式配置目录、原始根、同一原生程序与质量probe。旧FER-01无参入口继续读取原目录，不自动重生成或覆盖历史协议。新的准备模块只生成FER-02协议/case，不另造进程管理器。

冻结程序、probe、协议/case、素材/路线与执行次序后，再开始正常进程。复用已有成功记录前核对身份，失败/截尾不覆盖。每进程继续原180秒/8GiB上限。

模式核对对CPU使用公开实际结果，对CBT使用有限输入/代次等级。质量采集和独立评价只在所有正常计时结束后执行，不并发抢占资源。分析和图表可离线重建，不重跑算法。

## 实施与验证顺序

1. 保存当前单CPU通用报告耗时、图数及来源哈希作为旧路径基线；保存混合报告遇到的CBT标签/显示缺口。
2. 建立进程统计与共享质量观察，补设备时间和缺测，写针对重复单位、失败保留和GPU错误加速的测试。
3. 接通通用科学图/HTML/Markdown，按小混合样本检查有效/无效质量与图片链接；修显示不改原数据。
4. 将正式执行配置化，验证旧FER协议解析和新参数传递；本阶段不运行完整矩阵。
5. 同CPU报告前后快验并列新增报告功能成本；实际打开混合图像，回填事实/审查并提交。

## 成本与风险

旧路径对照使用同CPU analysis，分离统计、绘图与媒体复制成本。混合报告是新增能力，记录输出图数/文件量/耗时，不将新增图像导出成本全部误称旧路径回归。发现明显同任务退化才补一次定向复测，不无限测font/文件缓存噪声。

预期离线验证为分钟级；不跑新native性能矩阵、C++构建或全量CTest。报告失败不能以跳过GPU、删除无效质量或更改算法作为修复。

## 出口

四算法通用报告/配置级统计可运行；真实混合证据及无效质量保留；科学图实际看过；正式编排可读取外部协议；旧FER入口未被覆盖；开发前后成本和架构审查已记录。完成后提交，再冻结并执行CEI-03总体实验。
