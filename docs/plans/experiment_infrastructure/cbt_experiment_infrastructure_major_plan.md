# CBT 全面实验接入与总体实验大规划

日期：2026-09-16。起点：`212bb48`。授权：用户要求全面接入已有实验基础设施并做总体实验；继承本任务自主闭环、每小阶段提交一次。代码风格继续参考DOD，先完成当前小阶段再开始下一阶段。

## 1. 问题、范围和完成标准

CBI已经建立真实D3D12持续运行、同代GPU网格捕获、独立质量和一个专用有限报告。当前通用`analyze/report/suite`仍有CPU假设，导致CBT不能完整使用统一证据链。此次目标是让Classic、DOD、Transactional和CBT通过同一配置、运行、分析及报告入口，随后得到一轮同后端、同程序的新实验。

“全面接入”指现有资产/材质/冻结路线、模式、矩阵、质量、统计、图表和报告均能识别CBT语义，不意味着运行所有资产×路线×材质的笛卡尔积。CBT仍限D3D12；CPU-only、OpenGL和CPU profiler入口明确拒绝。GPU算法本身、着色器、原语、质量阈值不改变。

验收包括：普通CBT timing不读回全网格也能完成分析；质量帧保留实际N；GPU时间按代次归属；CPU预算与GPU容量分开；通用报告可显示四算法、缺测和无效质量；总体实验全部尝试或留下明确失败；数表、真实画面与分析图均经过审阅。

## 2. 当前事实和复用边界

依据：[CBI证据](../../codebase/cbt_2024/gpu_experiment_evidence.md)、[有限比较事实](../../codebase/cbt_2024/comparison_workflow.md)、[EIP手册](../../codebase/experiment_infrastructure/usage.md)、[FER-01](fer_01_formal_experiment_plan.md)。

已核对代码：`runner/quality/result_adapters/analysis/suite/figures/report/visual_report/formal_study/formal_report`及统一CLI。

- `analysis.summarize`当前直接计算`faces/budget`，不允许CBT普通帧N缺测；阶段默认落入CPU五阶段。
- `compare_modes`将空GPU hash与CPU实际hash同等处理；不能因此证明GPU重复逻辑结果完全一致。
- `suite`只展开CPU预算/线程/前缀；CBT需要独立面积/容量维度，不能复制无意义CPU组合。
- `quality.pointwise_pair`以含CPU预算的`workloadId`为前置条件，阻止不同N但同参考域的合法逐点比较。
- 通用图表仅有三算法颜色/标签，质量—成本图默认CPU当前mesh；专用CBI报告已实现的GPU归约应移到共享观测层复用。
- `formal_study/formal_report`将FER-01目录、程序和三算法写死；历史报告保留，新一轮应使用配置化协议及统一分析。

## 3. 目标架构与依赖

```text
资产/材质/冻结路线 + 算法适用维度
→ suite / 正式协议
→ runner（唯一进程/输入与来源所有者）
→ frames.csv + CBT独立代次记录 + 实际mesh
→ result_adapters + GPU观测归约
→ analysis（唯一逐进程、逐阶段、质量与配对事实）
→ 进程统计 / 通用报告 / 科学图 / 真实画面
```

共享层不依赖CBI/FER目录；具体研究协议依赖共享工具。采用现有适配器、数据表和薄CLI，不引入插件框架、通用调度平台或第二个GPU捕获器。正式统计和报告不回调算法，不在绘图时决定新的实验样本。

## 5. 核心数据契约

### 5.1 CPU、GPU与数量

CPU完整更新时间和CBT主机命令录制时间分别标识。GPU计算、绘制时间按各自资源/采样代记录，不把不同代时间加为完整GPU帧。记录有效样本数量、缺失/尾部覆盖和预热归属。

CBT普通帧`faces/hash`缺测保持空；质量捕获帧才有同代实际N。延迟N可作为带采样代的独立观测，不能回填当前N。GPU容量利用率与CPU `N/B`分开，CBT的CPU预算标签不参与资源正确性或数量匹配。

### 5.2 一致性和质量

CPU同任务仍可核对真实mesh/hash和公开工作量。CBT正常计时没有完整网格，跨模式只证明输入/相机/机会与代次契约成立，不能因空hash相等宣称逻辑结果相同。捕获结果的质量只归属于自身实际mesh，不假设另一个GPU重复拥有相同几何。

逐点Dmax要求原始样本源、参数尺度、固定Q、相机矩阵、投影约定和可见域相同。允许显式按同域比较不同预算/实际N，同时列双方N和配对规则；不要求包含预算的`workloadId`相同。

无效质量保留原始结果和失败原因；有效指标留空，不绘制部分样本最大值。CBI已发现的canyon歧义不更改容差掩盖，若有限定位不能排除则继续作为无效证据，不能将其用于排名。

## 7. 总体实验预定范围

沿用FER四资产：Peking547、generated-ridge、dem-canyon、dem-sierra。CPU为原20配置：四资产50k、Peking另100k/200k，Classic1/DOD8/Transactional8；Peking50k与canyon50k另Transactional1。

新增每资产CBT面积16/8/4三个点，共12配置；动态512K，来源off/modified，记录资源/故障/饱和。CBT面积已预定，不按本轮质量结果校准。总体32配置，各3独立正常进程，共96；30个主配置各1视觉运行，4关键机会质量，共120评价。正式小规划在采集前确定交错种子和完整命令。

全部使用同一个当前D3D12程序，1280×720、中性材质、前三机会预热、原路线与尺度；Peking24机会，其他96。质量关键机会采用FER-01已有2/15/16/23及2/48/80/95，原CBI的32/64不混作同帧比较。

性能程序不带新profiler，构建/质量/作图不与正常测量并发。独立进程为统计单位，报告三进程原值及均值/范围，不从相关帧构造显著性。主表完整更新/帧包络与GPU各边界分别列示，跨设备/跨质量不能称同任务加速。

CBI-03 CPU工程回归保持OPEN；当前用户授权继续实验，不等于回归已修复。本轮所有算法同程序重新采集，避免重复上一轮CPU/CBT跨二进制混表。旧性能仅历史背景，不进入新总体。

## 8. 验证与资源边界

开发快验复用CBI-04成功、无效和CPU产物，覆盖空值、错代、缺样、不同预算、无效最近参考、CPU兼容。按影响选测试，不重建无变化的C++、不跑全部CTest。

每阶段记录修改前后离线处理成本；第一阶段CPU代表analysis，第二阶段小型混合report，第三阶段执行器和正式产物归约成本单列。几微秒差值不扩大调查；新功能开销与旧路径变化分开。

正式原生进程沿runner的180秒/8GiB限制；质量每帧180秒。失败、超时、恢复、无效样本不替换，不调阈值/线程/轮数追求正结果。整体资源异常可以中止剩余工作，但必须说明未执行清单。

视觉使用实际D3D12截图，查看不同资产方向/材质/转向/返回，科学图检查轴、数量、图例、缺口、见证。Agent视觉与用户验收分别记录，不能用数值测试代签图像。

## 9. 风险与最终交付

主要风险为GPU未采样当前N的误填、异步计时代错配、空hash假等价、容量当预算、无效质量冒充有效、统计重复混入视觉进程、同预算但不同N的错误胜负以及CPU旧回归误关闭。

交付统一CLI/事实手册、三阶段小规划和审查、FER-02配置与冻结身份、总体Markdown/HTML、进程统计/质量/配对CSV、图表与实际画面。原始mesh/程序/误差数组留忽略目录，精简报告和图随阶段提交。

最终状态分别列示：实验基础设施接入、实验执行、质量证据覆盖、性能/质量竞争性、已知工程问题。总体实验完成不代表新算法胜出，也不自动批准新的优化或GPU研究路线。
