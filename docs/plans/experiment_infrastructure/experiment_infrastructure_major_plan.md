## 1. 目标、研究边界与交付

把当前分散的实验资产、硬编码回放、逐阶段脚本和报告整理为一套**可复现、可观察、可追溯的实验工作流**：

~~~text
资产来源/生成配方
→ 统一高度与材质资产
→ 场景参数 + 冻结相机路线 + 算法配置
→ 正常计时 / 视觉采集 / 离线质量 / 函数采集
→ 同源结果归约
→ 性能图、质量图、真实画面、实验报告
→ 视觉审查与证据归档
~~~

完成后应能选择一个有来源的地形、一个版本化路线和一组明确算法配置，生成完整实验包；从报告里的任意图表或截图能定位到运行、帧、源码/二进制、实际输入和原始数据。

首批交付：

1. 保留现有2个输入，新增6类确定性生成地形、4类真实地形裁剪；每项有来源、变换、尺寸、尺度、哈希和预览。
2. 3种简单观察预设：中性光照、UV检查、基础地表贴图；素材限少量岩石/土壤/草地漫反射图。
3. 保留历史路线；新增环绕、接近返回、沿地形移动、转向暴露返回、静止恢复路线模板，并能录制关键帧和冻结回放。
4. 公共实验清单、最小启动/采集入口和运行身份索引，不再为每个新地形复制一个固定Peking入口。
5. 标准性能、工作量、质量、函数热点、线程时序图及中文报告流程。
6. 真实OpenGL/D3D12截图、固定时间线片段、对比页和明确视觉验收记录。

**基础设施验收不等于算法质量或论文结论通过。** PQ-01仍有持续质量残余；50k及以上优于DOD且Emax不明显退化仍是待验证目标。本规划不改质量策略、预留算法或默认配置，也不通过换资产/路线绕开既有反例。

依据：[开发规范](../../standards/development_guidelines.md)、[规划规范](../plan_guideline.md)、[TPI](../cpu_refinement/transactional_platform_integration_plan.md)、[SVE](../cpu_refinement/sve_01_scaling_viability_plan.md)、[PQ-01](../cpu_refinement/pq_01_quality_provenance_plan.md)、[FPR](../profiling/cpu_function_profiling_major_plan.md)。实现后按[事实规范](../../codebase/codebase_guideline.md)和[审查规范](../../reviews/review_guideline.md)交付。

## 3. 范围与不做的事项

本规划完善项目内离线资产工具、版本化清单、相机回放、少量渲染观察参数、帧采集、分析和报告。数据目录、持久状态和统计的职责显式分开。

不包含：

- 新拓扑原语、质量修复、reservation优化、GPU细分研究。
- OpenGL/D3D12上传资源重构或统一两者内部渲染模型。
- PBR、法线/位移贴图、阴影系统、天气、水面、植被、实时侵蚀。
- 通用GIS平台、素材网站镜像、数据仓库、远程任务队列或新的通用profiler。
- 在本阶段跑完全部正式论文矩阵，或以新增工作负载搜索有利结果。
- 为图好看改变计量数据、改变见证颜色范围而不披露、用截图视觉判断替代拓扑/预算/质量数值。

报告主格式为Markdown及离线HTML，图表提供SVG/PDF和PNG。Word排版与完整投稿模板不作为本次前置；未来需要时复用内容数据再单独导出，不绑定旧硬编码DOCX脚本。

## 4. 架构与职责判断

### 4.1 四层结构

~~~text
配置/资产层（assets、configs）
             ↓
离线准备与分析（scripts/experiment_infrastructure）
             ↓ 启动，不参与算法热路径
实验协议/回放（experiment/infrastructure、benchmark/experiment）
             ↓
公共算法接口 → Classic / DOD / Transactional
             ↓
现有TerrainRenderer → OpenGL / D3D12
             ↓ 仅视觉模式
帧回读/实际CPU网格 → 图像编码 / 独立质量 → 报告
~~~

- 算法层不读取文件目录、不感知报告/截图、不同路线名或素材供应商。
- Python负责联网获取、GIS/图像准备、进程编排、统计、绘图和报告；不重新实现算法、实际相机投影或独立质量公式。
- C++实验协议负责校验/冻结具体输入、相机采样及序号；回放负责驱动已有公共接口。
- 应用控制器只管理选择/录制/预览，不把资产处理、曲线生成和实验统计堆入`Application.cpp`。
- 后端拥有GPU回读资源；编码与图像拼版在实验输出层。共享CPU图像格式不意味着共享GPU实现。
- 旧FPR/正式CPU配对/TPI/PQ脚本保持可独立使用；新入口通过适配复用，不整体迁移历史实验。

### 4.2 关键复用与新增

| 决策 | 选择与原因 |
|---|---|
| 资产导入 | **Wrap**现有HeightMap；离线转换后用现有加载器核对实际uint16，运行时不引入GDAL |
| 简单材质 | **Extend**现有渲染设置/纹理加载/GLSL/HLSL；材质是渲染状态，不进入算法种子身份 |
| 历史相机 | **Reuse**旧公式并由高层兼容导出；新协议不依赖“轨迹必须A/64点”的旧约束 |
| 新清单与路线 | **Create**项目专用小协议；JSON描述配方/引用，CSV保存冻结行，避免新数据库或插件机制 |
| 实验驱动 | **Create**通用回放，复用公共算法工厂、`BuildTerrainLodViewInput`、渲染输出和帧计时 |
| Windows/WSL进程控制 | **Wrap/窄提取**已有runner，避免复制超时、身份和日志逻辑；旧argv默认不变 |
| CPU/GPU状态 | **Reuse**现有持续状态、Borrowed mesh和dirty范围；不因录制/截图而每帧重置算法 |
| 函数归因 | **Wrap**FPR后端/解析器，按新回放ROI接入；不再扩建profiler |
| 图表/报告 | **Create**结果适配与统一图形规格；可提取现有通用格式函数，但不改写旧统计判定 |

依赖只向下。`experiment/infrastructure`不得反向依赖`benchmark`；历史TPI相机位于benchmark，其兼容转换留在benchmark层，生成冻结行后再交给通用协议。无需把历史相机重写成近似Python公式。

### 4.3 依赖与替代方案

C++清单读入优先复用项目已有Boost.PropertyTree能力，并在边界显式验证字段、范围和整数身份，不把它当完整JSON Schema实现。Python标准库承担JSON/CSV；数值生成、作图和图像处理复用现有NumPy/Matplotlib/Pillow，版本在首次实施时锁定。GDAL仅用于离线真实DEM转换，FFmpeg仅用于可选视频编码；都不成为应用运行依赖。

首版选择本地文件清单而非数据库，原因是输入规模有限且便于Git审查；选择后端精确捕获而非长期依赖桌面截图，原因是必须关联实际帧与网格；选择模板化离线HTML而非新Web应用，原因是交付可直接浏览且无需维护服务。若后续确需改变这些边界，先补充规划再确认。

### 4.4 数据契约

| 对象 | 核心字段与不可隐含的语义 |
|---|---|
| `TerrainAsset` | 稳定ID/版本、类型、文件与样本哈希、真实宽高/位深、来源/许可/下载日期、生成种子/工具版本、裁剪/重投影/NoData/量化、物理跨度与高度范围 |
| `MaterialPreset` | 素材ID/哈希、颜色解释、平铺次数、高度染色强度、固定光照/线框；诊断与展示用途分列 |
| `CameraRecipe` | 路线版本、控制点/插值、参数坐标或世界坐标、参考地形高度偏移、名义时间、总机会数、停留/返回事件、分辨率/FOV/近远面 |
| `CameraFrame` | 帧序号、名义时间、实际float姿态、View、NO/ZO投影或其精确冻结编码、各哈希；不由实际耗时推进相机 |
| `ExperimentCase` | 资产/相机/材质版本，B/深度/阈值，算法及高度策略，固定/增长前缀，线程请求，初建/预热/停止规则，质量采样版本 |
| `RunManifest` | 运行ID、case/input/semantic/execution身份、源码/程序/构建/依赖、OS/CPU/后端/驱动/分辨率、时间口径、进程次序、模式、配额、状态及产物清单 |
| `FrameEvidence` | 帧/相机/更新序号、实际N/U、网格哈希、画面哈希、材质/视口/深度约定、质量身份、截图与逐帧数据引用 |
| `FigureSpec` | 输入文件/列/过滤/分组、统计单位、坐标/单位/范围、颜色/图例、异常处理、导出配置及来源摘要 |

JSON不重复放逐帧大数组；大表/二进制独立存储并由manifest引用。缺失与不适用记null/明确状态，不能伪装成0。每次运行独占新目录；失败/超时保留，不覆盖已用于报告的数据。

## 5. 地形资产体系

### 5.1 首批受控规模

拟定12个主资产，不自动生成所有尺寸×尺度组合：

| 类别 | 数量 | 首批内容/观察目的 |
|---|---:|---|
| 历史回归 | 2 | test129、Peking547，文件与旧协议保持不变 |
| 确定性生成 | 6 | 平面；非对称斜坡；局部尖峰；山脊；深谷；多尺度起伏 |
| 真实DEM裁剪 | 4 | 高起伏山地、河谷/峡谷、缓丘、低起伏平原；在运行新算法前选定地理范围 |

生成器使用数值函数、固定种子与参数，不用生成式图片充当高度事实。多尺度场固定频谱/幅度/种子，不为获得更多事务调参。建议主分辨率129/513/1025，至少一个新资产采用1001等非dyadic栅格；四个真实裁剪优先统一513或1025，具体分辨率与物理范围在EIP-02冻结。相同地形的分辨率派生项按需生成，最多4个，不列为独立自然场景。

每个资产给出：高度图预览、阴影地形图、坡度/高度直方图、两个方向的3D视图、尺度/分辨率/起伏说明。视觉检查方向、层阶、接缝、缺失洞、尖峰和重复模式，不能只看灰度缩略图。

### 5.2 已核对的网络来源候选

- 优先USGS 3DEP / The National Map。官方说明其产品免费且无使用限制；具体数据项仍保存来源和元数据。首批选定范围后只下载必要DEM，不下载全国数据或点云。[USGS产品与获取说明](https://www.usgs.gov/3dep-product-news)
- 可选OpenTopography用于以后补充区域；其开发者入口有API及访问条件，实施前核对具体数据集凭据/限额，首批不以取得密钥为前置。[开发者入口](https://opentopography.org/developers)
- 简单漫反射素材优先Poly Haven的CC0原始资产；网页、示例渲染与API条款独立，不把网站预览图当素材重新分发。[资产许可](https://polyhaven.com/license)、[API说明](https://polyhaven.com/af/our-api)

本轮只核对候选来源，没有下载、选择最终瓦片或锁定具体材质。EIP-02/03记录确切产品/素材ID、文件URL、日期、内容哈希及许可。旧Peking的源头资料如未找到，标记历史来源待补；不自行声明它可公开再分发。

自然地形候选可从Sierra Nevada山地、Colorado河谷、Appalachian缓丘及沿海低地中选取；这些是预选地貌范围，不是已获取的四个实验输入。裁剪依据地貌/完整性/尺寸，不能根据新算法的速度或质量挑选。

### 5.3 栅格转换与尺度

- 运行输入以16-bit单通道PNG或PGM为主，真实灰度范围不经过sRGB/gamma。
- GeoTIFF读取、重投影、裁剪、NoData处理在离线工具中完成；复用GDAL已有能力，冻结版本、命令、重采样核及轴顺序。[gdalwarp官方文档](https://gdal.org/en/stable/programs/gdalwarp.html)
- 当前算法使用方形参数域与单个`TerrainSize`，首版选择**投影到米制坐标后的方形裁剪**；不把经纬度栅格直接拉成正方形。
- 明确像素中心/栅格端点、东西/南北到U/V及X/Z的映射；用非对称解析斜坡检查镜像、转置、半像素偏移。
- 缺失值不能变成0高度或针状峰；首版优先无缺失裁剪。确需填补时保留mask、方法和占比，作为新派生资产，不能静默修图。
- 若水平范围为L米，采用统一比例s映射：`TerrainSize=sL`，`HeightScale=s(hmax-hmin)`，世界高度为`s(h-hmin)`；记录原始高程偏置。默认不做垂直夸张。
- 归一化量化公式、舍入规则、饱和数和残差均记录；已转换uint16及冻结双线性规则才是本次主参考，不把重采样后的输入称为未经处理的原始DEM。
- 多分辨率派生记录parent/hash/滤波规则；不能把不同分辨率当成同一个ground truth。降采样不能以无记录的模糊处理掩盖难例。

每个资产有源文件SHA与规范化样本SHA。运行前用C++现有加载器核对实际样本，不仅用Python确认PNG能打开。

## 6. 简单材质与真实画面

三种预设共用现有地形网格与着色路径：

1. **中性光照**：灰色基色、固定光照、无高度染色，用于看形状、法线、裂缝和高度漂移。
2. **UV检查**：带方向/尺度标识的棋盘格，可切已有线框，检查UV方向、拉伸和过细/过粗网格。
3. **基础地表**：岩石/土壤/草地中选择一张1K以内漫反射图，固定平铺/高度染色；用于展示，不能代替中性诊断图。

只参数化现有纹理、染色和平铺常量，不引入PBR或位移贴图。GLSL/HLSL各自实现相同观察参数，分别核对颜色空间和采样；不在此轮全局改变历史gamma规则，保留legacy预设。

材质改变不触发LOD种子/拓扑重建；资产改变是显式场景重置，并在记录中出现。材质加载失败保留上一有效资源并显示原因。两后端资源释放/上传沿各自现有所有权，不在实验控制器中管理GPU纹理。

所有质量比较至少有中性材质版本；展示纹理可能掩盖几何误差，禁止只展示纹理图后判质量相当。

| overview-orbit | 看整体细化分布、轮廓和方向，一周约96机会 |
| approach-return | 远→近→远，固定停留；看尺度变化与局部细化，约96机会 |
| terrain-traverse | 沿预先选定的山脊/河谷移动，参考源高度确定离地高度，约128机会 |
| reveal-return | 朝向变化暴露原不可见区，再精确返回并停留，约96机会 |
| stationary-recovery | 固定视图连续更新，24～32机会；无交换不自动宣告收敛 |

数量为首版模板建议，实际各路线配方在EIP-04生成前冻结，不按算法收敛结果延长。路线模板绑定资产世界坐标后形成不可变CameraFrame集合，不能在运行中依赖被测网格调整相机高度。

### 7.2 录制、编辑与回放

- GUI允许记录/删除关键姿态、设置停留机会数、导出配方；原始关键帧与最终冻结行都保存。
- 默认分段位置/朝向插值，避免穿地和up退化；平滑插值若启用，插值算法/参数进入版本与哈希。
- 地形碰撞检查依赖固定reference而非当前LOD；修正路线需先生成新版本，不能对不同算法自动修不同路径。
- 执行以update opportunity推进，每机会一轮公共更新；名义时间和实际耗时分列。不能用实际deltaTime让慢算法走不同位置。
- 切回初始视图与停留不会Reset；重置仅在明确实验边界执行，冷启动与预热分别记录。
- GUI拖动到任意帧时，默认重放起点至目标帧；没有真实检查点就不声称随机访问等价。预览自由飞行产生新会话，不污染冻结序列。
- 视频按固定名义帧率播放，不能把视频播放流畅当成实时达到该帧率；需要时另标每帧测得CPU时间。
- NO/ZO用同一逻辑姿态分别冻结投影与哈希；不强求不同后端的像素逐字节相同。相机FOV、near/far、视口、DPI和drawable尺寸全部入记录。
- 冻结浮点行须保证往返不损失实际float值，可用`max_digits10`文本或显式位编码；哈希针对规范化字段编码，不针对CSV排版。Python不独立重算GLM矩阵。

## 8. 采集边界、截图与回放

### 8.1 四类运行

| 模式 | 采集内容 | 时间能代表什么 |
|---|---|---|
| timing | 无profiler、无截图回读、无逐帧全域质量；记录已有阶段与平台时间 | 同模式同环境的正常执行成本 |
| visual | 真正GPU画面、固定关键帧或完整短序列、设置与帧身份 | 视觉与状态行为；截图等待/编码不作为正常时间 |
| quality | 对同源实际CPU网格作离线评价并导出必要点值 | 独立质量；离线成本另计 |
| profile | 单独perf或Tracy，ROI及版本匹配 | 热点/时序归因；不作为正式无工具速度 |

所有模式使用相同case与相机行。新算法同策略的normal/visual/quality回放必须核对逐帧决策与实际网格身份；若调度导致结果分叉，先标记不一致，不能混合拼报告。不同算法只要求相同输入/任务比较契约，不要求相同拓扑。

Windows平台计时与WSL CPU归因分栏。perf不能采原生Windows程序；需要时用同源Linux公共CPU回放诊断并披露实现/编译环境差异，不能把Linux函数比例直接乘Windows时间制造函数毫秒。

### 8.2 帧采集接口与后端差异

新增窄的诊断帧请求/结果接口：

- `RequestFrameCapture(id)`仅登记一次请求；同一帧不积压无限请求。
- 后端在实际渲染/Present生命周期内完成正确的颜色附件回读。
- `TakeFrameCapture()`返回自有CPU RGBA、宽高、通道/行方向、颜色解释及captureId；失败显式返回原因。
- GL从正确的未交换颜色缓冲读取，规范行方向；D3D12以自己的资源状态转换、copy footprint、readback heap及完成fence处理。
- 后端拥有GPU资源与排空义务；实验输出器在完成后编码PNG。关闭采集时不分配/回读帧缓冲，不新增GPU等待。
- UI开关决定捕获“纯场景”或“含面板”画面，明确采集点；不能拿桌面截图中的窗口大小代替实际drawable。
- 为精确关键帧允许诊断模式同步等待，费用留在visual模式。此接口不触碰现有网格上传策略。

影片从真实逐帧PNG按冻结顺序编码；首版可交付逐帧HTML播放器和MP4。缺FFmpeg时明确缺少视频编码产物，不用插帧/生成图补帧。每张图片有case/algorithm/policy/frame/view/mesh/image身份及捕获前后状态；不能用离线重画曲面替代平台画面。

### 8.3 质量证据

沿用双线性主参考、sampled Emax、Hmax、参数域等权RMS、Dmax与N/B。记录采样版本、层次、有效域、缺失/异常计数；不把RMS重命名成屏幕面积加权指标。

为误差图新增按需评价点UV/参考投影/可见性导出，复用评价器自身枚举，禁止在Python里猜核心Q编号映射。参数域热图与实际屏幕叠图分开；未采样/不可见/数值未知不同颜色，不插值出不存在的精度。输出镜头关键点与尾部误差见证，不只报告一个最大值。

参考预览用固定源heightfield的高分辨率表示，始终标明表示误差和分辨率；它帮助目视定位，数学质量仍由独立reference求值。

## 9. 性能分析、图形与报告工作流

### 9.1 数据归约先于绘图

~~~text
不可变raw + manifest
→ schema/身份/完整性检查
→ 同协议分组与独立进程归约
→ analysis.json / 明确列义的表
→ FigureSpec → SVG/PDF/PNG
→ Markdown/HTML报告
→ 实际打开图像和报告，记录视觉审查
~~~

图表不重新计算一套“胜负”；只能消费同一analysis。不同CSV版本由显式适配器处理，不能模糊匹配列名或把缺列填0。已有TPI/PQ/SVE可导入作历史说明，但不混成同一正式统计总体。

统计要求：

- 独立进程为主要重复单位；先记录每进程内部帧摘要，再计算配置间比较。
- 冷启动、静止、运动、返回/恢复分别展示；所有帧总览仍保留。
- 开发快验一配置一进程，只报告描述统计与限制；不从24相关帧产生伪置信区间。
- 正式重复数、顺序、预热和误差带算法在未来实验协议中另冻结；不沿用旧五进程工具的默认工作量。
- 同任务serial→parallel才称多核加速；DOD与新策略质量不同的时间比标为“成本比”，与质量/实际N并列。
- n=实际活动面、B=预算上限、q=质量样本数、r/m=前缀额度、b=批准批宽分开，不能以B代替实际工作量。
- 零事务、失败、截尾、质量未完成、缺栈都保留。无穷/分母0显示不可定义，不删除较慢数据。
- 将基础设施可用、视觉观察完成、算法质量、性能可行性与论文结论分别标记。

### 9.2 首批标准图

| 图 | 必须回答的问题 |
|---|---|
| 地形与路线总览 | 输入到底是什么、路线覆盖哪里、何时转向/返回 |
| 完整时间—预算/实际N | 50k/100k/200k时成本如何变化；20k作小规模参照，不默认重新跑规模矩阵 |
| 阶段分解 | 全局求值、接收/回收认证、预留、提交、续接及未归属成本各多少；只堆叠互斥时间 |
| 线程收益 | 同任务1/4/8线程实测；只画实际存在的点，未测不补线性趋势 |
| 工作量与兑现链 | raw→examined→need→feasible→executed；配对、冲突、批宽与时间是否共同放大 |
| 连续质量/恢复 | Emax、Dmax、Hmax、RMS、实际N/U及视图事件；含返回后静止尾段 |
| 质量—时间散点 | 显示不同策略的交换关系；不预设“肉眼不可见”阈值 |
| 函数热点 | self/inclusive、采样数/有效性、源码符号与调用路径，不把包含关系累加 |
| 线程时序 | 同一捕获的主线程/工作线程、ROI、派发/等待/执行，未解释空白保持未知 |
| 实际画面与误差对照 | 同帧、同视口、同材质、固定裁剪区域与色标，直接联系质量见证 |

函数报告提供全符号表；正文列主要热点并显示“其余/未知”的采样权重，不只保存Top10。每个有实质占比的主热点关联算法阶段、输入规模参数、调用/循环结构和有依据的复杂度说明。perf样本数不是精确调用数，Tracy已标记区间次数也不是全部C++函数调用数。复杂度无法确认时标“未审计”，不自动生成O(n)装饰结论。

FPR的两类采集分开运行。图可按case/frame/phase关联，但不能将两次不同运行的时钟拼成同一条精确轨迹。

### 9.3 视觉制作规范与报告模板

- 算法/策略颜色全报告固定，兼顾色觉差异；图例同时用线型/符号，不只靠颜色。
- 共享比较图使用相同轴限、热图色限与裁剪范围；需要局部放大时同时给全范围图并标注。
- 字号、单位、图注、样本数、错误/缺失状态清楚；PDF/SVG用于排版，PNG供预览；嵌入或记录中文字体与版本。
- 图旁保存数据CSV/JSON和FigureSpec，图注带来源运行ID、统计单位与是否同质量/同任务。
- 报告按“问题与假设→输入与协议→正确性/视觉→性能/工作量→函数归因→质量与恢复→限制与下一步”组织。
- 算法结论由研究者写明依据；生成器只填表/拼图/标状态，不自动把最快者写成获胜或把零事务写成收敛。
- HTML离线可看原图、关键帧序列和原始表；每次运行独立报告，最终索引链接各次报告，不覆盖历史。
- 如需PDF报告，采用一个固定导出流程并逐页渲染检查；DOCX投稿排版以后再做，不为此先建文档框架。

## 12. 视觉验收是明确门禁

本轮按用户要求，**只通过编译、单元测试或数值表不能关闭视觉相关阶段**。Agent必须实际打开/查看产物，不能以文件存在或已生成PNG代替视觉检查；最终提供给用户可直接查看的图、影片/逐帧页和审查记录。

| 对象 | 视觉检查项 | 必须保存的证据 |
|---|---|---|
| 地形资产 | 方位/比例/缺失/台阶/非自然尖峰，解析地形与预期一致 | 高度图、方向标识、阴影与两个角度真实视图 |
| 材质 | 色彩/平铺/方向/接缝、法线和形状是否被掩盖 | 同相机中性/UV/地表预设对照 |
| 相机 | 覆盖、速度变化、转向/返回、地形穿越、停留期间仍更新 | 路线图+事件标记+真实短序列 |
| 平台捕获 | 真实后端、正确帧、方向、分辨率、DPI、UI范围 | 原图及帧/网格manifest |
| 连续质量 | 轮廓、裂缝、popping、离屏改变/重新暴露、残余坏区 | 固定见证裁剪、返回前后序列、独立误差图 |
| 分析图 | 标签、单位、图例、字体、遮挡、色标/轴范围、截尾/缺失 | SVG/PDF/PNG及FigureSpec/原表 |
| 实验报告 | 页面层级、图注、分页/表格截断、链接、结论与证据一致 | 离线HTML；若导出PDF则逐页渲染预览 |

视觉问题分为“基础设施错误”和“被测算法问题”：错帧/镜像/隐藏异常/错误图例必须修正；真实几何劣化应如实展示并记录，不能修图或删除镜头让基础设施验收通过。

记录四个独立字段：`automatedChecks`、`agentVisualReview`、`userVisualReview`、`algorithmQualityStatus`。用户尚未检查时只能写“待用户视觉评审”，不代签。视觉观察不构成人眼不可感知证明，数值门禁也不能代替实际观看。

## 13. 最小测试、资源与停止机制

### 13.1 开发快验与正式实验分开

- 首批资产库不是运行矩阵。阶段验收优先用历史Peking24机会、一个生成输入、一个新自然输入；预算优先50k，输入容量不足则先登记适用范围。
- 正式20k→50k→100k→200k、固定/增长前缀及1/4/8线程配置可以表达和生成清单，**本规划不默认执行完整组合**。
- 需要比较同任务并行时用一个配置的serial/parallel；Classic/DOD/新算法都要能选择，但不在每小阶段全跑全部算法。
- PQ默认拟合与冻结旧点配置显式命名；新工具不能悄悄把默认策略改成消融B。
- 每阶段运行前选择足够的输入/测试/视觉产物和停止标准；已有证据充分则复用，无关CTest/后端不跑。

### 13.2 性能回归

每个小阶段保存修改前/后版本、程序、输入、相机、环境与同边界结果；正常计时顺序执行，不并行构建、截图、perf/Tracy或转码。离线工具变动比较固定数据集处理时间/RSS，新增能力费用单列，不免除基础设施的性能核查。

默认每配置一独立进程；明显工程影响按开发规范第7.3节的 `max(0.05ms, 5%×基线, 已有波动)` 筛查。少量帧不声称稳定P95或统计显著，遇具体风险至多一次定向复测。性能问题单独写原因/证据，依规划规范第12.2节确定修复归属；不能自动扩大到算法优化。

### 13.3 资源预算与中止

- 首版运行输入默认不超过1025²；不主动新增4K/8K高度图和大纹理。6生成+4真实主资产之外不自动扩库。
- 新增可提交资产/小图首轮预计不超过64MiB；单文件超过8MiB时优先缩小**可发布派生预览/资产规格**或仅记录获取配方，不以静默修改被测分辨率降低实验成本。
- 原DEM下载缓存累计上限2GiB，单次请求/处理上限10分钟；超出先记录来源/大小与未完成项，不自动下载更大区域。下载失败可保留为未取得，不用生成资产冒充真实DEM。
- 每个自动平台/CPU回放仍以180秒、8GiB为初始外层上限；素材离线处理/评价按单阶段限额另列。超限写资源受限/截尾，不能等同数学不可行或稳定耗时等于限额。
- 每小阶段开发采集目标5～15分钟，首次上限20分钟，素材下载/构建/离线评价/视觉观看分列。EIP-08全流程上限30分钟自动采集，视觉检查另计；不足则记录剩余范围。
- profiler沿用FPR的采样/文件/窗口限制，不安装新内核、不修改全局权限、不同时开两套采集器。
- 发生错帧、状态重置不一致、数据/图表来源错配、预算/拓扑破坏或源样本转换不一致，停止相关路径，先修基础设施。算法既有质量反例保留，不无限追加运行。
