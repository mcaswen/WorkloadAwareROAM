# TPI-04：D3D12 消费事实

日期：2026-09-15。实现前版本 a4f4fd9，依据[小规划](../../plans/cpu_refinement/tpi_04_d3d12_consumption_plan.md)。原始命令、构建、CSV、日志和前版二进制位于忽略目录 benchmark-output/cpu-refinement/tpi-04/run-01。

## 生命周期与职责

D3D12 沿用两份独立映射网格资源。BeginFrame 等待当前帧 fence 后才复用；更新按帧累计 PendingUpdateRanges，成功复制后才清除该帧待消费状态。未消费帧不保存 CPU 数组裸指针，追赶时读取最新完整输出。Render 才发生的延后复制也计入上传时间与字节。

持续更新、暂停、单步、设置/来源重置和失败输出规则与 OpenGL 一致。暂停时恢复资源只上传最新网格，不增加 BuildSequence。两个后端保留各自 uploader，没有新增共同资源抽象。

增长缓冲释放旧资源后立即清零容量并要求全量；区间累积发生分配异常时所有帧升级为全量。失败帧禁止绘制失配资源。有限诊断钩子模拟释放之后分配失败，不代表设备移除或真实 OOM 已获验证。

## 原生运行证据

Ubuntu 编排原生 Windows/MSVC RelWithDebInfo，tests OFF、运行接入 ON；GPU 为 NVIDIA RTX 5090 D。D3D12 请求 Agility 614，实际日志显示加载系统 D3D12Core 6.2.26100.9278，不能把请求版本写成实际运行版本。

真实图形检查退出 0：新算法初始 3619 面；持续序号增加，暂停/暂停恢复保持序号，单步只增加一次；全量同步 607992 字节；分配失败后恢复，再经两个帧槽追赶，最终空更新为 0 字节；窗口变化、预算降到 512、来源重载和切回 DOD 完成。序号没有为恢复而重置。D3D12 分配失败是消费者错误，核心 Ready 状态不等同于上传成功。

OpenGL 针对暂停恢复的有限重验退出 0；注入上传错误后完整恢复，暂停恢复保持序号 4。复用 TPI-02 NO/ZO 数值证据，未重跑无关核心矩阵。

## 边界

真实 GPU 消费、帧轮转、容量失败恢复通过有限检查；设备移除、任意驱动异常和任意跨帧资源压力未验证。默认输入零事务，非空事务的真实增量上传仍由 TPI-05 核查，不能以 CPU 夹具替代该自然覆盖。注释检查 src 15.7%、renderer 12.1%；规范和计划逐项比对完成。
