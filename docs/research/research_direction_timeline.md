# 研究方向演变与决策时间线

整理日期：2026-09-18。Git 截止：`c95ace0`。本页同时记录该提交之后、截至用户要求编写本页的会话决定；这些决定不冒充已经实施或提交的修改。

**本项目需要回答的问题逐步发生了变化：从等价执行策略的交叉，经过严格目标的发现与物化，转向自主生成事务的 CPU LOD；随后又发现，事务可执行、具有并行度、能够持续运行，并不同时意味着质量与成本具有竞争力。** 当前重点重新落在旧质量策略的性能可行性，但已发现的质量反例仍然有效。

## 1. 如何读这份历史

### 1.1 三种来源与时间

- **用户提示词**解释当时的目标、异议、授权和优先级。本文的 `U01` 等编号是本次整理分配的引用编号，不是聊天系统消息 ID；引文来自本会话可见的用户原话。数学下标、富文本空白和换行作阅读性整理；省略上下文的引文只代表所摘录部分。没有可核对的消息时间戳，因此只按出现次序与相关文档、提交对应，不为提示词补造具体时刻。
- **阶段文档、结果与审查**解释实际得到什么、为什么停止，以及证据边界。规划是目标，报告是所记录结果，二者不能互相替代。本文为历史核查，没有重新运行旧实验或全部 Lean 工程。
- **Git**证明材料何时进入当前仓库历史，不能单凭提交日期认定实验或讨论恰在当天发生。完整 131 项提交见[提交台账](research_history/commits.csv)，来源指纹及复核方式见[证据说明](research_history/README.md)。

当前分支的首个提交是 **2026-08-20 `aa6bb71`**；早期里程碑文档却记录了 **2026-07-03** 等日期。7月～8月前期只能称为“既有文档记载”，不能伪造一条从7月开始的 Git 提交链。本文没有完整项目早期聊天导出，也不推测第三方 `RoamTesting` 仓库如何由“另一个版本的我们”产生。

以下状态有不同含义：**讨论候选、批准规划、已实施、有限验证通过、暂停、关闭、已归档**。特别是“已完成小阶段”不自动等于“研究假设成立”；“关闭这轮投入”不等于一般不可能性定理。未注明外部评审的审查是项目内 Agent 自审。

### 1.2 文档职责

本页回答“为什么从上一方向走到下一方向”，不替代原规划、推导、数据或代码事实。原记录保留原日期和结论；本页遇到后续修正会指出修正来源。证明阅读仍从[推导总目录](derivations/README.md)和[数学总览](derivations/mathematical_derivations.md)进入。

本次只新增研究历史与证据导航，不切换生产默认值，不实施性能优化，不恢复已归档分支。每次后续转向应追加日期、证据、用户决定及承接阶段，不改写旧条目使历史看起来必然通向今天。

<a id="r01"></a>
### R01　最初主问题：工作量能否决定各阶段的执行策略

8月21日～9月1日，`a928ac7`、`ea4249d`及`1ee5af5`～`7d771cc`先建立阶段事实、策略预设、评分边界、拓扑辅助、统一结果核查与基准入口；`d2c106b`进入正式实验准备。原问题定义见[工作量感知问题](../parallel-roam/19-workload-aware-problem-definition.md)。

核心假设是：合并评分、细分评分、合并拓扑、细分拓扑、网格提交的串并行收益随工作量变化，足够稳定的交叉可以支持策略选择。**这里的候选必须解决同一个阶段任务并保持声明结果等价**；不能把改变网格的算法与单纯执行替换混成同一个交叉点。

这条线的遗产是可比较边界与完整计费，而不是后来所有新算法都必须满足原动态请求轨迹。

<a id="r02"></a>
### R02　用户把CPU pilot前移，限制基础设施先行

**用户触发 U01：**“先把五个 CPU pass 的可靠配对跑出来，再碰 OpenGL/D3D12 uploader 大重构。”随后又要求“直接把数字也改连续，然后重新映射成完整规划”。

PREP-01～03于9月9日落盘：`bb1a89c`参数化并行下限，`72f9c5f`冻结最小输入，`4d7ab68`建立工作量发现。9月10日`7522db7`接入五阶段配对。早先提示词的阶段号对应重排前草案；现行记录中PREP-04是最小配对，PREP-05是pilot，不能按最早提案编号反推实施顺序。

**关键约束。** 用户质疑OpenGL与D3D12上传模型不同，相关规划不再把“复用上传实现”理解成跨后端共用一个资源模型。研究投入优先由CPU证据决定，上传大重构没有因为准备规划存在就自动开始。

<a id="r03"></a>
### R03　`sampleIndex=14`将“安全并发”与“严格greedy等价”分开

**用户触发 U02：**“并行 planner 只能从 global priority 的连续前缀中取候选。一旦遇到第一个不能并行安全提交的候选，后面的候选全部不再提前提交。”

PREP-04在Peking20k的`sampleIndex=14`发现：两条路径都合法且预算相同，却产生不同叶集、队列和网格。这不是物理编号差异。[反例分析](../reviews/formal_experiment/prep_04_split_topology_equivalence_analysis.md)保留了两边各6个独有叶的证据；`ec8792e`按连续前缀修复，`2faaa3a`完成移交。

**另一路决定 U03：**“这个性能问题暂时关闭，下次把验收标准放宽一下……不用再扣几微秒细节。”`662a730`记录的是接受未决小差值、调整后续工程筛查，而不是证明没有退化。此后用户又明确不要跑冗余测试；工程快验和正式统计采样逐渐分开。

**意义。** 这一阶段增强了对照可信度，却也收紧了自然可并行范围；后来的“没有并行”必须相对这套执行契约解释。

<a id="r04"></a>
### R04　P5完成，但五阶段通用交叉路线没有通过

9月11日`bb23e2a`记录[P5结果](../reviews/formal_experiment/prep_05_cpu_crossover_pilot_gate_review.md)：三个独立进程、113个冻结输入。合并/细分评分分别有17/19个三次稳定并行优势点；合并拓扑只有5/17项实际并行，细分拓扑0/24；网格脏提交有4个稳定串行优势点和3个稳定并行优势点。

**当时出口。** 只有网格提交满足双向交叉规则，未满足完整路线至少三个CPU阶段的投入门槛，因此不自动进入PREP-06。不能写成“所有阶段均无交叉”，也不能把细分0/24解释成所有合法算法理论上都无法并行。

**用户转向 U04：**“ROAM 的全局 greedy ordering 到底有多少是获得其网格质量所必需的，又有多少只是限制多核并行度的执行约束？”紧接着用户说“不是你先别改研究问题，我们再讨论讨论”。方向由此进入讨论，尚未当场替换正式研究定义。

## 4. 放松排序、批量优先与理论探索

<a id="r05"></a>
### R05　排序松弛Gate：先定义质量，再检验保守批次

**用户契约 U05：**“拓扑合法性与三角形预算保持严格约束，只允许通过放松 greedy 排序引入可测量的几何近似损失”。用户进一步要求分开调度优先级、独立质量与严格串行基线；串行网格不是几何真值。

`c3d27a4`记录讨论和离线规划，`3c6b574`建立单根观察。批次只能从批前快照生成，新请求不能借助批内已执行成员的信息追加。首版限定保留严格头请求、保守不相交读写集合与只放松细分排序；负结果只能否定这一受限模型。

**参考策略转折 U06：**“Primary reference=raw height samples + bilinear interpolation”。固定对角线规则网格与DOD表示存在不匹配，用户先限定只跑test129，再要求同输出加密及非二进制整齐尺寸Peking校准。`a0f3551`锁定双线性源参考；最细ROAM只作诊断，评价仍须区分采样最大值与连续数学上界。

[GATE-03结果](../reviews/ordering_relaxation/gate_03_snapshot_relaxation_review.md)仅在完成输入找到最大宽度2/4/5，各只有一个多成员批次；高负载配置触发资源上限，完整独立质量比较未完成。**U07：**“行，这轮gate03先关闭，之前的实现移入过时文件夹。”`b078d59`于9月12日归档。关闭理由是当前机会与取证成本不足，不是一般排序松弛不可能。

<a id="r06"></a>
### R06　CPU-CBT：先取得批量结构，再谈质量接近ROAM

**用户触发 U08：**“还是那个观点，就是不碰gpu的研究。还是利用这些 C++ 参考实现研究 CPU 批量更新。”参考来自`third_party/RoamTesting/src/algorithms/cbt_2024`。

`9db18d3`建立持续串行原型，`a3738d6`并行化模板本地填写；外邻传播、计划、简化与占用维护仍串行。原参考、新串行、新并行三档分开比较，Peking保留80/12尺度，一轮编排明确为本项目组合的参考原语驱动CPU语义。

[CPU-CBT-02](../reviews/cpu_cbt/cpu_cbt_02_parallel_bisect_review.md)证明真实线程参与与持续状态一致，但新串行/并行的完整更新累计配对比值约1.0124和1.0133，收益很弱；test129准备路径另有未修复局部成本。`f9f316c`归档时保留问题，没有追认为性能通过。

这否定了**这一保守CPU映射已足够实用**，没有否定后来作为GPU对照的CBT-2024，也没有证明所有批量细分都慢。

<a id="r07"></a>
### R07　从“葬礼”到保留CPU执行研究：交叉不是唯一贡献出口

**用户提示 U09：**“给它办个葬礼吧”，随后明确“但是！没有结束……不意味着相对classic roam的并行优化，crossover/执行策略探索没有价值或者科研贡献了。”

这次讨论的实质不是否认负结果，而是取消“必须找到多个交叉或全新拓扑算法，才可能形成文章”的隐含前提。用户强调多阶段拆分、边界对照、并行实现和优化本来就是贡献候选，并明确目标期刊为 **The Visual Computer，而非TVCG**。

9月12日`1601717`形成[CPU研究定义](../plans/formal_experiment/cpu_roam_research_definition.md)：固定策略可以成为结果，阶段单侧优势和不可比情形也应报告；不以Workload-Aware项目名强迫训练在线选择器。该定位保留至今作为可收缩回归的研究基础，不构成期刊录用承诺。

<a id="r08"></a>
### R08　阈值闭包与激活谱：数学可解不等于动态目标便宜

**用户触发 U10：**“最先证明的不是次模性”，而是固定依赖闭包是否保持并集；随后把重点放到阈值可行性与硬预算目标。`f1f1b1d`建立[理论工作区](roam_threshold/README.md)。固定依赖、阈值闭包、激活表示形成条件证明链；现有评分不自动等于独立几何误差，Lean只覆盖声明的抽象模型。

**增量Gate提示 U11：**“判断 dependency-saturated activation spectrum 和 hard-budget threshold 能否在连续视点变化下按‘受影响区域’增量维护，而不是重新扫描完整潜在层次。”

`e95b85b`记录[No-Go](roam_threshold/incremental_gate.md)：在已知变化源的前提下可以局部传播，但相机变化后如何便宜发现全部相关变化仍未解决；已有机制覆盖使本轮没有形成要求的新算法。显式精确谱的线性坏情况，不是所有隐式算法的不可能性证明。

后续最小修改量方向被用户保留但暂存：**U12：**“它主要优化的是……最少需要发生多少拓扑修改”，而当前要解决“改变工作依赖结构”。[recourse记录](roam_recourse/minimum_change_note.md)没有因与当前目标正交而被判无价值。

<a id="r09"></a>
### R09　必要依赖审计反过来否定了过强的低并行度叙事

用户提出forced refinement可能是结构成本，并考虑用必要依赖上界解释阶段特化；但随后明确 **U13：“这不是一个决定，我只是跟你讨论这条路线是否可行”**。不能把此前长段意见追认为永久停止新算法探索。

`037c698`记录[方向](roam_parallelism/direction_note.md)，`24c6391`完成[必要依赖审计](roam_parallelism/necessary_dependency_audit.md)。三个局部例子表明，递归调用或逐菱形发布链可以在允许私有准备、联合发布时被消去。

**用户验收 U14：**“forced-split 的递归/发布链不能直接当成 CPU 必需关键路径”。因此没有继续建设“ROAM理论低并行度分析器”。这次负出口针对证书不足，并不证明高并行度可达；它防止了用实现顺序循环论证算法下界。

<a id="r10"></a>
### R10　工作膨胀与参数化成本语义，暴露完整状态生成缺口

**用户问题 U15：**“为了降低 span、制造并行工作，我们额外增加了多少 work？”先提出Work–Inflation Gate，继而要求优先形式化/参数化成本模型，避免把机器噪声与算法机制混在一起。

`24c6391`留下[测量契约草案](roam_parallelism/work_inflation_measurement_contract.md)，`69ab803`的[PCSG报告](roam_parallelism/parametric_cost_semantics_gate.md)则在第一项拓扑同任务审计停止。评分、脏写可以给出分区等价；固定目标叶集却不自动产生邻接、身份、队列和完整持久状态，不能把这一大步写成免费的“发布”。

出口是“限定候选下成本完整比较尚未成立”，没有扩建Lean框架，也没有否定参数化分析。这一缺口直接提出了下一问题：已知目标后，怎样真正构造可继续更新的状态？

## 5. 给定目标的物化，与严格目标发现的分离

<a id="r11"></a>
### R11　MPR：端点差分物化获得支持，但目标仍是输入

**用户定义 U16：**“给定 M0 和合法目标 J，怎样直接物化一个完整、可继续增量更新的 ROAM state？”用户进一步把 **continuation-state locality** 指为核心，要求不能只输出合法渲染网格。

`1e05b24`建立[理论与原型规划](roam_parallelism/target_materialization_gate.md)，`d876cea`、`d635a9b`实现串行/有限并行原型。叶差分至多3k、合并支持至多2k等结论服务于端点构造；12项支持集/队列等式经Lean检查，完整几何和原生C++并未一并形式化。

原型保留Pending、队列及后续操作，以共同表示下自然逐菱形参考比较，不能人为拖慢参考。**U17：**“直接标记为获得强验证可以继续”，对应算法可行性及续接证据，不是整体性能通过。

`602ed48`的MPR-03压力快验中k=27,783，串行物化约332→240ms、四线程约226ms，尚无稳定完整多核净收益。用户要求减少开发采样轮次并用WSL Ubuntu编排；[原型结果](roam_parallelism/target_materialization_prototype.md)保留未完成正式统计的边界。目标发现、差分认证和导入始终另计。

<a id="r12"></a>
### R12　NMP把任务扩大为目标发现，语义解耦成立却不便宜

**用户推进 U18：**“意思就是让新算法直接替代原来的拓扑pass，不行吗”，并要求保留原/新开关。`c2cd2d8`规划原生接入，`2f04f48`实现NMP-01严格逻辑Planner。

这一步把问题从给定J变成自己产生与Legacy动态执行相同的J、Δ、Γ。Γ被限制为历史、失败、强制来源等续接义务，不能携带完整答案状态。有限夹具中不调用旧完整拓扑阶段、不复制全生产状态，严格决策及端点一致；但旧节点局部并不意味着所有堆访问稀疏。

用户要求强性能目标，后将理想目标明确为 **U19：“Tplan ≤ 0.5 × Tlegacy”**，并允许按证据扩展原优化规划。`c36286f`时压力Planner约133.892ms、同期Legacy61.801ms，仍未过80%门槛。早期约941ms、1088ms等来自不同对照记录，不能拼成一条同条件曲线。见[性能规划及实施账本](../plans/roam_parallelism/native_planner_performance_plan.md)。

**结果。** 严格决策与生产修改可以分开，不代表分开后更快；目标发现成为真正阻塞，NMP-02没有自动启动。

<a id="r13"></a>
### R13　用户追问定理用途，迫使端点证明与逐步模拟重新分界

**用户质疑 U20：**“原推导推导出了 i - j 模型，但是j 还必须要legacy算给我？这有什么用？”另提出E1：中间轨迹不同而最终目标/ΔΓ/预算相同，并要求先查Lean实际证明了什么。

`2f7e5a0`的[契约追溯审计](../reviews/roam_parallelism/native_planner_contract_traceability_audit.md)确认：`repair_split_queue_exact`、`repair_merge_queue_exact`是给定端点的局部修复；没有要求每次根、堆物理状态和维护时刻都一样。严格请求轨迹来自NMP新增的目标发现契约，不能反向写成Lean定理要求。原生失败/阻塞等义务也不能由抽象支持集自动覆盖。

**后续 U21：**“先把‘候选出生规则是否完备’证明清楚。”`2d8809f`留下[局部出生证明](roam_parallelism/native_candidate_birth_proof.md)与[方向性维护/在线归约](roam_parallelism/native_target_discovery_reduction_derivation.md)。保守有限出生集合和条件队列替换成立，未实现新懒堆，未得到2～5倍便宜目标发现算法；E1没有因此落地。

**历史裁决。** 给定目标物化的局部性没有被推翻；“据此已经找到实用完整CPU ROAM替代算法”的推论不成立。不能把这两件事都写成成功，也不能都写成数学失败。

## 6. 自主事务算法形成：不再等待Legacy给出目标

<a id="r14"></a>
### R14　独立greedy候选与一般one-ring的正确定位

**用户触发 U22：**“只借用roam的greedy思想，但是不用它那个推导和算法，我们自己发明一个greedy版本，可并行的拓扑算法。”随后强调 **U23：“你的推导过程也要留痕，不只写结论”**。

`8af1a41`包含[局部预算交换](cpu_refinement/greedy_local_exchange_candidate.md)、[高度拟合](cpu_refinement/local_height_minimax_derivation.md)、[有界补丁](cpu_refinement/bounded_patch_refit_derivation.md)和[一般邻域回收](cpu_refinement/cavity_budget_recovery_derivation.md)。从三价删点扩展到任意合法内部点one-ring重剖分、固定净释放2面，保留停滞、形状无解及成本反例。

**定位纠正 U24：**“当前邻域预算回收 / cavity retriangulation 不是论文的新主线……Topology Pass / Budget Reallocation 的一个核心更新机制。”多边形DP是局部精确可行性oracle，删点、翻边、独立集等已有原语不能各自冒称原创。

**结构变化。** 新算法自行形成需求与交易，不再要求终态是严格ROAM层次cut；保留的是全局优先考虑需求、硬预算和声明质量约束。不能继续声称严格重现Classic的动态逐请求greedy。

<a id="r15"></a>
### R15　GMP锁定的是拆解串行反馈循环，不是“首次多阶段”

**用户契约 U25：**“不要把‘multi-pass’本身作为主要创新表述”，并要求正式定义“batch-snapshot global priority-ordered greedy reservation”。

`1b93ca8`总规划、`64b00aa`执行契约、`e01cd06`事务组合、`ed277cf`自然Gate、`02f351f`/`b6ddc6d`准入与边界相继落盘。快照形成全局全序需求，按冻结目录/回收池不可回退预留；新请求等下一快照。P为急迫度，接收收益和回收损伤分别评价；完整读写集合而非仅删除面重叠决定冲突。

[四个自然快照](cpu_refinement/transaction_backend_gate.md)执行交换21/23/0/1。test129证明一般回收能兑现三价原语无法兑现的需求，Peking则暴露优先级与可见认证证据错位。局部DP区分快路漏解与当前操作类别无解，但没有进入正常运行。

**准入范围。** 自主需求→提案→认证→预留→应用→下一轮生成已经成立，足以进入持续原型；固定当前视图采样误差不增，却出现全域高度误差增加。自然非平凡批次不是多核加速或长期质量证明。

<a id="r16"></a>
### R16　GTP持续原型：多核真实，但成本主体在上游

`1414c3c`、`749d48f`、`74d7762`、`9b3711f`依次建立单批串行、局部续接与输出、动态参考、有限多核。用户允许大规划内小阶段自主闭环，但进一步强调 **U26：“完成一个小规划之后，再开始后续小规划。并且完成一个就提交一次。”**

[持续原型及接入成本分析](cpu_refinement/gtp_platform_performance_analysis.md)显示：真正拓扑写入很小，发现、认证、视图刷新和维护占主要成本。有限四线程收益不能弥补完整路径与DOD的巨大差距。理论局部支撑有界，也不代表样本数、证书算术和持续维护为常数。

用户要求下一阶段先查“不该存在的工作”，并在实施工作削减之前插入函数级采样。此时平台接入没有被当成自动消除成本的手段。

<a id="r17"></a>
### R17　FPR→GWR：从猜热点转为证据驱动的工作削减

**用户提示 U27：**“我们必须要用上它，而不是盲猜到底哪些部分开销最大。建议使用 `perf` + Tracy”。随后要求报告涵盖有占比的函数、时序和算法复杂度，不能只交几项阶段计时。

`77ef897`规划，`081c90f`～`8ef2882`建立采样/时序流程，`114c00d`补[完整函数报告](profiling/cpu_function_profiling_findings.md)和[算法复杂度说明](cpu_refinement/transactional_algorithm_overview.md)。test129主要在认证、定位与精确算术；Peking主要在换视图的密集Q投影、建序和发布，两类输入需要不同削减策略。

`7425736`闭环[GWR](cpu_refinement/gwr_final_results.md)：持久结构事实、视图缓冲、精确前缀、惰性目录/局部证据等保留；没有实际削减的视图块界候选撤回。同轮C4 test129约18.915→15.037ms、Peking28.789→11.226ms，仍分别约DOD的24.59/3.93倍。

**边界。** GWR完成只意味着这一轮候选闭环，不证明优化空间耗尽。没有把暂停的规划、失败候选或小阶段完成，改写成完整性能竞争通过。

<a id="r18"></a>
### R18　SVE规模实验揭示固定前缀和增长前缀的两种失败

**用户提示 U28：**“scaling viability experiment，20k→50k→100k→200k”；又要求“固定一轮，增长的也测一轮”“8核也测一轮，都和基线对比”。`c7e6cd1`于9月15日归档，报告自身标9月14日。

[SVE结果](cpu_refinement/sve_01_scaling_results.md)中，固定64在50k以上零事务，不能拿低更新成本代表有效适应；增长组64/160/320/640有真实事务和8线程收益，却在大档放大预留工作并出现64～67px误差。200k增长/C8移动约131.66ms中预留约78.91ms，局部提交继续并行的整体上限很小。

用户随后询问是否已优化充分，并决定接平台再判断。此决定是进一步观察的授权，不追认SVE已满足同质量竞争条件。后来不同报告的200k快慢反转，必须分别核对视图序列、种子、政策、前缀、系统与计时窗口，不能当成同版随机回归。

<a id="r19"></a>
### R19　TPI接入成立，质量却成为明确阻塞项

`880574c`规划；`b7b4a52`、`2341710`、`a4f4fd9`、`4b66cb6`、`01ecf96`完成核心/适配、OpenGL、D3D12与真实持续观测。[平台报告](cpu_refinement/tpi_platform_results_and_headroom.md)记录独立算法切换、Pending/脏范围与增量上传，同任务B1/C8约3.46倍完整暖路径收益。

**用户转向 U29：**“等下，性能问题先缓缓”，并认可先做最小质量来源追溯、再做冻结存活点高度消融。预留优化暂停，避免优化随后会被质量政策改变的事务人口。

## 7. 持续质量与正式实验：从单个见证到政策差异

<a id="r20"></a>
### R20　PQ-01纠正了“旧点改高造成一切”的最初猜测

<a id="r24"></a>
### R24　QPC-01与04A～C：先修质量表达，再谈预留优化

### 8.1 贯穿各轮的四条认识

1. **给定答案后的构造，与答案发现不同。** 从阈值谱、PCSG、MPR到NMP，反复暴露的不是一个共同已证失败定理，而是发现、构造、续接的成本不能互相藏起来。
2. **局部结构规模与完整工作量不同。** 邻域度数和修改面数有界，样本访问、精确数值、优先维护、预留搜索仍可能昂贵。可并行的最后写入很小，不足以保证完整更新受益。
3. **安全、进展、可恢复与好结果不同。** 固定视图最大值不增允许误差转移；逐点约束能挡坏更新但也会拒绝更新；请求存在也不代表目录可行。Sierra/Canyon的不同结果要求分别解释。
4. **阶段通过必须带对象。** 自然批次存在、原型持续、平台接入、同任务并行、工程降本、长期质量和论文竞争力是不同出口。用户多次纠正的正是这些越界推断。

### 8.2 不能在后续论文中拼接的证据

- 不能用旧策略较快的时间配新策略更好的某个质量分位数，称同一方法已同时获得两者。
- 不能把P5的严格回退写成拓扑普遍低并行度，再把GMP不同语义下的批宽当作推翻该“定理”。原本就没有这个定理。
- 不能把MPR的端点Lean证明直接当作当前一般连接事务算法的生产正确性证明。
- 不能把CBT较粗档位的较高误差单独作为胜出依据，却不报其更少面数和设备成本；也不能把错误/歧义观察当作有效质量排名。
- 不能把历史WSL与Windows、不同种子/轨迹/前缀/政策、暖窗口与移动窗口混成一条性能改善曲线。

## 9. 用户提示词如何持续改变了工作方法

这些要求是研究过程的一部分，而不是实现结束后的装饰。来源是本会话连续用户消息及[现行开发规范](../standards/development_guidelines.md)。

| 用户要求或纠正 | 实际沉淀 | 历史边界 |
|---|---|---|
| 修改前阅读开发规范和阶段规划，完成后核查 | 前置阅读、职责判断、阶段审查 | 文档存在不等于每个旧阶段都已完美执行 |
| `summary`格式、自然注释、正文不超过三行 | 注释规范与后续DOD风格要求 | 不把“换行”当语义改善，不据此扩大科研结论 |

| 性能退化独立分析、由用户决定修复归属 | 前后基线和独立问题记录 | 暂时关闭保留风险，不追认修复 |

| 相机、资产、图表、报告沉淀，视觉验收 | EIP及后续统一比较链 | Agent图像检查不自动等于用户视觉签收 |

## 10. 如何继续维护这份时间线

每次真正改变研究投入时追加一条，格式为：**时间依据 → 当时问题 → 用户原话/决定 → 新证据 → 采取的动作 → 明确保留与未证明之处 → 规划/报告/提交**。普通修复不必都新增方向条目，可以归入所属阶段；提交台账则保留完整记录。

不以最新结果覆盖旧结果；同一条路线重新开放时另记“重新开放的依据”。遇到用户明确说“只是讨论”，状态保持候选。发现此前归因错误时写出旧解释、反证和新解释，而不删除失误。

本页的下一条预期记录是**旧质量策略性能小规划及其同版基线**，不是预先宣告它会胜过Classic/DOD。用户已认可优先方向，但本历史整理没有代替那份规划或实施。
