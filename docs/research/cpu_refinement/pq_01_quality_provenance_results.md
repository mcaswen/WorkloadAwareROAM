2026-09-15。对应[小规划](../../plans/cpu_refinement/pq_01_quality_provenance_plan.md)、[代码事实](../../codebase/cpu_refinement/pq_01_quality_provenance_facts.md)、[审查](../../reviews/cpu_refinement/pq_01_quality_provenance_review.md)。

## 1. 阶段出口

**来源追溯闭环；冻结存活点高度的有限消融有利；持续质量修复尚未完成。**

两处数十像素退化的直接来源均为 H 接收提案创建的新点：新高度变量在本次全部可见认证样本中的系数为零，二维拟合仍把新点选为高度 **6**。存活旧点同时有小幅调整，但不能把主要退化归因为“旧点被大幅改高”。回收提案不是这两个首次严重退化的直接来源。

B 消融只冻结存活点高度，沿用原新点拟合与认证，在同一轨迹中把 frame15 的 sampled Emax 从 **66.081137px 降到 2.351050px**，返回后的 **31.125805px 降到 0.441886px**；仍完成 **145 次预算交换**。然而 frame15 的 DOD 为 **0.418727px**，B 相对 DOD 的逐点超额最大退化为 **2.320578px**。返回后 Emax 相同，但逐点最大超额仍有 **0.101125px**。

因此没有宣布同质量优于 DOD，也没有把 B 改成默认算法。未继续优化 reservation、改 HeightGuard、新点规则或增加几何原语。

## 3. 几何来源：两次 H 引入不可见的新高度

固定 UV 来自原离线评价，不跟随物理面槽位或核心样本编号：

- q0 = (0.96336996555328369, 0.7967032790184021)
- q1 = (0.020757021382451057, 0.11965811997652054)

| 项目 | q0 首次严重恶化 | q1 首次严重恶化 |
|---|---|---|
| frame / sample / 批中 exchange | 5 / 18 / 0 | 9 / 34 / 2 |
| 接收根 / 类型 | 1623 / H | -389 / H |
| 存活旧中心 | 402 | 12299 |
| 提案新点身份 | -383940 | -1667538 |
| 新点 UV | (0.9635416667,0.796875) | (0.0208333333,0.1197916667) |
| 新点最终高度 | **6** | **6** |
| 旧中心高度变化 | 1.145347238 → 1.096436946 | 1.012368441 → 0.987094623 |
| 见证曲面高度变化 | **1.163525689 → 5.838407513** | **1.026973039 → 5.926865755** |
| 该视图见证可见性 | 不可见 | 不可见 |

| 旧中心非零系数样本数 | 27 | 3 |

| 接受目标 | 0.059620px | 0.015678px |

证据为 a-provenance-support/transactions.jsonl 的 freeVisibleSupport / points / witnesses / errorUpperSquared。额外系数审计单独运行一次，目的在于确认自由变量是否受实际认证输入约束，不增加性能采样轮数。

为什么“高度6”可以出现：

1. TransactionalProposals::Prepare 对 H 收集旧中心邻域，支持中包括未被重新切分的面。该中心周围可以有可见样本，而新点所在的小面不在可见样本覆盖中。
2. TransactionalCertification::Fit 令自由变量为相对原高度的增量，每个自由高度的绝对区间为 [-HeightScale, 2*HeightScale]，此处为 [-12,24]。
3. 每个可见样本的线性约束只通过其重心系数影响自由高度。这里新点系数全部为零，因此可见质量/投影约束无法缩小新高度的区间。
4. 二维分支取裁剪后多边形的**顶点算术平均**。在本例中，约束只裁旧中心方向，另一方向仍是完整区间；新高度被选为 (-12+24)/2=6。不是源高度6，也不是区间认证算错。
5. 最终 Measure/Accepts 继续检查相同当前可见样本，因此小幅调整旧中心能改善可见误差，而未被约束的新点仍获准发布。

这同时暴露两层问题：可见质量契约容许离屏几何自由度；二维可行点选择又对这些自由度引入了不必要的大位移。单纯继续收紧当前可见误差阈值，不能给一个系数始终为零的变量增加信息。此判断针对记录的这两次事务，不泛化为所有 H 都发生同样问题。

## 4. 返回后为何没有恢复

### 4.1 q0：高优先级可见，但接收操作形状受阻

frame6 q0 已可见，覆盖根排名4，内部误差约51px；frame6、7、8执行了覆盖它的 E/E/F 接收，降低很小的局部误差。随后覆盖根变成 -189。

frame15，q0覆盖根排名1、优先值约66.081374px，其 E/F/H 目录全部返回 shape_infeasible。因此主要原因不是“不进入前160”，也不是本帧没有 donor，而是该根当前目录在形状检查阶段就失败。后续返回视图仍有这个约束。

这里的“失败”是当前目录/形状约束的实现判断，**没有运行更一般的可行性 oracle，不能表述成任何局部修复都不可能**。

### 4.2 q1：先冲突，随后极小进展，再形状受阻

| frame | 覆盖根/排名 | 观察 |
|---|---|---|
| 15 | -400 / 42 | E已认证；160个 donor 经质量与内部足迹检查可行，154个尚未复用，但相对更早预留资源的可用数为0，未执行 |
| 16 | -400 / 39 | E被选择；见证高度5.926865755→5.926808208 |
| 17–23 | -955 / 43 | 目录全部 shape_infeasible，见证不再改变 |

frame16 的固定 UV 内部误差为 31.126181823 → 31.125810049px，只改善约0.000372px。接收提案的 .01px 进展门槛约束其核心样本最大值，**并不保证任意独立评价点逐次改善.01px**。frame17–23的28次交换发生在别处，不能用总交换数证明这两处在恢复。

### 4.3 核心 Q 与独立评价点不能混同

两套采样共享原始双线性参考，但采样位置不完全相同。核心单元内模板在六分栅格上为 (0,0),(3,0),(0,3),(3,3),(4,2),(2,4)；独立评价器采用其固定三角采样模板及 float 输出坐标。

q0近似位于核心栅格点；q1约为六分栅格坐标(68,392)，余数(2,2)，不是核心模板点。因此 q1 的独立见证误差约31px而覆盖面核心优先值约27px，不足以证明优先缓存失效。诊断按固定 UV 求双线性参考和内部曲面，最终质量按真实 float 网格重新评价，两者数值分别保存。

## 9. 下一步应依据什么决定

本阶段已完成，不继续叠加修复。最具体的未解决项是：

1. 不能让没有质量约束信息的高度自由度任意漂移；最小位移/零位移选择是有针对性的候选，但尚未实施、也不是跨视图误差保证。
2. 存活点固定仍允许删点/重连造成局部插值变化，B的2.35px残余证明仅此还不足以宣称接近DOD。
3. .01px局部样本最大值进展不提供任意独立见证的恢复速率；当前形状目录可能卡住已恶化区域。
4. 若后续要采用B，需要明确它是更窄的事务语言，并补齐残余质量与恢复契约，再以变化后的事务负载评估性能。

本次结果支持继续一个有边界的质量问题研究；不支持恢复“性能已胜出”的叙事，也不支持默认启用B。
