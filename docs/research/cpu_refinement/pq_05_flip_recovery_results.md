# PQ-05：净零翻边的持续接入结果

2026-09-15；[规划](../../plans/cpu_refinement/pq_05_flip_recovery_integration_plan.md)、[代码事实](../../codebase/cpu_refinement/pq_05_flip_recovery_facts.md)、[架构审查](../../reviews/cpu_refinement/pq_05_flip_recovery_review.md)。代码基线`eebf9bd`，本阶段在其上实现默认关闭的有限翻边恢复。

本轮把PQ-04的离线存在性证据变成了真实恢复：**没有指定frame8、根身份或q2生产触发条件，原全局顺序自行选择了一次有效翻边。** 保持原145次预算交换，额外执行1次净零恢复；没有增加预算、前缀、恢复轮数或高度自由度。开关仍默认关闭，本结果不是将其改为默认政策的决定。

## 7. 过程、检查与停止

1. 修改前保存源身份和原生平台B；局部提交先通过净零满预算、类型伪造、改高、冲突、反序、共享只读点、正逆质量等夹具。
2. 用原全量重算oracle核查样本owner、闭贡献、优先级、donor索引；增量消费者核查真实几何/法线/索引。两批不消费Pending再合并消费、准备失败和过期代际均覆盖。
3. 关闭路径复现后，按原7项采集方案取得B/C探针、B8/C8/C1正常、B/C视觉。只追加了已登记的一次默认性能复核；五份C评价没有扩Q或轨迹。
4. 公共生命周期夹具补查设置切换触发重新初建、稳定政策续接、零宽暂停与Reset。原高度政策夹具仍通过。旧认证/提交主要风险由新定向夹具和B黄金轨迹覆盖，没有运行全CTest或D3D12矩阵。
5. 首次构建使用了错误目标名`ParallelROAM`，修正为现有`parallel_roam`；一次图表脚本PNG后缀错误在离线绘图修正。没有算法失败后修改输入、目标阈值或删除慢样本。

本轮达到规划的有限持续改善出口，保留默认关闭。剩余误差、高优先级恢复能力和最终同质量性能仍待后续独立判断；不自动加入PQ-03高度选值、扩大目录、延长轨迹或一般性能优化。
