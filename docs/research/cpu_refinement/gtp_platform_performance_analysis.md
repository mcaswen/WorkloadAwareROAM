# 持续事务原型接入平台前的性能空间与复杂度分析

2026-09-14；在 GTP-04 提交 `9b3711f` 后撰写，数值随后按预登记同会话环境核查更新。依据[实测结果 §7](gtp_04_multicore_results.md#7-最终同会话环境核查)和[执行代码事实](../../codebase/cpu_refinement/gtp_04_multicore_facts.md)。本文是证据与条件分析，不是新增实施授权或已完成的平台测试

## 1. 当前判断

**直接接入平台不会自然变得比 Legacy 快。** 当前 C 相对自身单线程 B 的完整收益约 1.94×/1.47×，但两条冻结轨迹的绝对时间仍明显高于 Classic/DOD。收益主要来自接收/回收认证和视图评分；真正修改几何记录的工作很少，继续只并行拓扑写入无法填补差距

这条路线已经解决了“当前网格能否自己产生需求、决定并执行事务”的可执行性问题，不再等 Legacy 给出 J；**尚未解决的是便宜地发现和认证有用事务。** 不能把“目标来源存在”与“目标来源具有竞争性成本”合并

最初观察到的 test 单线程 +12.07% 在排除明显 WSL 启动干扰后未复现，旧/新 B 为 290.752/285.557ms，暂记无稳定版本相关证据。原始负面数据及定位过程仍保留；正式实验继续防止新增执行边界人为拖慢 B，不能只报有利的一组

仍有明确可优化空间，尤其是反复样本定位、相同投影/几何证据重算、未尝试提案的提前构造，以及视图刷新中的串行全 Q 写回和树索引重建。但源码能指出冗余，不等于已证明这些改动能带来所需的约 10～31 倍整体降耗。目前不承诺超过 Legacy，更不承诺 2～5 倍

## 2. 比较基准与实际距离

下面是每次更新的八帧算术平均，ms。原型含发现、认证、预留、视图、持续状态和 CPU mesh；Legacy 是公共 BuildRenderData 完整边界。两者初始化、文件、全量质量诊断都单列，不含真实图形上传/绘制

| 场景 | Classic | DOD 默认 | 新 B / 1 线程 | 新 C / 4 线程 |
| --- | ---: | ---: | ---: | ---: |
| test129，B=4096 | 0.541 | 0.589 | 35.695 | 18.397 |
| Peking，B=20000 | 10.875 | 2.977 | 42.975 | 29.226 |

DOD 实际使用 8 线程，Classic 1 线程。家族从自身空状态回放 0～13，再走八个视图；原型从冻结 sample14 的 DOD 来源状态开始自己的轨迹，历史与语义不同。**这张表是现实性能量级上下文，不是同任务算法优劣证明。** 正式比较还须固定计算资源及可比质量/预算/收敛程度

即使只把 DOD 的时间当作工程目标，当前 C 仍需消除：

| 场景 | C / DOD 时间量级 | 达到相同时间需降低 C 总成本 |
| --- | ---: | ---: |
| test129 | 31.23 倍 | 96.80% |
| Peking | 9.82 倍 | 89.82% |

相对 Classic，分别约 33.98 倍和 2.69 倍；Peking 若只要求追平 Classic，仍需降低约 62.79% 总成本。这个距离不能用“再省掉一次小 mesh 复制”解释：原型、Classic 和 DOD 都已有借用 mesh 输出，原型正常更新也没有全状态副本

质量没有为当前额外成本提供已验证的整体回报：返回视图三者 sampled maximum 相同，但原型 RMS 略高，Peking Hmax 约 4.1129，而 Classic/DOD 约 0.0813；test 的返回逐点 excess 未在一次更新恢复。不同任务可以有不同收益目标，但不能从本次数据声称“更慢是因为整体质量更好”

## 3. 应使用哪些规模参数

| 符号 | 含义 |
| --- | --- |
| n、n* | 活动面规模、已分配面/点存储规模；二者应区分，不能把容量增长隐藏 |
| q | 固定公共 Q 的样本数，test=98817，Peking=1790881 |
| a | 当前全部闭面—样本关联数量，包含共享边重复贡献 |
| r、m | 请求前缀、共同 donor 池上限，本轮各不超过 64 |
| c | 每 root 的 receiver 目录上限，本轮不超过 8 |
| b | 本批实际成功事务数；与 r、m 或线程数不同 |
| d | 最大顶点度/局部面支持尺度；当前最小角 atan(1/3) 在合法参数域网格上给出 d≤19 |
| sᵢ、xᵢ | 第 i 个提案实际样本量、精确数值工作量 |
| t、e、z | 局部需维护的状态/候选条目、受影响面样本访问量、新面包围盒位置测试量 |
| u | 尚未消费的脏输出块/区间规模 |

d 的界只约束拓扑。单个大三角形或 one-ring 可以覆盖大量 Q，因此 sᵢ、e、z 并非 O(1)。已登记 SampleTouches 也没有包含每一次字段读取、容器操作或精确几何回退；B/C 计数相同不能解释为总 CPU work 完全相同

特别地，当前 `WorkLedger::Proposals` 在进入 Fit 时增加，不是“所有已构造目录项”的数量。`ExactChecks` 也不覆盖 Weights/Orientation/Shape 的全部有理数分支，不能凭它占比较低就断言精确计算成本很小

## 4. 按源码计费的时间和空间复杂度

以下为操作规模模型，树查找按 log 计；有理数运算另计位复杂度。不是直接 CPU 时间定理

| 阶段 | 当前工作界/参数化成本 | 当前并发边界 |
| --- | --- | --- |
| 初建 | 状态树索引 O(n* log n*)；样本包围盒位置测试 z₀、关联 a 与 Q 初始化另加；输出 O(n*) | 单次串行，初始化单列 |
| 同视图读取需求 | O(r+m)，顺序读已有索引前缀 | 串行、很小 |
| 换视图投影 | Θ(q) 投影；私有投影数组初始化、最终写回也是 Θ(q) | 投影四线程，初始化/写回目前串行 |
| 换视图评分及索引 | O(a+n*d log n*)，包括全部面归约、顶点邻域、set/map 建序 | 面归约并行，建序串行 |
| 目录构造 | 每项几何 O(d log n*)，闭样本收集/排序 O(sᵢ log sᵢ)，另有 root 见证扫描 | root 之间并行，当前先完整构造目录 |
| 一自由高度 Fit | 覆盖面搜索及约束通常 O(sᵢ d log d)，加精确见证和发布后认证 | 提案内部串行，不同 root 并行 |
| 两自由高度 Fit | 上项加逐约束多边形裁剪/去重成本 F₂，见下文 | 同上 |
| 回收原语 | 固定耳切朴素最坏 O(d³ log d) 加样本收集、覆盖/误差认证 | donor 之间并行；不包含离线 DP |
| 配对/预留 | 最多 r·m 次配对；与至多 b 个已批准事务比较，保守 O(r m b d log d)，另加模糊质量区间的精确复核 | 串行 |
| 几何直接准备/发布 | O(bd log(n*+bd)+(bd)log(bd)+b²d log d)，含局部树操作、规范排序与批次冲突复核 | 唯一面记录填写可分块，其余目前串行 |
| 局部样本/候选修复 | O((e+z)log(t+e+1)+t log n*) 加位置谓词；不能只写 O(b) | 当前串行 |
| 增量 mesh 与 Pending | O(bd) 属性写入；Pending 合并/排序 O((u+bd)log(u+bd))，另加偶发容量搬移 | 属性块分块，合并/写回串行 |

局部候选支持会扩至邻面/邻点；固定 d 和固定扩散半径时 t 受 b 控制，但它们拥有的样本总量仍须单独计费。数组几何增长有摊销意义，单次扩容仍可能搬移 O(n*)，不可向每一帧承诺纯局部延迟

两自由高度的 `ClipPolygon` 对每条约束遍历当前多边形，并以线性 find 去重全部结果。若第 j 次裁剪的顶点数为 vⱼ，其实际计费应为：

`F₂ = Σⱼ O(vⱼ + vⱼ²)`

在半平面裁剪保持凸性的通常算术模型下，vⱼ=O(j)，至多 O(sᵢ) 条约束，当前写法可给出 O(sᵢ³) 的保守界；若只线性遍历裁剪而没有该去重，通常界才是 O(sᵢ²)。这不表示本次自然运行实际达到立方，也不把浮点拟合器当精确 LP oracle；真实 binary64 执行仍按各 vⱼ 计费。不能因为自由变量只有两个，就把整个拟合写成 O(sᵢ)

精确分支使用 cpp_rational/cpp_int，并含见证整数平方根。若最大中间整数位数为 ℓ，应为这些算术另附成本函数 χ(ℓ)，不能视作普通一次 double 加乘。当前未逐项测 ℓ 或几何精确回退数，故不报一个伪精确的常数

持续空间为 O(n*+q+a) 加输出容量、Pending；批次私有提案需 O(Σsᵢ+bd+t+e)，同时存活的各拟合器再各加 O(maxⱼ vⱼ)，换视图暂存 O(q+n*)。并行增加线程私有账本及任务结果，但不会复制四份完整当前状态。相同 q 下，数据布局和缓存流量仍可能改变实际耗时

因此当前完整算法既不是 O(k) materializer，也不是只由 n 决定的 ROAM 更新。它是“全局视图工作 + 有限前缀发现/认证 + 局部事务与续接”的组合

## 5. 固定当前并行边界，还能靠加线程改善多少

从 B 的非重叠六个可分块阶段取时间总和 P₁，其余记 S₁：

`T̂(p) = S₁ + P₁/p`

这是保持当前工作量、把分块部分理想均分且额外税为零的**工程敏感性模型**。S₁ 不是算法必需串行 span；改变表示、减少工作或扩大合法并发边界会改变它。不能把下表叫作“ROAM 并行度理论上限”

| 八次总量，ms | test129 | Peking |
| --- | ---: | ---: |
| B 总时间 | 285.557 | 343.800 |
| P₁ | 230.329 | 192.792 |
| S₁ | 55.227 | 151.007 |
| 理想固定边界 p=4 | 112.810 | 199.205 |
| 实测 C p=4 | 147.179 | 233.808 |
| 只加线程、p→∞ 的模型值 | 55.227 | 151.007 |

即使把这六段全部免费，固定其余实现的模型值仍远高于本次 Legacy 时间量级。**仅扩大线程数不够，必须减少总工作或改变当前串行维护方式。** 模型是必要的数量级筛查，不是对更好实现的否定证明

test 的四线程 receiver/donor 合计仍为 85.770ms，约占整段 58%；即使其余全免费也明显高于 Legacy。Peking 五次换视图的四线程投影合计 30.466ms，平均每次 6.093ms；当前单独投影就已超过 DOD 的整帧均值 2.977ms，尚未加 74.159ms 的全局建序和串行写回

本 panel 只有 5/8 次更新改变视图。真实连续移动可能接近每帧刷新。若仅保持其他工作成本不变、把视图刷新频率提高到 1，C 的敏感性估计约为 test 19.8ms、Peking 45.2ms/帧。这不是新增轨迹实测：运动也会改变需求、认证和质量，不能把该估计当性能承诺

同样，原始记录中部分静止 Peking 帧 C 的 2.1～2.3ms 低于家族的 3～4ms，仅说明“无视图全扫、少事务”可能出现局部有利区间；历史/质量不等价且完整轨迹仍慢，不能挑这几帧宣称整体胜出

## 6. 源码中明确存在的优化空间

| 优先方向 | 当前事实 | 可研究的削减方式与边界 |
| --- | --- | --- |
| 提案内重复位置判定 | Fit 先 CoveringFace，再 Weights，再搜索 Faces 求自由系数；Measure/Accepts 又定位同样本 | 参数坐标不随高度拟合变化，可保存样本→局部面/插值证据并复用；仍需认证实际发布高度，不能用近似缓存替代证明 |
| 重复投影/参考构造 | 同样本在多个提案、约束和认证中重建参考及 Clip；区间运算有大量 outward rounding | 缓存与 view/参数域绑定的系数或证据，减少重复算术；视图/坐标失效规则和内存成本必须计入 |
| 不会被尝试的目录项 | Receivers 一次构造全部 E/F/H，随后可能首项成功就退出 Fit | 按冻结目录次序惰性构造，保留相同候选人口和同分顺序；观察返回提案/原因是否一致 |
| 两变量裁剪 | 每条约束执行全局线性 find 去重，造成潜在平方子步骤 | 减少重复顶点处理，限定数值/输出语义；不能因为拟合器快而放松最终认证 |
| 配对与足迹重建 | donor 几何已缓存，但 pair 循环重复构造其 footprint；成功后仍继续审计余池 | 同快照缓存 footprint；把实际选择与必要分母证据区分。已找到成功交换就已证明该需求可行，不必为了该布尔结论查完剩余 pair；完整拒绝分布如仍要收集应另记诊断成本 |
| 视图串行写回 | Projection 为私有数组，发布又逐 Q 写回 SampleValue，暂存还需初始化 | 把视图派生列与持久参考/owner 分开，以预分配双缓冲和交换发布保持异常原子性；不能把 O(q) 工作藏到帧外 |
| 全局树索引重建 | 每次 view 改变，所有 ordered set/map 重新分配插入 | 考虑连续记录、批量建序/局部后续修复；必须同时保持全局前缀、稳定 tie-break 和 A 参考竞争力 |
| 粒度选择 | 面/mesh 填写不到毫秒总量，派发反而增加费用 | 这些微小块直接串行可省固定税，但收益不足以改变 Legacy 数量级差距 |

上述多项是在保留当前请求/质量契约下减少重复工作，价值高于盲目更换所有容器。另一方面，缓存并不免费：比如给每个候选永久保存全部样本证据可能重新产生 q 倍重复存储。应优先局部提案生命周期复用，用减少的真实定位/约束/分配数量和完整时间验收

**仍不能保证本表足以追平 Legacy。** 特别是高分辨率 Q 在相机每帧变化时的 Θ(q) 评价，以及当前全局索引成本，不会因局部补丁只有几个面而消失。如果必须依靠少评样本、改变 urgency、跳过前缀失败者或放松质量证书才能达标，那已是算法/实验契约变化，不能归入无害工程优化

也不能把初次 test 单线程 +12.07% 观察的根因直接归到本表：重复定位等工作在旧版本同样存在，且该差值没有稳定复现。它们是绝对性能空间，不是已确认的版本回归原因

## 7. 平台接入边界及会增加的成本

当前已经有可借用的持续 TerrainMeshData 和 Pending，所以公共接口适配可以避免整网格复制。应新增独立算法 ID，经 ITerrainLodAlgorithm 返回 BorrowedCpuMesh、generation 和顶点/索引区间；不能把新状态塞进 DOD 节点表后继续调用旧 WriteDomainTriangle 重新采高度

| 接入项 | 当前状态 | 成本与未解决义务 |
| --- | --- | --- |
| 冷启动 | 本次只从冻结合法 seed 初始化一次 | 正常平台仍需确定自身合法初网格来源；可选自建粗/规则网格或显式一次 Legacy bootstrap，各自时间/质量须计费。不能声称已验证从空态快速收敛 |
| 参数变化 | SetView 允许相机/分辨率变化，拒绝预算/尺度/参考规则变化 | 预算降低到当前 N 以下不能靠现有净零交换实现；需明确定义 reset 或另行收缩语义，不可默默继续超预算 |
| 普通更新 | 自有发现和局部状态，已包含 mesh 准备 | 接口包装只增加小型配置/统计/区间转换，不会凭空减掉认证或 q 扫描 |
| 输出借用 | 核心已持有 mesh，消费返回独立区间 | 可做到 O(区间数) 包装；双方已有借用，不能重复申领“省全量复制”的优势 |
| 初次/容量变化上传 | 尚未接入 | 首次可能全量，后续是否增量受各后端资源容量/同步限制；需要实际字节和 CPU 提交时间 |
| normals/属性 | 原型按实际拟合面产生几何法线 | 不复用旧 source 法线/高度来掩盖曲面；最终显示属性和质量评价要分开 |
| OpenGL / D3D12 | 都消费公共 CPU mesh/ranges，但各有 UploadMeshData | 各自处理 buffer/staging/fence，不能预设一种共同上传实现或零等待 |

源码显示两个现有渲染器都可消费借用网格及区间，但这只说明接口可复用，没有验证新原型的具体范围/容量/空更新处理已全部适配。上传发生在 CPU 更新后；CPU 提交/等待需要计入，GPU 流水可能与其他帧重叠，不能简单把 CPU 与 GPU 独立计时无条件相加

“接入后性能提高”的可行来源是同时实现了明确的降工作改动，而不是注册算法、删除 JSON 或开启 GUI。本次 JSON、全量核查本来就在计时外，不能把它们的耗时从表中 18.4/29.2ms 直接扣除；移除后的间接缓存/调度影响仍须实测。若接入仅作可视化诊断，可有工具价值，但不能拿这种价值替代性能结论

## 8. 何种条件下才可能快于 Legacy

在固定实际质量/预算目标及完整边界后，必要条件仍是：

`T_view + T_discovery/certification + T_reservation + T_continuation + T_mesh + T_adapter < T_Legacy`

当前有利因素是请求/回收池有限、局部状态更新确实不需要 replay 或全域恢复、认证在四线程有可测收益。可能的有利负载是视图不变或可低成本刷新、每提案样本少、事务兑现率高、Legacy 本来承担较多动态拓扑维护的区间

不利负载是 q/n 很高的移动相机、前缀大量无接收证据、长时间无事务但仍重复认证，以及只修改少数面却构造大批提案/证书。扩大三角形预算未必自动有利：样本/面可能降低，但本实现换视图建序又随 n log n 增长。需要在相同数据和质量条件下验证交点，不能从复杂度符号推出一个固定的“n 超过多少就赢”

对当前实现的具体预期：

- **直接接入、只做必要适配：** 预计保持当前 CPU 成本数量级，加上传与平台维护；没有理由预期整体胜过 Legacy
- **只加线程或并行 live 写入：** 当前固定边界模型已显示不足，尤其真正写入只占很小部分
- **减少重复发现/认证及重做视图派生表示：** 有实质空间，但倍率未知；必须先证明对应成本下降，而不能预支 2×、5× 或必然追平
- **更大工作负载：** 可能改变相对成本，但现在没有新实验支持；不会为寻找胜出点自动扩矩阵或换样本

因此性能导向的下一步应优先验证有限的降工作改动，再决定是否值得为性能做平台接入。连续质量还应独立解决，不能用性能成功替代视域返回恢复。本文不关闭算法研究方向，也不把这次两个输入当作一般不可能性证明
