# TPI 接入结果、性能空间与 Legacy 对照

2026-09-15。对应 [TPI 大规划](../../plans/cpu_refinement/transactional_platform_integration_plan.md)及[末阶段规划](../../plans/cpu_refinement/tpi_05_platform_evidence_plan.md)。有效原始采集位于忽略目录 `benchmark-output/cpu-refinement/tpi-05/run-02`；首轮诊断器问题保留在 run-01。

**接入及有限持续运行成立；优化空间没有耗尽；尚不能证明同质量优于 DOD。** 8线程相对同任务串行有约3.46×完整暖 CPU-ready 收益。Peking时间已接近DOD，但实际输出关键帧出现66.08px、返回后仍31.13px误差，因此二者不能作为等质量性能配对。

## 1. 分类型出口

| 对象 | 结论 | 边界 |
|---|---|---|
| 可链接核心/公共适配 | PASS | 同一核心、独立实例，生产核心不链接研究 oracle |
| GUI/CLI、静止更新、暂停/单步/重置 | PASS | TPI-03/04 有限生命周期检查 |
| OpenGL / D3D12 消费 | PASS | 各自资源恢复及真实非空增量上传；不是设备移除保证 |
| 两条自然持续轨迹 | PASS | 24机会不断开、不重导入、不超预算 |
| 同任务多核收益 | 有限正证据 | B1/C8共48帧输出/决策一致；每配置一个独立进程 |
| 连续质量可接受性 | 未通过该主张 | Peking明显退化，冻结返回窗口未恢复；未定义感知阈值 |
| 同质量优于 Classic/DOD | UNKNOWN | 时间接近不能补足质量差距 |
| 优化空间耗尽 | 未证明 | 预留、密集Q、认证、样本续接仍有明确成本 |

与旧 Lean 的关系不变：已知目标端点物化定理不是本算法目标选择、几何认证或生产C++的完整证明。本轮没有调用NMP Planner，也不要求Legacy提供下一帧目标J。

## 2. 环境、输入和计时契约

主平台为 Windows11 10.0.26200、MSVC RelWithDebInfo、Ryzen9 9950X3D（16核32线程）、RTX5090D、平衡电源模式。Ubuntu/WSL编排原生工具和进程；8是请求worker数，未绑专核，不代表测得八个物理核同时忙碌。毫秒不与历史WSL/GNU结果拼比。

- Peking：547²、80/12、depth20、B50000、split/merge .25/.10、r=m160、orbit64。
- test129：129²、30/4、depth14、B4096、split/merge4/2、r=m64、A轨迹。
- 1280×720、60°、near .1/far500；24机会为 `[14,14,14,15,16,18,22,26,30,34,38,42,46,50,54,58,14,14,14,14,14,14,14,14]`。
- frame0冷；1/2和17～23静止；3～15移动/转向，16返回。每算法每机会执行一次，不运行至收敛。DOD静止结果是强制update成本，不是普通交互缓存跳过的零成本。
- 新算法只做一次当前视图DOD种子：Peking49999面、test1294096面。B/C仅线程数不同，种子固定串行。不是旧SVE历史0～14演化状态。
- 旧renderer默认视图初始化后显式Reset，首个冻结视图从干净实例开始；前置费用留在setup，不伪装成最佳cold-start算法。

关闭全量PassEvidence、topology validation、配对尾扫和Tracy。normal/export各自独立进程，逐帧核对属性/索引哈希及决策摘要，关键帧0/2/15/16/23独立评价。哈希和有限几何检查在Present之后、帧计时之外，仍会改变帧间缓存/GPU重叠；本结果是可审计有限图形回放，**不是无探针交互FPS或正式统计显著性结论**。

CPU-ready包含核心、适配和临时结果释放；上传分列。frame是BeginFrame→Update→Render→Present包络，不含GUI，不把GPU时间再相加。OpenGL没有实现GPU query/显式fence-wait统计，原始零值为占位，报告为N/A；隐式等待仍可能进入upload/Render/Present。D3D12 GPU数值延迟返回，不逐帧强配对。

有效原生14进程总约27.89秒，25次离线评价约10.78秒；最大观测原生PeakWorkingSet约237.3MiB，未触及8GiB/180秒限制。没有通过大量重复取最优值。

### 冷启动

首个冻结输出CPU-ready：test129 C8 **302.157ms**、DOD **7.867ms**；Peking C8 **1445.491ms**、DOD **176.419ms**、Classic **248.119ms**。另有窗口/后端/资产/历史初始化setup约153～326ms。新算法冷启动含一次DOD种子、源/Q/结构和输出初建，不能用暖时间掩盖。

### D3D12次后端：Peking前8机会

C8执行22次交换，暖7帧CPU-ready **32.982ms**、上传 **.278ms**、帧包络 **33.860ms**；DOD分别 **38.169 / 2.369 / 41.389ms**。延迟GPU查询约.017ms、显式等待0，不据此宣称完整GPU工作或跨后端速度一致。另一帧槽首次追赶包含额外全量同步，不能与OpenGL24帧均值直接比较。NO/ZO不要求浮点发布逐位一致，也不据次后端时间扩成质量通过。

## 4. 实际float输出的独立质量

## 7. 时间与空间复杂度

沿用[算法推导页](transactional_algorithm_overview.md)，这里补平台/增长前缀边界。N为持久槽位/索引规模，n活动面，q固定Q，a闭面关联；r/m可至640，K=256块，d≤19仅为拓扑度；P实际pair，b批宽，f足迹；sᵢ/aᵢ提案样本/关联，sΔ/aΔ/z续接样本/关联/包围框测试，u脏块，Λ扩容搬移，X变长精确算术费用。

| 工作 | 当前保守工作量 | 解释 |
|---|---|---|
| seed/import/init | `W_DOD_seed + O(N log(2+N)+q+a+z₀)+X` | 包括初建验证，不只是O(n)复制 |
| 设置/视图身份 | O(1)固定字段 | 没有每帧全源哈希或M0复制 |
| 视图投影/归约 | `O(q+a+N+n log(2+N))+X` | 全Q仍在；静止不重复 |
| 块索引/前缀 | 建序`O(N log K+nd)`，查询`O(N/K+(r+m)log(2+N/K))` | 扫64个不能直接得到全局top64 |
| 提案/接收认证 | `Σ O(aᵢlog(2+aᵢ)+(d+sᵢd)log(2+N)+Fᵢ)+X` | 一维F线性；二维ClipPolygon去重保守立方界仍在 |
| donor生成认证 | `O(md³log(2+N))+Σ O(aᵢlog(2+aᵢ)+sᵢdlog(2+N))+X` | Need=0跳过，否则共同池；不是最终b个 |
| reservation | `O(P(b+1)f log(2+f))+X`，P≤rm | 计入足迹合并/冲突，不将f偷换成样本数 |
| topology准备发布 | `O((b²d+bd²)log(2+N+bd))+Λ` | 含批内复核、串行容器维护 |
| sample/候选续接 | `O((z+aΔ+sΔ+td)log(2+N+sΔ+bd)+hKlogK)+X+Λ` | t局部记录、h脏块；样本未被degree界约束 |
| mesh/范围 | `O(bd log(2+N+bd)+(u+bd)log(2+u+bd))+Λ` | 填写可并行，Pending/活动索引仍维护 |
| 公共适配 | O(范围数+有限统计数) | 借用输出，正常不全量复制 |
| GPU消费 | 普通O(范围数+字节)，初建/扩容/恢复全量 | D3D12每帧槽独立追赶，驱动/同步另计 |

这不是一个O(k)或普适O(n/p)更新算法。固定r/m/d仍不能消掉q、证书样本和精确算术；8线程覆盖投影、按面评分、不同receiver/donor及独占填写。串行预留、索引、样本续接、发布和最慢分块限制完整扩展。

空间至少 `O(N+q+a+Σproposal证据+bf+u)`，有双视图缓冲、source、prepared topology/mesh、有限账本，精确临时整数还受位长影响；没有复制8份完整状态。GPU按帧容量维护。观测RSS含窗口/驱动/资产，不是纯算法精确空间。

## 8. 能否比Legacy快

**当前不能承诺幅度，也不能断言没有机会。** 已观察到明确同任务多核收益，Peking暖CPU/帧包络与DOD同量级；但有限前缀、不同决策和跨视图质量损失均影响比较，尚未证明相同质量/响应约束下的优势。

可用性能贡献至少要求：持续质量/返回恢复进入声明质量预算；完整发现/认证/预留/续接总工作可竞争；批宽足以摊薄并行税。只有最后一项不够。本轮没有扩大输入找有利crossover，200k只引用SVE既有成本，不伪装平台新数据。

test129目前没有替换DOD的性能理由。Peking没有出现数量级平台适配税，也有明确多核信号；但跨视图误差是直接实用性限制。**研究可继续评估，接入PASS不等于性能竞争力或论文结果PASS。**

## 9. 收尾

本阶段没有改核心选择、数值证书、前缀、拟合或线程边界。run-01只修正检查器绕序误判和启动器ExitCode缺失，原记录保留。run-02九个normal、五个export、25个quality完成；7组逐帧身份核对、10组Dmax。输出无错误日志，有限几何/预算/资源检查通过；不扩大成任意输入或驱动正确性保证。
