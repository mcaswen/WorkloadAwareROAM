# QPC-06F：高度拒绝与样本提示的推导记录

2026-09-18。对应[小规划](../../plans/cpu_refinement/qpc_06f_height_rejection_plan.md)。HR-01～05纸面推导及有限源码对应已完成，过程与反例保留；不是Lean机械证明。性能另见[结果](qpc_06f_height_rejection_results.md)。

## 1. 对象与HR-01：充分拒绝

固定一个合法源高E/F/H提案、核心binary64曲面、当前参考源与完整闭支持Q。对q定义旧/新高度残差平方u0/u1和高度目标平方c。真实二进制输入按精确实数解释；当前区间算术给出包含它们的闭区间U0/U1/C。

若U1.low > max(U0.high,C.high)，则逐步有：

1. u1 >= U1.low；
2. max(u0,c) <= max(U0.high,C.high)；
3. 合并严格不等式得u1 > max(u0,c)。

这直接违反既有逐点损伤条件。完整安全证书要求每个支持样本均满足该条件，因此一个这样的q已经足以否决整个提案。区间相交、等号、非有限界只是不足以拒绝；不能解释成不合格。

## 2. HR-02：单样本内前移

原顺序为当前人口核对、高度求值、屏幕求值、高度拒绝、屏幕拒绝/接受/精确回退。先前移的只有由HR-01证明的高度拒绝。当前人口核对、样本次序、其他分支保留。

`ScreenPrepared`只计算数值，没有修改提案或生产状态；正常未触限、未启用浮点陷阱的路径中，其被跳过不能改变原高度拒绝结论。未得到严格高度分离时仍走原完整路径，表达式端点和精确回退不改变。参考可见性仍可能求投影，因此不能把这一步称为消灭全部投影。

## 3. HR-03：提示不是证书

缓存仅保存q的身份。每次使用先确认q属于当前核心支持，再按当前面序重新求闭覆盖、参考、可见人口和高度区间。任何根、几何或视图变化都不赋予旧结果效力。

若重新验证满足HR-01，则拒绝安全；否则从原首样本开始完整认证。错误或过期提示至多浪费取证成本，不能证明接受，也不能跳过成功提案的双域核查。源/Q重新绑定时清空，禁止将不同集合中同一整数身份误当同一样本。

错误尝试：直接缓存“根x高度失败”。反例是根仍存在，但相邻事务改变了覆盖或本次目录位置，旧失败点可能已经修复。即使新增复杂revision，也需要完整依赖；本轮不采用该路线。

## 4. HR-04：实际决策等价及边界

在原认证器正确、资源足够、相同合法输入的前提下，原完整认证不可能接受HR-01明确违反的提案；提示未拒绝的提案完整走原顺序。因此接受集合一致。固定目录顺序后首个成功项一致；源高准备及形状分类保持，翻边资格一致。固定根序、预算与冲突规则，逐批归纳得到相同实际事务和后续状态。

这个推导没有保证首拒绝理由逐字相同：原次序可能先看到屏幕损伤或数值未知，提示先看到高度损伤。当前生产`NeedsFlipRecovery`只区分E/F/H是否全部为`shape_infeasible`，两种质量拒绝均不满足；IntentResults/Attempts保留为诊断和空批结果，不据它们生成新质量规则。实施仍需影子重放审计所有实际提前拒绝。

配额例外：额外提示访问可能使某条有限资源运行更早退出，提前拒绝也可能避免旧路径触限。这不是正常完成定理的反例，也不是同任务加速证据。触限必须保持无部分发布并单列，不伪造访问计数。

## 5. HR-05：成本

设完整支持准备为c_i，S1原数值遍历v_i，提示查询/重证h_i，实际提前拒绝集合A。提示未拒绝时的剩余完整遍历记为v'_i，则精确记账为：

\[
W_1=\sum_i(c_i+v_i),\qquad
W_2=\sum_i(c_i+h_i)+\sum_{i\notin A}v'_i+W_{merge}.
\]

相减得到真正的收支条件：

\[
W_2<W_1\iff
\sum_{i\in A}v_i+\sum_{i\notin A}(v_i-v'_i)>\sum_i h_i+W_{merge}.
\]

**实施后对初稿的修正：**初稿直接把v'_i写成v_i，但当前Recheck与后续循环共用同次域内的面证据，因此提示可能已初始化部分系数。样本对象仍重建，面系数不必重建；不能把总成本强行称为“原成本加一次提示”。在固定非负原语计数、面系数仅记忆原表达式的模型下，v'_i≤v_i，故`Σ命中v_i>Σh_i+Wmerge`是充分条件，不是必要条件。机器缓存、分配器和调度的实际时间不受这条原语不等式保证。

完整支持排序/去重仍最坏O(s log s)，未命中遍历仍O(sd)，提示成员查询O(log s)、闭覆盖O(d)，有理算术另受位长控制。有序提示索引固定容量C=2048，查询/归并O(log C)，存储O(C)。高拒绝率并不推出高复遇率，后者也不推出高区间可判定率。

这里v_i取S1的原序数值遍历，避免把S1已经省去的屏幕工作再计给提示。对失败点靠前、很少复遇的输入，h_i可能大于省去的v_i；加入提示不具有逐提案必然提速性质。面证据预热不更换表达式/首覆盖顺序，其数值等价沿用06E的FE-01～03。

## 6. 反例、回退和生产义务

| 情形 | 错误推导 | 当前处理/检查 |
|---|---|---|
| 旧失败样本已被相邻事务修复 | 同根同样本仍失败 | 重新定位和求当前高度；专项对成功曲面的所有样本身份施加旧提示仍获得完整证书 |
| 目录ordinal仍相同，UV或连接已变 | 相同键可复用旧面/参考 | 只复用整数身份；当前支持binary_search和闭覆盖重新求值 |
| 旧根消失或提示不在当前支持 | 缓存命中足以拒绝 | 新根完整键不同不命中；域外仅计数并回退 |
| 区间相交或恰好等号 | 不够安全就当损伤 | 谓词返回false；保留原有理回退，17×17残差专项与等号/非有限夹具核对 |
| 原遍历前面的样本先数值未知 | 新理由必须与原理由相同 | 接受/拒绝相同不要求首拒绝理由相同；实际影子理由分列，不把unknown改写成原序已证不可行 |
| 核心通过但float失败 | 核心安全意味着可发布 | 提示不生成成功证书，仍走原float域；复用已有逐点专项 |
| 提示未拒绝，完整循环再访问同点 | 提示检查免费 | Touch、证据对象和时间如实计费；不把hint miss后的访问去重伪装成收益 |
| Remember后Apply准备抛异常 | 缓存与业务状态必须同一事务回滚 | 提示可保留但下一次重新验证；生产拓扑发布仍沿原无失败区，缓存不具有语义权威 |

以上证明依赖Certify输入已经是合法目录项；它没有替任意三角化补结构证明。固定源/Q身份是Pipeline契约，不是提示键中自带完整几何身份。极端配额、浮点trap及资源分配失败不在正常完成的时间/轨迹等价范围内。
