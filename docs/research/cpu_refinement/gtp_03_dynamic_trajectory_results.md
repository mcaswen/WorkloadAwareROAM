## 3. 质量与恢复限制

每次在固定当前视图内发布的 screen maximum 没有上升。test 最终返回 view14 时 A/B screen max 均 1.573643px，但 RMS 分别 0.383004/0.385016；Hmax 为 0.0784314/0.0901961。Peking 返回 screen max 均 0.496345px，Hmax 均 4.112899

| 场景/策略 | 返回前 excess / 一次更新后 excess | 新进入可见域 Q / 最大误差前后 | 判断 |
| --- | --- | --- | --- |
| test / A | 0.486300 / 0.486300px | 10 / 0.183596px 不变 | 恢复时间 >1 次，右删失 |
| test / B | 1.125149 / 1.125149px | 10 / 0.183596px 不变 | 恢复时间 >1 次，右删失 |
| Peking / A | 0 / 0 | 120 / 0.144224px 不变 | 此参考差值未增加 |
| Peking / B | 0 / 0 | 120 / 0.144224px 不变 | 此参考差值未增加 |

excess 分别相对于各策略自己离开前第 3 轮的逐点误差，并非 A 与 B 之间的直接质量差。1e-9 仅用于数值相等诊断，不是视觉阈值。Peking 的零 excess 也不能证明此前视域外改高区域已经恢复；这个很短的视域变化并未覆盖所有退化区域

**全局 maximum 不变不足以表述局部恢复。** 当前没有机制保证规定轮数内回到离开前逐点质量，有限前缀、证据域和局部接受共同限制后续恢复。这是算法质量契约的开放风险，不能以增加更多快照或放宽阈值消去

## 4. 出口

持续状态和公平动态参考可执行，发现/认证/维护的真实费用清楚。test B 的认证仍占主要成本，Peking 的 view refresh 占主要成本，存在值得独立测量的并行段。因此进入 GTP-04 的理由是验证**相同 B 决策下的有限多核收益**，不是认定当前质量已达到生产要求

本阶段不修改 quality acceptance、前缀、primitive 或轨迹。生产接入仍未授权；后续若考虑实际算法应用，必须另外处理 P/evidence 错位、局部恢复与质量 operating points。GTP-04 即使提速，也不能替代这些质量工作
