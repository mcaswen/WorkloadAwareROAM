# QPC-06J：有限剩余空间核查与06G～06J结账

2026-09-18。依据[有限队列](../../plans/cpu_refinement/qpc_06_remaining_work_plan.md)和[06J小规划](../../plans/cpu_refinement/qpc_06j_remaining_cost_audit_plan.md)。

## 1. 结论与适用范围

**本轮有限减工探索完成；有收益，但没有完整性能突破，也没有证明优化空间耗尽。** 06G保留坐标与参考高度分离，06H保留失败准备后移、撤回低复用支持缓存，06I保留无用插值删除与固定参考复用，06J用最终perf/Tracy及实际人口决定不追加捐赠方惰性认证。质量政策、原语、候选顺序、数值判定和生产并发边界均未改变。

|---|---:|---:|---:|---:|---:|
| Sierra源高完整CPU | 110.643 | 106.031 | 107.427 | 105.708 | −4.46% |

旧Fit这一行使用同一逐点质量政策，只改变接收高度策略，不是DOD，也不是旧质量对照L。第一列为06G前本轮冻结程序复测，不与06F历史110.589/65.830ms混用。每配置一次独立进程快验，Sierra在06H出现疑似退化时按约定补了一次未修改06G参考；这些均值不是多进程统计显著性结论。三阶段所有三条96机会的主要逻辑字段、网格哈希相同。

本轮最明确的时间信号来自06G；06H/I主要确实删除了工作，并没有稳定的大幅总时间收益。Sierra源高最终仍约为同政策旧Fit的1.58倍，不能据此把源高升为默认。50k是预算上限，Sierra实际仅约9k～11.6k面；没有新增饱和50k/200k、DOD同质量竞争或持续恢复通过的证据。

## 2. 输入、计时与采样可信度

沿06F冻结Sierra/Canyon、源高、逐点目标、误差优先、固定旧点；边界细分为Sierra关闭、Canyon开启，前缀与捐赠池各160、8线程、96机会。移动为3～31、返回32～63、静止64～95。06J不再重复Windows矩阵，原生完整成本复用06I；Linux仅用于最后的函数与时序归因。不同系统、编译器和探针边界的时间不能串成一条加速曲线。

| Linux最终构建移动均值，ms | Sierra | Canyon |
|---|---:|---:|
| 帧指针构建，无捕获 | 63.560 | 37.453 |
| 同构建perf捕获 | 63.977 | 37.698 |
| Tracy构建，未连接捕获 | 62.473 | — |
| Tracy连接捕获 | 65.369 | — |

perf扰动约0.66%/0.65%，Sierra Tracy连接相对同构建未连接约4.64%。每种模式96机会与06I原生逻辑/曲面哈希一致。恢复诊断另启进程，不混入普通时间；失败提示的影子重放会明显放大认证CPU工作，不能拿其任务时间当正常路径时间。

perf使用移动窗口的全部参与线程事件权重。Sierra/Canyon分别有4,607/3,243个窗口样本；报告丢失样本0、缺栈0、未知自身符号0、单帧栈0。但含未知祖先的样本分别4,304/3,172，**调用链并不完整**。以下自身份额可用于热点定位，包含子调用份额是已恢复栈的观测归因，不是精确完整调用树。它们既不是Windows墙钟份额，也不能把嵌套包含份额相加。

## 3. 剩余函数热点：认证仍主导

| 函数/内核 | Sierra自身% | Sierra包含子调用% | Canyon自身% | Canyon包含子调用% |
|---|---:|---:|---:|---:|
| `PointwiseQuality::Certify` | 0.48 | 73.74 | 0.15 | 56.95 |
| `CheckSample` | 0.41 | 41.11 | 0.31 | 21.92 |
| `QualitySampleEvidence::Cover` | 0.63 | 21.32 | 0.34 | 18.47 |
| `__nextafter` | 21.21 | 21.21 | 13.23 | 13.23 |
| Boost主要`eval_gcd`实例 | 7.66 | 9.49 | 7.25 | 8.29 |
| 大整数`do_assign_float<long double>` | 4.62 | 6.88 | 6.01 | 8.85 |
| 主要大整数除法实例 | 3.67 | 3.69 | 5.12 | 5.18 |
| `Samples::Project` | 4.45 | 4.45 | 6.26 | 6.26 |
| `Samples::Prepare` | 1.74 | 4.47 | 0.19 | 0.49 |
| `Certification::Measure` | 0 | 0.11 | 0.03 | 9.10 |
| `ErrorBounds` | 0 | 0.11 | 0.22 | 8.39 |
| `CoveringFace` | 0 | 0.02 | 0.09 | 3.95 |

表中Boost项是具体实例，不是合并全部重载；完整符号、调用边、压缩栈见第9节。`__nextafter`在Sierra中21.14个百分点由已解析逐点路径解释，Canyon为逐点10.08、回收2.07、其他1.08个百分点。Canyon视图评分匿名任务自身7.77%、包含12.09%，视图投影任务自身4.16%、包含11.19%；这与普通阶段时间共同说明视图工作也是实质成本。

源码链为`Reservation → PointwiseQuality::Certify → CheckSample → QualitySampleEvidence::Cover / QualityFaceEvidence → 区间/有理算术`。06G省掉“只需要坐标却先求参考高度”，但未改变候选面覆盖、逐点损伤与进展判断。因此后续覆盖仍需要有理边界回退，区间表达式仍调用外向舍入。这解释了参考高度构造数大降、数值核却仍占主要CPU工作，并不矛盾。

若一项提案检查s个样本、覆盖至多f个旧/新局部面，当前覆盖检查上界含O(sf)，另有支持收集/排序及精确算术位复杂度。f受局部拓扑约束，s不由最小角界限制；有理运算不能一律按常数计费。实际Sierra移动有842,002次精确覆盖请求、72,106次精确参考构造；Canyon分别697,918和36,749。前者远高于后者，说明继续只优化参考高度构造不能自动消除剩余精确计算。

仍可能研究保守浮点过滤器、固定/整数参数域谓词、避免重复有理正规化或更细证据复用，但必须证明溢出、舍入、不确定分支和双表示域契约。**当前没有证明这些数值费用全是必要成本，也没有一个已验证可直接替换的低成本内核。** 本轮不改精度、不加epsilon、不把未知变接受。

接收阶段任务总和是线程区间之和，不等于核CPU时间；控制线程等待约38.60ms主要覆盖工作线程执行，不可当作可删除的同步税。平均均衡比约0.894。frame21仍有长尾：派发62.793ms、最长任务62.561ms、均衡比0.634；该任务44次逐点认证合计59.335ms，最长单次16.465ms，Fit调用0。这里还存在任务内部长认证，但不是把线程池收尾优化0.1ms就能消除的问题。

若要拆分一次认证，需要保留提案顺序、首次确定拒绝、进展汇总和异常语义；属于新并行粒度设计。现有短面/网格任务确有固定派发税，但合计绝对成本很小。本轮不再增线程或拆更多小任务。

## 5. 已探索候选：删除了什么、为什么没有更大收益

### 5.1 06G：坐标与参考高度

[06G报告](qpc_06g_coordinate_evidence_results.md)记录CE-01/02推导。Sierra移动精确参考构造438,788→72,106，区间参考2,283,289→1,235,382；被检查样本1,235,382、精确覆盖请求842,002均不变。这是明确删除无用构造，不是减少质量样本或认证义务。保留。

### 5.2 06H：失败准备后移；缓存试作撤回

[06H报告](qpc_06h_certification_preparation_results.md)记录CP-01/02。失败提示先做同一闭面支持成员判断，只有未被提示否决的路径才收集/排序完整支持；证书对象在双域通过后绑定。Sierra移动完整支持构建4,891次，减少7,838次失败路径准备；完整证书分配1,495次，原认证入口11,234次。样本和面证据人口保持。

尝试的根内最近支持缓存只有**1次命中/4,891次完整域循环**。提示机制已经消掉大量反复失败，剩下完整认证并非不断消费同一支持。撤回组件、接口和热路径缓存分支，保留程序、补丁、失败结果；不把它推广成“任意跨根证据复用都无效”。初次候选Sierra114.107ms包含未修改样本阶段也变慢；追加06G参考110.827、最终无缓存107.427，故未把一次回退全归因于缓存，见[时序调查](../../reviews/cpu_refinement/qpc_06h_timing_analysis.md)。

### 5.3 06I：样本续接

[06I报告](qpc_06i_sample_continuation_results.md)记录SC-01/02。枚举只需要包含关系，不需要被丢弃的重心权重；源/Q/比例不变时，参考高度也是持久事实。Sierra移动分别删除387,036次无用权重计算、复用387,036次参考高度。但完整样本准备22.306→22.147ms，没有大幅下降。

06J账本解释其余工作：Sierra仍有2,000,031次样本定位测试，46,059,513次样本求值计数（含视图刷新，不能全归续接）。诊断移动样本修复总0.403789s，其中`next_order`总0.025573s，约6.33%；两者是同一诊断的嵌套时间，不与Windows22.147ms相减。当前局部修复也不是全局排序：`PriorityIndex::PrepareRepair`只处理受影响的256记录块，但样本定位、闭面贡献、映射和投影仍有真实工作。

36,048次归属更新为同批再次选择，占387,036次更新的9.31%。改为最终归属后只投影一次最多直接消去这些重复求值，不能省对应闭面包含与局部状态维护；还可能删除中间投影异常，故本轮不实施。剩余复杂度应按被枚举位置a、闭面贡献c、实际更新u、修复块b计费，不能仅按事务数k宣称O(k)。

## 6. 捐赠方：纠正“已经完全惰性”，但当前没有未触达人口

`Reservation.cpp`共同池非空且存在需求时，先由`execution.Run`并行创建/认证所有捐赠提案；足迹才是在配对首次触达时构造。不能把“惰性足迹”写成“惰性认证”。

| 移动29机会计数 | Sierra | Canyon |
|---|---:|---:|
| 提前认证的捐赠候选 | 0 | 4,640 |
| 配对实际首次触达的捐赠候选 | 0 | 4,640 |
| 可仅靠不认证未触达候选删除的数量 | 0 | 0 |

诊断使用`TransactionalExecution.Diagnostics=false`，保留正常成功即停；不是完整枚举模式制造的全触达。Canyon返回段同样5,120/5,120。在这些段中仍有未成功请求遍历共同池，故提前认证人口全部会被真实配对访问。把现有并行认证改为串行按需不能减少数量，可能延长串行路径，本轮关闭该候选。结论仅限冻结输入，不排除另一些高成功率负载存在未触达捐赠方。

**仍有另一项未证的重复义务。** `Proposals::Donor`先调用旧`Certification::Measure`，逐点政策再调用`PointwiseQuality::Certify`；新政策虽跳过旧`Accepts`，却没有跳过Measure。Canyon的Measure包含份额9.10%值得重视。但Measure也以`projection_unknown`拒绝不可投影提案，不能因其旧最大值阈值不再消费就整段删除。后续若要取消，须先证明逐点证书覆盖该投影定义域义务，或保留便宜的同等定义域检查。**本轮没有此蕴含证明，故未实施；不把它包装为已排除优化空间。**

## 7. 视图、预留与剩余空间的边界

当前`PrepareView`已有持久双缓冲和`PublishView`交换，优先级已是分块索引/有限前缀查询。不能继续把旧版全Q复制回写、完整有序树重建作为尚待删除的工作。

仍存在全部Q投影、闭面样本归约、活动面评分及索引构造。令c为闭面贡献数，Sf/Sv为面/点物理槽数，a为捐赠评分读取的关联面次数，L=256为索引块长：当前准备包含O(q+c+N+Sf+Sv+a)，两侧分块排序至多另加O((Sf+Sv)log L)。前缀查询用各非空块首合并；有b块时包含O(b+r log b)，并不免除视图变化后的索引建立。槽数可能大于活动数，不能以N暗中替代所有分配/扫描成本。

Canyon普通Linux视图9.968ms；独立诊断提供的投影、评分、顺序构造总时间分别0.105899/0.113440/0.062505s（移动29机会），是另一遍阶段分解，不能与前者强行相加相等。它们共同说明不仅投影，面归约与索引也要付费。精确跳过非竞争区域需要可信上界和失效规则，不能直接假设相机变化只影响少量样本。没有证明所有等价算法都必须访问全Q，本轮也不新建层次查询算法。

当前普通Linux预留Sierra0.439/Canyon0.536ms；即使整个阶段免费，完整移动包络直接最多下降约0.69%/1.43%。拓扑准备、发布、网格准备合计0.829+0.112+0.146和0.217+0.020+0.121ms，约1.71%/0.96%。这些是同一计时遍的零成本敏感性，不是可实现收益。历史200k预留放大仍是别的负载/政策上的问题，不能被本次小人口否定，也不能搬来解释当前认证热点。

| 空间 | 本轮处置 | 仍开放的最小问题 |
|---|---|---|
| 坐标/高度、失败准备、无用插值 | 实施保留 | 已有同任务减工和有限计时，不继续宣称更大收益 |
| 根内支持缓存 | 试作撤回 | 更广复用须先证明人口和生命周期，不直接建大缓存 |
| 捐赠按需认证 | 当前无未触达人口，未实施 | 别的负载是否有可消除人口 |
| 旧Measure与逐点证书 | 明确记录，未删除 | 投影未知/拒绝语义是否可由新证书完整替代 |
| 精确覆盖及数值内核 | 仍是主要热点 | 更便宜保守谓词和数值表示的等价证明 |
| 样本最终归属后单次求值 | 未实施 | 中间投影异常及原子失败语义；定位/集合成本另计 |
| 全Q视图与精确前缀 | 当前算法工作仍在 | 可剪枝上界、查询代价和持续维护，不是简单省循环 |
| 预留/短提交/更多线程 | 本输入收益上限低 | 不据此关闭历史大批宽扩展性问题 |

因此本轮完成的是“列出的直接冗余与有限候选已逐项结账”，不是证明合理极限、不是证明剩余均为不可避免成本，也不是自动进入新算法分支。

## 8. 诊断差异、验收与构建恢复

Canyon最初因配对计数比较失败而停在分析阶段。追溯确认恢复工具每机会直接`Reservation::Plan`，正常`Pipeline::Update`会复用已认证空批。frames65～95正常`pairs=0`，恢复诊断每帧23,360；两边96帧的面数、哈希、需求、可行数量和执行数均相同。仅在静止、曲面和投影哈希均与上一帧相同、无新增事务的条件下允许此物理工作差异；其他差异仍报错。原捕获未重跑、未改删较慢样本，只重新归约。捐赠人口判断采用移动/返回段，不用这31帧的额外诊断工作。

06J只增加既有账本的CSV导出与专用归约脚本，无生产算法改动。复用06I三项定向测试及原生验收；最终Linux帧指针/Tracy构建、两条恢复诊断和各捕获均完成。没有重跑全项目测试，也没有声称进行了新的视觉签收；相同曲面复用已有证据。日常原生CMake配置已恢复`CBT_2024=ON / BUILD_TESTS=OFF`，冻结测量程序不被重建覆盖。
