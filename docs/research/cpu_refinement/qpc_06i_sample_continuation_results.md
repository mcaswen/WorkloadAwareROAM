# QPC-06I 样本续接减工：推导与结果

## 1. 冻结任务与源码原因

承接06H，输入仍为Sierra/Canyon源高及Sierra旧Fit代表，8线程、前缀160、96机会、D3D12普通CPU-ready。以06H final作前基线，保留06F/G历史结果。原始文件在`benchmark-output/cpu-refinement/qpc-06i/`。

`Enumerate`原先调用Weights，后者在成员谓词通过后计算StoredWeights，但枚举只返回身份，丢弃了系数。Prepare/Refresh随后又按原StoredWeights计算实际插值。Prepare中的Evaluate还重复计算固定源高度。这两项由源码可直接确认，不以perf占比猜测因果。

## 2. SC-01：成员判断与插值分离

原Weights可写为`if C(q,f) then w=W(q,f); return true`，Enumerate仅消费布尔值。新的私有Contains就是原C的逐边浮点过滤/精确回退，公开Weights仍组合C与W。因此闭面包含、共享边和Q人口不变，只消去枚举中未消费的W。

反例边界：如果改成简单epsilon包含或把边界丢到唯一owner，就会改变人口；本实现未改任何谓词、除法、区间或有理表达式。初始化也使用Contains枚举，但实际插值与共享高度检查仍保留，不能把成员资格当高度合法性。

## 3. SC-02：固定参考复用

持久参考值为初始化时的`SourceHeight(Decode(q), HeightScale)`。源/Q属于Samples，SetView拒绝改变HeightScale；拓扑事务不改变参考。故任意合法续接时刻t都有`h_ref(q,t)=h_ref(q,0)`，可以直接复用Geometry中的binary64值。

Prepare仍按原顺序更新owner、计算相同网格高度、绝对高度误差并执行原Project。没有用认证的有理参考替换运行时double参考，也没有省略当前投影或中间异常检查。初始化Evaluate不改，非法改变源/比例不在本不变量内。

## 4. 一次最终归属后求值：先计数，不自动实施

当前PreparedTopology.Faces按槽位遍历，理论上同一共享样本可能先归较大身份、再归较小身份。增加ownerSelections/reselections累计，复用已有newFaces查找结果，不为计数再查询一次。若重复极少，两遍重排及新临时映射没有价值。

即使有重复，删除中间Project会改变跨近面/非有限异常的观察点，需要单独说明前提；仅最终mesh哈希相同不足以证明任意输入行为等价。本轮保留原序列。

## 5. 成本与验收

局部候选定位仍O(a)，闭面贡献/映射维护和优先级修复仍按实际访问计费；删除每个枚举接收样本一次权重计算、每次owner更新一次源高插值。没有把完整样本续接改写成O(k)或O(1)。工作计数采用现有账本，在循环外归并，正常性能包含这些计数。

三条96机会逻辑字段、曲面哈希均相同。Linux持续状态、逐点质量、执行三个相关专项完成；原生构建和Sierra诊断完整。原始时序与均值/中位/P95见[精简数据](data/qpc_06i_sample_continuation/summary.json)。完整时间都在5%工程波动带内，不能把1.6%Sierra下降宣称成稳定整体收益；没有触发扩大重复矩阵。

Sierra移动实际少计算387,036次未使用权重，复用387,036次源高；样本更新顺序和投影次数不变。36,048次归属更新属于同批重复选择，占9.31%，因此理论上最多只省这部分投影，不会省掉对应面的闭贡献定位和最终优先级修复。由于还涉及中间投影异常语义，本轮不实现“两遍最终owner求值”；不以9.31%次数推算9.31%整个样本准备时间。

两个删除的算术确实存在，但受影响函数整体仍约22ms，说明主要剩余工作在其余定位、集合与顺序维护。保留无新状态的简单减工，结论为“局部重复计算删除，完整性能没有突破”；下一阶段以最终profile定位，不继续凭算术次数预支收益。没有改变持续质量状态、默认政策或DOD竞争性结论。
