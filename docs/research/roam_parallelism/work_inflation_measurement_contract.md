# Work–Inflation Gate：能力评估与最小测量契约

> 日期：2026-09-12；状态：**候选解释与待 Review 契约，尚未实施新测量**。
> 后续安排：用户希望优先进行参数化成本语义分析；本契约保留为测量备选，暂缓新增插桩和采集，不以旧测量结果拟合或预设新模型。
> 前提：用户认可[必要依赖审计](necessary_dependency_audit.md)的阶段出口，暂不建设理论低并行度分析器。本契约不改写[现有研究定义](../../plans/formal_experiment/cpu_roam_research_definition.md)。

## 1. 判断与可被否证的问题

这个方向值得做。它比较已有执行方式的成本，更接近现有数据能够回答的问题；不需要先证明所有合法实现都必须遵守某条发布链。

本 Gate 的问题是：**三类阶段的逻辑工作、执行组织成本和累计 CPU 成本，是否足以解释已经观测到的墙钟差异？** “增加并行度会增加多少工作”是动机，但本轮没有测量语义 span，不能宣称已经测出了某种 work–span 交换曲线。

待检验的解释包括：评分接近工作量不变的数据并行；拓扑尝试或批量映射增加准备工作；网格提交的固定执行成本随规模摊薄。竞争解释必须同时保留：实际并行部分太小、发生串行回退、负载不均、单项计算成本变化及尚未定位的内存/调度限制。数据不支持时，应缩小或放弃统一解释。

数据布局改善也不必表现为逻辑操作数减少：它可能降低每项操作成本。不能把所有 DOD 优化都归入“减少操作数量”。

## 2. 现有能力是否足够

结论：**足够启动 A/B/D 的有边界测量；不足以直接完成逐阶段 A→B→C→D 的全部归因。主要缺口是把已经存在的计数按实际动作导出，以及取得可分辨、边界一致的阶段累计 CPU 成本。**

以下是对当前源码和已归档材料的定向核对，不是新测量结果。

### 两项先纠正的历史解释

1. P5 的 24 个自然 split topology 目标全部未进入实际并行提交。因此本 Gate 对 DOD 首先研究的是**并行准备后回退的额外成本**，不能称为已经观察到“降低 span 后的代价”，也不能由此否定其他批量实现。
2. [CPU-CBT-02 结果](../../plans/cpu_cbt/cpu_cbt_02_parallel_bisect_plan.md)中，新串行模板填写仅占两个场景完整累计更新约 **0.066% / 0.209%**。新串行/新并行的完整累计耗时比中位数约 **1.0124 / 1.0133**，跨进程范围都跨过 1。已知的强解释是并行部分很小；分类、计划等成本很多原本就存在于三个动作中，不能全部记为并行化新增工作。此处为历史结果引用，不是本轮复现。

CPU-CBT 保留 reference serial / new serial / new parallel 三档：前一对反映移植、数据组织和新边界的成本，后一对反映同一新实现的线程收益。它与 DOD 语义不同，只作独立案例，不重建归档程序、不合并比值。

## 3. 冻结比较对象与成本边界

主对照为评分的 `SerialFullRefresh / ParallelFullRefresh`、拓扑的 `SerialImmediate / ParallelAssisted`、网格的 `SerialDirty / ParallelDirty`。现有网格配对还执行 `SerialFull`，保留其输出，但只作为减少写入工作量的旁证，不混入纯线程收益。

`S` 指原生串行动作；`P_p` 指请求 p 个线程的并行动作。只有实际分支支持相同执行结构时，`P_1` 才能代表并行实现的一线程版本；它不能自动视作 `P_p` 的完全相同串行执行。当前评分/网格的一线程分支会省去线程派发，拓扑的一线程请求仍可能构建计划。

每个动作从同一阶段输入独立执行，保留阶段、相机、资产、预算、输入/结果哈希、请求/实际动作、线程请求、实际路径及回退原因。线程计数字段主要描述区间任务/执行策略，不能证明恰有 p 个不同操作系统线程同时忙碌。

| 成本 | 所属边界 |
| --- | --- |
| 状态复制、输入哈希、来源重放、共同工作量探测、线程池创建/预热、结果验证和 CSV 写出 | 配对设施，阶段墙钟外；单独留档，不算生产新增工作 |
| 生产快照、候选排序/分类、分区、真实容器分配、派发、等待、归并、发布及收敛 | 阶段完整调用内；即使发生回退也全部计入 |
| 来源轨迹的完整更新 | 单独的真实连续调用；不能由不同冻结状态上的阶段中位数相加得到 |

计量关闭集合固定为 `EnablePassEvidence=false`、`EnableTopologyValidation=false`、`EnableTopologyPairEvidence=false`。正确性取证留在计时外。第一轮不启用完整拓扑访问观察，也不引入任务内原子计数或线程身份追踪。

## 4. A/B：逻辑工作和新增执行组织

工作量是一个有单位的向量，不能把评分次数、字节数和拓扑修改次数相加成任意的 W。每项标明 **实测计数 / 由执行路径与输入精确推得 / 仅有下界或代理 / 缺测**。分母为零时报告新增绝对数量，不制造无穷大的 inflation 比率。

| 阶段 | 最小逻辑工作账本 | 首版执行组织账本 |
| --- | --- | --- |
| split scoring | 实际 `SplitScoreEntryCount`；每项一次评分/镜像写回，串并行一致性核查 | 评分包络、串行重建堆包络；是否派发及任务区间数。堆比较、派发和屏障单项成本暂缺 |
| split topology | 实际快照候选数、内部/边界分类数；阶段前后 `SplitCount`、`ForcedSplitCount`、`MergeCount`、拒绝数及预算拒绝数的差 | 快照、构造计划、归并/维护、串行收敛已有计时；是否计划后回退；排序输入长度作为规模代理，不能称为比较次数 |
| mesh commit | 实际更新三角形数、脏区间数、实际全量/增量路径；合法脏提交每三角形写 3 个顶点与 3 个索引 | 共用计划、容器调整、区间填写和最终维护的源码归属表；完整调用计时。首轮不新增内部细分计时 |

`ForcedSplitCount` 是 `SplitCount` 的子集，不能重复相加。统计必须在执行前保存、执行后且结果取证前读取，不能把来源帧已有修改带入本次阶段。尝试/拒绝计数不等于所有递归访问量；基础成功修改只是总体工作的一个分量。

网格写入数的推导以合法槽位、叶节点及真实脏计划为条件；若现有验证不能证实，则只报告更新数代理，不冒称已经统计实际写入。这里的顶点/索引写入不包括容量增长、初始化、缓存流量和上传字节。

快照遍历规模、计划中排序/分类的候选规模可按已执行分支计入；可能提前停止的循环只记上界或未知。计时外 `WorkloadProbe` 的公共计划不能记在 S 或 P 的执行工作中。两个动作都做的维护不是并行新增工作。

各内部计时可能嵌套或采用扣除语义，**不拼成完整墙钟，不把“总时间减去几个子项”命名为屏障或缓存成本**。本轮允许保留未拆分部分；只有该缺口确实阻止阶段出口判断时，再说明唯一需要补测的包络。

## 5. C：累计 CPU 成本的准入契约

同一调用边界内定义 C 为整个进程所有相关线程的用户态与内核态 CPU 时间增量，包含调用/协调线程和线程池线程。该边界内不得同时运行另一实验或与阶段无关的后台任务。

\[
I_{\mathrm{cpu}}(p)=C_{P_p}/C_S,\qquad
S_p=T_S/T_{P_p}.
\]

Windows 的 `GetProcessTimes` 汇总进程线程 CPU 时间，FILETIME 的 100 ns 是表示单位，不是有效分辨率保证；[官方说明](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-getprocesstimes)也说明多线程累计时间可以超过墙钟。现有适配层 `CpuUtilizationPercent` 与阶段/流水线墙钟边界不同，不能相乘还原阶段 C。

**首轮采用独立成本诊断采集，与干净墙钟配对分开。** 只在真实阶段执行前后读取现有进程 CPU 累计值，复制、哈希、验证和 I/O 排除在外；读取顺序、边界包络、采样开销和有效性状态写入结果。干净墙钟路径不增加这些系统调用。两种采集分别报告，不能把诊断 C 与干净 T 当作同一次精确计量。

先对每类阶段的高工作量目标做一次有界预检：保存空包络及真实动作的原始增量，检查 API 失败、零值、量化、系统调用开销与同动作重复的离散程度。空包络只作有效性参照，不从每项结果机械扣除。预检固定一次，最多沿用一个进程的 5 次预热、30 次重复；不得为分辨几个微秒无限增加重复或人为复制生产工作。若变化无法可靠区别于量化/观察影响，C 标为 `unresolved`，不把 0 当无 CPU 工作，不以“不显著”宣称 C 相等。

外部工具已有 [QueryProcessCycleTime](https://learn.microsoft.com/en-us/windows/win32/api/realtimeapiset/nf-realtimeapiset-queryprocesscycletime)，其结果包括所有进程线程的用户/内核周期。但现有外部边界覆盖整个子进程，不能除以调用次数得到阶段值。若 CPU 时间不可分辨，本 Gate 先允许 C 缺测；把周期计数接入阶段、ETW 或逐线程计时均不自动成为后备建设任务。

累计 CPU 时间不是指令数：等待是否消耗 CPU、缓存停顿、频率和每项成本都可能改变结果。C 增大只支持“累计执行成本增大”，不足以定位缓存或同步原因。

在同一次且同边界的有效采集内，可报告平均占用核数代理 A=C/T，并核对恒等关系 `S_p=(A_p/A_S)/I_cpu`。这是成本记账，不是独立因果证据、语义并行度或 span 的测量。

## 7. 出口与不能推出的结论

| 出口 | 所需证据及措辞 |
| --- | --- |
| 解释得到支持 | 同状态/结果下，实际工作账本与包络变化能够解释墙钟方向；有可用 C 时补充累计成本，按阶段陈述，不声称证明因果唯一性 |
| 部分支持 | 例如评分逻辑工作一致、拓扑回退准备可见、网格规模相关；C 或内部拆分不足时，只保留得到支持的部分，不能写统一机制已证实 |
| 当前解释不足 | 真实并行、逻辑工作变化小且可靠 C 也接近串行，墙钟仍不扩展；记录具体未决项，再决定是否值得单独调查内存、调度或依赖 |
| 不值得继续采集 | 已有数据足以说明主要问题是小并行占比/回退，或观测设施成本超过收益；完成边界报告即可，不必补齐全部列 |

拓扑回退的负结果只针对当前动作与目标；CPU-CBT 结果只针对已实现并行边界。网格两端案例不能分离地形、预算和数据布局的混杂因素，不能据此拟合普遍阈值。若要正式论文的因果消融或总体适用范围，应另行规划，不能在此 Gate 中不断增加场景寻找正结果。

首版最不可替代的是**真实路径、同结果配对、实际工作单位、直接墙钟边界，以及新增工作和双方共有工作的区分**。阶段 C 对“实际 CPU work inflation”这一更强主张不可替代，但不是启动有限 Gate 的前置条件。精确 span、逐字段访问、每次屏障、缓存事件和全面硬件计数均不是本轮必需品。
