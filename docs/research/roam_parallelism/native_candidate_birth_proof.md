# 原生严格候选的局部出生与发布证明

> 日期：2026-09-13；依据：[NMP-CB](../../plans/roam_parallelism/native_candidate_birth_proof_plan.md)；源码基线 `c36286f`。
> 状态：**Pass（保守局部出生/发布契约）；纸面证明与原生有界核查完成。没有实现新堆，不代表性能通过**。
> 后续推导：§7 给出只读旧堆与新增版本的条件正确性、按变化计费的队列界和资格缓存的条件；纯变化触发不足以替代原生重新接纳。没有实现生产决策队列，也没有得到 2～5 倍性能保证。

## 1. 结论范围与证据来源

本研究检验的是同一严格控制器的决策信息维护，不求解新的目标，也不引用端点 Lean 定理来代替目标发现正确性。采用纸面操作语义证明，测试只核查该语义与原生代码的对应。

完备性对象是当前 Legacy 的逻辑候选观察域，不是重新证明“所有几何上允许合并的组必然进入 Legacy 队列”。如果原实现从未登记某个理想几何候选，本 Gate 的严格兼容目标不会据此把它加入新决策域。

先得到一条保守但有限的规则：一次成功基础细分或整个菱形合并，合并候选的新生、重新接纳及重新评分，均可由修改前后至多 84 个局部节点枚举覆盖。细分成员的出生则由实际激活的孩子/父节点覆盖。失败移除、阻塞和纯预算变化另列。

**这不是“仅孩子/父组就足够”的证明，也没有证明无需原邻域和资格查询。** 潜在收益是局部事务内暂时删除再恢复同一条目的过程不必转化为堆操作，以及失效条目无需任意位置删除。是否足以显著减少 Tplan 仍未知。

## 2. 冻结状态、身份和严格观察域

令 S 包含当前活动拓扑、缓存、历史/轮次、逻辑候选登记表 K、纯评分环境、预算/预留和控制位置。K 是决策语义的有限部分映射，不是物理堆布局：细分记录为 `(Path, storedScore)`；合并记录为 `(representativePath, partnerPath或空, storedScore)`。

`HeadRelevant(S,x) ⇔ x ∈ dom(K)`。它不是 `ShouldSplit(x)` 或 `CanMerge(x)`：这两个谓词分别用于头部停止判断和选出之后的执行复核。保留所有逻辑成员，包括 ±`float::max()` 抑制项及等待失败复核的旧条目。新的条目验证器只能验证 K 中的当前版本，不能以理想拓扑资格取代 K。

细分逻辑身份为 `(Split,Path)`。合并逻辑身份为 `(Merge,规范化实际成员Path集合)`，至多两个成员；比较键另存原生代表 Path，不能以集合的哈希或物理槽位比较。组从单成员变成双成员就是旧身份失效和新身份出生；同一组重新接纳沿用身份但发布新版本。此定义不假定原生动态 Base 等同 MPR 的固定 `Group`。

输入前提：有限缓存；有效下标访问；唯一且不溢出的 Path；缓存孩子成对存在或缺席，Parent/Path 关系固定；来源堆顺序、成员关联和活动索引相互一致；一次调用无外部并发修改，视图/评分参数、轮次、上一帧迟滞和入口迭代上限固定。所有参与观察及后续生成的队列键限定为有限浮点数，含有限哨兵，排除 NaN/Inf；手工有限键可作为初始 storedScore。此键域上原生分数/Path 比较是严格全序；浮点相等时用唯一代表 Path 打破平局。非有限输入不由本证明默许支持。

纯几何分数 q(Path) 在调用内固定，不等于登记键总是 q。局部重新入队按当前抑制/伙伴重新计算键，未触及的已有键继续保留。错误注入可破坏 `IsSplit` 与活动索引的一致，仍不能提前丢掉 Legacy 将选择后失败的登记成员；越界或已损坏的反向关联不在一般证明输入域中。

`NextRequest` 包括：迭代限制停止、低分合并、细分请求、根失败后的预算交换、阻塞与停止结果。预算上下文是输入，不把 `NextRequest` 简化为一次 max。队列物理形状和逆向槽位不是这些观察的组成部分。

## 3. 局部规则及出生完备性

### 3.1 有界支持

对有效节点 v，定义

\[
D_S(v)=\{v,parent(v),leftChild(v),rightChild(v),base(v),left(v),right(v)\},
\]

\[
H_S(v)=D_S(v)\cup\{parent(w),base(w):w\in D_S(v)\}.
\]

丢弃无效项并按首次出现去重，故 `|H_S(v)|≤21`。这是展开源码读取后的明确枚举，不调用旧刷新器作黑箱。

基础细分 r 的 a 是完成全部必要 forced 前置后、实际提交 r 时的 Base。在缓存孩子创建之后、活动转换之前取
`V⁻=H_S(r)∪H_S(a)`；活动转换完成后取 `V⁺=H_S'(r)∪H_S'(a)`。令 V 为先 V⁻ 后 V⁺ 的有序去重并，`|V|≤84`。

整个合并同样使用操作前的 r/a；成对合并后追加双方邻域，单侧合并后只追加 r，仍满足 84 上界。二者都在这个有限区间内清理旧登记、再刷新，不在中间查询严格队首。forced 递归在每次基础提交之前进行，因此一次根的上界是这些基础操作支持之和，不是 84，也不是净 Δ 的大小。

### 3.2 候选解析与局部登记语义

定义 `G(S,v)`：按照活动内部、活动叶孩子、Base 为无效/活动叶，或互指内部 Base 与其活动叶孩子的规则，得到规范代表和伙伴；否则为空。它检查 O(1) 个字段。组键按组中任一 `SplitBuild` 为本轮则取最大哨兵，否则取两侧 q 的最大值。

操作区间的逻辑登记变化可独立写为：

1. 对 V⁻ 中每个节点，从旧 K 的成员→组关联找到登记组并逻辑移除，至多每个节点一个组。此处不删除物理堆条目。
2. 遍历 V：计算 `G(S',v)`。若为空或代表仍关联到已有组，跳过；否则清理其伙伴可能关联的旧组，登记新的组与键。这个防御分支也要处理，不能默认从未发生。
3. 完成局部登记后，把涉及的旧组、新组、伙伴受害组与区间入口比较，只发布最终存在性/键/身份发生变化的记录。没有变化的区间端点记录沿用原版本。

这里保留了原生局部**逻辑**维护的顺序和代价，去除了对堆位置的要求；不是声称清理和资格工作已经消失。受影响组由 V⁻ 的登记查询及 V 的解析/伙伴查询枚举，不通过遍历全部 K 求差分。测试可以全量求差分核对这个集合，但算法规则不能如此构造。

**引理 B-M（合并候选出生）。** 在上述区间中，若 x 在出口登记、入口未登记，则 x 来自 `G(S',v)`，其中 `v∈V`。

证明：步骤 1 和伙伴清理只能删除；新记录只能由步骤 2 的插入产生。设 x 最后一次被插入时的扫描节点为 v。期间拓扑 S' 不变，解析所得身份就是 x；后续没有再删除它才会出现在出口。因此 x 被有限解析集合覆盖。该论证同时覆盖新拓扑资格、失败候选重新接纳和身份改组，不要求资格本身刚变成 true。

**引理 K-M（改键/旧组失效）。** 出口仍存在但键改变的组，必定经历步骤 2 的重新登记；消失的入口组必定被 V⁻ 的关联查询或步骤 2 的伙伴清理命中。因此它们也由上述受影响组集合覆盖。现存代表导致跳过时不会重新计算 storedScore；这与源实现一致。

**引理 B-S（细分候选出生）。** 基础细分只删除父叶登记、插入两个孩子；单侧合并只删除两个孩子、插入父叶。故出生分别包含于 `{child0(r),child1(r)}` 和 `{r}`。阻塞仅重写该叶键；缓存创建但未激活不出生；纯预算预留/释放不更改成员。成对合并按两次叶转换合并这些集合。

缓存缺失时，源码在采集 V⁻ 前创建两个新孩子。新孩子此前无登记，其 parent 是 r、Base 初始无效；这不会增加需要清理的旧组。核查器可在前快照尚未包含孩子时略去这些新节点的旧关联查询，但必须用实际出口孩子补齐 V⁺ 并单列创建数。复用缓存孩子已有关系，不能作同样省略。

### 3.3 所有转移的审计结论

| 转移 | 细分登记 | 合并登记 | 标记/键/生命周期 |
| --- | --- | --- | --- |
| 普通 split | 父退出，两个孩子出生 | 按 B-M/K-M 处理 V；新 ready 组可能存在 | 父写本轮 SplitBuild，组被抑制仍是登记成员 |
| forced split | 与普通基础 split 相同 | 同一 V 规则，根结果不取消已完成前置 | `PrepareSplitNodeState` 无论原因均写 SplitBuild；强制来源另外写入 |
| 单侧/成对 merge | 孩子退出，父出生 | 同一 V 规则，可能向更高父组出生 | 每个恢复父写 MergeBuild；其细分键被抑制，仍保留条目 |
| split block | 仅该成员改键 | 无直接变动 | 写 SplitBlockedBuild；本调用内没有清除此字段的普通路径 |
| failed merge removal | 无 | 移除该登记组 | 失败缺席不能由理想资格自动解除；保留对应处置 |
| 后续重新接纳 | 无特殊规则 | 被后续 V 解析并实际插入时出生 | 撤销实际插入代表/伙伴的失败记录；并非“资格恢复就自动撤销” |
| cache birth / reuse | 创建本身无出生，激活用 B-S | 后续由 V 解析 | 创建、激活、历史字段不混为一个事件；不得清空旧 blocked/merge 标记 |
| reserve / release | 无 | 无 | 预算仍改变后续分支，不能因此从 K 移除候选 |
| budget exchange | 取失败前置之后的登记头 | 执行 merge 时用其自身规则 | 中途成功前置、实际释放和停止保持原逻辑 |
| Base/代表/伙伴改组 | 除叶转换外无直接修改 | 解析为新成员集合；旧组按关联清理 | 审计旧伙伴和新伙伴，比较仍按原生代表 Path |
| 帧/评分切换 | 重新初始化覆盖 | 重新初始化覆盖 | 不属于本调用局部维护定理；不承诺跨帧 O(1) |

“split 后没有 merge birth”若指逻辑登记就是错误命题：新组可以以最大哨兵入队。若仅指新组不会立即执行反向合并，还需键域/阈值和预算分支条件；它不用于主证明。

失败重新接纳说明更小规则的风险：一个组在拓扑上一直 ready，但被显式移除后，在后续邻域触及时重新登记。仅从 Leaf/MergeReady 的 false→true 集合发布会漏掉它。此处先保留 V；要进一步减少邻域访问，需要额外证明更小触发集合，当前没有把这个任务偷算完成。

## 4. 发布、极值和控制归纳

维护逻辑登记 K 和只追加的版本条目集合 A。为每个身份保存不回退的版本号；物理槽位重用不影响身份。入口读取 Q₀ 个来源条目，建立 K、成员索引和 A 的总费用记为 `C_seed(Q₀)`，不把读取量等同构造费用。局部区间结束时只处理上述枚举出的受影响身份：出口相同不动；删除使版本失效；新建或改键增加版本并追加当前记录。

**覆盖不变量**：每次严格查询前，所有 `x∈dom(K)` 都至少有一个 A 中条目，其身份、版本和键与 K 一致。**可靠性不变量**：A 中被判为有效的条目必须对应当前 K；判断不包含 `ShouldSplit` 或 primitive 的成功条件。

证明：初始化满足。局部支持外 K 不变；支持内改变由 B-M/K-M/B-S 及独立的阻塞/失败规则完整枚举，按版本发布保持覆盖；删除只使旧版本无效。区间端点未改变的组无需失效，因区间内没有严格头部观察。即使中间移除后恢复同一键，失败生命周期仍按真实重新接纳处理，不由版本不变推导“什么都没发生”。

有限 A 按原生全序取头并弹掉无效版本。由于覆盖，每个 K 成员都有当前有效记录；因可靠性，不会接受额外的语义成员。因此首个有效头与 K 极值完全一致；同分由相同代表 Path 决定。空 K 时所有历史条目最终被排除，返回原空队列语义。

控制归纳以同一 S、迭代和预算为起点。低分合并头、细分头、迟滞和停止谓词相同，给出同一请求；保持原 primitive 后，同一 forced 路径、部分失败和标记/预算得到同一逻辑状态。再次完整发布后，失败预算交换读取同一新合并头，阻塞和失败移除也相同。逐观察点归纳得到同一严格轨迹和目标端点。

**限定**：这是一条“保留这些原生转移 + 完整局部发布 ⇒ 同请求”的纸面定理，不证明一个尚未实现的新 Planner，也不证明 Γ 可由净 Δ 独自恢复。无序条目账本的测试不等于真实 heap 原型。

## 5. 复杂度与尚未获得的收益

记 m 为实际基础细分、整组合并、阻塞与失败处置数，Q₀ 为初始条目数，q 为严格头部观察次数。每个局部节点最多 21，每个完整支持至多 84；解析为常数次字段读取，登记查找成本记为 L，不假设容器免费。

在节点寻址和纯评分均为单位原语的模型中，局部枚举及登记工作为 `O(m·L)`（常数含原邻域和资格复核），初始化 `C_seed(Q₀)` 另计。若使用有序登记表，可取 `L=O(log(Q₀+m))`，从未排序来源逐条建立登记索引一般付 `O(Q₀ log Q₀)`；线性读取/追加 A 不使整个初始化自动成为 O(Q₀)。采用哈希期望线性构造时须另写哈希及分配假设。需要额外 Path 解码时独立计入 H。保留参数化费用时，还应分别列出字段访问次数乘 `c_field`、登记操作次数乘 `c_registry`、实际评分次数乘 `c_score`，不能把它们视作免费。本结论仅关于候选维护，不包含目标发现所需的其他 primitive、邻接、分配或出口提取。本结论不依赖全域 n 扫描，但绝非 O(|Δ|)：失败、forced 以及没有净事件变化的维护都计入 m。

版本发布总数 p、实际过期弹出数 z 单列，`z≤Q₀+p`；驻留条目最坏 `Q₀+p`。一个比较堆的 push/pop 模型费用为 `O((p+z) log(Q₀+p))`，q 次验证还要付登记查询费用。清理、分配、构造和销毁不能移出 Tplan；本轮没有实测这些堆费用。

已可从语义中删除：任意位置 heap remove、对应 sift/反向槽位修复，以及区间端点相同记录的重复版本发布。仍需要：局部节点枚举、资格与键判定、成员→组登记、失败生命周期、预算/活动计数及来源条目初始化。不能用含 stale 的 heap 大小代替真实叶数。

此登记只需候选成员的关联，不在数学上要求为所有 n 个缓存节点建立 `SplitPosition/MergePosition`；但当前 View/Membership 四字段投影仍是实际实现，是否整体消失只能由后续原型实测。历史 25115 次恢复已由 NMP-01P 延期机制节省，不再记一次新收益。

## 6. 原生核查、反例和出口

实现为 [DataOrientedRoamCandidateBirthTests.cpp](../../../tests/DataOrientedRoamCandidateBirthTests.cpp)，只登记为独立 CTest 目标。Legacy 驱动真实操作；独立局部规则维护登记表和无序版本账本。每个受支持区间出口完整比较成员/身份/键，并核对当前版本覆盖、数学极值和 **Legacy 实际 heap front**。核查器不调用原 `Refresh` 生成答案，也不依赖 `NativePlanningQueues`，不运行新 controller。

观察到的 `SplitComplete` 已在该基础细分刷新之后；合并则等 `MergeRootEnd` 成功后才比较，`MergeComplete` 仅记录实际合并节点。请求、停止、根失败和后续迭代也检查真实头部。每次字段写和半个菱形中间状态没有全量原生检查，依赖 §3 的无查询区间及源代码对应。不存在把串行执行轨迹直接当必要依赖的推导。

| 迭代保护 | 保留入口上限及后增停止规则 |
| 核查器自测 | 漏一个高分出生、持续成员改键未发布两类错误均被独立成员答案检出 |
| 12 个有界配置 | 深度 2～4 × 余量 0～3，每个最多 64 次迭代；全部一致。前 8 个仅覆盖深度停止，不能充作 8 组新拓扑覆盖 |

故障夹具不是自然共形 workload 的普遍可达性证明；它用于保留既有防御语义。显式生命周期例也是有意构造的 API 转移，不冒称其本身由某次自然预算交换生成。自然失败缺席仍不能靠无失败样本免证。

`pendingFailureRecords` 是诊断登记表中的待处置记录，不能直接当作最终 Γ 数量；是否构成原生端点义务还需最终资格及缺席检查，本轮未替换该提取器。

### 7.2 隐式初始覆盖与版本覆盖

不再把全部 K₀ 复制到新账本。维护：

| 对象 | 内容与职责 |
| --- | --- |
| 只读 H₀ | 初始版本条目，包含尚未读到的后代 |
| F | 旧堆搜索边界，只保存少量 H₀ 下标及其冻结排序键 |
| B | 已发布的新版本条目堆，保存身份、版本和排序键 |
| C | 发生过可观察登记变化的身份及当前版本/键/缺席信息 |
| A | 按需修改的成员→组逻辑关联；没有覆盖的成员从来源关联读取 |

C 中没有记录的来源身份，隐含地仍以初始版本 0 存在。初始无该身份时，隐含缺席。身份出现可观察删除、新增、改键或改组时更新 C；出口存在的变化条目追加到 B，删除则保留缺席及版本记录。版本不回退且不能在恢复初始键时删除覆盖记录，防止旧条目错误复活或已展开条目失去覆盖。

如果同一无查询区间的入口、出口身份与键完全相同，可以保留原版本；这不免除区间内失败记录撤销等 Γ 生命周期。C 和 A 不是堆反向位置：它们记录当前语义成员及分组，仍需查询、分配和维护。

于是 §4 的覆盖改写为：每个当前 K 成员，要么由一个仍有效的 H₀ 初始版本隐式覆盖，要么由 B 中一个当前版本覆盖。覆盖不要求提前把 H₀ 所有后代读入内存中的新容器。

**初始化。** 每个非空旧堆仅把下标 0 放入 F，B/C/A 初始为空。借用来源关联的前提下，这个队列启动只需要常数次访问；不等于整个 Planner 或视点更新的启动为常数费用。

### 7.3 查询算法及严格队首证明

查询不先分别清空两侧所有无效项。先比较 F 与 B 的头部，处理较优的一侧：

```text
Head():
    while F 或 B 非空:
        比较两侧头部冻结排序键，选取较优条目 e
        if e 来自 F:
            if 其初始版本仍属于当前 K:
                return e                  // 只读，不弹出有效条目
            从 F 弹出这个旧下标
            将 H₀ 中存在的两个孩子下标加入 F
        else:
            if e 的身份、版本和键仍属于当前 K:
                return e                  // 只读，不弹出有效条目
            从 B 弹出这个过期版本
    return 原生空队列结果
```

相同排序键的历史物理条目可以另加稳定的来源/序号次序；当前有效成员之间仍按原生代表 Path 区分，不能更改逻辑 tie-break。验证器只验证登记版本，不过滤“执行会失败”或“迟滞会停止”的头部。

**引理 R-F：旧堆边界覆盖。** F 中的下标所根植的未展开子树，两两不交并覆盖所有尚未展开的旧条目。每棵子树的根在原生全序上不劣于其任何后代。

证明：初始只有旧根，覆盖整个堆。展开一个根后用两个孩子的子树替换它，保持覆盖；原堆有序性给出优先级支配关系。原根逻辑失效不会改变其孩子的初始键，所以不能把“根失效”解释为“整棵子树失效”。

**引理 R-H：返回的头等于当前 K 的极值。** 查询终止并返回当前 K 中最优条目；空结果当且仅当 K 为空。

证明：由隐式覆盖，任一当前成员由 B 或未失效的旧条目覆盖。B 的头支配 B 内其余条目；R-F 保证 F 的头支配所有尚未展开的旧初始键。若选中的条目有效，它因此优于所有当前有效成员；无效时只移除不属于 K 的版本，并保持旧堆边界覆盖。有限条目每次失败至少弹出一个，故终止。旧身份的键发生改变时，原键不能继续充当它当前键的界，但该身份已经在 C 中失效，新键由 B 覆盖；此处必须使用改键发布完备性。

一个有用的省略：若 B 的有效头已经优于 F 的根，即使 F 内有大量失效项，也可以直接返回 B 的头。没必要为了求这次极值而先清理旧堆。

结合 §4 的原生控制归纳，在相同逻辑转移、局部发布和生命周期处理的前提下，仍有 `NextRequest_new = NextRequest_Legacy`。这只证明新的队列表示可以替换，不能由此删除逻辑转移本身。

### 7.4 按实际变化计费的较强队列界

记 Q₀ 为两堆初始总条目数，t₀ 为其中至少发生过一次可观察登记变化的初始身份数；b 为追加的新版本总数，r 为实际弹出的旧初始条目数，z 为实际弹出的新增过期版本数，q 为实际队首查询次数。

**引理 R-W：**

\[
r\le t_0\le Q_0,\qquad z\le b.
\]

证明：有效头查询不弹出条目。一个旧初始条目只会因它的版本已经失效而被弹出，因此每次旧弹出对应一个发生过登记变化的初始身份；每个原下标至多展开一次。新的每个物理版本同样至多弹出一次。版本不回退保证删除后恢复旧键仍由新版本承担覆盖。

设非空来源堆数 s≤2。引入 F 的旧下标总数 u 和 F 总大小满足：

\[
u\le\min(Q_0,s+2r),\qquad |F|\le s+r.
\]

这比笼统的“枚举 r 个旧候选”更强：在此特定的、非消费式严格头查询模型中，旧堆处理量受初始成员的实际变化控制。若把有效 Head 当作迭代器消费，或者先枚举整张排序列表，这个界就不能沿用。

令 t 为 C 中曾变化身份数、L(t) 为 C/A 一次登记查询费用。比较堆模型的队列费用为：

\[
W_{queue}=
O\bigl((r+1)\log(r+2)+(b+z)\log(b+2)+q\bigr)
+O\bigl((q+r+z)L(t)\bigr)+W_{publish}+W_{sourceLookup}.
\]

所有局部关联写入和版本发布中的登记操作计入 `W_publish`；来源键/身份解码计入 `W_sourceLookup`。若 C/A 用平衡树，L(t) 可计为 `O(log(t+2))`；不能默认它和 Legacy 的直接数组访问一样便宜。哈希期望常数查询需要独立的分配、装载率和哈希假设。

额外空间为 `O(r+b+t+a)`，a 是成员关联覆盖规模；不含只读来源自身，也不含其余逻辑拓扑状态。构造、增长、析构均计费。没有每次删除的可变堆位置或对应反向位置更新。

在 §3 的保守规则下，t₀、b、a 受实际 m 次基础转移的局部支持累计控制，常数含最多 84 个节点；不是按净 `|Δ|` 控制。候选经历多次变更后恢复，仍可能有 b 很大而净 Δ 很小。r 接近 Q₀ 的情况仍然存在：例如大量高优先级旧项失效，仅剩最低优先级初始成员，此时必须付实际展开费用。

### 7.5 资格缓存能证明什么，不能省略什么

针对 §3 的纯几何解析 G(S,v)，可以证明一个精确的读依赖缓存引理。R 是某次确定性求值实际读取的完整逻辑资源集合，含活动/存在性、孩子、Base、对侧 Base 与孩子、代表 Path 等；分支条件的读取也必须包含。逻辑资源用稳定身份表示，不把可复用物理槽位误作永恒身份。

**引理 R-C：** 若 R 中所有资源的值到下次查询都未改变，且求值环境不变，则再次执行 G 的分支、读取序列和返回值相同。

证明：按旧求值的读取/分支序列归纳。下一次读取的地址由此前相同的输入和分支决定，因此仍在旧 R 中并取得相同值。包括“当前不存在/无效”在内的判定也相同，直到返回相同结果。新关系会使读取集合发生变化，但必须先经过旧执行已读取的关系或分支输入改变；该证书因此先失效，重算后重新登记 R。

此引理允许缓存 **G 的返回值**，不允许省略整个有副作用的 `InsertMergeQueueNodeIfEligible`。后者还读当前成员登记、处理伙伴受害组、重新评分和撤销失败记录。

可实现证书有两种费用取舍：每次查询检查 R 的全部 revision，会保留 O(|R|) 次访问；写入时通知订阅该资源的证书，可把干净缓存查询降为一次标记检查，但付出订阅索引、通知与重绑定费用。不能同时把两侧成本都省去。

设 g 为原资格求值请求数、e 为实际重算数、U 为写入触发的订阅访问数、A 为订阅绑定/解除动作数，缓存有收益至少要求：

\[
(g-e)c_G > g c_{check}+U c_{notify}+A c_{bind}.
\]

没有证明每个资源的订阅者数量为常数。若一次状态变化使许多证书失效，U 必须如实增长；若每次请求前读集都发生变化，e=g，缓存只有新增成本。资格正确性不推出高命中率或加速。

同样思路可用于纯邻域 H(S,v)，但其读集也包含实际关系及分支判定，而且修改根的前后邻域很可能反复失效。本轮没有证明它能显著降低原 1795522 次邻域访问，不能把“可缓存”写成“已取消”。

### 7.6 更小触发集合的反例与限制

**反例 R-1：资格不变仍会出生。** 合并组 x 拓扑上始终 ready，却因失败从 K 移除。之后按原生规则执行 `Refresh` 触及 x，重新登记该组；G 的输入和输出可以完全不变。若只在 G 依赖写入或 `MergeReady` 的 false→true 时发布，便漏掉 x。设 x 优先于另一个现存组 y，严格头部随即分叉。§6 的失败/重新接纳原生核查和同拓扑显式例已记录这类边界。

**反例 R-2：几何不变不代表 storedScore 无需更新。** 本报告输入域允许初始手工有限 storedScore。令一个已登记组的存储分数为 1，固定纯评分为 10，另一组分数为 5；重新登记前后 G 不变，但原生重插将前者变成 10，合并头由该组变成另一个组。只缓存几何资格并忽略这次登记/重新评分会出错。此例针对完整手工键输入契约，不冒称自然已评分来源一定存在这种失配。

**反例 R-3：不能把执行资格当版本有效性。** 仍在 K 中但 primitive 将失败的组，必须先被严格控制器选择、执行并记录失败。提前以 `CanMerge=false` 清理会跳过这次观察和生命周期。有限抑制条目、迟滞停止项也不能随意删除。

因此，“只有实际几何变化才需要维护候选”在当前完整契约下不成立。保留一个正确的 G 缓存可以减少重复字段求值，但触及、失败重新接纳、存储键更新和伙伴关联效果仍须按规则处理。即使 G 缓存命中，也应使用缓存结果执行应发生的登记动作。

还不能证明把前后至多 84 个节点的原局部支持缩成只有孩子/父组。想去掉剩余邻域遍历，需要另证更小触发集合覆盖失败重新接纳、改键与防御性伙伴清理；或者先收窄合法输入/观察契约并重新评审。这里没有为性能目的默默收窄输入。

### 7.7 完整成本与 2～5 倍要求

上述 R-H/R-W 给出可取消工作，但完整发现仍是：

\[
W_{discover}=W_{stateInit}+W_{logicalTransitions}+W_{localSupport}
+W_{score}+W_{queue}+W_{\Delta,\Gamma}+W_{allocation/cleanup}.
\]

队列相关的全量堆复制和可变反向位置维护可以由新表示取消；节点覆盖初始化、动态邻接、活动语义、孩子缓存/历史、失败处置和出口费用并没有由本节取消。输入只读不等于不维护任何私有逻辑状态。初始成员关联可借用不等于生产最终队列已被恢复。

| 成本 | 本轮结论 |
| --- | --- |
| 决策堆全部 Q₀ 条目的复制/重新建堆 | 在 §7.1 前提下可以取消，用只读边界替代 |
| 任意位置删除、相应 sift 与可变反向位置维护 | 可以取消，支付版本登记和实际过期头费用 |
| 队列成员全 N 行可变位置投影 | 数学上不必需；已有来源关联按需借用，当前实现尚未替换，其他 N 相关准备费用仍单列 |
| 区间端点未变的物理重发 | 可以避免；NMP-01P 已消除的 25115 次恢复不能再次算收益 |
| 重复 G 字段求值 | 条件可缓存；命中率和通知成本未知 |
| 原生逻辑登记、失败重新接纳、伙伴处理 | 未取消，几何变化触发不足以替代 |
| 所有邻域访问、逻辑拓扑模拟与 Γ 提取 | 未证明可取消或按净 Δ 计费 |

把原生状态修改替换成更贵的私有访问仍可能抵消队列节省。若目标为相对 Legacy 快 s 倍，完整账本必须满足：

\[
T_{discover}\le T_{Legacy}/s.
\]

“少掉的费用减去新增费用”至少要达到 Legacy 的 50%（s=2）或 80%（s=5），不能以某个子项大幅减少替代完整条件。这里没有这些原生费用系数，也没有已实现的新算法计时。

按 NMP-01P 已记录压力口径，Legacy 为约 61.801 ms，发现目标对应约 30.901/12.360 ms。还有一个直接的设计预算约束：当前粗遍提取/排序 14.224、汇总 5.618、销毁 0.633 ms，合计约 20.475 ms。**若新方案原样保留这组出口费用，5 倍目标仅出口就超额；2 倍目标给其余全部发现只剩约 10.426 ms。** 这只是沿用当前量级的条件预算检查，不把不同遍的插桩费用当成机器无关下界，也不承诺出口必然保持这些数值。

复制来源再执行 Legacy 是另一条必须比较的直接求解基线，其复制、同等输出提取和清理需要单列；不能把现有 61.801 ms 自动改称已经测过的“完整复制＋求解＋相同输出”费用。性能表述继续沿用原报告边界，不通过更换口径宣布本构造通过。

### 7.8 抽象核查与本轮出口

只运行 Ubuntu Python 标准库抽象核查，产物放在既有忽略目录：`benchmark-output/roam-materialization/nmp-cb/readonly_queue_model_check.py` 及 `readonly_queue_model_result.json`。核查器借用只读初始映射，独立全量字典提供极值答案；后者只服务核查，不用于新查询算法。它输入已知登记变化，**不自动发现出生，不验证新 C++ 或新原生状态表示**。

固定范围：两种优先方向、3 个初始身份构成的 4 个合法初始堆排列；4 个可操作身份，每步删除或取 -1/0/1 三档键，共 16 种操作；深度至多 3。合计 17476 个操作前缀，另加 500 个固定种子长序列操作和定向例，共 17986 次独立答案核查，每次重复查询两次以确认有效头不会被提前消费。

定向例覆盖：过期旧根仍展开孩子、隐藏旧成员改键后优先出现、删除并观察后恢复原键、同代表的组身份更换、有限抑制哨兵、空来源、新条目优于全部旧项时不清理旧堆、126 个过期旧项仍需实际展开的最坏例。逐点检查 `r≤t₀`、`u≤min(Q₀,1+2r)`、`|F|≤1+r` 和 `z≤b`。三个错误变体——漏发改善键、过期根剪掉子树、删除版本后回退默认 0——均产生错误队首并被检出。

最终这次抽象核查约 0.041604 s；这是小模型自检费用，不是 Planner 性能。脚本 SHA-256：`0583f22fa1732caa9849005bd585a1f9e5812ebb9abe8ca206c68364ac5a9340`。未运行新 CTest、生产构建、自然基准或完整矩阵；生产源码和旧严格夹具没有修改。纸面归纳承担一般参数下的证明，有限核查不能冒充 Lean 机械证明。

**本轮出口：队列替换的条件定理成立；主要工作削减仍未闭合，2～5 倍发现算法未成立。** 比原 §4 的显式初始覆盖更进一步，已证明旧堆可以按实际变化增量访问而不复制 Q₀；但纯几何变化触发不能覆盖整个原生维护语义，资格缓存仅有正确性及条件收益界。本结论不否定更便宜发现算法存在，也不批准直接进入新的生产实现。

这里的只读堆搜索、版本淘汰和读依赖缓存都是可独立解释的通用构造，不据此主张新颖性。[Chen 等的优先队列研究](https://www3.cs.stonybrook.edu/~rezaul/papers/TR-07-54.html)提供了避免某些原位更新的既有算法案例，其 Dijkstra 性能不能外推为 ROAM 的 2～5 倍证据。
